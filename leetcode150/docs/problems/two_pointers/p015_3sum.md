# 15. 3Sum

- Difficulty: Medium
- LeetCode: https://leetcode.com/problems/3sum/
- Official Group: Two Pointers
- Pattern Group: Two Pointers
- Patterns: two-pointers, sum

## Core Pattern

Reduce a higher-dimensional sum problem into a lower-dimensional one. For 3Sum, sort the array, fix one value, and solve the remaining two-value target with a two-pointer scan.

## Why Two Pointers Fits

After sorting, fixing `nums[fixed_index]` turns the problem into finding two values in the suffix that sum to `-nums[fixed_index]`. The suffix is sorted, so the pair sum changes predictably:

- moving `left` right increases or preserves the pair sum;
- moving `right` left decreases or preserves the pair sum.

Sorting also groups duplicates together. That matters because the problem asks for unique value triplets, not unique index triples. The same value combination should appear once even if many index combinations produce it.

## Recommended Approach

1. Sort `nums` in place.
2. Iterate `fixed_index` from `0` through `len(nums) - 3`.
3. If the fixed value equals the previous fixed value, skip it to avoid duplicate triplets.
4. If the fixed value is positive, break; all later values are also nonnegative and cannot sum to zero with it.
5. Set `left = fixed_index + 1` and `right = len(nums) - 1`.
6. Compute `current_sum = fixed_value + nums[left] + nums[right]`.
7. If the sum is zero, append the triplet, move both pointers, and skip duplicate left/right values.
8. If the sum is too small, increment `left`.
9. If the sum is too large, decrement `right`.

## Alternative Approaches

The brute-force baseline checks every triple and takes `O(n^3)` time. A hash-set approach can fix one value and search for complements in `O(n^2)` time, but it uses extra space for each fixed value and makes duplicate handling less transparent. Sorting plus two pointers keeps `O(n^2)` time, uses constant auxiliary space apart from output, and gives a clear local rule for avoiding duplicates.

## Correctness Sketch

For each distinct fixed value, the inner scan solves a sorted two-sum problem on the suffix. If `current_sum < 0`, every pair using the current `left` with an index at most `right` is too small, so advancing `left` discards no valid triplet. If `current_sum > 0`, every pair using the current `right` with an index at least `left` is too large, so decrementing `right` is safe. If the sum is zero, the triplet is valid. Skipping equal fixed values prevents generating the same first value twice, and skipping equal left/right values after a match prevents repeating the same remaining pair. Thus every unique zero-sum value triplet is produced exactly once.

## Trace

For `nums = [-1, 0, 1, 2, -1, -4]`, sorting gives `[-4, -1, -1, 0, 1, 2]`.

| Fixed | Left | Right | Sum | Action |
| --- | --- | --- | --- | --- |
| `-4` | `-1` | `2` | `-3` | too small, move `left` |
| `-4` | `0` | `2` | `-2` | too small, move `left` |
| `-1` | `-1` | `2` | `0` | record `[-1, -1, 2]`, move both |
| `-1` | `0` | `1` | `0` | record `[-1, 0, 1]`, move both |
| next `-1` |  |  |  | skip duplicate fixed value |

The result contains the two unique value triplets, regardless of output order.

## Complexity

- Time: `O(n^2)`. Sorting costs `O(n log n)`, and the fixed-index loop with a linear inner scan dominates.
- Space: `O(1)` auxiliary space beyond the output list, ignoring sorting internals.

## Common Pitfalls

- Forgetting to sort before using two pointers.
- Returning duplicate triplets when the same values appear at multiple indices.
- Skipping duplicate left/right values before recording a valid triplet instead of after.
- Comparing output lists without normalizing order in tests.
- Forgetting that the implementation sorts `nums` in place.
- Missing the early break when the fixed value becomes positive.

## Interview Script

"I sort the array, then fix one value and run a two-pointer two-sum search on the suffix for the negated fixed value. Sorting lets me move left when the sum is too small and right when it is too large. I skip duplicate fixed values and duplicate pointer values after recording a triplet so every value combination appears once."
