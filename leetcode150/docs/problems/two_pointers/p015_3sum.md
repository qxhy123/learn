# 15. 3Sum

- Difficulty: Medium
- LeetCode: https://leetcode.com/problems/3sum/
- Official Group: Two Pointers
- Pattern Group: Two Pointers
- Patterns: two-pointers, sum

## Core Pattern

Turn a three-value search into repeated sorted two-value searches: sort the array, fix one value, then use two pointers to find complementary pairs in the suffix.

## Why Two Pointers Fits

Once the array is sorted and one value is fixed, the remaining task is to find two values whose sum equals `-fixed_value`. The suffix is sorted, so the inner scan has the same monotonic behavior as Two Sum II: move `left` right to increase the sum, and move `right` left to decrease it. Sorting also clusters equal values, which makes duplicate removal systematic instead of ad hoc.

The key pattern transfer is that k-sum problems often become simpler after fixing one dimension and applying a lower-dimensional two-pointer search.

## Recommended Approach

1. Sort `nums` in place.
2. Iterate `fixed_index` from `0` to `len(nums) - 3`.
3. Skip `fixed_index` if it repeats the previous fixed value.
4. Stop when the fixed value is positive; all later values are nonnegative, so no zero-sum triplet can start there.
5. Set `left = fixed_index + 1` and `right = len(nums) - 1`.
6. Compute `fixed_value + nums[left] + nums[right]`.
7. If the sum is zero, record the triplet, move both pointers, and skip duplicate left/right values.
8. If the sum is too small, move `left` right.
9. If the sum is too large, move `right` left.

## Alternative Approaches

A triple loop is straightforward but takes `O(n^3)` time. Fixing one value and using a hash set for the other two can reach `O(n^2)`, but it uses extra space and duplicate handling is harder to teach cleanly. Sorting plus two pointers gives the same `O(n^2)` time, keeps auxiliary space constant apart from the output, and makes uniqueness a local pointer rule.

## Correctness Sketch

For each distinct fixed value, the algorithm searches the sorted suffix for pairs summing to `-fixed_value`. During that suffix scan, if the current sum is too small, every pair using the current `left` with any index up to `right` is also too small, so advancing `left` is safe. If the current sum is too large, every pair using the current `right` with any index from `left` upward is also too large, so decrementing `right` is safe. When the sum is zero, the value triplet is valid. Skipping equal fixed values and equal pointer values removes duplicate value triplets while preserving the next distinct candidate. Therefore every unique zero-sum triplet is emitted exactly once.

## Trace

For `[-1, 0, 1, 2, -1, -4]`, sort to `[-4, -1, -1, 0, 1, 2]`.

| Fixed value | Left value | Right value | Sum | Action |
| --- | --- | --- | --- | --- |
| `-4` | `-1` | `2` | `-3` | Too small, move `left` |
| `-4` | `0` | `2` | `-2` | Too small, keep moving `left` |
| `-1` | `-1` | `2` | `0` | Record `[-1, -1, 2]`, move both pointers |
| `-1` | `0` | `1` | `0` | Record `[-1, 0, 1]` |
| next `-1` |  |  |  | Skip duplicate fixed value |

The final unique triplets are `[[-1, -1, 2], [-1, 0, 1]]`, ignoring output order.

## Complexity

- Time: `O(n^2)`. Sorting costs `O(n log n)`, and the fixed-index loop with an inner linear two-pointer scan dominates.
- Space: `O(1)` auxiliary space beyond the returned triplets, ignoring language-specific sorting internals.

## Common Pitfalls

- Forgetting to sort before applying two pointers.
- Skipping duplicates before recording a valid triplet instead of after pointer movement.
- Skipping duplicate fixed values but not duplicate left/right values.
- Returning duplicate triplets with different indices but the same values.
- Writing tests that compare raw output order instead of normalized triplet values.
- Forgetting that sorting mutates the input list.

## Interview Script

"I sort the array so the two-pointer sum movement is monotonic. Then I fix one value and search the suffix for two values that sum to its negation. I skip duplicate fixed values and, after recording a triplet, skip duplicate left and right values so each value combination is returned once."
