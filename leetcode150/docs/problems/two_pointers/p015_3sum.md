# 15. 3Sum

- Difficulty: Medium
- LeetCode: https://leetcode.com/problems/3sum/
- Official Group: Two Pointers
- Pattern Group: Two Pointers
- Tags: two-pointers, sorting, sum

## Core Pattern

Reduce a `k`-sum problem by fixing one value and turning the remaining search into a sorted two-sum scan. The outer loop chooses the anchor, and the inner pointers eliminate impossible pairs by using monotonic movement and duplicate skipping.

## Why Two Pointers Fits

Sorting turns the suffix after each fixed index into an ordered search space. Once the array is sorted, a sum that is too small can only be increased by moving the left pointer, and a sum that is too large can only be decreased by moving the right pointer. Sorting also groups equal values together, which makes duplicate triplets easy to skip in a deterministic way.

## Recommended Approach

1. Sort `nums` in place.
2. Iterate `fixed_index` from left to right while there are at least two elements to the right.
3. Skip the current fixed value if it equals the previous fixed value.
4. Stop early if the fixed value becomes positive, because later values are also positive and cannot sum to zero.
5. Set `left = fixed_index + 1` and `right = len(nums) - 1`.
6. Compute the three-number sum.
7. If the sum is zero, record the triplet, move both pointers inward, and skip duplicate values on both sides.
8. If the sum is too small, move `left += 1`; if it is too large, move `right -= 1`.

The output order is flexible, so the important requirement is uniqueness, not a particular listing order.

## Alternative Approaches

A brute-force triple loop checks every combination and takes `O(n^3)` time. Another alternative is to fix one number and use a hash structure for the remaining pair, which still gives `O(n^2)` time but complicates duplicate handling and typically uses extra space. Sorting plus two pointers keeps the runtime quadratic while making the uniqueness rule much easier to reason about.

## Correctness Sketch

For each distinct fixed value, the inner two-pointer scan explores every viable pair in the sorted suffix without repeating a value combination. If the current sum is too small, then increasing `left` is safe because all smaller or equal right choices are no better, and the current pair cannot reach zero. If the current sum is too large, then decreasing `right` is safe for the symmetric reason. When a zero-sum triplet is found, moving both pointers inward and skipping equal neighboring values prevents the same value multiset from being emitted again. The outer duplicate check ensures each fixed value is handled once, and the early break on positive fixed values is valid because no later combination can bring the sum back down to zero.

## Trace

For `nums = [-1, 0, 1, 2, -1, -4]`, sorting gives `[-4, -1, -1, 0, 1, 2]`.

| Fixed value | Left value | Right value | Sum | Action |
| --- | --- | --- | --- | --- |
| `-4` | `-1` | `2` | `-3` | Sum too small, move `left` |
| `-4` | `-1` | `2` | `-3` | Still too small, move `left` |
| `-4` | `0` | `2` | `-2` | Still too small, pointers cross, no triplet for `-4` |
| `-1` | `-1` | `2` | `0` | Record `[-1, -1, 2]`, then skip duplicates after moving inward |
| `-1` | `0` | `1` | `0` | Record `[-1, 0, 1]`, then move inward |
| next `-1` |  |  |  | Skip duplicate fixed value |

This trace shows both the elimination logic and the duplicate control. The two found triplets are the only unique zero-sum combinations in the array.

## Complexity

- Time: `O(n^2)` after sorting. The sort is `O(n log n)`, and the outer loop plus inner two-pointer scan dominates.
- Space: `O(1)` auxiliary space beyond the output list, ignoring the implementation details of the in-place sort.

## Common Pitfalls

- Forgetting to sort before using two pointers.
- Skipping duplicate fixed values, but not skipping duplicate left or right values after a match.
- Skipping duplicates before recording a valid triplet, which can accidentally miss the answer.
- Continuing the outer loop after the fixed value becomes positive.
- Comparing triplet order directly in tests even though the output order is flexible.
- Reusing the same index twice by moving pointers incorrectly after a match.

## Interview Script

"I sort the array, fix one number, and solve the remaining two-sum problem with left and right pointers. If the sum is too small, I move left; if it is too large, I move right.
