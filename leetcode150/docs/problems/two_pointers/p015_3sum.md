# 15. 3Sum

- Difficulty: Medium
- LeetCode: https://leetcode.com/problems/3sum/
- Official Group: Two Pointers
- Pattern Group: Two Pointers
- Patterns: two-pointers, sum

## First-Principles Explanation

### What The Problem Asks

Given an integer array `nums`, return every unique triplet `[a, b, c]` such that:

```text
a + b + c = 0
```

Each triplet must use three different array positions, but the answer is judged by values, not by positions. That means if the array contains repeated numbers, the same value triplet should appear only once.

For example, in `[-1, 0, 1, 2, -1, -4]`, both `-1` values can participate in a triplet, but the output should contain `[-1, 0, 1]` only once. The problem is therefore not just “find any three numbers.” It is “find all distinct value combinations of three numbers whose sum is zero.”

### Brute-Force Baseline

The most direct way to think about the problem is to try every triple of indices:

```text
for i from 0 to n - 3:
    for j from i + 1 to n - 2:
        for k from j + 1 to n - 1:
            if nums[i] + nums[j] + nums[k] == 0:
                record the sorted value triplet if it has not appeared before
```

This is correct because it checks every possible choice of three positions. But it costs `O(n^3)` time, and duplicate handling usually requires an additional set of normalized triplets.

The brute-force method teaches the real shape of the problem: a triplet is one fixed number plus a pair that supplies the remaining sum. If we choose one number `a`, the other two numbers must sum to `-a`.

So the problem can be reframed as:

```text
For each possible first value a,
find every unique pair b, c after it such that b + c = -a.
```

That reframing is the bridge from cubic time to quadratic time.

### Key Observation

If the array is sorted, then after fixing one value, the remaining pair search has useful direction.

Suppose the sorted array is:

```text
nums[fixed_index] <= nums[left] <= ... <= nums[right]
```

For a fixed value `a = nums[fixed_index]`, we want:

```text
nums[left] + nums[right] = -a
```

Because the remaining values are sorted:

- If `a + nums[left] + nums[right] < 0`, the sum is too small. Moving `right` left would only make the sum smaller or equal, so the only useful move is to increase `left`.
- If `a + nums[left] + nums[right] > 0`, the sum is too large. Moving `left` right would only make the sum larger or equal, so the only useful move is to decrease `right`.
- If the sum is exactly `0`, the current triplet is valid. Then both pointers must move, because keeping either value would reproduce the same pair with the same fixed value or fail to make progress.

This is the central first-principles reason two pointers work here: sorted order makes the pair sum monotonic with respect to pointer movement.

### Sorted Two-Pointer Invariant

After sorting, the algorithm fixes one index `fixed_index` and searches only the subarray to its right:

```text
fixed_index < left < right
```

During the inner loop, the active search space is the interval `[left, right]`. The invariant is:

```text
For the current fixed value, every unexamined pair that can still form a new valid triplet lies inside nums[left:right + 1].
```

Each pointer move preserves this invariant by discarding only impossible pairs:

- When the sum is too small, every pair using the current `left` with any index at or left of `right` is too small, because those right-side values are `<= nums[right]`. So `left` can be discarded.
- When the sum is too large, every pair using the current `right` with any index at or right of `left` is too large, because those left-side values are `>= nums[left]`. So `right` can be discarded.
- When a valid triplet is found, duplicates of the just-used `left` and `right` values can be skipped because they would create the same value triplet again.

The fixed index also has a duplicate rule: if `nums[fixed_index]` is the same as the previous fixed value, skip it. Otherwise the same set of pairs would be rediscovered for the same first value.

### Detailed Algorithm

1. Sort `nums` in ascending order.
2. Create an empty list `triplets`.
3. Iterate `fixed_index` from `0` through `len(nums) - 3`.
4. Let `fixed_value = nums[fixed_index]`.
5. If `fixed_value` equals the previous fixed value, continue to the next index to avoid duplicate triplets.
6. If `fixed_value > 0`, stop the outer loop. Since the array is sorted, all remaining values are also positive, so no later triplet can sum to zero.
7. Set `left = fixed_index + 1` and `right = len(nums) - 1`.
8. While `left < right`:
   - Compute `current_sum = fixed_value + nums[left] + nums[right]`.
   - If `current_sum == 0`, append the triplet, move both pointers inward, and skip duplicate `left` and `right` values.
   - If `current_sum < 0`, move `left` right to increase the sum.
   - If `current_sum > 0`, move `right` left to decrease the sum.
9. Return `triplets`.

The algorithm uses sorted order twice: first to make pointer movement safe, and second to make duplicate removal local. Once equal values are adjacent, duplicate fixed values and duplicate pair values can be skipped with simple neighboring comparisons.

### Detailed Example Walkthrough

Consider the official example:

```text
nums = [-1, 0, 1, 2, -1, -4]
```

Sort it:

```text
[-4, -1, -1, 0, 1, 2]
```

#### Fix `-4`

```text
fixed = -4
left = -1
right = 2
sum = -4 + -1 + 2 = -3
```

The sum is too small, so move `left` right.

```text
fixed = -4
left = -1
right = 2
sum = -3
```

Still too small, so move `left` right again.

```text
fixed = -4
left = 0
right = 2
sum = -2
```

Too small, move `left`.

```text
fixed = -4
left = 1
right = 2
sum = -1
```

Too small, move `left`. Now `left == right`, so the search for fixed `-4` is finished. There is no triplet starting with `-4`.

#### Fix first `-1`

```text
fixed = -1
left = -1
right = 2
sum = 0
```

Record:

```text
[-1, -1, 2]
```

Move both pointers inward:

```text
left = 0
right = 1
```

Now:

```text
fixed = -1
left = 0
right = 1
sum = 0
```

Record:

```text
[-1, 0, 1]
```

Move both pointers inward. The inner loop ends.

#### Fix second `-1`

The next fixed value is also `-1`. Skip it, because fixing this duplicate would rediscover the same value triplets that were already found with the previous `-1`.

#### Fix `0`

```text
fixed = 0
left = 1
right = 2
sum = 3
```

The sum is too large, so move `right` left. The pointers cross, so this fixed value is finished.

The final answer is:

```text
[[-1, -1, 2], [-1, 0, 1]]
```

The order of triplets is not important for LeetCode, but each triplet must be unique.

### Code/Pseudocode

```python
def threeSum(nums: list[int]) -> list[list[int]]:
    nums.sort()
    triplets = []

    for fixed_index in range(len(nums) - 2):
        fixed_value = nums[fixed_index]

        if fixed_index > 0 and fixed_value == nums[fixed_index - 1]:
            continue

        if fixed_value > 0:
            break

        left = fixed_index + 1
        right = len(nums) - 1

        while left < right:
            current_sum = fixed_value + nums[left] + nums[right]

            if current_sum == 0:
                triplets.append([fixed_value, nums[left], nums[right]])
                left += 1
                right -= 1

                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1
            elif current_sum < 0:
                left += 1
            else:
                right -= 1

    return triplets
```

### Correctness

We prove that the algorithm returns exactly the unique triplets whose values sum to zero.

First, every recorded triplet is valid. The algorithm appends a triplet only after computing `fixed_value + nums[left] + nums[right]` and finding that it equals zero. The indices are distinct because the loop always maintains `fixed_index < left < right`. Therefore every appended triplet uses three different positions and sums to zero.

Second, the algorithm does not miss any valid triplet. Fix an outer-loop value `a`. The inner loop starts with the full suffix to the right of `a`, so every possible pair for that fixed index is initially inside the active range. If the current sum is too small, then any pair using the current `left` and a smaller `right` value would be no larger than the current sum, so it also cannot reach zero. Discarding `left` cannot remove a valid pair. If the current sum is too large, then any pair using the current `right` and a larger `left` value would be no smaller than the current sum, so it also cannot reach zero. Discarding `right` cannot remove a valid pair. Thus every pointer move preserves all still-possible valid pairs until they are either found or proven impossible.

Third, the algorithm returns unique value triplets. Duplicate fixed values are skipped, so the same first value is not processed twice. After a valid triplet is found, duplicate copies of the just-used left and right values are skipped, so the same second or third value combination is not appended again for that fixed value. Since the array is sorted, equal values are adjacent, and these local duplicate checks remove all repeated value triplets.

Finally, if `fixed_value > 0`, the algorithm safely stops. In a sorted array, the fixed value and all later values are positive, so every remaining possible triplet has a positive sum and cannot equal zero.

Therefore the algorithm returns all and only the unique zero-sum triplets.

### Complexity

- Time: `O(n^2)`. Sorting costs `O(n log n)`, and for each fixed index the two pointers move inward at most `O(n)` total steps. The quadratic pair searches dominate.
- Space: `O(1)` auxiliary space excluding the output list, assuming in-place sorting. The output itself can contain many triplets and is not counted as auxiliary space.

### Common Pitfalls

- Forgetting to sort first. Without sorted order, moving `left` or `right` has no monotonic meaning.
- Returning duplicate triplets. Skip duplicate fixed values and skip duplicate pair values after recording a valid triplet.
- Skipping duplicates before recording the triplet. The safe moment to skip inner duplicates is after appending and moving both pointers off the recorded values.
- Moving only one pointer after finding a valid triplet. Both values were used; keeping one pointer risks duplicates or slow progress.
- Using `left = 0` for every fixed value. The pair must come after the fixed index so the same element is not reused and each combination has one canonical order.
- Missing the early stop when `fixed_value > 0`. This optimization is not required for correctness, but it follows directly from sorted order.
- Counting index combinations instead of value combinations. The problem wants unique triplet values, not every distinct set of indices that sums to zero.

### First-Principles Summary

3Sum looks like a three-number search, but after one value is fixed, it becomes a sorted two-number search. Sorting creates a line of numbers where moving the left pointer can only increase the pair sum and moving the right pointer can only decrease it. That monotonic structure gives a proof for every discarded candidate: when the sum is too small, the current left value cannot work with any remaining right value; when the sum is too large, the current right value cannot work with any remaining left value.

The duplicate rules are also a consequence of sorting. Equal values become neighbors, so the algorithm can skip repeated fixed values and repeated pair values exactly where they would otherwise reproduce the same triplet.

The essence is:

```text
sort values
fix one value
use opposite pointers to find the needed complementary pair
move only the pointer whose side is proven impossible
skip adjacent duplicates to return value-unique triplets
```
