# 第 3 章：搭建列表、表单与基础导航

## 当前问题

有了应用壳和状态直觉之后，产品仍然只有一个抽象的空壳。真正的任务应用至少需要三样东西：显示一组任务、让用户输入信息、让用户知道自己在什么页面流里。

## 核心机制

`List`、`Form` 和导航容器并不是三个互不相关的 API。它们共同构成了最基础的应用骨架：`List` 负责展示变化中的集合，`Form` 负责把用户输入组织成可编辑结构，`NavigationSplitView` 负责在 `iOS + macOS` 双平台上给出稳定的信息架构。你现在学习的不是控件目录，而是一个产品骨架如何由这些容器协作搭起来。

## 在 FocusList 里的落点

`FocusList` 的 `Inbox` 代表任务列表面，`Settings` 代表结构化输入面，而侧栏则承担最小导航地图。即使功能还很少，这三样东西已经让应用具备了“能浏览、能输入、知道自己在哪”的基本产品体验。这也是为什么我们早早引入导航：不是为了显得完整，而是因为产品结构本来就依赖它。

## 常见误区

最常见的错误是把所有内容堆进一个长页面，等功能多了再想办法切开。另一个错误是为了“跨平台”而回避结构清晰的导航容器，结果让界面在两个平台上都显得别扭。跨平台不是求一个最低公分母，而是先建立稳定结构，再针对平台细化。

## 本章小结

现在的 `FocusList` 已经拥有最小产品骨架：任务列表、输入界面和导航结构。后面我们会不断扩展功能，但这三层骨架不会消失，它们只会被重新组织得更像一个真正产品。
