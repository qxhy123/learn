# Part 1 Lab：完成你的第一个 FocusList 冲刺

## 场景

你刚做完 Part 1，手里有一个能跑的 `FocusList` 起点：有侧栏、有 `Inbox`、有最基础的输入流。但它还远远不能算“讲清楚了状态和页面骨架”。这个 lab 的目的，就是把你刚学的应用壳、局部状态和导航结构真正用起来。

## 实验目标

完成这三个任务：

1. 修一个状态放错位置导致的界面更新问题
2. 给 `Inbox` 加一个真正可用的新增任务输入流
3. 把侧栏和详情面的关系解释清楚，而不是让它们只是同时存在

## 起始检查

先确认 starter 是干净的：

```bash
cd swift-tutorial/projects/focuslist/starter
swift test
swift build --product FocusListApp
```

如果这里就失败，先不要继续实验。

## 任务一：修正状态所有权

假设你为了图省事，把新增任务输入框的草稿文本也塞进了 `FocusStore`。请把它改回局部 `@State`。

你应该能回答：

- 为什么草稿文本不该进共享核心？
- 如果把它放进 `FocusStore`，会给后续 Part 2 带来什么噪音？

## 任务二：让新增任务流真正可用

现在把 `InboxView` 的输入区域补完整，满足这几个验收条件：

- 输入空白字符串时不能新增
- 成功新增后，输入框会清空
- 新增后的任务立刻出现在列表里

如果你完成后仍然需要手动刷新界面，说明状态链路没有接对。

## 任务三：检查导航是否真的有骨架

打开 `FocusListRootView`，回答并调整：

- 侧栏是不是只在堆按钮，还是已经在承担产品入口？
- 详情区域默认展示 `Inbox` 是否合理？
- `Settings` 作为当前阶段入口，是否已经有足够清楚的位置？

把你的结论写成三条简短说明，留在实验记录里。

## 交付物

完成 lab 后，你应该至少能给出：

- 改过的 `InboxView`
- 一段解释局部状态与共享状态边界的文字
- 一段解释侧栏/详情关系的文字

## 通过标准

只有同时满足下面三点，这次 lab 才算完成：

- starter 仍能通过构建和测试
- 你能解释为什么草稿状态不进 `FocusCore`
- 你能说清当前 `FocusList` 的页面骨架已经成立，但产品功能还远远不够
