# Swift Tutorial Labs

## 什么是 labs

`labs/` 是 part-level 的综合实验区。正文章节会在局部主题上逐步建立能力，而 labs 负责把一个 part 内部分散的语言点、工程点和项目改造点重新拼成一次完整训练。你可以把它理解为“这一部分学完之后，是否真的能把能力整合起来”的检验面。

## 它和章节 drills 有什么不同

章节内 drills 更像局部检查点，关注的是当前主题是否听懂、当前例子是否能跟上、当前 API 或设计判断是否能复述。labs 则不是局部练习，它会故意跨章节组合任务：要求你调试一个跨模块问题、重构一段已经能跑但边界很差的代码、补一个缺失测试、或者把语言特性和项目结构一起重新判断。

换句话说，drills 主要验证“这一章会不会”，labs 主要验证“这一部分能不能真正用起来”。如果你只做章节练习，不做 labs，通常会高估自己对整条工程主线的掌握程度。

## 什么时候做 part-level labs

最推荐的时机是每完成一个 part 的正文之后立刻做对应 lab。此时你对该部分的概念还新鲜，也最容易暴露哪些知识只是“看懂了”，哪些已经真正变成可操作能力。

如果你是跳读某一部分补弱项，也建议在补完该部分后做对应 lab，而不是只读完就结束。尤其是项目线发生阶段切换时更该做 lab：例如 Part 1 完成 `TaskCLI Lite` 后、Part 4 强化 `TaskCore + TaskCLI` 之后、以及 Part 6 把 `TaskFlow` 架起来之后，这些节点都适合用综合实验把局部能力重新对齐成系统判断。
