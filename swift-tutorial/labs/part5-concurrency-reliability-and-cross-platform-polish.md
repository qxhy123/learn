# Part 5 Lab：并发、失败面与跨平台打磨

## 场景

这一部分开始，`FocusList` 已经具备真实产品的很多症状：会刷新、会搜索、会失败、会取消，还要在 `iOS` 和 `macOS` 上都顺手。这个 lab 的目标，就是检查你能不能把这些问题当成产品系统问题，而不是零散 API 问题来处理。

## 任务一：设计一次刷新失败但可恢复的路径

选择一个异步动作，例如刷新搜索结果或同步任务。为它补上一条完整状态流：

1. 加载中是什么表现
2. 失败时显示什么
3. 用户如何重试
4. 旧数据是否保留

### 验收点

- 失败不等于空状态
- 用户知道下一步可以做什么
- 旧内容不会被无意义清空

## 任务二：区分主动取消与真正错误

找一个会被取消的异步任务，设计 UI 反馈：

- 用户主动取消时，是否需要提示
- 新搜索替代旧搜索时，是否需要静默结束
- 真正失败时，是否需要可见反馈

把这三种情况写成一张表，说明为什么反馈强度不同。

## 任务三：写出两条必须跨平台分化的交互

分别从 `iOS` 和 `macOS` 视角找两处必须分化的体验，例如：

- 导航组织
- 键盘快捷键与右键菜单
- 列表信息密度
- 编辑流呈现方式

要求你解释：为什么这些差异应该停留在表达层，而不是拆散共享核心。

## 通过标准

这次 lab 只有在下面条件都满足时才算通过：

- 你明确区分了取消、失败和空状态
- 你能说清后台任务归谁所有
- 你指出了跨平台共享边界和分化边界，而不是只说“两个平台不一样”
