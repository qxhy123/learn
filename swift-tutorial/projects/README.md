# Swift Tutorial Projects

## 这组项目是干什么的

`projects/` 不是正文之外的“附赠代码区”，而是整套 Swift 教程的工程主线。主章节负责解释为什么某个语言或工程能力现在必须出现，项目目录则负责把这些能力落到连续演化的真实载体上。你不需要在每一章都从零新建一个 demo，而是沿着同一个任务管理领域，持续强化已有系统。

## 三个项目表面

### `TaskCLI Lite`

这是第一阶段的最小落点。它只要求最基本的任务列表、添加、完成能力，目的是把 Part 1 的 Swift 基础语义真正压到输入、输出、状态与控制流上。它故意不复杂，因为这一阶段最重要的是建立正确的语言直觉，而不是追求功能数量。

### `TaskCore + TaskCLI`

这是第二阶段到第四阶段的工程主线。`TaskCore` 承担领域模型、状态变化、测试边界以及后续可复用能力，`TaskCLI` 则承担命令行入口、参数解释、输出组织和对核心模块的编排。这里的重点是把“会写 Swift”推进成“能维护 Swift 工程”。

### `TaskFlow`

这是第五、六部分的 SwiftUI 客户端。它不是重新定义任务管理领域，而是复用前面已经形成的共享核心，站在 `TaskCore` 之上建立 UI、状态流和应用结构。这样做能迫使你把 SwiftUI 看成工程体系中的一个客户端，而不是一个脱离前文的新教程。

## `starter / milestones / final` 分别表示什么

`starter/` 表示该阶段刚开始时读者手里的起点。它应该足够简单、足够可运行，让你能看见当前系统哪里弱，而不是一开始就面对一份已经做好的答案。

`milestones/` 记录阶段性落点。它们不是完整代码镜像，而是对关键阶段成果、决策和结构变化的说明，帮助读者把“为什么现在这样改”与“改完后系统多了什么能力”对齐。

`final/` 表示该项目线在当前教学阶段结束时应该达到的状态。它不是为了让读者跳过过程直接抄答案，而是为了提供一个稳定参照，说明这一阶段的学习到底要把系统推进到哪里，以及它如何和下一条项目线衔接。

## 章节如何连接到项目

Part 1 的章节会直接把基础语法收束到 `TaskCLI Lite`，所以第一条项目线更像一个语义着陆区。Part 2 到 Part 4 的章节则持续改造同一领域，把项目升级成 `TaskCore + TaskCLI`，并让建模、测试、包边界、并发与可靠性都能在真实代码里找到位置。

Part 5 到 Part 6 的章节不会抛弃前面的工程成果，而是把它们带进 `TaskFlow`。也就是说，SwiftUI 章节不是在讲“另一门课”，而是在讲“已有系统多了一个 UI 客户端后，哪些抽象和数据流判断会变得关键”。Part 7 与 Part 8 再反过来统一三条表面，让全书形成一个真正连续的工程闭环。
