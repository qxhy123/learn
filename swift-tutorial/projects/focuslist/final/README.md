# FocusList Final：成品状态

## 课程结束时，你应该交付出的是什么

最终的 `FocusList` 不只是一个能运行的 SwiftUI 项目，而是一条完整的现代 Swift 产品线：

- 有清楚产品结构的 App
- 有稳定共享规则的 `FocusCore`
- 有可复用验证面的 `focusctl`
- 有测试、脚本和复盘支撑的工程闭环

## 最终产品应该具备哪些特征

- 任务、项目、计划、筛选和搜索这些概念边界清楚
- 编辑流、失败恢复和空状态都能解释当前产品语义
- 共享核心只承接共享规则，不混入 UI 暂态
- `iOS` 与 `macOS` 共享同一产品中心，但表达自然分化

## 最终工程应该具备哪些特征

- `SwiftPM` target 边界明确
- 关键行为由 `Swift Testing` 保护
- CLI 可以复用核心规则
- 验证脚本能帮助你快速确认课程结构和 starter 健康度

## 最后一次自查

如果课程结束时你不仅能展示这些能力，还能解释：

- 为什么某条状态不该进共享核心
- 为什么某个失败要保留草稿而不是直接回退
- 为什么平台差异应该停留在表达层

那这条项目线就真正完成了它的任务。
