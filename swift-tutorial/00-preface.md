# 前言：如何使用本教程

## 教程设计理念

这套教程按“语言语义 -> 工程边界 -> 平台专项 -> 综合设计”展开，而不是按 API 热门程度或 UI 结果图来排顺序。原因很直接：Swift 真正难的地方不在写出第一段代码，而在于你是否能稳定判断值与引用、Optional、协议与泛型、包边界、并发隔离、状态流和系统演进这些问题。

因此，本教程刻意把“为什么这一章现在出现”放在比“这一章包含哪些关键字”更高的位置。每个部分都要回答三个问题：你当前的直觉哪里不稳、项目哪一段因此脆弱、引入新的 Swift 能力之后到底解决了什么。只有这样，教程才能从知识点清单变成训练判断力的路径。

## 为什么主读者是“会别的语言但没系统学过 Swift”

Swift 的入门阻力并不主要来自语法数量，而是来自旧经验迁移的偏差。写过别的语言的人通常已经懂循环、函数、类、模块、测试，但也更容易把 Swift 错看成“带点语法糖的熟语言”。一旦这样理解，就会低估值语义、Optional 设计、协议扩展、类型驱动 API、Actor 隔离、SwiftUI 数据流这些 Swift 特有的判断点。

把主读者设定为“已有编程经验，但没系统学过 Swift”，可以让教程跳过过于原始的编程启蒙，把篇幅用在最容易误判的 Swift 语义和工程决策上。这也解释了本教程为什么会频繁做跨语言对照：不是为了炫技，而是为了明确告诉你，哪些旧直觉可以沿用，哪些必须重建。

## 为什么先讲 Swift 语言与工程本体，再讲 Apple 专项

很多 Swift 学习路径一开始就直接进入 SwiftUI 或 iOS 页面搭建，这会让读者很快得到“能做点东西”的反馈，但也容易把 Swift 误学成某个 UI 框架的附属语言。本教程故意反过来：先讲语言、建模、包、测试、并发、可靠性，再讲 SwiftUI 和应用架构。

这样做有两个好处。第一，你会在进入 Apple 专项之前就具备足够的工程判断，不会把所有问题都塞进 View 层。第二，SwiftUI 章节可以真正复用前面的 `TaskCore` 和 `TaskCLI` 经验，而不是重新发明一个与前文脱节的 demo 世界。Apple 专项因此不是一条孤立支线，而是 Swift 工程主线的自然延伸。

## 强双语写作约定

本教程采用“中文主叙述 + 英文术语保真”的强双语约定。中文负责解释概念、推导设计、比较取舍、指出坏味道；英文保留类型名、协议名、模块名、命令名、API 名和必要的原文术语，例如 `struct`、`actor`、`Sendable`、`Swift Package Manager`、`Task`、`Binding`。

首次出现的重要术语通常会给出中英文对应，之后优先使用更适合当前语境的写法，但不会为了看起来“国际化”而把整段解释写成中英夹杂的噪音。你应该把双语约定理解为减少歧义的工程手段，而不是装饰性的排版风格。

## 环境与工具要求

前四部分以 Swift 语言、命令行和包工程为主，要求你具备当前稳定版 Swift toolchain、终端、Git，以及能够运行 Swift Package Manager 的本地环境。进入 SwiftUI 部分后，推荐使用能完整支持 SwiftUI 预览、调试和模拟器能力的 Apple 开发环境。

更具体地说，CLI/Core 主线需要你能执行 `swift`, `swiftc`, `swift build`, `swift test`；SwiftUI 主线需要你能创建和运行本地 App 工程，并观察状态、导航和预览变化。如果你的环境暂时只支持命令行 Swift，也可以先完成前四部分，再在补齐 Apple 环境后进入第五、六部分。

## 推荐学习路径

如果你是首次系统学习 Swift，建议严格按章节顺序推进：先读本前言，再读 README 中的八部分地图，然后从 Part 1 开始一路推进到 Part 8。每完成一个部分，做一次对应的 `labs/` 综合实验，用实验来验证你是否真的把这一部分的零散能力整合起来了。

如果你已经写过少量 Swift，可以先用 README 定位自己的薄弱层。例如，语法会写但建模不稳，就从 Part 2 补起；SPM 和测试经验薄弱，就重点读 Part 3；想做 SwiftUI，但项目会越写越乱，就不要跳过 Part 3 和 Part 4。唯一不推荐的路径是“只看 SwiftUI，不补前面的工程本体”，因为那会直接削弱后面所有架构判断。

## 项目线说明

整套教程围绕一个稳定的任务管理领域推进，项目线不是点缀，而是课程结构本身。Part 1 产出 `TaskCLI Lite`，用最小 CLI 让基础语义落地；Part 2 到 Part 4 把它扩展为 `TaskCore + TaskCLI`，引入更清晰的模型、边界、测试与并发设计；Part 5 到 Part 6 再在共享核心之上发展 `TaskFlow` 这个 SwiftUI 客户端。

Part 7 和 Part 8 的任务不是再起一个新项目，而是统一前面的三条表面，让你重新审视共享抽象、系统边界、可靠性与演进路线。也就是说，项目线的目标不是给教程增加“做了个 app”的表面成就，而是持续制造真实的工程压力，让每一章都有明确落点。

## 本教程不追求什么

本教程不追求最短时间内做出最多界面，也不追求把所有 Apple 框架各讲一遍，更不打算把服务端 Swift、底层 runtime、跨平台 GUI、所有第三方库生态都纳入主线。它也不会为了显得“全”而把高级话题讲成名词博览会。

它追求的是另一件事：给你一条足够长、足够稳、足够工程化的 Swift 学习主线。学完之后，你不一定见过所有框架，但应该已经具备继续进入 iOS/macOS、SwiftUI、库设计、并发工程和更高阶系统设计的可靠起点。
