使用规则

规则含义
先分层先判断指标属于训练、推理、平台、数据/RAG 哪条链路。
看分位数SLO 和事故归因看 P50/P95/P99、最慢 rank、最坏租户或最长 prompt。
绑定 workload指标必须绑定模型、数据、输入输出长度、batch、并发、硬件、镜像和引擎版本。
记录反证每次归因都写“它不能证明什么”，防止把相关性当因果。

核心指标

指标定义通常意味着不能证明下一跳
MFU实际模型 FLOPs / 理论硬件峰值 FLOPs算子形状、batch、并行策略或 overlap 改善/退化不能单独证明成本更低或训练更好step time、SM util、NCCL tail、data wait
HFU硬件实际执行 FLOPs / 理论峰值硬件更忙，或无效计算、重算增加不能证明有效训练效率提升MFU、tokens/s、padding、recompute
step timeoptimizer step 的端到端 wall time训练吞吐变化不能说明瓶颈在哪一段step breakdown、data wait、AllReduce
TTFT请求进入服务到首 token 返回排队、路由、tokenize、prefill、冷启动或长 prompt 问题不能证明流式生成稳定queue wait、prefill time、prompt tokens、cold start
TPOT / ITL输出 token 平均耗时 / 相邻 token 间隔decode、调度、KV、显存带宽或 batch 形态变化不能反映首 token 前的问题decode time、active sequences、KV usage
goodput满足 SLO 和质量约束的有效吞吐可售卖容量变化不能替代 raw throughput，也不能证明公平error rate、P99、cost/request、tenant split
queue wait请求或作业等待资源、队列或调度的时间容量不足、配额、碎片化、batching 或 autoscaling 滞后不能证明模型 runtime 慢allocation latency、quota、pending reason
cardinalitymetrics/log labels 的唯一组合数量动态标签可能推高观测成本和查询延迟不能证明业务流量变大top labels、series count、query latency
recall@k相关文档在前 k 个检索结果中出现的比例embedding、chunking、index 或 hybrid retrieval 变化不能证明最终答案正确MRR/NDCG、citation accuracy、answer correctness
