附录 E · 端到端主线案例

用 LLaMA-7B/70B 生命周期把数据、训练、checkpoint、registry、vLLM serving、autoscaling 和 incident 串成同一条工程证据链。

数据准备训练基线分布式训练发布回滚线上事故
读法：先看每个阶段的关键产物是否存在，再用一个指标纵向追踪，最后用常见故障反推需要保留哪些证据。

2. 阶段路线图

阶段目标关键产物关键指标常见故障
1. 数据准备把原始语料变成可复现、可恢复、可审计的训练样本。数据快照 ID、清洗规则、tokenizer 版本、packing 配置、dataset manifest。有效 token 数、重复率、过滤率、sequence utilization、DataLoader 吞吐。tokenizer 与模型配置不匹配；远程 shard 小文件过多；resume 后 shuffle 变化。
2. 单机 baseline建立可解释的 step time、显存和吞吐基线。baseline 配置、固定 batch/seq_len、profiler trace、显存预算表。tokens/s、MFU/HFU、GPU utilization、HBM peak、DataLoader wait、H2D 时间。GPU 利用率低但根因在 CPU tokenizer；OOM 来自 activation 或 optimizer state 估算错误。
3. 分布式训练扩到目标 GPU 数，并保持吞吐、收敛和恢复语义可解释。并行策略表、拓扑 placement、NCCL/env 配置、扩展性 benchmark。scaling efficiency、通信占比、straggler gap、step variance、loss continuity。NCCL fallback 到 socket；跨机 TP 放错拓扑；慢节点拖垮全局 step。
4. Checkpoint让训练能在故障、抢占、升级和发布转换中恢复到明确状态。sharded checkpoint、manifest、checksum、RNG/optimizer/scheduler/dataset state。checkpoint 写入时间、RPO、RTO、对象数量、restore 成功率、loss resume delta。manifest 未原子提交；只保存权重；checkpoint storm 打爆存储。
5. Registry把 checkpoint 转成可发布、可回滚、可审计的模型版本。model package、tokenizer/config、eval report、stage alias、release gate。离线 eval、golden prompt diff、artifact size、签名/扫描状态。checkpoint 与 tokenizer 错配；registry alias 被覆盖；量化后质量未过门禁。
6. vLLM serving明确 prefill/decode、KV Cache、批处理和路由边界。serving spec、engine 参数、TP 配置、routing policy、load test report。TTFT、ITL、P95/P99、tokens/s、KV hit/evict、OOM 次数。长上下文挤爆 KV Cache；prefix cache 被随机路由拉低；70B 冷启动过慢。
7. Autoscaling让副本、队列、配额和降级策略随负载变化。scaler 配置、队列指标、SLO policy、tenant quota、降级规则。queue wait、goodput、SLO burn rate、replica ready time、cost/request。只按 GPU 利用率扩容；扩容速度慢于流量斜率；scale down 杀掉热副本。
8. Incident把线上异常收敛为证据、缓解动作、根因和防复发项。incident timeline、dashboard snapshot、release diff、rollback/degrade 记录。error rate、P99、SLO burn、OOM/restart、bad output rate、MTTA/MTTR。模型 alias 切换后质量下降；KV OOM 重启风暴；回滚只回模型未回 tokenizer。

3. 使用方式

  • 横向读路线图，确认每阶段都有可交付产物，而不是只有口头约定。
  • 纵向挑一个指标追踪，例如 tokens/s 从数据、训练、serving 到 autoscaling 是否口径一致。
  • 用“常见故障”反推证据，每个故障都应能落到日志、指标、manifest、release record 或 incident timeline。
核心判断：端到端案例不是为了把系统做复杂，而是让每次训练、发布和事故都有可回放的证据链。
