1. 训练 step critical path

用途：把一次训练 step 拆成数据、计算、通信、优化器和 checkpoint 等可观测阶段，定位 GPU idle、NCCL tail 或 IO 抖动来自哪里。

flowchart LR A[DataLoader read/decode] --> B[Host collate and pin] B --> C[H2D copy] C --> D[Forward kernels] D --> E[Backward kernels] E --> F[Gradient buckets ready] F --> G[NCCL ReduceScatter or AllReduce] G --> H[Optimizer step] H --> I[Checkpoint or metrics async work] I --> A D -. overlap window .-> G E -. overlap window .-> G

读图要点：先看关键路径上哪一段暴露在 step wall time 中，再看虚线 overlap 是否真的发生。NCCL kernel 长不一定等于网络慢，可能是某个 rank 晚进入 collective。

2. 推理 prefill/decode

用途：说明在线推理里 TTFT、TPOT/ITL 和吞吐分别受 prefill、decode、调度和 KV Cache 影响，避免只用单次 forward latency 解释线上体验。

sequenceDiagram participant C as Client participant R as Router participant Q as Scheduler Queue participant E as Engine participant K as KV Cache C->>R: request(prompt, max_tokens) R->>Q: route by model/tenant/cache affinity Q->>E: prefill batch E->>K: allocate/write prompt KV blocks E-->>C: first token loop decode steps Q->>E: continuous batch next token E->>K: read previous KV, append new KV E-->>C: streamed token end

读图要点：prefill 通常决定 TTFT，decode 循环决定 TPOT/ITL 和 tokens/s。路由如果打散 prefix cache 或让长 prompt 堆在同一队列，会同时影响首 token 和后续吞吐。

3. KV cache block table

用途：展示 PagedAttention 类实现如何用 block table 把逻辑 token 序列映射到物理 KV block，从而减少连续大块显存分配和碎片。

flowchart LR subgraph Logical[Logical sequences] S1[seq A tokens 0..95] S2[seq B tokens 0..47] S3[seq C tokens 0..79] end subgraph Table[Block table] T1[A: 7, 3, 12] T2[B: 5, 9] T3[C: 7, 3, 18] end subgraph Physical[Physical KV blocks] B3[block 3] B5[block 5] B7[block 7 shared prefix] B9[block 9] B12[block 12] B18[block 18] end S1 --> T1 S2 --> T2 S3 --> T3 T1 --> B7 T1 --> B3 T1 --> B12 T2 --> B5 T2 --> B9 T3 --> B7 T3 --> B3 T3 --> B18

读图要点：逻辑上连续的上下文不要求物理上连续。共享 prefix、释放尾部 block、eviction 和租户限额都应围绕 block table 和物理 block 池观察。

4. NCCL topology / transport

用途：把 NCCL 的拓扑选择、节点内 P2P、跨节点 RDMA/socket transport 和 bootstrap/control path 放在一张图里，辅助排查 timeout、socket fallback 和 rail 绑定错误。

NET/Socket fallback .-> BN

读图要点：数据面 transport 和 bootstrap/control path 可能不同。看到 NET/Socket fallback 时，优先查 HCA 可见性、GID、容器权限、net plugin 和 GPU/NIC/NUMA 绑定。

5. 平台控制面 / 数据面

用途：区分“声明目标和做决策”的控制面与“搬运数据和执行 workload”的数据面，方便讨论平台边界、责任归属和事故复盘。

flowchart TB subgraph Control[Control plane] API[Platform API] Sched[Scheduler and quota] Release[ReleaseUnit and policy] Obs[Observability rules] end subgraph Data[Data plane] Train[Training jobs] Serve[Inference pods] Store[Dataset/artifact storage] Net[GPU/NIC/network fabric] end API --> Sched API --> Release Sched --> Train Sched --> Serve Release --> Serve Obs --> API Train --> Store Serve --> Store Train --> Net Serve --> Net Net --> Obs Store --> Obs

读图要点：控制面负责 spec、准入、调度、发布状态和策略；数据面负责真实训练、推理、存储和网络流量。事故分析要同时问“决策是否正确”和“执行路径是否符合预期”。
