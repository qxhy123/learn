1. 实验约定

准备小模型、小数据集和独立实验目录。目标不是追求绝对性能，而是让每一阶段都有基线、证据和回滚动作。

export LAB_ID=ai-infra-e2e-$(date +%Y%m%d-%H%M%S)
export LAB_ROOT=$PWD/runs/$LAB_ID
mkdir -p "$LAB_ROOT"/{data,profiles,checkpoints,serving,release,observability}
证据用途
run.env记录镜像、驱动、CUDA、PyTorch、NCCL、vLLM、模型和数据版本
config.yaml记录 batch、seq_len、并行策略、checkpoint 周期和 serving 参数
metrics.jsonl统一写入 tokens/s、step time、P95/P99、错误率和资源指标
events.log记录人工动作、故障注入、回滚和重跑时间点

2. 八阶段主线

阶段目标预期信号通过标准
数据加载瓶颈判断 GPU 是否被数据链路饿住worker、pin memory、冷热缓存、H2D copy 的影响可分离数据链路稳定提供训练所需 token/s 的 1.2 倍以上，或明确瓶颈层
单机训练 profiling建立可解释 step time baselineprofiler 中 data wait、kernel、H2D、optimizer 占比清楚能回答瓶颈是数据、计算、显存还是框架开销
DDP 通信验证通信路径和扩展效率NCCL 使用预期 RDMA/NVLink 路径，不是 socket fallback扩展效率有数字结论，慢点能归到网络、拓扑、batch、bucket 或数据倾斜
Checkpoint 恢复证明训练可中断、可恢复manifest 原子提交，resume 后 step、lr、loss 和数据游标连续人为中断后能从最近完整 checkpoint 恢复
vLLM / Serving建立 TTFT、ITL、吞吐和 KV 边界queue、prefill、decode、KV headroom 可拆分固定输入分布下 P50/P95/P99、错误率和显存水位达标
量化实验比较延迟收益和质量风险模型、tokenizer、engine、quant artifact digest 绑定质量 gate、延迟、吞吐和回滚目标都可验证
发布回滚验证灰度、门禁和 rollbackcanary 指标、golden set、A/B 和告警能阻断扩大流量错误 tokenizer 或错误参数 canary 可被拦截并回滚
可观测性闭环把事件、指标、日志、trace 串成 EvidenceBundleburn rate、queue、KV、error、quality、cost 能同屏归因事故演练有症状、范围、时间线、变更、修复和复测阈值

3. 最终验收

验收项要求
可复现同一 commit、配置、数据 shard 和镜像能复跑关键阶段
可解释每个性能结论都有指标、profile 或日志证据
可恢复训练中断、serving canary 失败和质量回退都有明确 rollback target
可运营指标、告警、成本和事故记录能进入平台日常治理
