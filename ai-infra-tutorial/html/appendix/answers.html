第 1-25 章答案入口

下表压缩了正文参考答案的主要入口。完整答案在源 Markdown 中逐题展开；本页保留每章最关键的判题方向，便于从 HTML 站点快速跳回对应教学章节。

章节对应正文主要答案入口判题要点
第 1 章什么是 AI InfraAI Infra 与训练模型的区别、系统分层、推理超时排查、组件与平台能力差异。能区分局部模型任务和长期运行平台；能说清业务层、模型层、平台层、资源层的职责。
第 2 章算力、存储与网络端到端吞吐由短板决定、对象存储 / SSD / 主存 / 显存分层、网络对训练和推理的影响、训练 step 拆解。用链路而不是单点指标回答；能把 storage、CPU、H2D、GPU、all-reduce 放进同一条时间线。
第 3 章从模型实验到生产系统能跑与能交付的差异、数据到反馈闭环、模型发布新增步骤、从脚本部署补平台能力。强调版本、评测、制品、灰度、回滚和反馈，而不只看接口是否启动。
第 4 章GPU 与加速器GPU 选型不能只看峰值算力、训练和推理硬件诉求差异、四句口诀分析模型场景、H200 优先任务。同时看显存容量、带宽、互联、精度支持、batch 形态和可用性。
第 5 章内存、互联与 IO为什么从数据怎么走开始、PCIe / NVLink / RDMA 影响场景、单机扩多机互联数字、接受 TCP 的条件、冷热存储分层。能把拓扑、带宽、延迟、运维复杂度和 workload 绑定判断。
第 6 章CUDA、运行时与算子执行小 kernel 开销、同步点破坏 overlap、成熟库优先条件、attention kernel 快但 step 不快的后续排查。从 kernel launch、stream、copy、同步和端到端 step time 解释性能。
第 7 章单机训练系统单机基线的重要性、step 时间拆解、GPU 利用率周期性下降、LLaMA 13B 显存估算、nvidia-smi 与 MFU。能把参数、梯度、优化器、激活、fragmentation 和 input pipeline 一起估算。
第 8 章数据并行多机收益变差、ring all-reduce 成本、扩展效率排查、checkpoint 策略随通信占比调整。回答应包含通信量、同步等待、慢节点、网络拓扑和恢复成本。
第 9 章模型并行与流水并行DP 无法解决模型放不下、TP / PP 切分对象、ZeRO 1/2/3、checkpoint 与 TP/PP、128K+ context parallelism。能说明“切参数、切层、切状态、切上下文”的不同边界。
第 10 章内存优化、检查点与恢复训练显存构成、Adam 状态倍数、激活重计算、分布式 checkpoint、SafeTensors、训练 checkpoint 与部署包、异步 checkpoint、自动重试和弹性训练。把显存账本、恢复语义、分片一致性和重试副作用讲清楚。
第 10b 章对齐训练与后训练基础设施PPO / DPO / GRPO 差异、多模型显存账本、偏好数据、RM 共置或服务化、rollout、KL、LLM-as-judge、恢复策略。能区分 pretraining、post-training、alignment 的系统形态；注意 reward hacking 和多模型状态一致性。
第 10c 章Fine-Tuning 与多 AdapterFT 队列隔离、LoRA / QLoRA 成本结构、adapter 一等制品、FTaaS 状态机、Multi-LoRA 显存和路由、base model 灰度、adapter 清理。答案要覆盖训练侧、registry、评测、热加载、兼容性和租户治理。
第 11 章数据管道数据问题被误判成模型问题、训练与在线特征目标差异、回流数据流图、数据管道设计、数十亿样本读取、质量验证、point-in-time correctness。重点看数据版本、质量、延迟、血缘和在线 / 离线一致性。
第 12 章制品、模型与检查点管理checkpoint 不能直接当生产包、模型最小元数据、状态管理进入控制面、无法回滚案例、对象存储与 registry 分工、训练到发布链路。把文件、元数据、状态机、责任人和发布单元绑定。
第 13 章特征、向量与缓存embedding 升级与索引重建、特征缓存一致性、缓存不能绕过权限、向量索引元数据、HNSW / IVF / PQ、全量重建、prefix cache key。版本、权限、索引构建参数和缓存 key 是核心边界。
第 14 章在线推理架构不能只看模型执行时间、网关 / 路由 / 副本池、尾延迟、RAG 分段拆解、冷启动、vLLM / Triton / KServe、prefill/decode、TTFT/TPOT/ITL、goodput、降级规则。用端到端时延、队列、下游依赖、调度和用户体验回答。
第 15 章批处理、调度与 KV Cache批处理影响延迟、prefill/decode 差异、KV Cache 显存压力、continuous batching、长上下文、spec decoding、KV handoff、vLLM 调参和 P99 TTFT 排查。能用 KV 公式估算显存，并解释吞吐与尾延迟的交换。
第 16 章量化、编译与推理引擎量化收益与硬件绑定、编译与量化差异、引擎与框架、PTQ/QAT、KV Cache 仍是瓶颈、shape contract、memory-bound/compute-bound、引擎迁移评估。不能只引用 benchmark；必须说明模型、shape、batch、硬件、质量和运维代价。
第 17 章多租户与成本治理多租户必要性、单位请求成本、公平性与利用率、租户策略、noisy neighbor、chargeback、warm pool、TCO、预算软着陆、大户治理、容量准备。回答要兼顾隔离、利用率、预算、SLA 和行为激励。
第 18 章容器与运行时训练镜像与推理镜像目标差异、容器能启动但 GPU 不可用排查、AI 镜像分层、镜像治理与宿主机驱动。把镜像、驱动、runtime、device plugin、CUDA 兼容矩阵一起看。
第 19 章Kubernetes for AIK8s 是底座不是平台、训练和推理对象选择、GPU 不能当普通 CPU、额外调度语义。区分通用编排能力和 AI 平台控制面能力。

高频答案模式

这些模式贯穿多章。只要题目要求设计、排障或评估方案，通常都需要把下面的维度显式写出来。

题型推荐回答骨架容易扣分的偏差
概念区分题先定义对象，再用目标、时间尺度、状态、失败处理和协作方式对比。只背名词，不说明边界和后果。
架构设计题画层次、标数据流、标控制面、标状态归属、标回滚和观测点。只有组件堆叠，没有版本、权限、队列和责任边界。
性能排查题先拆端到端时间线，再按最可能解释现象的层级排查：队列、资源、模型、下游。直接调参数或换硬件，没有基线和对照实验。
显存 / 成本估算题列账本：权重、梯度、优化器、激活、KV Cache、碎片、安全余量、利用率。只算参数大小，忽略并发、状态和峰值。
发布治理题写清发布单元、门禁、灰度、监控、回滚、审计和例外流程。把治理写成文档或审批，不落到平台控制点。
安全隔离题明确身份、Secret、数据、模型、镜像、网络、租户、日志和审计边界。只写 API 鉴权，忽略模型权重、RAG、缓存和供应链。
压缩阅读提醒：如果你的答案能说出“先看什么、为什么、看不到再查什么、结论如何被验证”，通常比罗列工具名更接近参考答案。

Part 0 新增答案

Part 0 四章是体系结构基础新增练习题，题号对应正文中的 0a-*、0b-*、0c-*、0d-*。这里保留判题要点，便于快速复习底层系统约束。

0a CPU 微架构

题目范围参考答案要点
CPI、冒险、ROB、预测CPI 可写成 1 + branch stall + cache miss stall + dependency stall + structural stall；RAW 是真实数据依赖，WAR/WAW 是名字依赖，可由 renaming 缓解；ROB 支持乱序执行、顺序提交、精确异常和错误路径回滚；方向预测回答走不走，BTB 回答跳到哪里。
cold path 与尾延迟AI 服务的异常分支、低频 tokenizer 规则、罕见 schema 和工具调用错误路径可能缺少分支历史和 i-cache 热度，第一次触发时会叠加误预测、cache miss、动态加载和数据访问开销。
SIMD、cache line、关联度SIMD 理论收益受向量宽度限制，但真实收益还受内存带宽、对齐、分支、gather/scatter 和短字符串影响；只读 8B 却搬 64B cache line 会浪费带宽；热点地址映射同一 set 会产生关联度冲突。
MESI、伪共享、counter共享 cache line 上的频繁写入会触发 invalidation storm；多 worker counter 应按 cache line padding，让每个线程写独立 line，最终再汇总。
完整排查 runbook固定数据、batch、worker 数和 CPU 频率，记录吞吐与 p95/p99；用 perf stat 看 IPC、cache miss、branch miss、context switch；用 perf record 找热点；用 perf c2c 查伪共享；再做 NUMA、padding、预取、SIMD 的 A/B。
Tokenizer host bottleneck拆读取、解压、tokenize、collate、H2D；优化离线预 tokenization、批量 tokenizer、SIMD / 多进程、减少 GIL 热点、NUMA 绑定、pinned memory 和 overlap；最终看 GPU idle time 是否下降。

0b 内存、虚拟内存与 IO

题目范围参考答案要点
虚拟地址、TLB、Page CacheCPU 先查 TLB，miss 后页表遍历；连续虚拟地址不保证物理连续。第二轮 dataset 更快通常是 Page Cache 命中，应通过 drop caches、iostat、vmtouch、mincore 对比验证。
dirty page、THP、NUMAcheckpoint 写入先进入 Page Cache，达到 dirty 阈值后可能被 writeback 节流；THP 降低 TLB 压力但可能制造 compaction / split 延迟尖峰；DataLoader、内存分配、GPU PCIe root complex 应尽量同 NUMA node。
PCIe、fork COW、io_uringPCIe 带宽由代际和 lane 数决定，需检查拓扑和降速；fork 后写大对象会触发 COW 内存暴涨；io_uring 适合大量异步 IO 或减少 syscall 开销，但不能解决磁盘、对象存储尾延迟或同步语义问题。
pinned memory 与拓扑Pinned memory 提高异步 H2D，但过多会挤压可回收内存和 Page Cache；要看 GPU、NIC、NVMe 是否挂在同一 root complex，跨 socket 会影响 GPUDirect、RDMA 和 H2D。
8 GPU DataLoader 与 checkpoint按 GPU 拓扑绑定 worker、内存和预取 buffer；每卡独立或均衡队列，记录每卡 input wait。大 checkpoint 用分片临时文件、并发写、校验、fsync 文件和目录、原子 rename / manifest 切换。
低延迟推理 IO减少阻塞 syscall、连接抖动和内存分配；权重和配置预加载或 mmap 预热；不要让首次请求承担 page fault、模型加载、TLS 建连和动态编译成本。

0c 文件系统与存储内核

题目范围参考答案要点
VFS、write()、journal文件读取经过路径解析、dentry / inode、权限、Page Cache、文件系统方法、block layer 和设备驱动；write() 成功不等于持久落盘；ext4 journal 主要保护元数据一致性，频繁大 checkpoint 可能增加写放大和尾延迟。
XFS、对象存储、IOPSXFS 适合大文件、并发写和大目录；对象存储适合不可变 shard、归档和分发，不具备 POSIX rename / fsync 语义；小随机 IO 吞吐约等于 IOPS x block_size，小文件训练容易被 IOPS 和元数据限制。
Page Cache、O_DIRECT、小文件benchmark 第二次快可能测到内存缓存；O_DIRECT 减少 Page Cache 污染但要求对齐，不等于持久化；大量小文件会放大 open/stat/list、inode、目录锁和 MDS 压力，应考虑 shard / tar / webdataset。
ZFS 与 checkpoint 发布协议ZFS 适合快照、校验、压缩和可回滚 dataset，但要验证 COW 写放大、ARC 内存和 sync 写尾延迟；checkpoint 推荐 tmp 写入、分片校验、manifest、fsync、原子切换和失败清理。
混合存储与 stripe本地 NVMe 做热缓存和 spill，并行 FS 做训练热层和最近 checkpoint，对象存储归档和跨集群分发；大 checkpoint 按 rank、OSS 和目标吞吐设置 stripe，小文件先减少数量再谈 stripe。

0d 网络协议栈基础

题目范围参考答案要点
send()、三次握手、MTUsend() 路径包括用户 buffer、syscall、socket buffer、TCP/IP、qdisc、驱动、DMA ring、NIC；三次握手确认双方收发能力并同步序列号；MTU 9000 比 1500 包数少，但 jumbo frame 必须端到端一致。
窗口、命令、RSSreceive window 防止接收端 buffer 被打爆，congestion window 防止网络路径拥塞；排查命令可包括 ip、ss、ethtool -S、tcpdump、iperf3、nstat、ib_write_bw；RSS 把 flow 分到多个 RX queue，配置不当会单核软中断打满。
CUBIC / BBR、RDMA、RoCECUBIC 主要按丢包和窗口增长调节，BBR 估计瓶颈带宽和 RTT；RDMA Write 经注册内存、QP、WR、HCA DMA、CQ 完成，绕过远端 CPU 数据路径；RoCE v2 需要 ECN/PFC 降低丢包，但配置不当会造成 pause storm。
NCCL fallback 与 32 节点验收看 NCCL_DEBUG=INFO 中 NET/IB、NET/Socket、GID、HCA 和拓扑；用 nccl-tests 对比预期 RDMA 带宽。32 节点验收要覆盖链路速率、MTU、ECN/PFC、错误计数、GPU-NIC 拓扑、跨 rack all-reduce 和不同节点组合。
推理控制面 IO 与亲和放置低到中等并发可用成熟 HTTP server + epoll；高并发、长连接、流式响应关注 backpressure 和 flush；调度时让 GPU 使用同 socket、同 PCIe switch 或拓扑最近的 NIC，多 rail 避免跨 socket 绕路和 rail 不均衡。
Part 0 总结：这些题的共同目标是让你能把 AI Infra 的性能和可靠性问题落回 CPU、内存、文件系统和网络的真实约束，而不是只停在框架参数层。
