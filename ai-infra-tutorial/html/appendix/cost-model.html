成本模型不是财务表格，而是工程决策工具：钱花在哪条链路、哪个变量最敏感、优化是否牺牲稳定性和交付速度。

1. 通用公式

GPU 成本 = GPU 数量 * 运行小时 * 单 GPU 小时价格
有效 GPU 成本 = GPU 成本 / 有效利用率

训练每 B token 成本 = 总训练成本 / 训练 token 数 * 1e9
推理每 1M token 成本 = 总推理成本 / token 总数 * 1e6

失败放大系数 =
  (成功运行 GPU hours + 失败浪费 GPU hours) / 成功运行 GPU hours

有效利用率要看能转化为业务或训练进度的指标。训练看 tokens/s、step time、MFU；推理看 goodput、SLO 内吞吐和成功请求。

优先级：先降低失败放大系数，再提升有效吞吐，最后压缩 checkpoint、存储和评测成本。

3. 推理成本模型

请求成本 =
  prefill token 数 * prefill 单 token 成本
  + decode token 数 * decode 单 token 成本
  + 请求排队和调度成本
  + KV Cache 占用成本
变量成本影响工程判断
Prefill长 prompt 增加首 token 前计算关注 TTFT、prompt length、prefix cache
Decode输出 token 持续占用迭代和显存带宽关注 ITL、TPOT、active sequences
Batching提升吞吐但增加排队和长尾按 SLO 分层，而不是追求最大 batch
KV Cache长上下文长期占用显存机会成本用 token 分布做容量规划，不只用 QPS
量化可能降成本，也可能带来质量和维护成本必须绑定质量 gate、fallback 和回滚路径

5. 决策检查清单

  • 是否统一了成本口径：失败重试、checkpoint、评测、灰度和平台摊销是否计入。
  • 是否先看 goodput，而不是 raw throughput 或瞬时 GPU utilization。
  • 是否把质量、稳定性、回滚和人力维护成本纳入优化收益。
  • 是否按租户、模型、队列、版本和请求形态做归因。
