2. GPU 利用率低

症状是 step time 变长、SM util 长期低于预期、GPU 空洞和 batch wait 增加。第一批证据包括 DCGM / nvidia-smi dmon、torch.profiler、nsys 时间线、DataLoader wait、H2D 带宽、CPU perf stat 和数据源吞吐。

假设树覆盖数据加载或 tokenizer 慢、H2D/NUMA/pinned memory 不匹配、小算子或 kernel launch 过多、存储或网络喂数不足，以及调度拓扑错误。复测时固定 batch、seq_len、数据版本和节点，比较 step time、tokens/s、SM util、batch wait；无效时回滚到上一版数据加载、runtime 参数或 placement。

3. NCCL timeout

症状是部分 rank 卡在 collective，日志出现 NCCL timeout，step p99 抖动或作业 abort。先收集 rank 日志、NCCL_DEBUG=INFO、nccl-tests、topology dump、GPU/NIC/CPU 拓扑、IB/RoCE 端口错误、PFC/ECN、placement 和同时间 checkpoint / 数据流量。

常见假设包括 rail 错误、socket fallback、慢 rank、RoCE 拥塞、checkpoint 抢网络、NCCL/env 版本组合变化。不要一开始只调大 timeout；应在同节点集合复测 nccl-tests 和真实训练窗口，必要时回滚 NCCL/env、placement policy 或流量隔离配置。

4. Checkpoint 卡住

症状是 checkpoint 阶段 GPU util 掉到 0，写入前快后慢，fsync 或 manifest 提交长尾，恢复演练失败。证据包括 checkpoint size / shard 数、写入耗时分布、iostat、pidstat、Dirty/Writeback、对象存储 put/list 延迟、并行文件系统指标、manifest 和 checksum。

假设树覆盖 dirty page 债务、rank 并发写打满存储、小文件或 manifest 元数据热点、checkpoint storm、对象存储语义误用、原子提交协议缺失。复测 checkpoint p95/p99、restore drill、崩溃矩阵和 loss resume delta；失败时回滚到上一个完整 manifest 和已验证 writer。

5. TTFT 飙升

症状是 Time To First Token 的 P95/P99 突然升高，TPOT 可能正常。先按 prompt length 分桶看 TTFT/TPOT、queue wait、batch size、prefill/decode 分解、cold start、路由命中、prefix cache hit、engine 日志和发布 diff。

假设树覆盖 prefill 队列堆积、长 prompt 分布变化、batching 参数变化、冷启动或扩容滞后、prefix cache 被路由打散、网关或下游增加首包等待、新模型或量化 engine 改变 prefill 性能。用固定 trace 回放复测分桶指标；若 SLO burn 继续，回滚 engine、batching 参数、router 或模型 ReleaseUnit。

6. KV OOM

症状是 CUDA OOM、KV cache eviction 激增、worker 重启、长上下文失败或多租户互相挤占显存。第一批证据包括模型尺寸、max context、并发、active sequence、KV block 使用率、evict/recompute、GPU memory summary、OOM 日志、tenant 和路由维度。

假设树覆盖 max_num_seqs / max_model_len 超预算、长上下文突增、prefix cache 或 speculative decoding 额外占用、LoRA / CUDA Graph buffer 未入账、多租户 headroom 不足、KV 未被量化策略覆盖。复测 OOM 次数、KV watermarks、吞吐和 P99；必要时回滚 context、engine 参数、限流策略或副本规格。

7. RAG 召回下降

症状是 Recall@K、MRR、命中文档覆盖率下降，答案引用减少或不相关。证据包括 golden query 集、embedding 模型版本、index manifest、chunking 配置、过滤条件、hybrid search 权重、reranker 版本、向量库 build / compact 日志。

常见假设是数据源或 chunking 变化、embedding/tokenizer 变更未重建、index alias 指错、ANN 参数或压缩降低召回、metadata filter 误过滤、reranker/prompt 掩盖检索回退、增量索引漏写。用 golden query 和线上抽样回放复测，未达阈值时回滚 index manifest、embedding、chunking 或 reranker。

8. 发布后质量回退

症状是模型、prompt、router、adapter、RAG index 或推理引擎发布后质量指标下降。先收集 ReleaseUnit diff、模型/tokenizer/prompt/adapter/index/image digest、离线 eval、A/B 和 canary 指标、golden prompt diff、日志采样、回滚目标和审批记录。

假设树覆盖权重与 tokenizer/config 不匹配、prompt 或 guardrail 变更、RAG index/embedding 错配、量化或 engine 质量损失、灰度污染实验、数据飞轮反馈污染、评测门禁不足。回滚应回整个 ReleaseUnit，而不是只回模型，并用 golden set、shadow 样本和 canary 阈值验证恢复。
