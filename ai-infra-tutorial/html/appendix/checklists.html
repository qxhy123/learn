上线前检查

上线前检查的目标是确认发布单元、资源边界、回滚路径和观测链路都已经就绪。训练任务偏向可复现和可恢复，推理服务偏向延迟、版本一致性和灰度回滚，Agent / Tool Use 还要额外检查预算、工具权限和副作用控制。

训练任务上线前检查

检查项通过标准缺失风险
数据快照数据快照已固定，且能回溯来源、版本和处理脚本。训练结果无法复现，问题样本难以定位。
发布产物镜像、代码版本和配置文件一起归档。恢复或复跑时无法还原同一运行环境。
资源配额GPU、CPU、内存、磁盘配额明确。作业挤占公共资源或运行中被驱逐。
Checkpoint 策略保存频率与恢复目标一致。故障后损失过多进度，或存储压力过大。
观测接入指标、日志、告警已接入。失败后只能靠人工翻日志定位。
重试策略失败重试不会导致重复写入或资源泄漏。重复产物、孤儿进程、存储残留或账单异常。

大规模训练作业预检清单

  • nccl-tests 或等价 all-reduce benchmark 已通过。
  • 所有节点 GPU ECC 错误为零。
  • 所有节点间 IB / RoCE 链路健康。
  • 驱动版本和 CUDA 版本与镜像兼容矩阵匹配。
  • Checkpoint 写入路径可用，空间充足。
  • Elastic training 的 rendezvous 配置正确。
  • 慢节点检测和自动替换机制已经就绪。
预检边界：大规模训练不要只检查单节点可运行；跨节点通信、共享存储、驱动兼容和慢节点替换必须在正式占用队列前完成。

推理服务上线前检查

检查项通过标准关注点
请求协议协议、超时、限流策略明确。避免调用方无限等待或突发流量击穿服务。
版本一致性模型版本、tokenizer、配置完全匹配。避免同一模型 ID 下出现不可解释的输出差异。
发布单元模型、prompt、few-shot、guard rail、检索配置作为同一发布单元管理。避免只回滚模型而漏掉上下文配置。
冷启动冷启动时间在可接受范围内。影响扩容、故障迁移和灰度切换。
服务策略批处理、缓存、并发策略已验证。影响吞吐、尾延迟和资源利用率。
发布路径具备金丝雀、灰度和回滚路径。问题版本可以快速收敛影响面。
质量监控有业务质量监控，不只是系统指标。系统健康不等于回答质量健康。

Agent / Tool Use 上线前检查

  • 最大步数、最大 token 预算、最大 wall-clock 时间已配置。
  • 工具白名单明确，并按任务类型限制可调用工具。
  • 工具执行在沙箱或隔离环境内完成。
  • Credentials 做到 scoped、短期、最小权限。
  • 有副作用动作具备 approval gate 或人工接管路径。
  • Step trace、工具调用日志、失败原因可审计。
  • 超预算后的回退路径已经验证。
Agent 红线：只限制模型输出不够；工具权限、执行环境、审批门禁和审计链路必须同时成立。

成本、治理与安全

成本与治理检查用于确认资源使用可以归因、可限制、可回收。安全检查用于确认镜像、依赖、密钥、网络和敏感数据不会因为上线流程自动化而失控。

成本与治理检查

  • GPU 利用率可见。
  • 资源可以按团队或项目归因。
  • 长时间空闲实例有回收策略。
  • 敏感数据与模型权重已做权限隔离。
  • 关键运维与发布操作记录了审计日志。

安全上线检查清单

类别检查项失败信号
镜像来源镜像已完成签名或来源校验。只要 tag 匹配就能进入生产。
漏洞处理镜像和依赖已完成漏洞扫描，高危项有结论。Critical / High 漏洞无人确认仍继续发布。
SecretsSecrets 通过 Secret Manager / K8s Secret 注入，不硬编码。Token 出现在代码、镜像、日志或 Helm values 明文中。
运行身份运行用户为非 root，容器能力已最小化。默认 root 加宽权限，容器能力未收敛。
访问边界网络策略、入口鉴权和租户隔离已配置。内部服务默认互通，跨租户访问无法审计。
敏感输出日志、trace、错误返回避免输出敏感数据。日志系统可以搜索到凭据、用户原文或内部路径。
责任归属模型、索引、prompt 和配置都有版本与责任人。线上行为无法映射到具体发布单元。
回滚安全回滚路径同样满足权限和安全规则。旧版本绕过当前准入策略。
治理落点：合格的治理不是多一份审批文档，而是 CI、准入控制、调度器、网关、账单和审计系统能自动执行同一组边界。

性能与系统排查

性能问题应先判断瓶颈层：GPU 计算、CPU 主机侧、数据加载、网络等待、存储等待、调度等待或服务策略。确认层次后，再用固定输入、固定并发和可复现实验命令比较优化前后。

性能压测检查清单

  • 已拿到单副本吞吐与延迟基线。
  • 多副本扩展后吞吐接近预期线性增长。
  • P95 / P99 延迟在目标 SLO 内。
  • 压测期间没有出现 OOM、CUDA error 或 GPU reset。
  • 冷启动、预热和扩缩容过程已单独测试。
  • 连续运行 30 分钟以上后指标仍然稳定。

CPU 性能排查清单

排查方向检查项常用工具 / 指标
瓶颈归因先区分瓶颈在 GPU 计算、CPU 主机侧、数据加载、网络等待还是存储等待。GPU 利用率、队列等待、端到端 trace
基础计数器记录 cycles、instructions、IPC/CPI、branch-misses、cache-misses、context-switches。perf stat
热点定位找到 DataLoader、tokenizer、preprocessing、网关或序列化热点。perf record/report、VTune
向量化检查热点循环是否被 SIMD 向量化，编译器报告是否存在 alias、分支或非连续内存访问阻碍。编译器 vectorization report
并发扩展检查线程数增加后吞吐是否线性增长，是否出现 lock contention、false sharing 或调度开销。吞吐曲线、锁等待、上下文切换
缓存与内存检查 L1/L2/L3 miss、working set 大小、cache line 访问模式和伪共享。perf c2c、cache miss 指标、padding 实验
NUMA检查 CPU core、内存、GPU、NIC 是否在同一 socket 或合理拓扑下。numactl、lstopo、PCIe 拓扑
大内存行为把 page fault、TLB miss、THP/HugeTLB 状态纳入排查。perf、vmstat、内核 THP 配置
复现实验记录固定输入、固定线程数、固定 CPU 频率和可复现实验命令。Benchmark 脚本、环境快照

文件系统选型清单

问题需要确认的内容
Workload 类型Checkpoint 大文件写、dataset 顺序读、小文件随机读、向量索引读写，还是归档冷存。
核心目标吞吐、IOPS、尾延迟、崩溃一致性、快照、压缩、成本或 POSIX 语义。
一致性边界write()、fsync()、rename、manifest、对象存储 multipart 的语义是否明确。
Page CachePage Cache 是期望的加速层，还是会污染 benchmark 或挤压训练进程内存。
本地文件系统ext4 journal、XFS 并发元数据路径、ZFS COW/ARC/快照是否匹配读写模式。
并行文件系统Stripe 设置是否正确，MDS 是否会被小文件、目录列表或频繁 stat 打爆。
对象存储对象存储是归档和 shard 分发层，还是被错误当成本地 POSIX 文件系统使用。
验收方法使用 fio、ior、mdtest、真实 shard 读取和真实 checkpoint 写入分别验收。
Checkpoint 发布设计临时文件、完整性校验、manifest 原子切换和失败清理。
冷热分层规划本地 NVMe、并行 FS、对象存储之间的数据生命周期和回收策略。
压测提醒：合成 benchmark 只能给出边界条件，最终仍要用真实 shard 读取、真实 checkpoint 写入和真实并发模式验收。

常见排障入口

训练太慢

  • 先看 GPU 利用率，再看数据加载与网络等待。
  • 区分是单机瓶颈还是分布式通信瓶颈。
  • 先定位瓶颈层，再决定是否需要优化代码。

推理延迟飙升

  • 看请求量变化、批处理策略和缓存命中率。
  • 看是否发生频繁扩缩容或模型重新加载。
  • 看下游依赖是否拖慢整个链路。

成本异常升高

  • 看是否存在资源闲置、过度副本、错误实例规格。
  • 看是否缺少配额与自动回收。
  • 看是否把离线任务错误地放到高价在线集群。
排障顺序：先确认影响面和最近变更，再用指标确定瓶颈层，最后进入具体工具；不要在没有基线的情况下直接调参数。

学习路线

  1. 上线评审先从 上线前检查 确认发布单元、资源、观测和回滚路径。
  2. 生产准入继续使用 成本、治理与安全 确认权限、审计、镜像和 Secrets 边界。
  3. 性能问题优先阅读 性能与系统排查，避免把 CPU、网络、存储和服务策略混在一起猜。
  4. 分布式训练或文档站点问题再进入 网络与文档构建 的专项清单。
