## 输入
- prompt 会告诉你：单元号、负责的章节（给 .md 绝对路径）、输出文件。
- 逐章 Read 它的 .md 全文，再 Read 本部分的 examples 文件（代码示例库）。吃透：这章在讲什么、核心概念、代码怎么写、关键对比、易错点/误区、小结。

## 输出
- Write 到指定文件（如 `_build/tdd/u1.json`），内容是**关卡数组**，顺序与给定章节顺序一致。每关：`{ "title", "subtitle", "intro": [...卡片...], "questions": [...] }`，**不写 id**。合法 JSON。
- `title`：`第N章中文名`（如 `TDD 是什么`、`Mock 与打桩`）。`subtitle`：一句话点出本关主题（如 `红绿重构循环 · 为什么先写测试`）。

## 学新知 intro（7~10 张卡，按章灵活）
典型卡序（不是每章都全有，按内容取舍）：
1. **这一章在解决什么** — 用一段话点出本章主题 + 为什么重要 / 解决什么痛点。
2. **核心概念** — 把本章最关键的概念讲清（定义 + 一句白话解释）。
3. **机制 / 怎么做** — 如红绿重构循环、Mock 的工作方式、夹具生命周期等；可用 `steps` 写流程。
4. **为什么这样做** — 用「为什么…？因为…」自问自答，讲清这个实践/概念背后的道理。**这是最该深的一张卡，不能省。**
5. **代码示例** — `body` 里放 Python 代码围栏（测试代码 + 必要的生产代码），照原章节/examples 写（见代码规则）。
6. **关键对比 / 要点**（按需）— 如 Stub vs Mock、状态验证 vs 行为验证、各断言方法的适用场景（很适合配合 match 题）。
7. **易错点 / 误区** — 列表，3~6 条，照原章节的「常见误解」。
8. **小结** — 一句话收束本关要记住的东西。

## 口吻：正常、清楚的专业表达（务必照 ✅）
同一意思三档对照：
- ❌ **论文腔**：「定理1：测试隔离性可表述为……」「综上所述，证毕」
- ❌ **太大白话 / 俚语**：「这玩意儿说白了就是……」「瞎测一通」「整个测试糊上去」
- ✅ **正常**：「为什么测试之间要相互独立？因为一旦它们共享状态，一个测试失败就可能连累别的，你就分不清到底哪里真的错了。」

要点：用「为什么…？因为…」组织推理；用词正经（隔离性、测试替身、状态验证、行为验证、夹具）；不用编号定理体，也不用俚语；术语第一次出现用一句白话点一下。深度不能因为口吻变白而下降。

## 代码硬规则（违反会导致前端代码块渲染破裂）
- 代码只放卡片 `body` 或 `tip`（按 Markdown 渲染、支持围栏）。`steps`/`title`/`prompt`/选项 只支持**行内** `code`。
- ` ```python ` 起、` ``` ` 收。**代码内部不能有空行**（空行会把代码块切断）；用 4 空格缩进、不要 Tab。
- JSON 字符串里换行写 `\n`。代码照原章节/examples 写，保持可运行、可看懂，单段 ≤ ~24 行（长示例可拆成「测试代码」「生产代码」两张卡或两个相邻围栏，但每个围栏内不留空行）。

## 题目 questions（每关 10~12 道，考理解不考记忆）
schema：
- `{"type":"choice","prompt","options":[...],"answer":0,"explain"}`（answer 是 0 基下标）
- `{"type":"input","prompt","accept":["assertEqual","assertequal"],"explain"}`（accept 列全写法；可问断言/方法名、术语、数值）
- `{"type":"judge","prompt","answer":true,"explain"}`
- `{"type":"match","prompt","left":[...],"right":[...],"explain"}`

深度题方向：为什么先写测试 / 为什么测试要独立、区分相似概念（Stub vs Mock vs Spy、状态验证 vs 行为验证、单元 vs 集成）、给一段测试代码问它测的是什么 / 会不会通过、选对断言方法、判断一个「常见误解」对错、红绿重构每步该做什么。
均衡：choice ≤ 6；judge、match 各 ≥ 1；input ≥ 2。每题都写 `explain`。

### 配对题铁律
`right[i]` 必须是 `left[i]` 的正确答案，**按下标对齐存放，绝对不要把 right 打乱**（前端会自己随机显示）。写完每道 match 逐项核对 left[i] ↔ right[i]。

## 排版
行内 `$...$`（TDD 课基本用不到公式）、代码 / 标识符 / 方法名用反引号；不要裸写 `$`；术语首次给中英对照（如 测试替身 test double）。

## 自检（写文件前）
- 卡数 7~10、含「为什么这样做」深度卡；代码无空行无 Tab、能直接看懂；口吻对照 ✅（无定理体、无俚语）。
- 每关 10~12 题、类型均衡、每题有 explain、答案 / 下标亲自核对；每道 match 逐项对齐。
- 合法 JSON、关卡顺序与给定章节一致。
