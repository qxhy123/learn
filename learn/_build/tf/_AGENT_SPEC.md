## 学新知 intro（7~10 张卡，按章灵活）
典型卡序（按内容取舍）：
1. **这一章在解决什么** — 一段话点出本章主题 + 它解决的建模/工程痛点（如「RNN 为什么不够」）。
2. **核心概念 / 直觉** — 关键机制的直觉解释（先白话，再上公式）。
3. **数学表达** — 关键公式用 `$...$` / `$$...$$`，最核心的一条可放卡片 `formula` 字段（纯 LaTeX，不含 $）。逐符号解释（$Q,K,V$ 是什么、维度多少）。
4. **为什么这样设计** — 用「为什么…？因为…」自问自答讲透动机与取舍（如「为什么除以 $\sqrt{d_k}$」「为什么要多头」「为什么 LayerNorm 不是 BatchNorm」「为什么位置编码用正弦」）。**这是最该深的一张卡，不能省。**
5. **PyTorch 实现** — `body` 里放 Python 代码围栏（见代码规则），照原章节的从零实现，体现本关要点。
6. **关键对比 / 维度演算**（按需）— 如 编码器 vs 解码器、BERT vs GPT vs T5、各 PEFT 方法对比、张量形状逐步演算（很适合配 match 题）。
7. **易错点** — 列表 3~6 条，照原章节常见坑（如忘记缩放、mask 加在 softmax 前还是后、训练推理不一致）。
8. **小结** — 一句话收束本关要记住的东西。

## 口吻：正常、清楚的专业表达（务必照 ✅）
同一意思三档对照：
- ❌ **论文腔**：「定义 4.1：自注意力可形式化为三元映射……」「综上所述，证毕」
- ❌ **太大白话 / 俚语**：「这玩意儿说白了就是加权平均糊一糊」「随便除个数防爆炸」
- ✅ **正常**：「为什么注意力分数要除以 $\sqrt{d_k}$？因为当维度 $d_k$ 较大时，$QK^T$ 的方差会随维度线性增大，点积值变得很大，softmax 会被推到饱和区、梯度几乎为零。除以 $\sqrt{d_k}$ 正好把方差拉回 1，让 softmax 保持在敏感区间。」

要点：用「为什么…？因为…」组织推理；用词正经（缩放点积、掩码、残差连接、层归一化、自回归）；不用编号定义体，也不用俚语；术语首次出现给中英对照 + 一句白话。深度不能因为口吻变白而下降。

## 公式与代码硬规则
- 行内公式 `$...$`、独立公式 `$$...$$`；**公式内中文必须包 `\text{}`**；不要在正文裸写 `$`。
- 代码只放卡片 `body` 或 `tip`。` ```python ` 起、` ``` ` 收。**代码内部不能有空行**（会把代码块切断）；4 空格缩进、不要 Tab；**代码里别用 `$`**。JSON 字符串里换行写 `\n`，单段 ≤ ~24 行。
- `steps`/`title`/`prompt`/选项 只支持行内 `code` 与 `$...$`，不能放围栏块。

## 题目 questions（每关 10~12 道，考理解不考记忆）
schema：
- `{"type":"choice","prompt","options":[...],"answer":0,"explain"}`（answer 是 0 基下标）
- `{"type":"input","prompt","accept":["sqrt(d_k)","√d_k","根号dk"],"explain"}`（accept 列全写法；可问公式成分、复杂度 O(n^2)、维度数值、术语）
- `{"type":"judge","prompt","answer":true,"explain"}`
- `{"type":"match","prompt","left":[...],"right":[...],"explain"}`

深度题方向：为什么除以 $\sqrt{d_k}$ / 为什么多头 / mask 怎么加、张量形状演算（给 batch/seq/d_model 问某步形状）、复杂度（自注意力 $O(n^2 d)$）、区分相似概念（编码器 vs 解码器、BERT vs GPT 的预训练目标、LoRA vs Adapter vs Prefix）、判断常见误解对错、给场景选架构/方法。
均衡：choice ≤ 6；judge、match 各 ≥ 1；input ≥ 2。每题都写 `explain`。

### 配对题铁律
`right[i]` 必须是 `left[i]` 的正确答案，**按下标对齐存放，绝对不要把 right 打乱**（前端会自己随机显示）。写完每道 match 逐项核对 left[i] ↔ right[i]。（很适合 模型 ↔ 预训练目标、符号 ↔ 含义、方法 ↔ 适用场景。）
