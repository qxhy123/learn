## 输入

- 结构化元信息在 `_build/lc150/_meta_<uN>.json`：每题有 `number/title/difficulty/signature/leetcode_url/patterns/examples` 和 **`doc_abs`（题解文档绝对路径）**。

## 输出
- Write 到 prompt 指定的文件（如 `_build/lc150/u1_1.json`），内容是**关卡数组**，顺序与给定题序一致。每关：`{ "title", "subtitle", "intro": [...卡片...], "questions": [...] }`，**不要写 id**。务必合法 JSON。
- `title`：`题号. 中文名 (English Name)`；`subtitle`：`难度 · 中文模式名`（如 `Medium · 双指针`）。

## 学新知 intro（7~10 张卡，参考例子的 9 张，按题灵活取舍）
典型卡序：
1. **题目到底在问什么** — 复述题意 + 1 个最小 example + 难度 + LeetCode 链接（纯文本 URL）。
2. **先看最直接的做法** — 朴素 / 暴力基线（绝大多数题都有；给代码或清晰思路），点明它的代价或破绽，引出优化动机。
3. **核心思路** — 关键洞察 / 为什么本模式（双指针、滑窗、DP…）成立（这里放配图）。
4. **为什么这样做是对的** — 用「为什么…？因为…」自问自答，把正确性 / 循环不变量讲清。**这是最该深的一张卡，不能省。**
5. **完整步骤** — 用 `steps` 写算法主干（每步一句，可含行内 `code`、$...$）。
6. **代码** — `body` 里放一个 Python 围栏块（见「代码硬规则」）。
7. **走查（按需）** — 拿 1~3 个例子逐步追踪状态变化（含边界例子）。
8. **复杂度** — 推导时间 / 空间，破除常见误判（如「嵌套循环 ≠ $O(n^2)$」、摊还、为什么是这个空间）。
9. **易错点** — 列表，3~6 条。

## 口吻：正常、清楚的专业表达（务必照 ✅）
同一句话三档对照：
- ❌ **论文腔**：「引理1（跳过是安全的）：`s[left]` 非字母数字 ⇒ 它不属于任何镜像对」「循环不变量可表述为…」「综上，证毕」
- ❌ **太大白话 / 俚语**：「凭什么能跳过标点？它们压根不在干净序列里」「扒干净」「瞎蒙」「废了」「俩指针」
- ✅ **正常（照这个写）**：「为什么可以直接跳过标点、空格？因为它们根本不在过滤后序列里，不属于任何一对镜像字符，跳过它们不会丢失任何信息」

要点：用「为什么…？因为…」的自问自答来组织推理；用词正经（过滤后序列 / 向中间移动 / 立即返回 / 易错点 / 边界情况）；**不用编号引理体，也不用俚语口水词**；术语第一次出现时用一句白话点一下（如「循环不变量，也就是每轮都成立的那句话」）。深度不能因为口吻变白而下降。

## 代码硬规则（违反会导致前端代码块渲染破裂）
- 代码只放卡片 `body` 或 `tip`（这两个按 Markdown 渲染、支持围栏）。`steps`/`title`/`prompt`/选项 只支持**行内** `code`，不能放围栏块。
- ` ```python ` 起、` ``` ` 收。**代码内部不能有空行**（空行会把代码块切断）；用 4 空格缩进、不要 Tab；代码里不要出现 `$`。
- JSON 字符串里换行写 `\n`，整段代码是一个字符串。用文档里那份最优解，≤ ~24 行。

## 题目 questions（每关 10~12 道，考推理不考记忆）
schema：
- `{"type":"choice","prompt","options":[...],"answer":0,"explain"}`（answer 是正确项 0 基下标）
- `{"type":"input","prompt","accept":["O(n)","O(N)","线性"],"explain"}`（accept 列全所有可接受写法）
- `{"type":"judge","prompt","answer":true,"explain"}`
- `{"type":"match","prompt","left":[...],"right":[...],"explain"}`

深度题方向（参考例子）：为什么跳过 / 移动某指针是安全的、循环不变量、一对不等为何即可否定、**为什么有嵌套循环仍是 $O(n)$**、忘记某一步会得到什么反例、暴力 vs 最优差在哪、给最小输入问输出 / 中间状态。
均衡：choice ≤ 6；judge、match 各 ≥ 1；input ≥ 2（其中复杂度至少 1~2 道）。每题都写 `explain`。

### 配对题铁律
`right[i]` 必须是 `left[i]` 的正确答案，**按下标对齐存放，绝对不要把 right 打乱顺序**（前端会自己随机打乱显示）。写完每道 match 逐项核对 left[i] ↔ right[i]。

## 配图
prompt 会列出本单元可用配图（如 `lc-two-pointers-1.svg`）。在合适关卡的某张卡加 `"image": "文件名"` + `"imageCaption"`，一般放在本单元第 1 关的「核心思路」卡做模式总览，多余的图放别的关。一张卡最多一张图。

## 排版
行内公式 `$...$`、独立 `$$...$$`，公式里中文包 `\text{}`；代码 / 标识符 / 变量用反引号；不要裸写 `$`；术语首次出现给中英对照。

- 卡数 7~10、含「为什么这样是对的」深度卡；代码无空行无 Tab、能直接看懂；口吻对照 ✅（无引理体、无俚语）。
- 每关 10~12 题、类型均衡、每题有 explain、答案 / 下标 / 复杂度都亲自核对；每道 match 逐项对齐。
- 合法 JSON、关卡顺序与给定题序一致。
