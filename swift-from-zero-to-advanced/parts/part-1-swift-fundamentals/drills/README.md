# Part 1 Drills

## Why Drills Exist

The chapters teach the ideas.
The drills force the reader to operate those ideas instead of only recognizing
them on the page.

Part 1 drills exist to make three things happen:

- confirm conceptual understanding, not just familiarity with keywords
- train code reading, because engineering depends on reading at least as much as writing
- push each chapter one step beyond the example so the reader starts making small decisions alone

If a reader skips the drills, Part 1 becomes much easier to misunderstand as
"Swift syntax exposure" instead of "Swift fundamentals practice."

## Required Drill Types

Each Part 1 chapter should include exactly these three drill categories:

- concept check
- code reading
- hands-on extension

The categories are intentional.
A concept check tests whether the reader can explain the underlying rule.
A code-reading task tests whether the reader can trace meaning from existing
Swift code.
A hands-on extension tests whether the reader can modify a small example
without losing control of it.

## Difficulty Rule

Part 1 drills should be short enough to fit inside a normal study session, but
they should increase difficulty in a disciplined way:

- concept checks should be answerable from the chapter's core idea
- code-reading tasks should require careful tracing, not hidden tricks
- hands-on extensions should add one meaningful twist, not a whole new subsystem

The rule is simple:
each drill should be slightly harder than the chapter example, but never so
large that it secretly becomes a Part 2 design problem.
