# Part 1 Checkpoint

## Required Demonstrations

To complete Part 1, the reader should be able to demonstrate all of the
following without relying on copy-paste alone:

- run Swift code with the toolchain and explain the `swift` versus `swiftc` distinction
- use values, mutability, and type inference deliberately in small examples
- read command-line input and produce clear formatted output
- route command behavior with readable control flow and named functions
- model task data with a `struct` and store task state in an array
- parse missing or invalid input safely with optionals and `if let`
- model known commands with an enum and route them through `switch`
- explain how those pieces integrate inside `TaskCLI Lite`

## Completion Standard

Part 1 is complete when the reader can do more than repeat isolated facts.
The standard is operational:

- they can explain what each Part 1 concept is for
- they can identify where each concept appears in the integrated CLI
- they can make a small extension without collapsing the program structure
- they do not need premature architecture to keep the code understandable

If the reader can build, read, and slightly extend `TaskCLI Lite` while still
explaining the semantics behind the code, Part 1 has done its job.
