1. rocm-smi 是什么

rocm-smi 是 ROCm System Management Interface 的命令行工具，通常位于 /opt/rocm/bin/rocm-smi。它通过 rocm_smi_lib 与 Linux amdgpu 驱动暴露的管理接口交互，用于查看和控制 AMD GPU 的运行状态。

它擅长什么
确认 AMD GPU 是否被 ROCm 识别、查看利用率/显存/温度/功耗/时钟、定位 KFD 进程、采集 PCIe/XGMI/RAS 线索、做维护窗口内的设备控制。
它不擅长什么
深度 kernel 性能剖析、算子级瓶颈分析、NCCL/RCCL 通信时间分解、PyTorch/HIP 应用逻辑定位。那些问题需要 profiler、框架日志和通信日志。
AI Infra 价值
它是 AMD GPU 节点排障的第一跳：先确认设备和驱动，再判断作业是否真正跑到 GPU，最后用功耗、时钟、温度、拓扑和错误计数补齐证据链。
# 最常见：查看全部 AMD GPU 当前状态
rocm-smi

# 若 PATH 未包含 ROCm
/opt/rocm/bin/rocm-smi

# 查看版本：注意 CLI 版本和 rocm_smi_lib 版本可能分别显示
rocm-smi --version

# 查看帮助，目标机器上的帮助永远是最终准绳
rocm-smi --help
版本提醒： ROCm 版本、GPU ASIC、内核驱动和权限都会影响字段与控制项是否可用。生产脚本应先记录 rocm-smi --version、rocminfo、内核版本和 GPU 型号。

2. 整体心智模型

ROCm 栈里，rocm-smi 不是训练框架的一部分，而是节点管理面工具。它看到的是驱动和设备状态，不一定解释应用为何慢。

3. 安装、路径与版本检查

在 ROCm 节点上，rocm-smi 通常随 ROCm SMI library 安装。不同发行版、ROCm meta package、容器镜像和集群基线会把它放在不同位置，最稳妥的做法是先确认命令位置、库版本、驱动和 GPU 可见性。

检查项命令判断
命令路径command -v rocm-smi || ls /opt/rocm/bin/rocm-smi存在且来自预期 ROCm 安装目录。
CLI 与库版本rocm-smi --version记录 ROCM-SMI 与 ROCM-SMI-LIB 版本，便于复盘。
ROCm 设备枚举rocminfo能看到目标 GPU agent；容器内也要验证。
内核驱动lsmod | grep amdgpuamdgpu 模块加载；计算场景还要关注 KFD。
设备节点ls -l /dev/kfd /dev/dri/renderD*容器和用户权限必须能访问计算设备。
# 节点入口检查模板
hostname
uname -r
command -v rocm-smi
rocm-smi --version
rocm-smi --showdriverversion
rocminfo | sed -n '1,80p'
兼容提醒： 如果 rocm-smi 可见但 rocminfo 不可见，可能只是管理面能读到设备，计算运行时未准备好；反过来也可能是 PATH 或包拆分问题。

4. 第一批安全只读命令

刚登录一台 AMD GPU 节点时，先跑只读命令。它们不会修改设备状态，适合日常巡检、作业排障起点和自动化采样。

人工巡检最小集 
rocm-smi
rocm-smi --showallinfo
rocm-smi --showuse --showmemuse --showtemp --showpower --showclocks
rocm-smi --showpids
硬件与拓扑线索 
rocm-smi --showhw --showbus --showproductname
rocm-smi --showtopo
rocm-smi --showtoponuma
rocm-smi --showxgmierr
命令风险用途
rocm-smi低默认状态快照。
rocm-smi -a / --showallinfo低温度、风扇、时钟等综合信息。
--showpids, --showpidgpus低查看 KFD 进程和进程使用的 GPU。
--showtopo*低查看 GPU 间访问、权重、hop、类型、NUMA。
--showrasinfo, --showpagesinfo低看 RAS、retired/pending/unreservable pages 等硬件可靠性线索。
团队约定： 在 runbook 里把命令分为“只读安全”“需维护窗口”“需下线节点”。值班人员不应靠记忆判断某个选项是否危险。

5. 默认输出与常用字段

直接运行 rocm-smi 会显示每张 AMD GPU 的当前状态。不同 ROCm 版本和 GPU 型号字段略有差异，但 AI Infra 排障关心的核心始终是：设备是否存在、利用率是否符合训练阶段、显存是否被占用、温度/功耗/时钟是否限制性能、是否有进程归因。

字段/概念怎么理解排障提示
GPU use / --showuseGPU 忙碌程度，常用于判断计算是否上卡。训练中长期低，查数据加载、CPU、I/O、RCCL 同步、batch 太小或进程未真正进入 HIP kernel。
VRAM use / --showmemuse显存使用比例或占用信息。显存高不代表正在计算；可能只是模型加载、缓存、挂起进程或服务常驻。
Temperature / --showtempGPU 温度或多传感器温度。高温会触发降频或保护，需结合风扇、机房温度和功耗。
Power / --showpower当前平均或 socket/package 功耗。利用率高但功耗低，可能是 memory-bound、小 batch、降频、采样窗口问题或非满载 workload。
Clocks / --showclocks当前 SCLK/MCLK 等频率。性能异常时必须看是否被 DPM、功耗、温度或手工锁频影响。
Perf level / --showperflevelDPM 性能等级策略，如 auto、low、high、manual。生产环境通常保持 auto；manual 常见于基准测试或特殊调优。
# 针对 AI 作业的常用一屏
rocm-smi --showuse --showmemuse --showtemp --showpower --showclocks --showperflevel

# 查看更完整状态
rocm-smi --showallinfo

# 只看硬件识别和驱动
rocm-smi --showhw --showproductname --showbus --showdriverversion
读数提醒： GPU 利用率是采样窗口内的近似读数。短 kernel、阶段性评估、checkpoint、分布式同步或推理突发流量，都可能让单次快照误导判断。

6. 设备选择、编号与稳定标识

-d / --device 可以限制命令作用于指定 GPU。人工临时查看用 index 很方便；自动化脚本需要同时记录 BDF/PCI Bus、unique ID、serial、product name 和容器内外的可见映射。

标识查看方式适用场景
GPU indexrocm-smi, rocm-smi -d 0人工巡检和临时查询，最短但可能随环境变化。
PCI Bus/BDFrocm-smi --showbus和 lspci、NUMA、硬件槽位、XGMI/PCIe 排障联动。
Unique IDrocm-smi --showuniqueid资产映射和跨重启识别，具体可用性依赖硬件。
Serial/Product--showserial, --showproductnameRMA、节点验收、库存系统对账。
# 只看第 0、1 张卡的利用率和显存
rocm-smi -d 0 1 --showuse --showmemuse

# 建立 GPU index 与硬件标识映射
rocm-smi --showbus --showuniqueid --showserial --showproductname

# 和 lspci 交叉验证
lspci -nn | grep -i -E 'amd|advanced micro devices|display|vga|3d'
容器提醒： 容器内 GPU index 可能经过设备插件或 cgroup 过滤后重映射。跨宿主机和容器排障时，不要只记录 “GPU 0”，至少记录 PCI Bus、节点名、容器 ID 和作业 ID。

7. 利用率、显存与瓶颈判断

显存是资源分配线索，利用率是活动线索；判断 AMD GPU 作业慢，必须再加入功耗、时钟、温度、进程、容器和训练阶段。
# 连续观察：用 watch 包一层，避免只看单次快照
watch -n 1 'rocm-smi --showuse --showmemuse --showpower --showtemp --showclocks'

# 低频记录到日志，便于回放
while true; do
  date '+%F %T'
  rocm-smi --showuse --showmemuse --showpower --showtemp --showclocks
  sleep 30
done >> rocm-smi-snapshot.log
经验规则： 如果应用日志显示 step time 慢，但 GPU use 低且 VRAM use 高，优先怀疑 GPU 之外的瓶颈：数据加载、CPU 预处理、网络同步、文件系统、rank 卡死或框架等待。

8. 温度、风扇、功耗与降频

AI 节点的稳定吞吐高度依赖功耗和散热。rocm-smi 能显示温度、风扇、功耗和最大功耗等字段，帮助判断是否存在 thermal throttle、power cap、风道堵塞或机柜功耗预算问题。

关注项命令解释
温度rocm-smi --showtemp不同 GPU 可能显示 edge/junction/memory 等传感器，不能跨型号简单比较。
风扇rocm-smi --showfan服务器被动散热卡可能没有可控风扇读数，要看整机风扇/BMC。
当前功耗rocm-smi --showpower训练满载时应与历史基线相近；明显偏低要查时钟、性能等级和 workload。
功耗上限rocm-smi --showmaxpower了解设备可消耗的最大 graphics/package power。
能耗计数rocm-smi --showenergycounter适合粗粒度作业能耗估算，注意采样粒度和重置语义。
# 查看温度、风扇、功耗与时钟
rocm-smi --showtemp --showfan --showpower --showmaxpower --showclocks

# 训练启动后观察是否功耗爬升
watch -n 2 'rocm-smi --showuse --showpower --showclocks --showtemp'
风扇控制警告： --setfan 会改变散热策略。除非你明确知道硬件散热设计、BMC 策略和回滚命令，否则不要在生产节点上手动降低风扇。

9. 时钟、DPM 与性能等级

AMD GPU 通过 DPM/performance level 动态调整频率。rocm-smi 可以显示当前时钟、可用频率范围、性能等级，也可以在维护场景中锁定或限制 SCLK/MCLK。排障时要先读，再决定是否需要改。

命令用途风险
--showclocks查看当前时钟频率。低，只读
--showgpuclocks查看 GPU 相关时钟。低，只读
--showclkfrq, --showsclkrange, --showmclkrange查看支持的时钟级别或范围。低，只读
--showperflevel查看 DPM performance level。低，只读
--setperflevel manual, --setsclk ..., --setmclk ...进入手动性能等级并设置频率级别 mask。高，改变设备行为
# 只读：确认当前时钟和可用范围
rocm-smi --showclocks --showperflevel --showclkfrq --showsclkrange --showmclkrange

# 维护窗口内示例：先记录状态，再改，再验证，再准备回滚
rocm-smi -d 0 --showperflevel --showclocks --showclkfrq
sudo rocm-smi -d 0 --setperflevel manual
sudo rocm-smi -d 0 --setsclk 5 6 7
rocm-smi -d 0 --showperflevel --showclocks

# 回滚到默认策略
sudo rocm-smi -d 0 --resetclocks
sudo rocm-smi -d 0 --setperflevel auto
调优边界： 锁时钟适合 benchmark 稳定性或特定平台验收，不应作为“训练慢”的第一反应。先证明瓶颈来自频率策略，再考虑变更。

10. 进程可见性与 KFD caveat

rocm-smi --showpids 主要关注 KFD 计算进程，也就是通过 ROCm/HIP 计算路径使用 GPU 的进程。它不一定完整呈现所有图形、显示、容器命名空间或短生命周期进程。AI Infra 排障时，要把 rocm-smi 的 PID 视图和 Linux 进程、调度器、容器运行时一起看。

# 查看当前 KFD PIDs
rocm-smi --showpids

# 显示更详细的 PID 信息，具体字段依赖版本
rocm-smi --showpids details

# 查看指定 PID 使用哪些 GPU；不带参数时通常显示全部
rocm-smi --showpidgpus
rocm-smi --showpidgpus 12345

# 把 PID 映射到用户、命令、父进程
ps -fp 12345
pstree -sap 12345
现象可能原因下一步
显存被占，但 --showpids 不明显进程短生命周期、容器命名空间、图形上下文、驱动残留或工具字段限制。查 ps、fuser /dev/kfd /dev/dri/renderD*、调度器作业和容器进程。
看到 PID 但不知道作业PID 属于容器内进程或 torchrun 子进程。用 ps -o pid,ppid,user,cmd、crictl/docker、Slurm/K8s 映射。
所有卡都显示低利用率作业等待同步、数据加载慢、rank 异常、RCCL 卡住。查训练日志、CPU/I/O、网络、RCCL_DEBUG 日志。
协作规范： 不要因为看到某个 PID 占显存就直接 kill -9。先确认用户、作业 ID、调度器状态和是否可安全重启。

11. 机器可读输出：JSON/CSV

默认输出适合人眼查看，不适合稳定解析。rocm-smi 支持 --json 和 --csv，用于巡检脚本、采样日志、CI 健康检查和排障证据收集。字段随版本和硬件变化，脚本要有容错。

# JSON：适合 jq 或 Python 解析
rocm-smi --showuse --showmemuse --showtemp --showpower --showclocks --json

# CSV：适合追加日志和表格处理
rocm-smi --showuse --showmemuse --showtemp --showpower --csv

# 建议同时记录命令版本和采样时间
{
  date '+%F %T'
  rocm-smi --version
  rocm-smi --showuse --showmemuse --showtemp --showpower --json
} > rocm-smi-evidence.jsonlog
输出优点注意事项
--json结构化，适合脚本、API、日志收集。字段名/层级可能随版本变化，解析时要检查 key 是否存在。
--csv简单、容易追加、适合 shell/awk。列顺序和单位要固定，升级后做兼容测试。
默认文本人眼友好，排障快。不要用脆弱正则解析默认大表格。
自动化建议： 把采集脚本绑定到固定 ROCm 镜像或节点基线；升级 ROCm 前，把 JSON/CSV 样例纳入兼容性测试。

12. 拓扑、PCIe、XGMI 与 NUMA

多卡训练性能不只取决于单卡 util。GPU 间互联、NUMA、NIC 位置和 rank 绑定都会影响 RCCL 通信效率。
# 拓扑总览
rocm-smi --showtopo

# 分别查看 GPU 间访问性、权重、hop、类型、NUMA
rocm-smi --showtopoaccess
rocm-smi --showtopoweight
rocm-smi --showtopohops
rocm-smi --showtopotype
rocm-smi --showtoponuma

# XGMI 错误线索
rocm-smi --showxgmierr
多卡建议： 对比慢节点和健康节点时，保存 rocm-smi --showtopo*、lspci -tv、NUMA 信息、NIC 位置和 RCCL 日志，单看 GPU 利用率通常不够。

13. ROCm 栈与容器可见性

容器里的 rocm-smi 读数受宿主机驱动、设备节点、用户权限、cgroup、Kubernetes device plugin 和镜像内 ROCm 版本共同影响。很多“GPU 不可用”问题不是 rocm-smi 本身坏了，而是容器没有拿到 /dev/kfd 或 /dev/dri/renderD*。

层次检查命令常见问题
宿主机驱动rocm-smi, rocminfo驱动未加载、ROCm 版本不匹配、GPU 不在支持矩阵。
设备节点ls -l /dev/kfd /dev/dri/renderD*容器未挂载设备、权限组不对、rootless 运行限制。
容器镜像command -v rocm-smi; rocm-smi --version镜像没装工具，或工具版本与宿主库组合不兼容。
调度器kubectl describe pod, scontrol show job资源未分配、设备插件过滤、环境变量映射错。
# Docker 示例：以宿主机设备为准，具体参数按平台安全策略调整
docker run --rm -it \
  --device=/dev/kfd \
  --device=/dev/dri \
  --group-add video \
  --group-add render \
  rocm/dev-ubuntu-22.04:latest \
  bash -lc 'rocminfo | head -80; rocm-smi'

# Kubernetes 容器内排查
ls -l /dev/kfd /dev/dri || true
rocminfo | sed -n '1,120p'
rocm-smi --showuse --showmemuse --showpids
容器 caveat： 容器里运行 rocm-smi 可能只能看到被分配的设备，也可能因权限不足无法执行某些控制项。生产变更应在宿主机维护流程里做，不要从业务容器随手改 GPU 状态。

14. 安全控制：重置、功耗、风扇、时钟

任何会改变 GPU 状态的命令，都应当被当作生产变更，而不是普通查询命令。

高风险控制项速查

操作示例安全要求
GPU resetsudo rocm-smi -d 0 --gpureset确认 GPU 无业务、驱动支持、影响范围明确；重置可能中断上下文。
功耗上限/Power OverDrivesudo rocm-smi -d 0 --setpoweroverdrive 500确认电源、散热、厂商规格和回滚；越规格风险高。
风扇sudo rocm-smi -d 0 --setfan 80%不要降低到不安全水平；回滚用 --resetfans。
性能等级/时钟sudo rocm-smi -d 0 --setperflevel manual --setsclk 5 6 7先记录可用时钟，单卡验证，准备 --resetclocks。
自动回答提示--autorespond y不推荐；会绕过人工确认，自动化必须另有审批门禁。
# 安全变更模板：先保存状态
rocm-smi -d 0 --showallinfo --json > before-gpu0.json

# 维护窗口内执行单项变更
sudo rocm-smi -d 0 --setperflevel high
rocm-smi -d 0 --showperflevel --showclocks --showpower --showtemp

# 回滚
sudo rocm-smi -d 0 --resetclocks
sudo rocm-smi -d 0 --setperflevel auto
sudo rocm-smi -d 0 --resetfans
sudo rocm-smi -d 0 --resetpoweroverdrive
越规格警告： OverDrive、手工电压/频率、功耗上调和风扇策略可能导致硬件损坏、系统不稳定或保修风险。AI 集群中不要把这些命令作为常规优化手段。

15. 分区、RAS、页面与硬件错误

在数据中心 GPU 上，rocm-smi 还可能暴露 compute partition、memory partition、RAS、retired pages、pending pages、unreservable pages、XGMI error 等可靠性与隔离相关信息。它们对节点验收、故障 GPU 隔离和 RMA 证据非常重要。

能力只读命令变更/重置命令用途
Compute partition--showcomputepartition--setcomputepartition ..., --resetcomputepartition调整计算分区模式，影响作业可见的计算资源。
Memory partition--showmemorypartition--setmemorypartition ..., --resetmemorypartition调整内存/NPS 分区，影响 NUMA 与带宽行为。
RAS info--showrasinfo--rasenable, --rasdisable, --rasinject查看可靠性、可用性、可服务性相关状态和错误计数。
Pages info--showpagesinfo, --showpendingpages, --showretiredpages通常不应随意改，由驱动/硬件策略管理。定位显存页错误、退役页、待处理页。
XGMI error--showxgmierr--resetxgmierr多 GPU 互联错误证据，重置计数前要先保存。
# 可靠性证据采集
rocm-smi --showrasinfo --showpagesinfo --showxgmierr --json > ras-pages-xgmi.json
dmesg -T | grep -i -E 'amdgpu|kfd|ras|xgmi|gpu' > kernel-gpu-events.log

# 重置错误计数前先保存证据
rocm-smi --showxgmierr
sudo rocm-smi --resetxgmierr
rocm-smi --showxgmierr
证据保全： 不要在未保存原始输出前清零错误计数、重置 GPU 或修改分区。硬件故障复盘最需要的是“什么时候、哪张卡、什么错误、业务影响是什么”。

16. rocm-smi vs nvidia-smi vs amd-smi

熟悉 NVIDIA 平台的人容易把 rocm-smi 当作 nvidia-smi 的一对一替代品。它们都能做 GPU 状态查看和部分管理，但底层驱动、字段语义、进程可见性、拓扑表达、MIG/partition 模型和未来演进方向不同。另一个重要事实是：AMD SMI 是 AMD 目前更统一的新管理接口方向，生产平台要关注迁移。

工具生态定位AI Infra 注意点
rocm-smiAMD ROCm / rocm_smi_lib传统 ROCm SMI CLI，查看和控制 AMD GPU。大量 ROCm 集群仍在用；选项强大但版本/硬件差异明显。
amd-smiAMD SMI较新的 AMD System Management Interface CLI/API。AMD 官方文档将 AMD SMI 作为后续统一方向；新平台应评估采用。
nvidia-smiNVIDIA 驱动 / NVMLNVIDIA GPU 标准 CLI。不要直接迁移字段名和脚本逻辑；ROCm 的 KFD、XGMI、分区模型不同。
# AMD ROCm 传统工具
rocm-smi --showuse --showmemuse --showpower --showtemp

# AMD 新 SMI 工具：如果环境已安装，按目标版本帮助使用
amd-smi --help
amd-smi monitor

# NVIDIA 对照，不要混用到 AMD 节点
nvidia-smi --query-gpu=utilization.gpu,memory.used,power.draw --format=csv
迁移建议： 新建平台或升级 ROCm 大版本时，把 rocm-smi 与 amd-smi 的字段覆盖、容器支持、Prometheus/exporter 集成和脚本兼容性一起评估，不要只替换命令名。

17. 排障剧本

下面的剧本按“先低风险、再深入、最后变更”的顺序组织。每一步都尽量收集证据，而不是直接修改 GPU 状态。

场景 A：训练任务很慢

# 1. 看 GPU 是否真的忙
rocm-smi --showuse --showmemuse --showpower --showclocks --showtemp

# 2. 看进程归属
rocm-smi --showpids details
ps -fp <PID>

# 3. 看拓扑和 NUMA 是否异常
rocm-smi --showtopo --showtoponuma

# 4. 应用层继续查
# PyTorch profiler / HIP profiler / RCCL_DEBUG / dataloader / filesystem / network

场景 B：容器里看不到 GPU

# 宿主机先确认
rocm-smi
rocminfo | sed -n '1,120p'

# 容器内确认设备节点和权限
ls -l /dev/kfd /dev/dri || true
id
groups
rocminfo | sed -n '1,120p'
rocm-smi || true

场景 C：GPU 温度高或疑似降频

rocm-smi --showtemp --showfan --showpower --showmaxpower --showclocks --showperflevel
dmesg -T | grep -i -E 'amdgpu|thermal|throttle|power'

# 不要先降频或改风扇；先看机房、风道、BMC、邻近卡和历史基线。

场景 D：疑似硬件错误

mkdir -p gpu-evidence
rocm-smi --showallinfo --json > gpu-evidence/rocm-smi-all.json
rocm-smi --showrasinfo --showpagesinfo --showxgmierr --json > gpu-evidence/ras-pages-xgmi.json
dmesg -T | grep -i -E 'amdgpu|kfd|ras|xgmi|gpu' > gpu-evidence/kernel-gpu.log
lspci -vv > gpu-evidence/lspci-vv.txt
排障顺序： 先证明“设备可见”和“作业上卡”，再判断“是否忙”和“是否被限制”，最后才考虑 reset、锁频、功耗、分区等状态变更。

18. 自动化巡检模板

自动化脚本应保守：只读采集、记录版本、固定字段、保存原始输出、遇到不可解析字段不直接失败。下面模板适合节点健康快照，不做任何设备变更。

#!/usr/bin/env bash
set -euo pipefail

out_dir="${1:-rocm-smi-health-$(hostname)-$(date +%Y%m%d-%H%M%S)}"
mkdir -p "$out_dir"

{
  echo "host=$(hostname)"
  echo "time=$(date -Is)"
  echo "kernel=$(uname -r)"
  command -v rocm-smi || true
  rocm-smi --version || true
} > "$out_dir/meta.txt"

rocm-smi --showallinfo --json > "$out_dir/rocm-smi-all.json" 2>"$out_dir/rocm-smi-all.err" || true
rocm-smi --showuse --showmemuse --showtemp --showpower --showclocks --csv > "$out_dir/metrics.csv" 2>"$out_dir/metrics.err" || true
rocm-smi --showpids details > "$out_dir/pids.txt" 2>"$out_dir/pids.err" || true
rocm-smi --showtopo --showtoponuma --showxgmierr > "$out_dir/topo-xgmi.txt" 2>"$out_dir/topo-xgmi.err" || true
rocm-smi --showrasinfo --showpagesinfo > "$out_dir/ras-pages.txt" 2>"$out_dir/ras-pages.err" || true

dmesg -T | grep -i -E 'amdgpu|kfd|gpu|ras|xgmi' > "$out_dir/kernel-gpu.log" || true
echo "saved: $out_dir"
自动化边界： 采集脚本可以无人值守；控制脚本不应无人值守。任何带 --set*、--reset*、--gpureset、--ras* 的脚本都要有审批、目标白名单和回滚日志。

19. 常见坑与 FAQ

Q：rocm-smi 能看到 GPU，训练框架看不到。
A：管理面可见不等于计算运行时可用。继续查 rocminfo、/dev/kfd、/dev/dri 权限、容器设备挂载、PyTorch ROCm 版本和 GPU 支持矩阵。
Q：显存高但利用率为 0，是不是坏了？
A：不一定。模型加载后等待数据、评估阶段、分布式同步、服务空闲、进程挂起都可能这样。看任务日志和时间窗口。
Q：能不能像 NVIDIA 一样解析默认表格？
A：不建议。用 --json 或 --csv，并把 ROCm 版本纳入兼容测试。
Q：为什么某些选项报不支持？
A：很多控制项依赖 ASIC、固件、内核、权限和平台策略。先看 rocm-smi --help 和目标 GPU 文档。
Q：为什么容器内外 GPU 编号不一致？
A：设备插件、cgroup 和容器运行时可能过滤或重映射设备。跨层定位时记录节点名、PCI Bus、容器 ID 和作业 ID。
Q：要不要新项目直接用 amd-smi？
A：如果目标 ROCm 版本和运维平台已支持，应该评估。现有集群仍可能依赖 rocm-smi 脚本，迁移要做字段和行为对照。
最后提醒： rocm-smi 不是“只读工具”。它包含很多能改变硬件状态的选项。把查询命令和变更命令分开管理，是 AI Infra 生产安全底线。
