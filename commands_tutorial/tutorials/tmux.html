tmux 深度教程：AI Infra 长任务、远程会话与协作排障

这份教程面向 AI Infra 与 Linux 运维场景：训练任务要跑几小时到几天，远程 SSH 会断，GPU 节点需要多人排障，日志需要持续观察和保存。tmux 的核心价值是把“终端界面”和“后台会话”解耦，让命令继续运行、窗口可重组、输出可回放、同一会话可被多人或多端附着。

AI Infra持久会话训练任务SSH 断线恢复窗口/面板日志捕获pair debugging安全长任务故障排查
一句话理解： tmux 是运行在服务器上的“终端会话管理器”：SSH 只是进入会话的通道，断开 SSH 不等于杀掉 tmux 会话里的训练、监控和排障命令。
最重要实践： 长训练先在 tmux 里启动，再用日志重定向或 pipe-pane/capture-pane 留证据；离开前用 tmux ls、ps、nvidia-smi 确认任务仍在运行。

1. tmux 解决什么问题

在 AI Infra 场景里，终端不是一次性命令入口，而是训练、压测、监控、排障的工作台。tmux 把这个工作台放在远程机器上的后台服务里，客户端断开后，会话仍然存在。

长任务不中断
训练、数据预处理、模型导出、压测脚本可以在 SSH 断开后继续运行。
多视图排障
一个窗口看训练日志，一个看 nvidia-smi，一个看网络或磁盘指标，不必开很多 SSH 终端。
协作可复现
同一 tmux 会话可以被多端附着，适合 pair debugging、交接现场和线上故障复盘。
# 查看已有会话
tmux ls

# 创建名为 train-a100 的会话
tmux new -s train-a100

# 在会话内按 Ctrl-b 再按 d 断开
# 之后重新进入
tmux attach -t train-a100
边界提醒： tmux 保住的是“终端会话”。机器重启、OOM killer、用户被强制登出、作业被调度器清理时，tmux 不能保证任务继续运行。

2. 核心心智模型

信息图：tmux 的整体心智模型

tmux 的关键不是“分屏”，而是远程节点上的持久会话服务端。分屏只是这个模型上的交互能力。

3. 安装、版本与环境检查

大多数 Linux 发行版都能直接安装 tmux。AI 集群里常见情况是登录节点有 tmux，计算节点镜像未必有；进入容器后也可能没有。

系统安装命令检查
Ubuntu/Debiansudo apt-get update && sudo apt-get install -y tmuxtmux -V
RHEL/CentOS/Rockysudo dnf install -y tmux 或 sudo yum install -y tmuxcommand -v tmux
macOS 本地测试brew install tmuxtmux -V
容器镜像在 Dockerfile 或基础镜像里安装确认容器不会因主进程退出而停止
# 基础检查
tmux -V
tmux info | sed -n '1,20p'

# 确认当前是否已经在 tmux 中
echo "$TMUX"

# 确认终端类型，排查颜色/按键问题时很有用
echo "$TERM"
版本建议： 新项目尽量使用 3.x 系列。旧集群上的 1.x/2.x 仍能完成持久会话，但部分配置项、复制模式和真彩色支持会有差异。

4. 第一个持久会话

最小安全流程是：创建命名会话、启动命令、断开、重新附着、确认任务存在。会话名要有业务含义，避免多个训练同时运行时找不到现场。

# 1. 创建命名会话
tmux new -s exp-resnet50-a100

# 2. 在 tmux 里启动任务，建议同时写日志
mkdir -p logs
python train.py --config configs/resnet50.yaml 2>&1 | tee logs/resnet50-$(date +%F-%H%M).log

# 3. 断开 tmux：按 Ctrl-b，然后按 d

# 4. 回到普通 shell 后查看会话
tmux ls

# 5. 重新进入
tmux attach -t exp-resnet50-a100
new -s
创建一个有名字的会话，适合长期任务。
detach
断开客户端，不杀会话；默认快捷键是 Ctrl-b d。
attach -t
按名称回到会话，继续看同一个终端现场。
不要混淆： 在 tmux 窗口里输入 exit 会退出当前 shell；如果那是最后一个 pane，窗口和会话可能随之结束。离开现场应使用 detach，不是 exit。

5. 会话、窗口、面板层级

tmux 的层级是 session → window → pane。AI Infra 工作中，通常一个实验或一次事故一个 session，一个主题一个 window，一个命令视角一个 pane。

层级类比AI Infra 用法常用命令
session一个工作现场一次训练、一次集群故障、一次发布窗口tmux new -s name、tmux attach -t name
window一个标签页train、gpu、logs、sshtmux new-window -n gpu
pane一个分屏终端日志、监控、shell、编辑器并排tmux split-window -h、tmux split-window -v
# 在已有会话里新建窗口
tmux new-window -n gpu

# 水平/垂直拆分当前窗口
tmux split-window -h
tmux split-window -v

# 给当前窗口改名
tmux rename-window train

# 列出层级
tmux list-sessions
tmux list-windows
tmux list-panes

图解：Session / Window / Pane 层级

建议把“会话名”绑定实验或事故，把“窗口名”绑定任务域，把“面板”绑定具体命令。

6. 前缀键与常用快捷键

tmux 的交互命令通常先按前缀键，再按一个动作键。默认前缀是 Ctrl-b，本文用 prefix 表示它。

快捷键作用使用场景
prefix ddetach安全离开训练现场
prefix c新建窗口新增监控/日志页
prefix ,重命名窗口把窗口改成 train/gpu
prefix %左右拆分 pane日志和 shell 并排
prefix "上下拆分 pane上面看监控，下面跑命令
prefix o切换 pane快速移动焦点
prefix z当前 pane 最大化/还原临时专注查看长日志
prefix [进入 copy mode滚动、搜索历史输出
prefix ?查看快捷键帮助忘记命令时自查
训练节点建议： 不要急着大改快捷键。团队共享机器上，默认 Ctrl-b 最容易沟通；个人机器再考虑改成 Ctrl-a。

7. Attach、Detach 与会话恢复

会话恢复是 tmux 最重要的能力。常用命令不多，但要理解“附着客户端”和“会话进程”是两件事。

# 查看所有会话
tmux ls

# 附着到唯一会话
tmux attach

# 附着到指定会话
tmux attach -t exp-resnet50-a100

# 如果会话已被其他终端附着，先踢掉其他客户端再进入
tmux attach -d -t exp-resnet50-a100

# 重命名会话
tmux rename-session -t old-name new-name

# 安全关闭空会话
tmux kill-session -t old-debug
场景命令说明
SSH 断线后回来tmux attach -t name回到原现场，任务应继续运行
屏幕尺寸混乱tmux attach -d -t name断开旧客户端，使用当前终端尺寸
不确定任务在哪tmux ls + tmux list-windows -t name先定位，不要乱 kill
会话太多tmux kill-session -t name只清理确认无任务的会话
破坏性命令： kill-session 会终止会话里的 shell 和前台命令。执行前先进入会话或用 tmux capture-pane/ps 确认没有重要进程。

8. AI 训练任务安全运行

tmux 让任务不随 SSH 断开而中断，但训练任务仍要自己做好日志、环境、退出状态和资源观测。不要把 tmux 当成作业调度器。

# 推荐：进入清晰命名的会话
tmux new -s train-llama-sft

# 推荐：记录环境快照
mkdir -p logs
{
  date
  hostname
  git rev-parse --short HEAD 2>/dev/null || true
  nvidia-smi --query-gpu=index,name,memory.total,driver_version --format=csv
  env | sort | sed -n '1,80p'
} | tee logs/run-env.txt

# 推荐：训练 stdout/stderr 同时显示和落盘
python -u train.py --config configs/sft.yaml 2>&1 | tee logs/train-$(date +%F-%H%M).log

# 另一个 pane 里观察 GPU
watch -n 2 nvidia-smi
用 python -u
关闭 Python 输出缓冲，日志更实时。
用 tee
终端可看，文件可追溯，适合训练和排障。
保留环境快照
提交号、节点名、驱动、CUDA、环境变量能减少复盘成本。
调度环境注意： 在 Slurm/Kubernetes 等环境中，tmux 不应绕过调度系统。它适合交互式 allocation 内的工作台，不适合私自占用共享 GPU。

9. 窗口/面板工作台布局

好的 tmux 布局能减少“我刚才在哪个终端跑了什么”的混乱。下面是一个训练节点上常用的四窗工作台。

# 创建工作台
tmux new -s exp-a100 -n train

# 在第 0 个窗口左右拆分：左训练，右日志
tmux split-window -h
tmux send-keys -t exp-a100:train.1 'tail -f logs/train.log' C-m

# 新建 GPU 监控窗口
tmux new-window -t exp-a100 -n gpu 'watch -n 2 nvidia-smi'

# 新建系统指标窗口
tmux new-window -t exp-a100 -n sys 'bash'
tmux split-window -t exp-a100:sys -v 'iostat -xz 1'

# 新建远程/调试窗口
tmux new-window -t exp-a100 -n debug 'bash'
窗口名推荐内容为什么
train训练命令 + 实时日志核心任务和输出放在第一现场
gpuwatch nvidia-smi、gpustat、dcgmi观察显存、功耗、util、ECC/Xid
sysiostat、free、top、ss判断瓶颈是 GPU、CPU、磁盘还是网络
debugpython、gdb、strace、ssh保留临时诊断命令区

10. 滚动、复制与搜索输出

tmux 的历史回看能力来自 pane 的 scrollback。进入 copy mode 后可以滚动和搜索，但历史长度受 history-limit 限制。

# 进入 copy mode
# prefix [

# copy mode 常用按键：
# PageUp/PageDown 或方向键滚动
# / 搜索，n 下一个匹配
# q 退出 copy mode

# 查看历史上限
tmux show-options -g history-limit

# 临时提高当前会话历史上限
tmux set-option -g history-limit 200000
不要只依赖 scrollback： scrollback 是交互缓存，不是审计日志。训练、压测和故障现场必须同时写入日志文件。
需求推荐做法原因
临时看前面输出prefix [ 进入 copy mode最快，不影响任务
保存当前 pane 历史capture-pane -S -适合事后留证
长期记录输出tee 或 pipe-pane不依赖 tmux 缓冲区大小

11. 日志捕获与证据保全

AI Infra 排障常常需要回看“错误第一次出现前后发生了什么”。tmux 提供两类能力：捕获已有 pane 历史，以及把未来输出管道到文件。

捕获已有输出

# 在会话外捕获指定 pane 全部可用历史
tmux capture-pane -t exp-a100:train.0 -S - -E - -p > logs/pane-train-capture.txt

# 只捕获最近 3000 行
tmux capture-pane -t exp-a100:train.0 -S -3000 -p > logs/recent.txt

持续记录未来输出

# 对当前 pane 开启 pipe-pane，-o 表示仅在未开启时开启
tmux pipe-pane -o 'cat >> logs/tmux-pane-#{session_name}-#{window_index}-#{pane_index}.log'

# 再执行一次可关闭当前 pane 的 pipe
tmux pipe-pane

训练命令层面的日志

# 最推荐：命令自己写日志，tmux 只是承载终端
python -u train.py --config config.yaml 2>&1 | tee -a logs/train.log

# 后台进程也保留日志和 PID
python -u train.py --config config.yaml > logs/train.log 2>&1 &
echo $! > logs/train.pid
取证原则： tee 记录“命令输出”，capture-pane 记录“终端现场”，pipe-pane 记录“pane 的未来输出”。重要任务最好至少使用 tee。

流程图：远程 SSH + tmux 工作流

标准路径是先进入 tmux，再启动关键任务。反过来先启动任务再想补救，通常只能用 shell job control 或重新启动。

12. 远程 SSH 与跳板机工作流

tmux 应运行在真正承载任务的机器上。只在本地或跳板机开 tmux，不能保护计算节点上的交互命令。

# 场景 A：直接登录训练节点
ssh gpu-node-01
tmux new -s exp-a100

# 场景 B：经跳板机登录，tmux 要开在最终节点
ssh bastion
ssh gpu-node-01
tmux attach -t exp-a100 || tmux new -s exp-a100

# 场景 C：一条命令进入远端 tmux
ssh gpu-node-01 'tmux attach -t exp-a100 || tmux new -s exp-a100'
位置tmux 放在哪里效果
本机电脑本地 tmux方便管理多个 SSH tab，但不能防远端命令因 SSH 断开而中止
跳板机bastion tmux保护跳板机上的 SSH 客户端，不等于保护计算节点任务
计算节点worker/gpu node tmux保护训练、监控、日志命令，是 AI Infra 的主要用法
多层 tmux 提醒： 本地 tmux + 远端 tmux 容易产生前缀键冲突。排障时先说清“现在操作的是哪一层 tmux”。

13. Pair Debugging 与共享会话

多人调试时，tmux 可以让两个人看到同一个终端现场。最简单方式是同一 Unix 用户登录后附着同一会话；更严格的共享需要控制 socket 权限和审计方式。

# 同一用户：A 创建会话
tmux new -s incident-nccl

# B 用同一用户登录同一机器后附着
tmux attach -t incident-nccl

# 查看当前有哪些客户端
tmux list-clients

# 必要时断开某个客户端
tmux detach-client -t /dev/pts/12
适合共享的内容
日志、监控、只读诊断命令、复现步骤、临时实验结果。
不适合共享的内容
包含云密钥、数据库密码、私有 token、生产 root shell 的无审计操作。
权限警告： 共享 tmux 等同共享 shell 控制权。不要把生产高权限会话暴露给不应执行命令的人；涉及敏感信息时优先使用只读日志、录屏或受控会议共享。

14. tmux 配置文件

用户级配置通常在 ~/.tmux.conf。AI Infra 机器上建议配置保持克制：提高历史、启用鼠标、改善颜色、保留默认前缀或明确团队约定。

# ~/.tmux.conf：保守实用版
set -g history-limit 200000
set -g mouse on
set -g status-interval 5
set -g base-index 1
setw -g pane-base-index 1

# 颜色兼容。不同终端可能需要调整 TERM/terminal-overrides
set -g default-terminal "screen-256color"
set -as terminal-overrides ",xterm-256color:RGB"

# 更清楚的状态栏
set -g status-left "#[bold] #S "
set -g status-right " #H %F %H:%M "

# 重新加载配置：prefix : source-file ~/.tmux.conf
配置作用风险
history-limit增加 scrollback 行数过大时占更多内存
mouse on鼠标切 pane、滚动复制行为和终端原生复制不同
default-terminal影响颜色和应用兼容配置不当会导致 vim/less 颜色异常
status-left/right状态栏显示会话、主机、时间过度复杂会干扰共享排障
团队建议： 共享集群上避免依赖过多插件和私有快捷键。教程、Runbook 和事故交接应以 tmux 默认行为为准。

对比图：tmux、screen、systemd、nohup 的边界

tmux 最适合“需要继续交互和观察的现场”；systemd/调度器更适合正式长期服务或批处理作业。

15. tmux vs screen/systemd/nohup

工具核心用途优点不足AI Infra 选择建议
tmux持久交互终端窗口/面板强、易共享、可恢复现场机器重启不保活，不是调度器训练调试、事故排障、交互式 GPU 会话首选
screen老牌持久终端很多旧系统自带交互和脚本化体验较弱没有 tmux 时可替代
nohup忽略 SIGHUP 后台运行极简单，适合单命令无交互现场，管理和排障弱短期单命令可用，训练复盘不如 tmux + tee
systemd系统服务管理重启、自恢复、日志集成、依赖管理需要 unit 文件和权限，不适合临时交互推理服务、常驻 agent、节点守护进程更适合
Slurm/K8s集群调度资源隔离、队列、公平性、审计交互成本更高正式训练作业应优先使用调度系统
# nohup 更像一次性后台化
nohup python train.py > logs/train.log 2>&1 &

# tmux 更像可恢复工作台
tmux new -s train
python -u train.py 2>&1 | tee logs/train.log

# systemd 更像正式服务
systemctl status inference.service
journalctl -u inference.service -f

16. 生产安全清单

tmux 本身很轻量，但它经常承载高成本 GPU 任务和生产排障 shell。安全使用的重点是命名、日志、权限、清理和退出方式。

启动前
命名会话确认节点确认 GPU记录环境准备日志目录
运行中
tee 记录监控显存观察磁盘避免误按 exit定期 checkpoint
协作时
说明会话名说明当前 pane避免泄露 token记录关键命令限制高权限共享
结束后
确认进程结束保存日志清理空会话释放 GPU补充复盘
# 离开前最小检查
tmux ls
ps -fu "$USER" | grep -E 'python|torchrun|deepspeed' | grep -v grep || true
nvidia-smi
df -h .

# 清理前先确认
tmux capture-pane -t exp-a100:train.0 -S -200 -p
tmux kill-session -t exp-a100  # 确认无重要任务后再执行
成本意识： 一个遗留 tmux 会话可能占着 8 张 GPU 空转一整晚。不要只看 tmux 是否存在，也要看进程、GPU util、显存、日志是否仍在推进。

故障图谱：tmux 现场排查路径

tmux 故障不要只盯着 tmux。AI 训练是否还活着，要同时看进程、GPU、日志和调度器状态。

17. 常见故障与排查

现象可能原因排查命令处理
no sessions会话确实结束、登录了错误机器、换了用户、机器重启hostname、whoami、last -x | head确认节点和用户；查训练日志与 checkpoint
attach 后画面尺寸异常旧客户端仍附着或终端尺寸变化tmux list-clientstmux attach -d -t name 或 detach 旧客户端

日志前面没了history-limit 太小，未落盘tmux show -g history-limit提高 history-limit；以后用 tee/pipe-pane
任务停止但 tmux 还在训练进程崩溃、OOM、磁盘满、调度器回收echo $?、dmesg、df -h、nvidia-smi先保存日志和 capture，再重跑或恢复 checkpoint

18. AI Infra 实战配方

配方 A：单机训练工作台

tmux new -s single-a100 -n train
mkdir -p logs
python -u train.py --config cfg.yaml 2>&1 | tee logs/train.log

# prefix c 新建窗口后运行
watch -n 2 nvidia-smi

配方 B：torchrun 多卡训练

tmux new -s torchrun-8gpu
mkdir -p logs
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
torchrun --nproc_per_node=8 train.py --config ds.yaml \
  2>&1 | tee logs/torchrun-$(date +%F-%H%M).log

配方 C：数据预处理 + 资源监控

tmux new -s preprocess -n job
python -u preprocess.py --input /data/raw --output /data/features \
  2>&1 | tee logs/preprocess.log

# 新 pane
iostat -xz 1

# 新 pane
watch -n 5 'du -sh /data/features; df -h /data'

配方 D：事故排障现场保全

# 进入事故会话后先保存现场
mkdir -p incident-logs
tmux capture-pane -S - -p > incident-logs/initial-pane.txt
tmux list-panes -a > incident-logs/tmux-panes.txt
ps -ef > incident-logs/ps.txt
nvidia-smi -q > incident-logs/nvidia-smi-q.txt

# 后续诊断命令继续用 tee 记录
journalctl --since "1 hour ago" 2>&1 | tee incident-logs/journal.txt
