1. strace 是什么，解决什么问题

strace 基于 Linux ptrace 机制观察进程的系统调用。只要程序需要文件、网络、进程、内存映射、信号、时间、权限或设备，它最终会通过 syscall 请求内核服务；strace 能把这些请求打印出来。

它擅长
定位文件不存在、权限拒绝、动态库加载、阻塞 I/O、网络连接失败、子进程启动、信号、进程卡在某个 syscall。
它不擅长
CPU 热点函数、GPU kernel、业务对象状态、Python 行级逻辑、内核内部长路径剖析和低开销全局观测。
AI Infra 价值
训练/推理进程卡住、dataloader 读盘慢、NFS 抖动、容器权限问题、模型文件打开失败、RPC 连接异常、进程 fork/exec 风暴。
# 看一个命令发起了哪些系统调用
strace -o /tmp/ls.strace ls /data/models

# 附加到运行中的进程，10 秒后 Ctrl-C 停止 strace，不会杀掉目标进程
strace -ttT -p 12345 -o /tmp/app.strace

# 只看文件相关调用，噪声更低
strace -f -e trace=file -p 12345 -o /tmp/app.file.strace
边界提醒： strace 看到的是“进程问内核要什么，以及内核怎么回答”。如果问题发生在纯用户态计算热点，应换 perf、语言 profiler 或应用日志。

3. 安装、版本、权限与内核限制

多数发行版可以直接安装 strace 包。附加到已有进程通常需要同用户、可 ptrace 权限，或 root/capability；容器中还可能受到 seccomp、AppArmor、SELinux、CAP_SYS_PTRACE 和宿主机策略限制。

环境安装/检查说明
Ubuntu/Debiansudo apt install strace容器镜像里常被裁剪，需要临时安装或用 debug image。
RHEL/CentOS/Rockysudo dnf install strace旧系统可用 yum install strace。
版本检查strace -V新版本对 syscall 解码、-e status、路径/FD 展示更友好。
权限检查cat /proc/sys/kernel/yama/ptrace_scopeUbuntu 等系统可能限制非父子进程 attach。
# 查看当前用户是否能附加目标进程
ps -o pid,user,comm -p 12345
strace -p 12345 -e trace=none

# 如果出现 Operation not permitted，需要检查用户、Yama、capability、容器权限
cat /proc/sys/kernel/yama/ptrace_scope 2>/dev/null || true
grep -E 'TracerPid|NoNewPrivs|Seccomp' /proc/12345/status
不要绕过平台策略： 在生产集群中提升 CAP_SYS_PTRACE、改 ptrace_scope 或进入宿主 namespace 都属于高权限操作，应走变更/审批流程。

4. 第一批命令：运行新进程与附加旧进程

strace 有两种基本用法：让它启动一个新命令，或附加到一个已经运行的进程。排障线上服务时通常用附加；复现问题和学习时建议启动新命令。

目标命令适用场景
追踪新命令strace -o /tmp/cmd.strace command args...本地复现、短命令、启动失败。
追踪已有进程strace -p PID -o /tmp/app.strace线上进程卡住、服务异常。
跟踪子进程/线程strace -f -p PID -o /tmp/app.stracePython multiprocessing、DataLoader workers、shell 脚本。
命令统计摘要strace -c command粗略看哪些 syscall 次数/耗时高。
# 追踪模型文件是否打开成功
strace -e trace=file -o /tmp/load-model.strace python load_model.py
grep -E 'ENOENT|EACCES|model|safetensors|bin' /tmp/load-model.strace

# 对运行中的推理服务追踪 15 秒，输出到文件
PID=$(pgrep -n -f 'python.*serve.py')
timeout 15s strace -ttT -f -p "$PID" -o /tmp/serve.strace
输出建议： 线上排障优先用 -o 写文件，不要把大量 syscall 打到终端；终端渲染本身会增加噪声，也不利于后处理。

5. 安全附加：-p、-f、短窗口与输出文件

strace -p 会通过 ptrace 附加目标进程。附加瞬间目标会被暂停，之后每次 syscall 进入/退出都可能触发上下文切换，所以开销可观。生产使用应控制窗口、过滤范围和输出量。

流程图：生产安全附加步骤

安全目标不是“永远不用 strace”，而是在可控窗口内收集足够证据，避免把观测变成事故。
# 推荐模板：短窗口 + 时间 + 耗时 + 子进程 + 输出文件
timeout 10s strace -ttT -f -p 12345 -o /tmp/app.strace

# 噪声更低：只看文件系统调用
timeout 10s strace -ttT -f -e trace=file -p 12345 -o /tmp/app.file.strace

# 线程很多时，先找最可疑 TID，再只追踪该线程
ps -L -p 12345 -o pid,tid,psr,stat,pcpu,wchan:24,comm
timeout 10s strace -ttT -p 12378 -o /tmp/thread.strace
生产警告： 不要对高 QPS 主路径长时间运行无过滤 strace -f -p。它会显著增加 syscall 密集型程序的延迟，尤其是网络代理、日志密集服务和大量小文件读取场景。

6. 过滤核心：-e trace=... 和 -e status=...

-e 是 strace 的核心降噪工具。多数生产问题不需要完整 syscall 流，而是需要聚焦文件、网络、进程、信号、内存映射或失败调用。

过滤方式命令示例适合定位
文件相关-e trace=file路径不存在、权限拒绝、模型/配置/动态库查找。
网络相关-e trace=networkconnect、accept、sendto、recvfrom、socket 配置。
进程相关-e trace=processfork、clone、execve、wait、进程风暴。
描述符相关-e trace=descread/write/close/poll/select/epoll 等 FD 行为。
只看失败-e status=failed快速找 ENOENT、EACCES、ECONNREFUSED、ETIMEDOUT。
指定 syscall-e trace=openat,statx,read精确追踪某类调用。
# 快速找失败调用
strace -f -e status=failed -p 12345 -o /tmp/failed.strace

# 文件问题：路径、权限、动态库、checkpoint
strace -f -e trace=file -yy -s 256 -p 12345 -o /tmp/file.strace

# 网络问题：连接、收发、socket 选项
strace -f -e trace=network -ttT -p 12345 -o /tmp/net.strace

# 只看 read/write/poll/epoll，判断是否卡在 I/O 等待
strace -f -e trace=read,write,poll,ppoll,select,pselect6,epoll_wait,epoll_pwait -ttT -p 12345 -o /tmp/io.strace
实战习惯： 先用 -e status=failed 找硬错误，再根据错误类型切到 trace=file、trace=network 或指定 syscall。

选择图：不同问题该追踪什么

大多数 strace 排障从“现象分类”开始，而不是直接打印所有 syscall。

7. 时间戳、耗时和卡住判断

判断“卡住”必须看时间。-tt 打印绝对时间，-T 打印每个 syscall 花费的时间，-r 打印相邻 syscall 的相对时间。AI 训练中常用 -ttT 找长时间停在 read、futex、poll、connect 或 wait4 的位置。

选项含义用法
-t秒级时间粗略排序。
-tt微秒级绝对时间和应用日志、GPU 日志对齐。
-tttepoch 时间便于脚本处理。
-Tsyscall 耗时找慢调用。
-r相邻调用间隔找调用之间的用户态停顿。
# 找 10 秒内耗时明显的系统调用
timeout 10s strace -ttT -f -p 12345 -o /tmp/trace.timing
grep -E '<[0-9]+\.[0-9]{3,}>' /tmp/trace.timing | head -50

# 只看可能阻塞的调用
timeout 10s strace -ttT -f \
  -e trace=read,write,poll,ppoll,select,pselect6,epoll_wait,futex,connect,accept4,wait4 \
  -p 12345 -o /tmp/blocking.strace
解释 caveat： <0.500123> 表示该 syscall 本身耗时约 500ms；如果相邻两行时间差很大但每个 syscall 耗时不长，可能时间花在用户态计算，此时应考虑 perf 或语言 profiler。

8. 读懂输出：参数、返回值、errno、未完成调用

一行 strace 输出通常是：时间、PID、syscall 名称、参数、返回值、错误码、耗时。理解返回值和 errno 是判断问题的关键。

12:10:33.123456 openat(AT_FDCWD, "/data/model.bin", O_RDONLY) = -1 ENOENT (No such file or directory) <0.000041>
12:10:33.124001 read(17, "....", 4096) = 4096 <0.000083>
12:10:33.125900 connect(8, {sa_family=AF_INET, sin_port=htons(6379), sin_addr=inet_addr("10.0.0.9")}, 16) = -1 ECONNREFUSED (Connection refused) <0.001432>
12:10:34.000000 futex(0x7f..., FUTEX_WAIT_PRIVATE, 2, NULL <unfinished ...>
12:10:37.000000 <... futex resumed>) = 0 <3.000000>
片段含义怎么解读
= 3返回文件描述符 3open/socket 成功。
= 4096返回字节数read/write 成功处理 4096 字节。
= -1 ENOENT失败且 errno 是 ENOENT路径不存在，常见于配置、模型、动态库查找。
<unfinished ...>调用尚未返回多线程/阻塞调用常见，稍后可能有 resumed 行。
<0.123456>syscall 耗时配合 -T 找慢调用。
错误不是都异常： 程序经常试探多个路径，看到少量 ENOENT 不一定是故障；故障证据通常是“关键路径上的失败”或“失败后没有有效 fallback”。

9. 文件系统 syscall：open、stat、read、write、fsync

AI Infra 中，文件问题常出现在模型加载、checkpoint、dataset shard、动态库、配置、证书、NFS/对象存储挂载和临时目录。trace=file 是定位这类问题的首选。

syscall常见含义异常线索
openat/open打开文件、目录、设备、动态库。ENOENT、EACCES、路径不符合预期。
stat/statx/newfstatat检查路径和元数据。大量重复 stat 表示路径搜索或 metadata 开销。
read/pread64读文件或 socket。小块读太多、耗时长、返回 0 表示 EOF。
write/pwrite64写日志、checkpoint、socket。EPIPE、短写、写入耗时长。
fsync/fdatasync强制落盘。checkpoint、日志系统导致长尾延迟。
# 找模型/数据路径访问错误
strace -f -e trace=file -yy -s 256 \
  python train.py --data /mnt/dataset --model /mnt/model \
  -o /tmp/train.file.strace

# 在运行中进程上查看文件失败
timeout 20s strace -f -e trace=file -e status=failed -p 12345 -o /tmp/file.failed

# 观察是否卡在读数据或 fsync
timeout 15s strace -ttT -f -e trace=read,pread64,write,pwrite64,fsync,fdatasync -p 12345 -o /tmp/file.io
dataloader 经验： 如果 GPU 低利用且 dataloader worker 大量停在 read/pread64 或 newfstatat，优先检查数据集存储、元数据压力、小文件数量、缓存命中、并发 worker 数和预取策略。

10. 网络 syscall：connect、accept、send、recv、DNS

strace 可观察 socket 创建、连接、收发和等待事件。它不替代抓包，但能快速回答：进程是否真的发起连接、连接到哪个 IP/端口、错误码是什么、是否卡在 connect 或 recvfrom。

syscall含义故障线索
socket创建 socket。地址族、协议是否符合预期。
connect主动连接。ECONNREFUSED、ETIMEDOUT、EINPROGRESS。
accept/accept4服务端接受连接。是否有新连接进入。
sendto/recvfrom发送/接收。短写、EAGAIN、长时间等待。
poll/epoll_wait等待 FD 事件。服务空闲、等待上游、事件循环阻塞。
# 网络连接失败定位
timeout 10s strace -ttT -f -e trace=network -p 12345 -o /tmp/net.strace
grep -E 'connect|ECONN|ETIMEDOUT|EHOST|ENET' /tmp/net.strace

# DNS 解析也常体现为文件和网络调用：resolv.conf、hosts、DNS socket
strace -f -ttT -e trace=file,network getent hosts example.com

# 推理服务是否一直等网络事件
timeout 10s strace -ttT -p 12345 -e trace=epoll_wait,poll,ppoll,recvfrom,sendto -o /tmp/eventloop.strace
网络解释边界： strace 看不到 TCP 重传、丢包、拥塞窗口、TLS 明文内容。需要包级证据时，配合 ss、tcpdump、tshark 或 eBPF 网络工具。

11. 进程、线程、fork/exec 与 -f

Python multiprocessing、PyTorch DataLoader(num_workers>0)、shell wrapper、worker supervisor 都可能创建子进程。默认 strace -p PID 不会自动跟踪新 fork 出来的进程；需要 -f 或 -ff。

选项作用建议
-f跟踪 fork/clone/vfork 出来的子进程，输出混在一个文件。快速查看整体行为。
-ff每个进程写独立输出文件，文件名附加 PID。worker 多、输出大时更易分析。
-p PID附加一个进程或线程。先定位目标，再窄追踪。
-e trace=process只看进程创建/执行/等待。排查 worker 启动、exec 失败。
# 跟踪 DataLoader worker 创建和 exec 行为
strace -f -e trace=process -o /tmp/train.process.strace python train.py

# 每个 PID 单独文件，适合多 worker
timeout 15s strace -ff -ttT -e trace=file,desc -p 12345 -o /tmp/train.worker
ls /tmp/train.worker.*

# 结合 ps 找线程/worker 状态
ps -eLf | grep 'train.py' | head -30
ps -L -p 12345 -o pid,tid,stat,wchan:24,pcpu,comm
线程说明： Linux 线程也是 task，有 TID。对高线程数服务，追踪整个进程可能噪声巨大；先用 ps -L、top -H、pidstat -t 找可疑 TID，再精确 -p TID。

12. AI dataloader / 训练进程卡住排障

训练“卡住”不等于 GPU 或框架 bug。常见原因包括数据读取慢、NFS metadata 卡顿、worker 阻塞在队列/锁、fork 后权限问题、共享内存不足、随机访问小文件、日志或 checkpoint fsync 抖动。strace 可以把这些猜测落到 syscall 证据。

案例图：GPU 等数据时的 syscall 线索

strace 的价值是把“GPU 在等数据”拆成可观察的主进程等待、worker 行为和存储路径证据。
# 1. 找训练进程和 worker
pgrep -af 'python.*train'
ps -eLf | grep 'train.py' | head -50

# 2. 对整个进程树短窗口追踪，拆分到每个 PID 文件
timeout 15s strace -ff -ttT -e trace=file,desc,process -p 12345 -o /tmp/train.strace

# 3. 找耗时 syscall 和关键错误
grep -R 'ENOENT\|EACCES\|<[1-9][0-9]*\.' /tmp/train.strace.* | head -100

# 4. 如果怀疑锁/队列等待，专门看 futex 和 poll
timeout 10s strace -ff -ttT -e trace=futex,poll,ppoll,epoll_wait,read,write -p 12345 -o /tmp/train.wait
观察可能原因下一步
worker 大量 newfstatat/openat 小文件数据集小文件和 metadata 压力。打包 shard、缓存 metadata、降低随机路径查找。
read/pread64 单次耗时长远端存储、磁盘抖动、页缓存未命中。结合 iostat、pidstat -d、存储监控。
主进程长时间 futex等待 worker 队列、锁或线程同步。看 worker 是否忙于 I/O 或已异常退出。
频繁 clone/wait4worker 反复崩溃/重启或脚本频繁拉起子进程。配合日志和 -e trace=process 定位退出码。

13. 容器、Kubernetes 和命名空间中的 strace

容器内使用 strace 的核心问题是权限和命名空间。你可能看不到宿主 PID，可能没有 CAP_SYS_PTRACE，也可能被 seccomp 禁止 ptrace。生产集群中应优先使用平台提供的 debug 工具链。

# Docker 本地调试：显式添加 ptrace 权限和放宽 seccomp
docker run --rm -it --cap-add SYS_PTRACE --security-opt seccomp=unconfined ubuntu:24.04 bash

# Kubernetes：用临时 debug 容器进入同一个 Pod 的进程 namespace
kubectl debug -it pod/my-pod --image=ubuntu:24.04 --target=my-container -- bash

# 容器内确认目标进程与权限
ps aux
grep -E 'CapEff|NoNewPrivs|Seccomp|TracerPid' /proc/1/status
问题表现处理思路
没有 strace 二进制strace: command not founddebug image、临时安装、sidecar/debug container。
没有 ptrace 权限Operation not permitted检查 CAP_SYS_PTRACE、securityContext、宿主策略。
PID namespace 不一致看不到目标 PID进入同一 Pod/容器 namespace 或用平台 debug 能力。
seccomp 限制ptrace 或某些 syscall 被拒绝使用受控 debug profile，不要私自放宽生产策略。
Kubernetes 安全提醒： 给 Pod 添加 SYS_PTRACE 或 seccomp=unconfined 会扩大攻击面。排障完成后必须移除，不要把 debug 权限固化到业务 Deployment。

14. 降低噪声：字符串、缓冲区、路径和 FD 解码

默认输出有时会截断字符串、只显示 FD 数字、或输出过多二进制内容。合理使用解码和长度选项能让结果更可读，但也可能暴露敏感数据。

选项作用注意
-s N设置字符串最大打印长度。-s 256 常用于路径/HTTP 片段；过大可能泄露 payload。
-y显示 FD 对应路径/对象。有助于看 read/write 在哪个文件或 socket。
-yy更详细解码 FD 协议地址等。网络和文件定位更直观。
-o FILE输出到文件。生产必备，便于 grep 和归档。
-ff -o PREFIX每个 PID 一个文件。多进程任务更容易分析。
-qq减少附加/退出提示。脚本化输出更干净。
# 更容易读路径和 FD
timeout 10s strace -f -ttT -yy -s 256 -e trace=file,network -p 12345 -o /tmp/rich.strace

# 多进程拆文件
timeout 10s strace -ff -ttT -yy -s 128 -p 12345 -o /tmp/app.strace

# 只保留失败和路径关键字
grep -E 'ENOENT|EACCES|ECONN|ETIMEDOUT|/data|/models|/dev/shm' /tmp/rich.strace | head -100
隐私提醒： -s 过大时可能打印 token、请求参数、文件路径、用户名、密钥片段或业务数据。共享 strace 日志前必须脱敏。

15. 开销、安全和数据治理

strace 的开销来自 ptrace trap、上下文切换、参数解码和输出写入。syscall 越密集，开销越高；输出越详细，开销和泄露风险越高。

低风险做法
短窗口、窄过滤、输出到本地临时文件、只追踪可疑 TID、复现环境先跑、业务低峰执行。
高风险做法
长时间无过滤 -f、大 -s 打印 payload、追踪高 QPS 代理、在共享节点随意提权。
性能风险
延迟上升、吞吐下降、调度扰动、trace 文件写满磁盘。
安全风险
泄露路径、参数、环境、网络地址、用户数据、密钥片段和内核/进程信息。
# 限制输出大小：timeout + 窄过滤 + 写 /tmp
timeout 8s strace -qq -ttT -f -e trace=file -s 128 -p 12345 -o /tmp/app.file.strace
du -h /tmp/app.file.strace

# 采集后先做基本脱敏示例，再共享
sed -E 's#(/home|/data)/[^" ]+#\1/REDACTED#g; s#token=[^&" ]+#token=REDACTED#g' /tmp/app.file.strace > /tmp/app.file.redacted
磁盘警告： 高吞吐进程的 strace 日志增长非常快。不要把输出写到业务数据盘或满盘敏感的目录；必要时用 timeout、head、独立临时盘或更窄过滤。

16. strace vs perf vs bpftrace vs lsof

这些工具回答的问题不同。正确选择工具，比把一个工具用到极限更重要。

工具主要回答优势局限
strace进程发起了哪些 syscall，结果和耗时是什么？直观、无需写程序、单进程证据强。开销较高，对高频 syscall 干扰明显。
perfCPU 时间花在哪里，硬件/内核事件如何？低开销采样、适合 CPU 热点和调用栈。不直接显示 syscall 参数和具体路径。
bpftrace在内核/用户探针上做低开销条件观测。灵活、可聚合、适合全局和生产观测。需要内核/BPF 权限和脚本能力。
lsof当前打开了哪些文件、socket、设备？快照简单，适合 FD 清点。不是时间序列，看不到调用过程和 errno。
tcpdump/ss网络包和 socket 状态。网络层证据强。不能解释应用为什么发起/不发起调用。

对比图：工具分工

strace 最强的是“具体 syscall 证据”，不是低开销长期监控。

17. 常见错误与 troubleshooting

Operation not permitted
检查用户是否一致、ptrace_scope、CAP_SYS_PTRACE、容器 seccomp/AppArmor/SELinux。
输出太多看不懂
加 -e trace=...、-e status=failed、-o、-ff，先按问题分类。
附加后服务变慢
缩短 timeout，只追踪 TID，减少 -s，避免无过滤 -f。
看到很多 ENOENT
确认是否为正常路径探测；找关键路径、最后成功路径和业务报错附近时间。
只有 futex 看不懂
futex 常表示锁/条件变量等待；结合线程状态、应用栈、perf 或语言 dump。
没有看到子进程
使用 -f 或 -ff，并确认 attach 时子进程是否已经存在。
网络问题证据不足
strace 只能看进程 socket 调用；配合 ss -tanp、tcpdump、DNS 工具。
日志包含敏感数据
降低 -s，避免追踪 payload syscall，分享前脱敏。

排障流程图：strace 结果不符合预期

当 strace 不够时，不要硬猜：检查目标、权限、过滤和问题层级，再决定是否换工具。

排障模板

# 1. 确认目标进程
ps -fp 12345
ps -L -p 12345 -o pid,tid,stat,wchan:24,pcpu,comm

# 2. 先只看失败
timeout 10s strace -f -e status=failed -p 12345 -o /tmp/failed.strace

# 3. 按失败类型切过滤
timeout 10s strace -f -ttT -e trace=file -p 12345 -o /tmp/file.strace
timeout 10s strace -f -ttT -e trace=network -p 12345 -o /tmp/net.strace

# 4. 如果 syscall 没有长耗时，考虑用户态 CPU/锁/语言运行时
perf top -p 12345

目标命令

生产 playbook

  1. 先确认业务现象、时间窗口、目标 PID/TID 和是否有子进程。
  2. 先跑只读快照工具：ps、top -H、lsof、ss，避免盲目 attach。
  3. 用 timeout 控制窗口，用 -o 写文件，用 -e 缩小范围。
  4. 优先收集 -ttT 时间证据和 errno 错误证据。
  5. 输出共享前脱敏，排障完成后删除含敏感信息的 trace。
