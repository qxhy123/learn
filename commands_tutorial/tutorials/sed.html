sed 深度教程：从流编辑模型到批量文本替换

这份教程按常用命令 sed 讲解。它不是简单替换命令清单，而是从“sed 如何逐行读取、放入模式空间、执行脚本、再输出”这个核心模型出发，系统讲清楚：地址选择、替换命令、删除与打印、多命令组合、原地修改、正则差异、跨行处理、与 grep/awk/perl 的边界，以及真实工程中的安全批量替换流程。

一句话理解： sed 是“流编辑器”：它从输入逐行读取文本，按脚本规则修改当前行或控制输出，适合在管道和批处理里做可重复的文本转换。
最重要原则： 先在标准输出 dry-run，确认结果后再用 -i 原地修改；跨平台脚本要特别注意 GNU sed 与 BSD/macOS sed 的 -i、-E、转义规则差异。

1. sed 是什么

sed 解决的问题是：把文本流按可重复规则转换成另一个文本流。它常被放在管道中，用来替换、过滤、删除、抽取或格式化文本。

它擅长什么
简单到中等复杂度的行级文本替换、删除、抽取、格式清洗，以及脚本化批量修改。
它不擅长什么
复杂结构化数据处理、深度解析 JSON/YAML/XML、多字段统计和复杂状态机。那时应考虑 jq、awk、Python 或专用解析器。
它的本质
读一行 → 放入模式空间 → 执行 sed 脚本 → 默认打印 → 读取下一行。
# 把每行第一个 foo 替换为 bar
printf 'foo foo\n' | sed 's/foo/bar/'

# 删除空行
sed '/^$/d' file.txt

# 只打印第 10 到 20 行
sed -n '10,20p' file.txt

# 批量替换前先 dry-run
sed 's/old.example.com/new.example.com/g' config.conf
关键区别： sed 默认按行处理并打印结果；它不会自动修改文件，除非你显式使用 -i。

信息图：sed 的整体心智模型

理解 sed 的关键不是背命令，而是看清楚：每一行进入模式空间后，脚本如何改写它、是否输出它。

2. 基本语法与第一批例子

sed [options] 'script' [file...]

# script = 地址 + 命令
# 没有 file 时从 stdin 读取
# 默认每处理完一行就打印模式空间
命令实际效果
sed 's/a/b/' file每行只替换第一个 a
sed 's/a/b/g' file每行替换所有 a
sed -n '1,5p' file只打印第 1 到 5 行
sed '/DEBUG/d' file删除包含 DEBUG 的行后输出

sed 默认输出修改后的文本

# 原文件不会被修改，只把结果写到 stdout
sed 's/dev/prod/g' app.conf > app.prod.conf

# 管道中继续处理
cat access.log | sed 's/  */ /g' | sed -n '1,10p'
第一性原理： sed 不“理解”配置文件或日志语义，它只是按脚本规则转换文本行。

3. 替换命令：s///

s 是 sed 最常用命令，形式是 s/模式/替换/标志。分隔符不一定是斜杠，处理路径或 URL 时可以换成 #、| 等。

写法含义例子
s/old/new/每行替换第一个匹配sed 's/http/https/'
s/old/new/g每行替换所有匹配sed 's/foo/bar/g'
s#old#new#g使用其他分隔符sed 's#/usr/bin#/opt/bin#g'
s/(...)/.../扩展正则分组，通常配 -Esed -E 's/([0-9]+)/[\1]/g'
# 替换域名
sed 's#http://old.example.com#https://new.example.com#g' config.txt

# 只替换行首的空白
sed 's/^[[:space:]]*//'

# 在匹配内容两侧加括号
printf 'id=123\n' | sed -E 's/([0-9]+)/[\1]/'
替换提醒： 替换部分中的 & 代表整个匹配文本；如果你想输出字面量 &，需要写成 \&。

流程图：地址选择如何决定命令是否执行

地址是 sed 的“条件”：地址匹配时才执行命令；没有地址时，对每一行执行。

4. 地址选择：行号、范围、正则

地址含义例子
3第 3 行sed '3d' file
2,5第 2 到 5 行sed -n '2,5p' file
/ERROR/匹配正则的行sed '/ERROR/d' log
/start/,/end/从匹配 start 到匹配 end 的范围sed -n '/BEGIN/,/END/p'
$最后一行sed '$d' file
# 只替换配置块中的内容
sed '/^server {/,/^}/ s/listen 80/listen 8080/' nginx.conf

# 删除注释和空行
sed '/^[[:space:]]*#/d; /^[[:space:]]*$/d' app.conf

# 打印最后一行
sed -n '$p' file.txt

5. 打印、删除、静默输出

sed 默认会打印每一轮结束后的模式空间。-n 可以关闭默认打印，此时通常配合 p 精确输出。

命令作用场景
p打印当前模式空间配合 -n 抽取行
d删除当前模式空间并进入下一轮过滤不需要的行
q退出 sed提前停止处理
=打印当前行号定位和调试
# 只打印匹配行，类似 grep
sed -n '/ERROR/p' app.log

# 打印第 100 行后退出
sed -n '100{p;q}' large.log

# 删除注释行
sed '/^[[:space:]]*#/d' config.conf

# 打印匹配行号和内容
sed -n '/timeout/{=;p}' app.conf
输出模型： 不加 -n 时再用 p，匹配行常会被打印两次；这是初学者最常见现象之一。

6. 多命令与脚本文件

多个 sed 命令可以用分号、多个 -e，或脚本文件组织。简单 one-liner 用分号；较复杂的规则建议写到文件里。

# 分号连接多个命令
sed 's/foo/bar/g; /^$/d' file.txt

# 多个 -e 更清楚
sed -e 's/foo/bar/g' -e '/^$/d' file.txt

# 使用脚本文件
cat > cleanup.sed <<'SED'
s/foo/bar/g
/^$/d
/^[[:space:]]*#/d
SED
sed -f cleanup.sed file.txt
分号
适合短命令，便于直接复制。
-e
适合在脚本里逐条拼接规则。
-f
适合复杂清洗规则，可版本化和复用。

7. 原地修改：-i 与备份

-i 会把 sed 输出写回原文件。它很方便，也很危险：命令写错会批量破坏文件。生产使用时建议先 dry-run，再备份，再执行。

# GNU sed：原地修改
sed -i 's/old/new/g' file.txt

# GNU sed：原地修改并保留 .bak 备份
sed -i.bak 's/old/new/g' file.txt

# macOS/BSD sed：无备份原地修改通常要写空字符串参数
sed -i '' 's/old/new/g' file.txt

# 跨平台更保守：写临时文件再 mv
sed 's/old/new/g' file.txt > file.txt.tmp && mv file.txt.tmp file.txt
生产警告： 不要直接对未知文件集合执行 sed -i。先用 grep -R 或 sed ... | diff -u file - 看变化，再用版本控制或备份兜底。

8. 正则、分组与引用

sed 默认使用基本正则表达式（BRE）。很多系统支持 -E 启用扩展正则表达式（ERE），这样分组和量词更接近现代习惯。

能力BRE 写法ERE 写法
分组\(...\)(...)
一次或多次\++
可选\??
或实现差异较多a|b
# 把 key=value 转成 key: value
printf 'host=localhost\n' | sed -E 's/^([^=]+)=(.*)$/\1: \2/'

# 规整多个空格
sed -E 's/[[:space:]]+/ /g' file.txt

# 使用 & 复用整个匹配
printf 'error\n' | sed 's/error/[&]/'
可移植提醒： 现代 GNU sed 和 BSD sed 都支持 -E，但老旧环境可能只支持 GNU 的 -r。跨平台脚本优先测试目标机器。

信息图：模式空间与保持空间

模式空间是主舞台；保持空间是临时仓库。掌握它们能理解高级 sed，但不要为了炫技牺牲可维护性。

9. 跨行处理与保持空间

sed 默认一行一行处理。需要跨行时，可以使用 N 把下一行追加到模式空间，或使用保持空间命令保存上下文。

命令作用
N读取下一行并追加到模式空间，中间包含换行符
h/H覆盖/追加到保持空间
g/G从保持空间覆盖/追加回模式空间
x交换模式空间和保持空间
# 把两行合成一行的简单演示
printf 'a\nb\nc\nd\n' | sed 'N;s/\n/ /'

# 删除反斜杠续行中的换行
sed ':a; /\\$/ { N; s/\\\n//; ba; }' file.txt
边界提醒： sed 能做跨行处理，但表达复杂、排障困难。只要规则变成“解析语言/格式”，优先考虑更适合的工具。

10. 和 find、xargs、grep、awk 的配合

find + sed

# 查看所有配置文件中的替换结果，不修改文件
find . -type f -name '*.conf' -print0 | xargs -0 sed 's/old/new/g'

# GNU sed 批量原地修改，先确认文件列表
find . -type f -name '*.conf' -print0 | xargs -0 grep -l 'old'
find . -type f -name '*.conf' -print0 | xargs -0 sed -i.bak 's/old/new/g'

grep + sed

# 先用 grep 缩小范围，再 sed 查看转换效果
grep -RIl 'old.example.com' . | xargs sed 's/old.example.com/new.example.com/g'

awk

# sed 适合替换；awk 更适合按字段计算
awk -F, '{sum += $3} END {print sum}' data.csv
安全组合： 文件名来自 find 时，优先使用 -print0 | xargs -0；不要把普通换行文本当成任意文件名列表。

11. 安全批量替换流程

推荐三步走

# 第一步：找出会被影响的文件
rg -l 'old.example.com' .
# 或无 rg 时：grep -RIl 'old.example.com' .

# 第二步：抽样 dry-run
sed 's/old.example.com/new.example.com/g' app.conf | diff -u app.conf -

# 第三步：备份后原地修改
find . -type f -name '*.conf' -print0 | xargs -0 sed -i.bak 's/old.example.com/new.example.com/g'

回滚

# 查看备份
find . -name '*.bak' -print

# 如果确认要恢复，可谨慎执行
find . -name '*.bak' -print0 | xargs -0 -I {} sh -c 'mv "$1" "${1%.bak}"' sh {}
批量修改警告： 如果项目有 Git，先确认 git status 干净；修改后用 git diff 审查，不要只相信 sed 命令本身。

12. GNU sed 与 BSD/macOS sed 差异

主题GNU sedBSD/macOS sed建议
-i 无备份sed -i 's/a/b/' filesed -i '' 's/a/b/' file跨平台脚本避免裸用 -i
扩展正则-E 通常可用，老习惯也见 -r-E优先 -E
转义细节部分扩展更宽松更接近 BSD 行为在目标系统测试
特殊地址/命令扩展GNU 扩展较多可能不支持脚本声明依赖环境
# 判断环境
sed --version 2>/dev/null | head -1 || sed -E '' /dev/null 2>/dev/null

# 跨平台保守替换：不用 -i
sed 's/old/new/g' file > file.tmp && mv file.tmp file

用例图：sed、grep、awk、perl 怎么选

sed 是行级替换和转换利器，但不是所有文本处理问题的唯一答案。

13. sed vs grep vs awk vs perl

工具优势劣势适合
sed轻量、流式、替换和行编辑很强复杂逻辑可读性差批量替换、删除、抽取行
grep/rg搜索快，语义直接不负责复杂修改查找匹配文件和行
awk字段处理、统计、报表强纯替换时比 sed 重列式文本、日志统计
perl正则强，多行处理强不一定适合团队维护复杂替换和兼容脚本
Python可测试、可维护、库生态强one-liner 不如 sed 轻结构化数据、复杂流程

14. 常见坑与排障

坑 1：忘记 -n 导致重复输出
sed -n '/x/p' 才是只打印匹配行。
坑 2：误用 -i 破坏文件
先 dry-run，再备份，再原地修改。
坑 3：斜杠转义太多
替换路径时用 s#old#new#g。
坑 4：BRE/ERE 混淆
需要现代分组和 + 时加 -E。
坑 5：& 被意外展开
替换文本中的字面量 & 写成 \&。
坑 6：macOS -i 语法不同
BSD sed 常用 sed -i '' ...。
坑 7：用 sed 解析复杂格式
JSON 用 jq，CSV 用专用工具或 Python。
坑 8：批量文件名不安全
配合 find -print0 | xargs -0。

排障模板

# 1. 先准备最小输入
printf 'foo=123\nbar=456\n' | sed -E 's/^([^=]+)=(.*)$/\1: \2/'

# 2. 加 -n 精确观察输出
sed -n '1,5p' file.txt

# 3. 对单个文件做 diff
sed 's/old/new/g' file.txt | diff -u file.txt -

# 4. 批量前先列出文件
find . -type f -name '*.conf' -print0 | xargs -0 -n 1 printf '[%s]\n'

排障流程图：sed 命令结果不对时怎么查

排障顺序：输入 → 地址 → 命令 → 输出控制 → 平台差异 → 文件修改风险。

15. 学习路线与练习任务

第一阶段：会用

  • 理解 sed 默认逐行处理和默认输出。
  • 掌握 s/old/new/g、d、p。
  • 会用 -n 精确打印需要的行。

第二阶段：安全

  • 掌握 dry-run、diff 和备份流程。
  • 理解 -i 在 GNU 与 BSD/macOS 上的差异。
  • 批量文件处理时用 find -print0 | xargs -0。

第三阶段：工程化

  • 掌握地址范围和多命令组合。
  • 掌握 -E、分组引用、替换中的 &。
  • 知道什么时候换 awk、perl、Python 或专用工具。

练习

  1. 用 printf 构造输入，观察 s/// 默认只替换第一个匹配。
  2. 用 sed -n '2,4p' 打印指定行范围。
  3. 写一个删除注释和空行的命令。
  4. 用 -E 把 key=value 转成 key: value。
  5. 用 diff -u file - 预览替换结果。
  6. 在测试目录里尝试 -i.bak 并恢复备份。
  7. 比较 GNU sed 和 macOS/BSD sed 的 -i 行为。
# 练习数据
mkdir -p /tmp/sed-demo && cd /tmp/sed-demo
cat > app.conf <<'EOF2'
# demo config
host=old.example.com
url=http://old.example.com/api

mode=dev
EOF2

# dry-run 替换
sed 's#old.example.com#new.example.com#g' app.conf

# 看 diff
sed 's#old.example.com#new.example.com#g' app.conf | diff -u app.conf -
