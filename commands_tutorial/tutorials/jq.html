jq 深度教程：AI Infra 场景下的 JSON 解析、过滤与自动化

这份教程围绕常用命令 jq 展开，不把它当成“美化 JSON 的小工具”，而是从“JSON 值流 + 过滤器管道”这个核心模型出发，系统讲清楚路径访问、数组和对象、select/map/group_by、raw 输出、Kubernetes/API 输出、流式处理大 JSON、shell 引号、与 yq/Python/jsonpath 的边界，以及 AI Infra 排障和自动化脚本中的安全实践。

一句话理解： jq 是 JSON 的命令行查询和转换语言：输入是 JSON，过滤器把它拆分、选择、重组，输出仍可保持 JSON，也可变成适合 shell 的纯文本。

1. jq 是什么，为什么 AI Infra 离不开它

jq 解决的问题是：把结构化 JSON 数据在命令行里可靠地查询、过滤、转换和输出。AI Infra 日常面对大量 JSON：Kubernetes API、云厂商 API、容器运行时 inspect、GPU 监控、模型服务响应、调度器事件、日志采集和指标快照。用 grep/sed 处理这些数据很容易被转义、数组顺序、字段缺失和嵌套结构击穿；jq 则直接理解 JSON 结构。

它擅长什么
提取字段、过滤数组、重组对象、生成 TSV/CSV、批量检查资源状态、从 API 响应中构造下一步命令。
它不擅长什么
复杂业务流程、长生命周期程序、大规模数据分析、需要单元测试和依赖管理的逻辑。那时应写 Python/Go。
它的本质
一个过滤器语言：每个过滤器接收 JSON 值，输出零个、一个或多个 JSON 值，过滤器之间可用 | 串联。
# 美化 JSON
cat response.json | jq .

# 从 Kubernetes pod 列表中取 namespace/name/node
kubectl get pods -A -o json |
  jq -r '.items[] | [.metadata.namespace, .metadata.name, .spec.nodeName] | @tsv'

# 找出失败的训练任务
jq -r '.jobs[] | select(.status.phase != "Succeeded") | .name' jobs.json
边界提醒： jq 只解析 JSON。YAML 用 yq，表格文本用 awk，二进制或 protobuf 输出用对应工具先转成 JSON。

2. 核心模型：JSON 值流与过滤器

jq 的关键不是命令选项，而是过滤器如何把 JSON 值变成另一个值流。

3. 安装、版本与输入输出

不同发行版通常都提供 jq 包。脚本里建议显式检查版本和命令是否存在，尤其是在最小化容器、GPU 节点、Kubernetes debug 容器或 CI runner 中。

任务命令说明
查看版本jq --version确认运行环境和本地一致。
格式化输入jq . file.json. 表示原样输出当前 JSON 值。
从 stdin 读取curl -s URL | jq .AI Infra API 排障最常见形态。
紧凑输出jq -c '.items[]'一行一个 JSON，适合日志和管道。
raw 输出jq -r '.metadata.name'去掉 JSON 字符串引号，适合 shell 文本。
# macOS
brew install jq

# Debian/Ubuntu
sudo apt-get update && sudo apt-get install -y jq

# RHEL/CentOS/Fedora
sudo dnf install -y jq || sudo yum install -y jq

# 最小容器中常见检查
command -v jq >/dev/null || { echo "jq is required" >&2; exit 2; }
输入合法性： jq 需要完整合法的 JSON。日志里如果是一行一个 JSON 对象，可以直接 jq -c ...；如果前面混有时间戳或普通文本，需要先清洗成 JSON。

4. 路径访问：点号、索引、可选字段

路径访问是 jq 的第一层能力。点号访问对象字段，方括号访问数组索引或特殊键名，问号避免缺字段时报错。AI Infra 输出经常字段很深，建议先用 jq 'keys'、jq '.items[0]' 探索结构，再写最终过滤器。

过滤器含义例子
.当前 JSON 值jq . pod.json
.metadata.name对象字段访问Pod、Node、Deployment 名称
.items[0]数组第一个元素查看列表输出的样例对象
.items[-1]数组最后一个元素查看最后一条事件
.metadata.labels["app.kubernetes.io/name"]特殊键名访问键里有点、斜杠或短横线时必须用方括号
.status.containerStatuses[]?.state可选访问字段缺失或数组为空时不硬失败
# 先看顶层字段
kubectl get node node-a -o json | jq 'keys'

# 查看列表中第一个对象的结构
kubectl get pods -A -o json | jq '.items[0] | {apiVersion, kind, metadata, spec, status}'

# 读取带特殊字符的 label
kubectl get pod train-0 -o json |
  jq -r '.metadata.labels["app.kubernetes.io/name"]'

# 缺字段时输出默认值，避免脚本里得到 null
jq -r '.status.hostIP // "unknown"' pod.json
null 不是空字符串： jq -r '.missing' 会输出文本 null。脚本里通常要写 .missing // "" 或显式判断。

5. 数组处理：迭代、切片、长度与扁平化

Kubernetes 列表、API 分页结果、GPU 列表、容器列表几乎都是数组。[] 是 jq 最重要的操作之一：它不是“取数组”，而是把数组中的每个元素依次输出成值流。

过滤器作用AI Infra 用法
.items[]展开数组逐个处理 Pod/Node/Event。
.items | length数组长度统计资源数量。
.items[0:5]切片抽样查看前 5 个对象。
[.items[] | .metadata.name]重新收集为数组生成名称数组给后续 JSON API。
flatten扁平化嵌套数组合并多节点的 GPU 列表。
# 每个 Pod 输出一行 JSON
kubectl get pods -A -o json | jq -c '.items[]'

# 统计命名空间中 Pod 数量
kubectl get pods -n training -o json | jq '.items | length'

# 输出前 5 个 Pod 的 namespace/name
kubectl get pods -A -o json |
  jq -r '.items[0:5][] | "\(.metadata.namespace)/\(.metadata.name)"'

# 把每个节点的 GPU 名称数组合并成一个数组
jq '[.nodes[].gpus[].name]' gpu-inventory.json
值流 vs 数组： .items[] | .metadata.name 输出多条值；[.items[] | .metadata.name] 输出一个数组。前者适合管道文本，后者适合继续作为 JSON 传给程序。

6. 对象处理：键、值、entries 与重组

对象处理常用于 labels、annotations、resource requests/limits、云厂商 tag、模型服务配置。jq 可以查看键集合、把对象转成键值数组，也可以重新构造更适合排障的对象。

过滤器含义备注
keys输出对象键数组键名排序后输出。
keys_unsorted按原顺序输出键探索 API 响应时更贴近原文。
to_entries对象转 [{key,value}]适合筛选 labels/tags。
from_entries[{key,value}] 转对象适合清洗后重组。
{name: .metadata.name, node: .spec.nodeName}构造新对象保留关键字段，减少噪音。
# 查看 node status 下有哪些字段
kubectl get node node-a -o json | jq '.status | keys'

# 输出所有 label 键值
kubectl get node node-a -o json |
  jq -r '.metadata.labels | to_entries[] | [.key, .value] | @tsv'

# 只保留和 GPU/拓扑相关的 label
kubectl get nodes -o json |
  jq '.items[] | {
    name: .metadata.name,
    labels: (.metadata.labels
      | to_entries
      | map(select(.key | test("gpu|nvidia|topology|zone"; "i")))
      | from_entries)
  }'
排障技巧： API 响应太大时，不要一上来复制整段 JSON。先用 jq 重组成只含关键字段的小对象，再贴到 issue、告警或复盘文档里。

7. 过滤与选择：select、布尔条件、正则

多数 AI Infra jq one-liner 都可以归纳为：展开列表，选择关心对象，重组字段，按机器可读或人可读格式输出。

select 是过滤器，它保留条件为真的输入值，丢弃条件为假的输入值。条件可以比较字段、判断是否存在、匹配正则、组合 and/or/not。

# 只看非 Running 的 Pod
kubectl get pods -A -o json |
  jq -r '.items[]
    | select(.status.phase != "Running")
    | [.metadata.namespace, .metadata.name, .status.phase]
    | @tsv'

# 找出被 OOMKilled 的容器
kubectl get pods -A -o json |
  jq -r '.items[] as $pod
    | $pod.status.containerStatuses[]?
    | select(.lastState.terminated.reason? == "OOMKilled")
    | [$pod.metadata.namespace, $pod.metadata.name, .name, .lastState.terminated.exitCode]
    | @tsv'

# 匹配 GPU 相关节点 label
kubectl get nodes -o json |
  jq -r '.items[]
    | select(.metadata.labels | keys[]? | test("gpu|nvidia"; "i"))
    | .metadata.name'
条件用途示例
.status.phase == "Failed"精确匹配状态失败作业、失败 Pod。
.spec.nodeName != null字段非空已调度 Pod。
has("resources")对象是否有键检查容器是否声明资源。
.metadata.name | test("^train-")正则匹配训练任务前缀。
(.restartCount // 0) > 3默认值后比较容器重启次数。

8. 转换与聚合：map、sort_by、group_by、reduce

map 对数组中每个元素应用过滤器并收集为新数组；sort_by 和 group_by 常用于按节点、命名空间、镜像、状态聚合；reduce 适合做计数、求和和构建索引。

过滤器作用注意
map(.metadata.name)数组元素逐个转换输入必须是数组。
sort_by(.spec.nodeName)按字段排序group_by 前通常先排序。
group_by(.status.phase)按字段分组相同 key 的对象组成一个数组。
add数组求和或对象合并类型不同语义不同。
reduce .[] as $x (...)自定义聚合适合构造计数字典。
# 按 Pod phase 统计数量
kubectl get pods -A -o json |
  jq '.items
    | group_by(.status.phase)
    | map({phase: .[0].status.phase, count: length})'

# 按节点统计 Pod 数，输出 TSV
kubectl get pods -A -o json |
  jq -r '.items
    | map(select(.spec.nodeName != null))
    | sort_by(.spec.nodeName)
    | group_by(.spec.nodeName)
    | map([.[0].spec.nodeName, length] | @tsv)
    | .[]'

# 构造 namespace -> pod_count 的对象
kubectl get pods -A -o json |
  jq '.items
    | reduce .[] as $p ({}; .[$p.metadata.namespace] += 1)'
group_by 注意： group_by(x) 依赖排序语义。为可读和可维护，显式写 sort_by(x) | group_by(x)，不要假设输入已排序。

9. raw 输出、TSV/CSV 与 shell 变量

默认情况下 jq 输出 JSON 字符串，会带双引号并转义特殊字符。-r 会输出 raw 字符串，适合 shell 变量、文件路径、表格、告警消息。生成多列文本时优先用 @tsv 或 @csv，不要手工拼接容易被空格和制表符破坏的文本。

形式命令适合场景
JSON 字符串jq '.metadata.name'继续给程序读取。
raw 字符串jq -r '.metadata.name'赋值给 shell 变量。
一行 JSONjq -c '.items[]'日志、消息队列、逐行处理。
TSVjq -r '[.name,.node] | @tsv'终端表格和脚本读取。
CSVjq -r '[.name,.value] | @csv'电子表格或报表。
# 安全地生成 TSV
kubectl get pods -A -o json |
  jq -r '.items[]
    | [.metadata.namespace, .metadata.name, (.spec.nodeName // "pending"), .status.phase]
    | @tsv'

# 读入 shell 变量：只期望一个值时加 -e，并处理失败
node_name=$(
  kubectl get pod train-0 -n training -o json |
    jq -er '.spec.nodeName'
) || { echo "pod is not scheduled or jq failed" >&2; exit 1; }

# 输出 CSV 报表
kubectl get nodes -o json |
  jq -r '.items[]
    | [.metadata.name, (.status.allocatable.cpu // ""), (.status.allocatable.memory // "")]
    | @csv'
脚本安全： 不要把未验证的 jq 输出直接拼进 eval 或未加引号的 shell 命令。读取 raw 文本后也要用 "$var" 引用。

10. Kubernetes 输出：kubectl -o json + jq

kubectl -o json 是 jq 在 AI Infra 中最常见的数据源。相比 kubectl get 默认表格，JSON 输出字段完整、结构稳定、适合自动化。相比 jsonpath，jq 在复杂条件、数组处理、聚合和可读性上通常更强。

Pod、Node、Container 基础排查

# 全集群 Pod 快照：namespace/name/node/phase/restarts
kubectl get pods -A -o json |
  jq -r '.items[] as $p
    | [
        $p.metadata.namespace,
        $p.metadata.name,
        ($p.spec.nodeName // "pending"),
        $p.status.phase,
        ([$p.status.containerStatuses[]?.restartCount] | add // 0)
      ]
    | @tsv'

# 找出 Pending Pod 的调度原因
kubectl get pods -A -o json |
  jq -r '.items[]
    | select(.status.phase == "Pending")
    | [
        .metadata.namespace,
        .metadata.name,
        (.status.conditions[]? | select(.type == "PodScheduled") | .reason // "unknown"),
        (.status.conditions[]? | select(.type == "PodScheduled") | .message // "")
      ]
    | @tsv'

# 查看节点不可调度和资源摘要
kubectl get nodes -o json |
  jq -r '.items[]
    | [
        .metadata.name,
        (.spec.unschedulable // false),
        .status.allocatable.cpu,
        .status.allocatable.memory,
        (.status.allocatable["nvidia.com/gpu"] // "0")
      ]
    | @tsv'

资源 requests/limits

# 找出没有 CPU/memory requests 的容器
kubectl get pods -A -o json |
  jq -r '.items[] as $p
    | $p.spec.containers[]
    | select((.resources.requests.cpu? // "") == "" or (.resources.requests.memory? // "") == "")
    | [$p.metadata.namespace, $p.metadata.name, .name] | @tsv'

# 找出申请 GPU 的 Pod
kubectl get pods -A -o json |
  jq -r '.items[] as $p
    | $p.spec.containers[]
    | select((.resources.requests["nvidia.com/gpu"]? // "0") != "0")
    | [
        $p.metadata.namespace,
        $p.metadata.name,
        .name,
        .resources.requests["nvidia.com/gpu"]
      ]
    | @tsv'
kubectl 技巧： 人眼快速查看用 kubectl get；脚本化、聚合、告警和跨资源关联时用 kubectl -o json | jq。

11. API 输出：curl、分页、错误体与鉴权

AI Infra 平台通常有模型服务、调度器、镜像仓库、实验平台、特征平台或云 API。用 curl -sS 获取 JSON，再用 jq 解析，是最小可用的调试链路。生产脚本需要区分 HTTP 错误、空响应、非 JSON 错误页和分页。

# 基础：检查模型服务健康响应
curl -fsS http://model-router.default.svc:8080/health |
  jq -e '.status == "ok"'

# 输出服务版本和 loaded model
curl -fsS http://model-router.default.svc:8080/v1/models |
  jq -r '.data[] | [.id, (.owned_by // "unknown")] | @tsv'

# 带 token 的 API：不要在命令历史里写死 token
curl -fsS \
  -H "Authorization: Bearer $API_TOKEN" \
  "https://infra-api.example.com/v1/jobs?limit=100" |
  jq -r '.items[] | [.id, .state, .created_at] | @tsv'

分页处理模板

# 假设 API 返回 {items: [...], next: "cursor"}，示意写法
cursor=""
while :; do
  page=$(
    curl -fsS -H "Authorization: Bearer $API_TOKEN" \
      "https://infra-api.example.com/v1/jobs?limit=100&cursor=$cursor"
  ) || exit 1

  printf '%s\n' "$page" |
    jq -r '.items[] | [.id, .state, .node // ""] | @tsv'

  cursor=$(printf '%s\n' "$page" | jq -r '.next // ""')
  [ -n "$cursor" ] || break
done
API 错误处理： curl -s 会隐藏错误细节。脚本中优先 curl -fsS，并把响应体保存到临时文件，失败时打印状态码和错误体的 jq 摘要。

12. AI Infra 实战：GPU、容器、节点和作业

jq 是 AI Infra 排障链路中的结构化数据枢纽：从控制面、运行时、指标源读取 JSON，再输出给人、脚本或下一段 API。

GPU 资源和作业视角

# gpustat --json：列出每张卡的显存和利用率
gpustat --json |
  jq -r '.gpus[]
    | [.index, .name, .memory.used, .memory.total, .utilization.gpu]
    | @tsv'

# 找出 GPU 利用率低但显存占用高的卡，常用于空转排查
gpustat --json |
  jq -r '.gpus[]
    | select((.utilization.gpu // 0) < 10 and (.memory.used // 0) > 10000)
    | [.index, .name, .memory.used, .memory.total, .utilization.gpu]
    | @tsv'

# Kubernetes 中找出 GPU Pod 分布
kubectl get pods -A -o json |
  jq -r '.items[] as $p
    | $p.spec.containers[]
    | select((.resources.requests["nvidia.com/gpu"]? // "0") != "0")
    | [
        $p.metadata.namespace,
        $p.metadata.name,
        ($p.spec.nodeName // "pending"),
        .name,
        .resources.requests["nvidia.com/gpu"]
      ]
    | @tsv'

容器 inspect 和镜像排查

# docker inspect：取镜像、入口、环境变量摘要
docker inspect train-container |
  jq '.[0] | {
    image: .Config.Image,
    entrypoint: .Config.Entrypoint,
    cmd: .Config.Cmd,
    env: (.Config.Env | map(select(test("CUDA|NCCL|RANK|WORLD_SIZE"))))
  }'

# crictl inspect：定位退出原因
sudo crictl inspect <container-id> |
  jq '.status | {id, metadata, state, exitCode, reason, message}'

13. 参数传入：--arg、--argjson、--slurpfile

把 shell 变量传给 jq 时，不要拼字符串构造过滤器。正确做法是用 --arg 传字符串，用 --argjson 传 JSON 值，用 --slurpfile 读入外部 JSON 文件数组。

选项用途例子
--arg name "$value"传入字符串$name 在 jq 中是 JSON 字符串。
--argjson n 3传入数字、布尔、对象、数组用于阈值、配置对象。
--slurpfile cfg file.json读入 JSON 文件，变量是数组适合黑名单、白名单、映射表。
env.VAR读取环境变量可用但不如 --arg 明确。
# 用 namespace 参数过滤 Pod
ns="training"
kubectl get pods -A -o json |
  jq -r --arg ns "$ns" '.items[]
    | select(.metadata.namespace == $ns)
    | .metadata.name'

# 数字阈值必须用 --argjson，否则会变成字符串比较
threshold=3
kubectl get pods -A -o json |
  jq -r --argjson threshold "$threshold" '.items[] as $p
    | $p.status.containerStatuses[]?
    | select((.restartCount // 0) > $threshold)
    | [$p.metadata.namespace, $p.metadata.name, .name, .restartCount]
    | @tsv'

# 用节点白名单文件过滤
cat > nodes.json <<'JSON'
["gpu-node-a", "gpu-node-b"]
JSON

kubectl get pods -A -o json |
  jq -r --slurpfile nodes nodes.json '.items[]
    | select(($nodes[0] | index(.spec.nodeName)) != null)
    | [.metadata.namespace, .metadata.name, .spec.nodeName]
    | @tsv'
不要这样做： jq ".items[] | select(.metadata.namespace == \"$ns\")" 容易被引号、反斜杠、换行和注入式内容破坏。用 --arg。

14. 大 JSON 与流式处理：-c、-s、--stream

AI Infra 的事件、日志、审计快照和监控导出可能很大。jq 默认会解析完整 JSON 值；如果输入是巨大数组，内存压力可能明显。常见优化路径是：让上游输出 JSON Lines、一行一个对象；用 -c 压缩输出；必要时用 --stream 处理路径和值事件。

模式作用适合
-c紧凑输出，每个 JSON 值一行日志管道、jsonl 文件。
-s / --slurp把多个输入 JSON 值读成数组小到中等规模 jsonl 聚合。
inputs读取后续 JSON 输入值jq -n 组合多个输入。
--stream输出 [path, value] 事件流超大 JSON 的路径级扫描。
fromjson把字符串解析为 JSON日志字段里嵌套 JSON 字符串。
# JSON Lines：一行一个对象，逐行过滤
jq -c 'select(.level == "error") | {ts, service, message}' app.jsonl

# 小规模 jsonl 聚合：读成数组后按 service 分组
jq -s 'sort_by(.service) | group_by(.service) | map({service: .[0].service, count: length})' app.jsonl

# 大数组先压成 jsonl，再交给后续工具
jq -c '.items[]' huge-k8s-dump.json > pods.jsonl
jq -r 'select(.status.phase != "Running") | [.metadata.namespace, .metadata.name] | @tsv' pods.jsonl

# --stream：只扫描所有 reason 字段的值
jq --stream 'select(.[0][-1] == "reason") | .[1]' huge-events.json
流式边界： --stream 输出的是路径和值，不再是原始对象；过滤器写法不同。只有在大 JSON 内存压力明显或只需少数字段时才优先考虑。

15. shell 引号与跨平台脚本

jq 过滤器里经常包含双引号、方括号、美元符号和反斜杠。Unix shell 中最稳妥的习惯是：过滤器整体用单引号，JSON 字符串用双引号，shell 变量通过 --arg 传入。Windows PowerShell 和 CMD 的引号规则不同，跨平台脚本要单独测试。

环境推荐写法说明
bash/zsh/shjq '.items[] | select(.name == "x")'外层单引号保护 jq 过滤器。
变量传入jq --arg ns "$ns" 'select(.ns == $ns)'不要字符串拼接。
键名含特殊字符.metadata.labels["a/b.c"]方括号访问。
PowerShelljq ".items[] | .metadata.name"引号和转义规则需按 PowerShell 调整。
# 正确：过滤器单引号，jq 内部字符串双引号
jq -r '.items[] | select(.status.phase == "Failed") | .metadata.name' pods.json

# 正确：shell 变量用 --arg
phase="Failed"
jq -r --arg phase "$phase" '.items[] | select(.status.phase == $phase) | .metadata.name' pods.json

# 正确：复杂过滤器写入文件，减少引号地狱
cat > failed-pods.jq <<'JQ'
.items[]
| select(.status.phase == "Failed")
| [.metadata.namespace, .metadata.name, (.status.reason // "")]
| @tsv
JQ
kubectl get pods -A -o json | jq -r -f failed-pods.jq
可维护性建议： jq 过滤器超过 5 到 10 行时，优先写到 .jq 文件并进入版本控制；这比在 shell 脚本里堆转义更容易 review。

16. jq vs yq vs Python vs jsonpath

工具选择不是信仰问题，而是输入格式、复杂度、可维护性和运行环境的权衡。AI Infra 脚本里 jq 通常负责“短链路 JSON 转换”，但不应该承担完整业务程序的职责。

工具优势劣势适合场景
jqJSON 原生、表达力强、管道友好、部署轻复杂逻辑可读性下降Kubernetes/API JSON 查询、告警摘要、轻量转换。
yqYAML/TOML/XML 等格式更方便版本和实现差异较大Helm values、Kubernetes manifest、配置文件。
kubectl -o jsonpath无需额外 jq 依赖复杂过滤、聚合和转义较难非常简单的字段提取。
Python可测试、可维护、库生态完整短 one-liner 较重分页复杂、重试、状态机、多 API 关联、长期维护脚本。
grep/sed/awk文本处理快，环境普遍不理解 JSON 结构粗筛日志、处理非结构化文本。
# jq：JSON 字段提取和重组
kubectl get nodes -o json | jq -r '.items[] | [.metadata.name, .status.allocatable.cpu] | @tsv'

# kubectl jsonpath：简单字段可以不用 jq
kubectl get pod train-0 -n training -o jsonpath='{.spec.nodeName}{"\n"}'

# Python：逻辑复杂时更清楚
python3 - <<'PY'
import json, sys
data = json.load(sys.stdin)
for item in data["items"]:
    if item.get("status", {}).get("phase") != "Running":
        print(item["metadata"]["namespace"], item["metadata"]["name"])
PY
经验法则： 一屏以内、无复杂状态、输入输出都是 JSON 或简单文本，用 jq；需要重试、分页、缓存、测试和错误分类，用 Python/Go。

17. 排障、安全与退出码

排障顺序：先验证输入 JSON，再探索路径和类型，最后检查空值、引号、退出码和脚本安全。

常见问题

问题 1：Cannot index array with string
你把数组当对象访问了。先看 type，再用 [] 展开或 [0] 取元素。
问题 2：Cannot iterate over null
字段不存在或是 null。用 []?、// [] 或先 select(.field != null)。
问题 3：输出多了引号
默认是 JSON 输出。给 shell 文本用 -r。
问题 4：条件没筛到数据
字符串和数字类型可能不同。用 type 检查，必要时 tonumber 或 tostring。
问题 5：脚本成功但值是 null
默认退出码仍可能是 0。需要强校验时用 jq -e。
问题 6：shell 变量导致语法错
不要拼过滤器。用 --arg、--argjson。
问题 7：大 JSON 很慢或 OOM
优先让上游输出 jsonl；再考虑 -c、分块、--stream。
问题 8：curl 返回 HTML 错误页
jq 会解析失败。用 curl -fsS 并检查 HTTP 状态码。

退出码与校验模板

# jq -e：最后输出 false 或 null 时返回非零，适合健康检查
curl -fsS http://model-router:8080/health |
  jq -e '.status == "ok"' >/dev/null

# 调试路径：逐步查看类型和样例
jq 'type' response.json
jq 'keys' response.json
jq '.items | type, length' response.json
jq '.items[0] | keys' response.json

# 最小复现：保存 API 响应，避免重复请求线上服务
curl -fsS "$URL" -o /tmp/response.json
jq '.items[] | select(.state != "ready")' /tmp/response.json
安全提醒： jq 本身不会修改 Kubernetes 或 API 状态，但它常用于生成后续命令。批量删除、重启、扩缩容前必须先打印待操作对象列表，再人工确认或设置显式确认开关。

18. 练习路线与可复用配方

第一阶段：读懂结构

  • 掌握 .、.field、.items[]、keys、type。
  • 会用 // 给缺字段设置默认值。
  • 知道什么时候用 -r，什么时候保留 JSON。

第二阶段：排障查询

  • 掌握 select、test、has、map。
  • 会从 Kubernetes JSON 中输出 namespace/name/node/status。
  • 会生成 TSV/CSV 供终端、表格或告警系统使用。

第三阶段：自动化和规模化

  • 掌握 --arg、--argjson、-f script.jq。
  • 会用 group_by、reduce 做计数和聚合。
  • 理解 jsonl、-c、-s、--stream 的取舍。

可复用配方

# 1. 查看 JSON 顶层结构
jq 'type, keys' response.json

# 2. 从列表中抽样一个对象
jq '.items[0]' response.json

# 3. 输出稳定 TSV
jq -r '.items[] | [.metadata.namespace, .metadata.name, (.spec.nodeName // "pending")] | @tsv' pods.json

# 4. 找出异常对象并保留上下文
jq '.items[] | select(.status.phase != "Running") | {name: .metadata.name, ns: .metadata.namespace, status: .status}' pods.json

# 5. 按字段计数
jq '.items | sort_by(.status.phase) | group_by(.status.phase) | map({phase: .[0].status.phase, count: length})' pods.json

# 6. 用外部参数过滤
jq -r --arg ns training '.items[] | select(.metadata.namespace == $ns) | .metadata.name' pods.json

# 7. 生成逐行 JSON，适合后续管道
jq -c '.items[] | {name: .metadata.name, node: .spec.nodeName, phase: .status.phase}' pods.json

# 8. 从嵌套容器状态中找 OOMKilled
jq -r '.items[] as $p
  | $p.status.containerStatuses[]?
  | select(.lastState.terminated.reason? == "OOMKilled")
  | [$p.metadata.namespace, $p.metadata.name, .name] | @tsv' pods.json
练习数据： 如果手头没有集群，可以把 kubectl get pods -A -o json 的输出保存成 pods.json；练习 jq 时只读本地文件，避免影响线上环境。
