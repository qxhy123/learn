1. 动态规划到底是什么

动态规划，英文 Dynamic Programming，简称 DP。它不是某一种固定公式，而是一种“利用子问题答案构造大问题答案”的方法论。DP 最适合解决满足以下特征的问题：

最优子结构
大问题的最优解可以由小问题的最优解组合得到。例如到达格子 (i,j) 的最小路径和来自上方或左方的最小路径和。
重叠子问题
暴力递归会反复计算同一个子问题。例如斐波那契中 fib(3) 会被多次计算。
无后效性
一旦状态确定，未来决策只依赖这个状态值，不需要知道它是怎么来的。否则状态定义不完整。

DP 与贪心、搜索的区别

方法核心思想适合场景风险
暴力搜索枚举所有可能规模小、验证思路指数爆炸
记忆化搜索搜索 + 缓存重复子问题递归依赖自然、状态较稀疏递归栈、状态设计仍然重要
动态规划按依赖顺序填表状态依赖清晰、需要稳定复杂度状态/转移/遍历顺序容易错
贪心每一步做局部最优选择可证明局部最优推出全局最优很多题看似贪心其实不成立
关键警告： DP 不是“看见最值就用 DP”。如果一个题的局部选择已经能被证明推出全局最优，贪心可能更简单；如果状态空间无法控制，DP 也会爆炸。

信息图：动态规划的本质模型

DP 的本质不是“填表”，而是把原本重复的搜索树压缩成状态图；填表只是其中一种计算状态图的方式。

2. 第一性原理：从暴力搜索到 DP

任何 DP 的起点都不是公式，而是暴力搜索。你先问：这个问题的所有可能选择是什么？暴力搜索会重复算哪些子问题？如果把重复子问题缓存起来，需要用什么变量唯一描述它？这个变量组合就是状态。

从搜索到 DP 的四步

  1. 定义递归含义：函数 f(x) 解决什么子问题？
  2. 列出选择：当前状态可以做哪些选择？
  3. 写出递归关系：当前答案如何由子问题答案得到？
  4. 发现重复并缓存：同一个 x 会被重复计算，就用 memo[x] 或 dp[x]。
# 暴力递归：会重复计算
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

# 记忆化：每个子问题算一次
def fib(n):
    memo = {}
    def dfs(i):
        if i <= 1:
            return i
        if i in memo:
            return memo[i]
        memo[i] = dfs(i - 1) + dfs(i - 2)
        return memo[i]
    return dfs(n)

# 表格 DP：按依赖顺序填表
def fib(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

状态图：暴力递归为什么会重复计算

暴力递归树中相同节点反复出现；记忆化/DP 把这些相同节点合并成一个状态。

3. DP 的五要素

分析一个 DP 题，永远围绕五个要素：

要素要回答的问题例子
状态定义dp[i] 或 dp[i][j] 到底表示什么？dp[i] 表示到第 i 阶的方法数
状态转移当前状态由哪些旧状态推来？dp[i] = dp[i-1] + dp[i-2]
初始条件最小子问题答案是什么？dp[0]=1, dp[1]=1
遍历顺序怎样保证依赖先被计算？i 从小到大
答案位置最终答案从哪里取？dp[n] 或 max(dp)
一套固定问法： “状态表示什么？选择是什么？从哪里转移？边界是什么？按什么顺序算？答案在哪里？” 这六句话可以拆开绝大多数基础 DP 题。

流程图：一道 DP 题的标准解题流程

DP 不是凭感觉套模板，而是按“问题类型 → 搜索选择 → 状态 → 转移 → 边界 → 顺序 → 复杂度”的流程稳定推出来。

4. 递归、记忆化、表格 DP 的关系

很多人觉得 DP 难，是因为直接从表格开始。更自然的路径是：先写递归，发现重复，再加 memo，最后如果需要再改成表格。

暴力递归
最接近题意，容易写选择关系，但重复计算严重。
记忆化搜索
在递归基础上加缓存。适合状态依赖复杂、只访问部分状态的题。
表格 DP
按依赖顺序主动填表。适合状态空间规则、需要优化空间的题。

转换方法

递归写法表格 DP 对应
递归函数参数DP 状态维度
递归出口DP 初始条件
递归调用状态转移依赖
递归调用方向填表遍历顺序的反方向
返回值最终答案位置

时序图：记忆化搜索与表格 DP 的计算顺序差异

记忆化是“自顶向下按需计算”，表格 DP 是“自底向上按序计算”。二者本质上都在计算同一张状态图。

5. 如何设计状态

状态设计是 DP 的核心。状态不是随便取变量，而是要完整描述一个子问题，同时又不能包含无关信息。

状态设计的三个标准

完整性
状态必须包含决定未来的全部信息。如果丢信息，就会违反无后效性。
最小性
不要带无关变量。状态维度越高，复杂度越高。
可转移性
状态之间必须能由选择关系连接，否则定义再漂亮也没用。

常见状态维度

维度来源典型状态常见题型
位置dp[i]、dp[i][j]爬楼梯、路径、序列
容量/资源dp[i][w]背包、预算、时间限制
区间dp[l][r]石子合并、戳气球、回文子串
树节点dp[u][state]树形 DP、树上选择
集合dp[mask]、dp[mask][i]状态压缩、旅行商、子集覆盖
有限状态机dp[i][state]股票买卖、自动机匹配、冷冻期
状态设计的本质问题： “如果两个过程走到同一个状态，它们之后的最优决策是否完全一样？” 如果答案是否定的，状态缺信息。

6. 如何写状态转移方程

状态转移来自“最后一步选择”。很多 DP 题都可以从最后一步倒推：如果最终状态是 dp[i]，它的最后一步可能来自哪里？

四类常见转移

目标聚合方式例子
求最小值min(...)最小路径和、编辑距离
求最大值max(...)背包最大价值、最长递增子序列
求方案数sum(...)爬楼梯、硬币组合数
求可行性or / bool能否分割等和子集、正则匹配

最后一步法

# 最小路径和
# 最后一步到达 (i,j)，只能从上方或左方来
dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])

# 01 背包
# 第 i 个物品最后的选择：不选 or 选
dp[i][w] = max(
    dp[i-1][w],
    dp[i-1][w-weight[i]] + value[i]
)

# 编辑距离
# 最后一个字符：相同则继承，不同则插入/删除/替换
dp[i][j] = min(
    dp[i-1][j] + 1,
    dp[i][j-1] + 1,
    dp[i-1][j-1] + cost
)
推转移口诀： 当前状态的答案 = 枚举最后一步选择 + 取对应子问题答案 + 合并代价。

状态转移图：网格路径 DP

状态转移图能直接告诉你遍历顺序：依赖箭头从旧状态指向新状态，旧状态必须先计算。

7. 遍历顺序与依赖关系

很多 DP bug 不是状态错，而是遍历顺序错。判断顺序的唯一标准：计算当前状态时，它依赖的状态必须已经有正确值。

常见遍历方向

题型依赖遍历顺序
一维前缀 DPdp[i] 依赖 dp[i-1]i 从小到大
网格 DP依赖上方和左方行列从小到大
01 背包一维优化dp[w] 依赖上一轮 dp[w-weight]容量从大到小
完全背包一维优化允许本轮重复使用当前物品容量从小到大
区间 DP大区间依赖小区间按区间长度从小到大
树形 DP父节点依赖子节点后序遍历
背包顺序最容易错： 01 背包一维优化必须倒序容量，完全背包通常正序容量。因为倒序/正序决定当前物品能否在同一轮被重复使用。

8. 经典例子：斐波那契与爬楼梯

爬楼梯

每次可以爬 1 阶或 2 阶，问到第 n 阶有多少种方法。

  • 状态：dp[i] 表示到第 i 阶的方法数。
  • 最后一步：从 i-1 走 1 阶，或从 i-2 走 2 阶。
  • 转移：dp[i] = dp[i-1] + dp[i-2]。
  • 边界：dp[0]=1，dp[1]=1。
def climb_stairs(n):
    dp = [0] * (n + 1)
    dp[0] = 1
    if n >= 1:
        dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

空间优化

def climb_stairs(n):
    a, b = 1, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
为什么能优化： 当前 dp[i] 只依赖前两个状态，所以不需要保留整张表。

9. 路径 DP：网格、最短/最大路径

路径 DP 的典型结构是二维网格：每个位置的答案由邻近位置转移而来。

最小路径和

def min_path_sum(grid):
    m, n = len(grid), len(grid[0])
    dp = [[0] * n for _ in range(m)]
    dp[0][0] = grid[0][0]

    for j in range(1, n):
        dp[0][j] = dp[0][j - 1] + grid[0][j]
    for i in range(1, m):
        dp[i][0] = dp[i - 1][0] + grid[i][0]

    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = grid[i][j] + min(dp[i - 1][j], dp[i][j - 1])

    return dp[m - 1][n - 1]

路径 DP 模板

问题状态转移
最小路径和dp[i][j] 到达该格最小代价min(up, left)+cost
不同路径数dp[i][j] 到该格路径数up + left
带障碍路径dp[i][j] 到该格路径数障碍格为 0，否则 up+left
最大礼物价值dp[i][j] 到该格最大价值max(up,left)+value

10. 背包 DP：01、完全、多重、分组

背包 DP 的本质是：在资源约束下做选择。典型资源是容量、时间、预算、人数、次数。

01 背包

每个物品最多选一次。

def zero_one_knapsack(weights, values, W):
    n = len(weights)
    dp = [0] * (W + 1)

    for i in range(n):
        w, v = weights[i], values[i]
        for cap in range(W, w - 1, -1):  # 倒序
            dp[cap] = max(dp[cap], dp[cap - w] + v)

    return dp[W]

完全背包

每个物品可以选无限次。

def complete_knapsack(weights, values, W):
    dp = [0] * (W + 1)

    for i in range(len(weights)):
        w, v = weights[i], values[i]
        for cap in range(w, W + 1):  # 正序
            dp[cap] = max(dp[cap], dp[cap - w] + v)

    return dp[W]

背包类型对照

类型每件物品可选次数一维容量遍历
01 背包0 或 1 次倒序
完全背包无限次正序
多重背包有限次拆分/二进制优化/单调队列
分组背包每组最多选一个组外循环，组内枚举

11. 序列 DP：LIS、LCS、编辑距离

序列 DP 的状态通常围绕“前 i 个元素”“两个序列的前 i/j 个元素”“以 i 结尾”来定义。

最长递增子序列 LIS

def length_of_lis(nums):
    n = len(nums)
    dp = [1] * n  # dp[i] = 以 nums[i] 结尾的 LIS 长度

    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)

    return max(dp)

最长公共子序列 LCS

def lcs(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    return dp[m][n]

编辑距离

def edit_distance(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(m + 1):
        dp[i][0] = i
    for j in range(n + 1):
        dp[0][j] = j

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = 1 + min(
                    dp[i - 1][j],     # 删除
                    dp[i][j - 1],     # 插入
                    dp[i - 1][j - 1]  # 替换
                )

    return dp[m][n]
序列 DP 常见状态差异： dp[i] 表示“以 i 结尾”时，答案经常是 max(dp)；dp[i] 表示“前 i 个元素”时，答案通常是 dp[n]。

矩阵图：LCS 的二维 DP 表

二维序列 DP 的关键是明确 dp[i][j] 表示“两个前缀”的关系，而不是单个位置。

12. 区间 DP：从小区间到大区间

区间 DP 的状态通常是 dp[l][r]，表示区间 [l,r] 上的答案。它的核心特点是：大区间依赖小区间，所以必须按区间长度从小到大计算。

通用模板

for length in range(1, n + 1):
    for l in range(0, n - length + 1):
        r = l + length - 1

        # 枚举分割点
        for k in range(l, r):
            dp[l][r] = best(
                dp[l][r],
                dp[l][k] + dp[k + 1][r] + cost(l, k, r)
            )

典型题

题型状态转移核心
石子合并dp[l][r] 合并区间最小代价枚举最后一次分割点
戳气球dp[l][r] 戳完开区间最大分数枚举最后戳的气球
回文子序列dp[l][r] 区间最长回文子序列比较两端字符
矩阵链乘dp[l][r] 矩阵链最小乘法代价枚举分割点

信息图：区间 DP 的计算顺序

区间 DP 的顺序由依赖决定：任何大区间都依赖更短的子区间。

13. 树形 DP：父子依赖

树形 DP 的状态通常定义在节点上，父节点答案依赖子节点答案。遍历顺序通常是后序遍历：先算子树，再算当前节点。

经典：树上打家劫舍

每个节点有价值，不能同时选父子节点，求最大价值。

  • dp[u][0]：不选节点 u 时，u 子树最大价值。
  • dp[u][1]：选节点 u 时，u 子树最大价值。
def tree_dp(root):
    def dfs(node):
        if not node:
            return (0, 0)  # not_choose, choose

        left0, left1 = dfs(node.left)
        right0, right1 = dfs(node.right)

        choose = node.val + left0 + right0
        not_choose = max(left0, left1) + max(right0, right1)

        return (not_choose, choose)

    return max(dfs(root))

树形 DP 常见套路

问题状态转移
选/不选节点dp[u][0/1]父子选择互斥
树的直径以节点向下最长路径合并两个最大子路径
树上背包dp[u][k]合并子树容量
换根 DP每个节点作为根的答案先子树，再 reroot

状态转移图：树形 DP 的后序计算

树形 DP 的“表”不是矩阵，而是树结构；依赖方向从子树指向父节点。

14. 状态压缩 DP：bitmask

当状态需要表示一个集合时，可以用二进制位压缩集合。第 i 位是 1 表示第 i 个元素已选择/已访问。

基础操作

# 判断第 i 位是否为 1
if mask & (1 << i):
    ...

# 把第 i 位置 1
mask2 = mask | (1 << i)

# 把第 i 位置 0
mask2 = mask & ~(1 << i)

# 枚举所有 mask
for mask in range(1 << n):
    ...

# 枚举 mask 中的元素
for i in range(n):
    if mask & (1 << i):
        ...

旅行商问题 TSP 简化状态

  • dp[mask][i]：已经访问集合 mask，当前停在 i 的最小代价。
  • 转移：从 i 去一个未访问的 j。
INF = 10**18

def tsp(dist):
    n = len(dist)
    dp = [[INF] * n for _ in range(1 << n)]
    dp[1][0] = 0

    for mask in range(1 << n):
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            for j in range(n):
                if mask & (1 << j):
                    continue
                nxt = mask | (1 << j)
                dp[nxt][j] = min(dp[nxt][j], dp[mask][i] + dist[i][j])

    full = (1 << n) - 1
    return min(dp[full][i] + dist[i][0] for i in range(n))
复杂度提醒： 状态压缩 DP 通常是 O(n·2^n) 或 O(n^2·2^n)。当 n 超过 20 左右就要非常谨慎。

信息图：bitmask 如何表示集合

bitmask 让“集合”变成整数，从而可以把集合状态放进数组下标。

15. DP 优化：从能过到更优

DP 优化的第一原则：先写出正确的朴素 DP，再看瓶颈在哪里。不要一开始就追求高级优化。

常见优化手段

优化解决什么典型场景
滚动数组空间从二维降到一维背包、网格、序列 DP
前缀和快速计算区间转移代价区间 DP、计数 DP
单调队列优化优化滑动范围内最大/最小转移多重背包、队列窗口 DP
二分 + 贪心替代某些 DPLIS 从 O(n²) 到 O(n log n)
斜率优化优化线性函数取最值特定形式的一维 DP
四边形不等式/Knuth 优化优化区间分割点枚举满足特殊单调性的区间 DP
状态压缩把集合状态压缩成整数n 小但集合关系复杂

滚动数组示例

# 网格 DP 二维转一维
def min_path_sum(grid):
    m, n = len(grid), len(grid[0])
    dp = [0] * n
    dp[0] = grid[0][0]

    for j in range(1, n):
        dp[j] = dp[j - 1] + grid[0][j]

    for i in range(1, m):
        dp[0] += grid[i][0]
        for j in range(1, n):
            dp[j] = grid[i][j] + min(dp[j], dp[j - 1])
    return dp[-1]
优化风险： 滚动数组会改变读写同一个数组的时序。优化后必须重新检查遍历顺序，否则容易把上一轮状态和当前轮状态混在一起。

16. 排障、常见坑与刷题路线

常见坑

坑 1：状态含义不清
代码写到一半才发现 dp[i] 不知道代表“前 i 个”还是“以 i 结尾”。
坑 2：边界条件错
dp[0]、空串、空集合、第一行第一列经常是 bug 来源。
坑 3：遍历顺序错
尤其是一维背包和滚动数组。
坑 4：答案位置错
有些题答案是 dp[n]，有些是 max(dp)，有些是表中某个范围。
坑 5：把贪心误写成 DP
没有重叠子问题或状态空间过大时，DP 可能不是最优解法。
坑 6：状态缺信息
未来决策还依赖历史，但状态没记录，导致转移错误。
坑 7：复杂度爆炸
状态数 × 转移代价超限制，需要优化或换思路。
坑 8：取模/溢出/INF 设置错
计数题取模，最短路类 DP 需要合理 INF。

排障流程

  1. 用一句话写清楚状态含义。
  2. 手算最小样例，把表格画出来。
  3. 检查每个状态依赖是否已经计算。
  4. 检查边界：空、1 个元素、第一行/列、容量 0。
  5. 检查答案取值位置。
  6. 检查复杂度是否符合输入范围。

刷题路线

阶段题型目标
入门斐波那契、爬楼梯、打家劫舍理解状态和转移
基础网格路径、最小路径和、不同路径掌握二维 DP 和边界
核心01 背包、完全背包、硬币兑换掌握选择和容量维度
序列LIS、LCS、编辑距离掌握前缀和结尾状态
进阶区间 DP、树形 DP、状态压缩掌握非线性状态结构
高级单调队列、斜率优化、四边形优化优化状态转移复杂度

用例图：动态规划适合解决哪些问题

DP 的应用不是按题面分类，而是按目标和状态结构分类：最值、计数、可行性、序列、资源、结构。

最终总结：DP 的核心心法

  1. 先从暴力搜索想选择，不要一上来硬套表格。
  2. 状态是“子问题的唯一描述”，不是随便起变量名。
  3. 转移来自“最后一步选择”或“当前选择”。
  4. 遍历顺序由依赖关系决定。
  5. 复杂度 = 状态数 × 每个状态的转移代价。
  6. 优化前先保证朴素 DP 正确。
  7. 每道题都要写清楚状态含义、转移、边界、顺序、答案位置。

推荐练习顺序：爬楼梯 → 打家劫舍 → 最小路径和 → 01 背包 → 完全背包 → LIS → LCS → 编辑距离 → 区间 DP → 树形 DP → 状态压缩 DP。
