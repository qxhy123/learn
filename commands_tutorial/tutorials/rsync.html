rsync 深度教程：从同步模型到安全增量备份

这份教程按 Linux 常用命令 rsync 讲解。它不是选项速查表，而是从“源端、目标端、文件列表、增量传输、删除策略”这个心智模型出发，系统讲清楚：源路径与目标路径、结尾斜杠语义、归档模式、dry-run、删除安全、SSH 传输、包含与排除规则、断点续传、备份策略、与 scp/cp 的边界，以及真实运维中的排障流程。

一句话理解： rsync 是“让目标端变得像源端”的同步工具；它先构建文件列表，再只传输必要差异，因此特别适合重复同步、远程部署和增量备份。
最重要原则： 第一次写命令或涉及 --delete、覆盖、批量排除时，先加 -n/--dry-run 和 -i/--itemize-changes 看清楚会发生什么，再执行真实同步。

1. rsync 是什么

rsync 用于在本机目录之间、主机之间、或通过 rsync daemon 同步文件。它的价值不只是“复制文件”，而是“可重复地同步目录状态”：已经相同的文件不会重复传，发生变化的文件只传必要内容，目标端可按规则新增、更新、删除或保留文件。

它擅长什么
增量备份、发布静态文件、同步大目录、保留权限和时间戳、通过 SSH 安全传输、按规则排除缓存和构建产物。
它不擅长什么
双向冲突合并、数据库热备、对象存储语义、实时同步、跨平台复杂权限映射。需要这些能力时应使用专门工具。
它的本质
比较源端与目标端，决定哪些文件需要创建、更新、删除或跳过，然后按选项执行。
# 本机目录同步：把 src/ 的内容同步到 dst/
rsync -av src/ dst/

# 远程同步：把本机 public/ 发布到服务器
rsync -avz public/ deploy@example.com:/var/www/site/

# 先预演，再执行
rsync -avni src/ dst/
rsync -avi src/ dst/
关键区别： rsync 默认不会删除目标端多出来的文件；只有显式使用 --delete 及相关选项时才会让目标目录更严格地镜像源目录。

信息图：rsync 的整体心智模型

学习 rsync 时先问四个问题：源是什么、目标是什么、哪些文件进入文件列表、目标端多余文件如何处理。

2. 基本语法与第一次同步

rsync [options] SOURCE... DESTINATION

# SOURCE 可以是本地路径，也可以是 user@host:/path/
# DESTINATION 可以是本地路径，也可以是 user@host:/path/
# 常用组合：-a 归档，-v 详细，-n dry-run，-i 显示变更类型
命令实际效果
rsync -av src/ dst/把 src/ 里面的内容同步到 dst/，保留常见元数据。
rsync -avn src/ dst/预演同步，不真正写入目标端。
rsync -avi src/ dst/执行同步，并显示每个变更项的类型。
rsync -avz src/ user@host:/backup/src/通过 SSH 传输到远程主机，压缩传输数据。

最小可验证示例

mkdir -p /tmp/rsync-demo/src /tmp/rsync-demo/dst
printf 'hello\n' > /tmp/rsync-demo/src/a.txt

# 先看会发生什么
rsync -avni /tmp/rsync-demo/src/ /tmp/rsync-demo/dst/

# 确认后执行
rsync -avi /tmp/rsync-demo/src/ /tmp/rsync-demo/dst/
输出习惯： 真实工作中推荐把 -a、-n、-i 连起来用：-ani 先看计划，确认后去掉 n。

信息图：结尾斜杠决定“复制目录本身”还是“复制目录内容”

斜杠只影响源路径的解释；目标路径末尾加不加斜杠通常不是同等风险点。新手最常见事故就是把 src 和 src/ 混淆。

3. 源/目标路径与结尾斜杠语义

rsync 的路径语义必须死记一个规则：源路径末尾有 /，表示同步“目录里的内容”；源路径末尾没有 /，表示同步“这个目录本身”。

命令源端含义目标结果
rsync -a project backup/复制 project 目录本身backup/project/...
rsync -a project/ backup/复制 project/ 内部内容backup/...
rsync -a file.txt backup/复制单个文件backup/file.txt
rsync -a file.txt backup/name.txt复制并改目标文件名backup/name.txt
# 推荐先用 tree 或 find 看结构
find src -maxdepth 2 -print

# 预演两种写法的差异
rsync -avni src dst/
rsync -avni src/ dst/
危险组合： rsync -a --delete empty-dir/ important-dir/ 会把目标目录同步成空目录。涉及 --delete 时，结尾斜杠不是小细节，而是安全边界。

4. 归档模式 -a 到底包含什么

-a 是 --archive，可理解为“递归同步并尽量保留文件元数据”。它常用于备份和部署，因为它比裸 rsync src/ dst/ 更接近复制目录树的真实状态。

等价子选项含义注意
-r递归进入目录同步目录树必需。
-l保留符号链接链接作为链接复制，而不是跟随到目标文件。
-p保留权限位远程用户需要有相应权限。
-t保留修改时间影响后续增量判断。
-g保留组非 root 用户可能无法完整保留。
-o保留属主通常只有 root 能完整保留。
-D保留设备文件和特殊文件常见于系统备份，普通部署较少关心。
# 常见部署：保留时间、权限、链接，并输出详细信息
rsync -av public/ deploy@example.com:/var/www/site/

# 如果不想保留属主和组，可显式调整
rsync -av --no-owner --no-group public/ deploy@example.com:/var/www/site/
实践建议： 日常目录同步优先从 -a 起步，再按目标环境去掉不适合的元数据保留项。

5. dry-run 与变更明细

-n/--dry-run 表示只计算和展示计划，不真正改目标端。-i/--itemize-changes 会展示每个文件的变化类型，是理解 rsync 行为的关键诊断工具。

# 最推荐的预演组合
rsync -avni src/ dst/

# 看统计信息
rsync -avnih --stats src/ dst/

# 只看哪些文件会变化
rsync -avni src/ dst/ | sed -n '/^[><ch.*]/p'
itemize 片段大致含义解释方式
>f+++++++++目标端新增普通文件> 表示发送到目标，f 表示文件。
>f.st......文件大小或时间变化常见于内容更新。
.d..t......目录时间戳变化通常不是内容风险。
*deleting将删除目标端文件只在启用删除类选项时出现，必须重点检查。
工作习惯： 把 rsync -avni ... 当成“同步计划审查”，而不是可有可无的预览。

安全流程图：涉及 --delete 时必须先预演

--delete 是让目标端更像源端的工具，不是“删除旧垃圾”的万能按钮。源端少了什么，目标端就可能被删什么。

6. 删除安全：--delete 不是清理按钮

默认情况下，目标端存在但源端不存在的文件会保留。加入 --delete 后，rsync 会删除目标端额外文件，使目标端更接近源端镜像。它非常有用，也非常危险。

# 安全写法：先预演删除
rsync -avni --delete src/ dst/

# 重点看 *deleting 行；确认后才执行
rsync -avi --delete src/ dst/
选项作用适用场景
--delete删除目标端多余文件镜像目录、静态站发布。
--delete-excluded目标端中被排除规则匹配的文件也删除需要严格清理目标端缓存时使用，风险更高。
--max-delete=N限制最多删除 N 个文件为自动任务增加保险丝。
--backup --backup-dir=DIR删除或覆盖前把旧文件移到备份目录需要可回滚同步。
生产警告： 自动化脚本里使用 --delete 时，建议加 --max-delete、日志、告警和备份目录。不要让一个空源目录把目标备份清空。

7. SSH 传输与远程路径

最常见的远程模式是通过 SSH：user@host:/path/。这时认证、端口、密钥、远程目录权限都由 SSH 和远程系统决定。

# 从本机推送到远程
rsync -avz public/ deploy@example.com:/var/www/site/

# 从远程拉取到本机
rsync -avz deploy@example.com:/var/log/nginx/ ./nginx-logs/

# 指定 SSH 端口和密钥
rsync -avz -e 'ssh -p 2222 -i ~/.ssh/deploy_key' public/ deploy@example.com:/var/www/site/

# 保留远程相对路径结构
rsync -avR deploy@example.com:/etc/nginx/nginx.conf ./backup/
推送
local/ user@host:/remote/
常用于部署。
拉取
user@host:/remote/ local/
常用于集中备份。
远程到远程
不建议初学者直接使用；先同步到中间机或在源端运行命令更可控。
权限提醒： rsync 不能绕过远程用户权限。写入 /var/www、保留属主、保留设备文件等操作，可能需要目标目录授权或 sudo 包装。

信息图：include/exclude 过滤规则如何影响文件列表

过滤规则不是事后隐藏输出，而是在构建文件列表时决定遍历和同步范围。目录能否被遍历，常取决于是否先包含 */。

8. include/exclude 过滤规则

--exclude 用于排除路径，--include 用于重新包含路径。复杂规则按出现顺序匹配，第一条命中的规则通常决定该路径命运。目录遍历尤其重要：如果父目录被排除，里面的文件就没有机会被包含。

常见排除

# 排除缓存、依赖、版本库
rsync -av \
  --exclude '.git/' \
  --exclude 'node_modules/' \
  --exclude '__pycache__/' \
  --exclude '*.log' \
  app/ deploy@example.com:/srv/app/

只同步特定类型

# 只同步目录、Python 文件和 static 下所有内容，最后排除其他
rsync -avni \
  --include '*/' \
  --include '*.py' \
  --include 'static/***' \
  --exclude '*' \
  app/ /tmp/app-preview/
模式含义备注
*.log匹配日志文件名不带斜杠时可匹配各层文件名。
/build/匹配传输根目录下的 build 目录前导 / 相对同步源根。
cache/匹配名为 cache 的目录末尾 / 表示目录。
static/***匹配 static 目录及其全部内容常用于包含整个子树。
过滤排障： 如果“明明 include 了却没有同步”，先检查父目录是否被允许遍历，通常需要在排除 * 之前加入 --include '*/'。

9. 断点续传与部分文件

大文件传输中断后，默认 rsync 可能会删除临时部分文件。使用 --partial 或 --partial-dir 可以保留未完成片段，下一次同步可复用，减少重传。

选项作用建议
--partial保留部分传输文件简单直接，但目标目录可能出现不完整文件。
--partial-dir=.rsync-partial把部分文件放到临时目录更整洁，适合脚本和部署。
--append假设目标文件只是缺少尾部并追加仅适合严格确认只追加的文件。
--append-verify追加后校验已有内容比 --append 更安全。
# 大文件备份，保留部分传输并显示进度
rsync -avh --progress --partial-dir=.rsync-partial videos/ backup:/data/videos/

# 网络不稳定时可重复运行同一条命令
rsync -avh --progress --partial-dir=.rsync-partial videos/ backup:/data/videos/
心智模型： rsync 的“可重复运行”是它的核心优势。失败后通常不要手工清理，先用同一组选项重新运行，让 rsync 自己比较状态。

10. 备份、快照与回滚

同步不是备份的全部。单纯 rsync -a --delete 会让目标端越来越像源端，也会把源端的误删同步过去。真正的备份需要保留历史版本或至少保留被覆盖、被删除的旧文件。

覆盖前保留旧文件

# 先预演：查看覆盖和删除计划
rsync -avni --delete --backup --backup-dir=../backup-old src/ backup/current/

# 确认后执行：旧文件进入 backup-old
rsync -avi --delete --backup --backup-dir=../backup-old src/ backup/current/

用硬链接构建日期快照

# 上一个快照作为硬链接基线，未变化文件不重复占用空间
TODAY=$(date +%F)
PREV=/backup/snapshots/latest
DEST=/backup/snapshots/$TODAY

mkdir -p "$DEST"
rsync -a --delete --link-dest="$PREV" /home/app/data/ "$DEST/"
ln -sfn "$DEST" /backup/snapshots/latest
快照提醒： --link-dest 适合文件级快照，但不要在不了解硬链接语义时手工修改旧快照里的文件。

11. 权限、属主、时间戳与链接

rsync 是否“同步成功”，不只看文件内容，还要看权限、属主、组、时间戳、符号链接、硬链接、ACL、扩展属性是否符合目标需求。-a 保留常见元数据，但并不包含所有平台特性。

需求常用选项说明
保留普通权限和时间戳-a大多数部署和备份的起点。
不保留属主/组--no-owner --no-group远程非 root 部署常用。
保留硬链接关系-H会增加内存和扫描成本。
保留 ACL-A需要两端文件系统和 rsync 支持。
保留扩展属性-XLinux/macOS 行为可能不同。
跟随符号链接-L复制链接指向的真实文件，需谨慎。
# Web 部署：通常不需要保留本机用户和组
rsync -av --no-owner --no-group public/ deploy@example.com:/var/www/site/

# 系统级备份：更完整保留元数据，通常需要 root 权限
rsync -aHAX --numeric-ids /etc/ backup:/srv/backup/etc/
链接风险： -L 会跟随符号链接，可能把源目录外的大量内容带入同步范围。除非明确需要，否则部署和备份中优先保留链接本身。

12. 性能、带宽与大目录优化

rsync 性能由三部分决定：扫描文件列表、比较差异、传输数据。小文件很多时，扫描和元数据开销可能比传输更重；大文件跨网络时，压缩、限速和部分传输更重要。

场景选项理由
跨公网传文本-z压缩能减少传输量。
局域网传大媒体通常不用 -z压缩视频收益小，还消耗 CPU。
限制带宽--bwlimit=10M避免影响业务网络。
显示整体进度--info=progress2比每个文件的 --progress 更适合大任务。
强制校验内容-c更准确但更慢，会读取两端文件内容。
# 大目录跨网络同步，显示整体进度并限速
rsync -ah --info=progress2 --bwlimit=20M data/ backup:/data/

# 两端时间戳不可信时，用校验和判断差异
rsync -avc src/ dst/
性能判断： 如果输出长时间停在 building file list，瓶颈通常是目录遍历和元数据读取，不是网络带宽。

用例图：rsync、scp、cp 怎么选

一次性复制用 cp 或 scp 更简单；只要任务变成“重复同步同一批文件”，rsync 的优势就会迅速显现。

13. rsync vs scp vs cp

工具优势劣势适合
cp本机复制直接、无远程依赖不做远程传输，不擅长增量同步和复杂过滤一次性本地复制。
scp远程复制语义简单，SSH 生态成熟重复传输时通常不如 rsync 高效，过滤和删除能力弱临时传几个文件。
rsync增量、过滤、保留元数据、dry-run、可删除、可备份路径和过滤语义需要学习，错误选项可能影响大量文件部署、备份、镜像、大目录同步。
# cp：本机一次性复制
cp -a src/ dst/

# scp：远程一次性复制
scp archive.tar.gz user@example.com:/tmp/

# rsync：重复同步目录
rsync -av --delete public/ user@example.com:/var/www/site/
选择原则： 如果你预计同一条复制任务会运行第二次，就优先考虑 rsync。

14. 部署与备份的安全工作流

生产中最可靠的 rsync 流程不是“写对一条神奇命令”，而是把预演、审查、执行、验证、回滚点串成固定流程。

静态站部署模板

# 1. 构建产物
npm run build

# 2. 预演：注意 --delete 会删除远程多余文件
rsync -avnih --delete dist/ deploy@example.com:/var/www/site/

# 3. 执行
rsync -avih --delete dist/ deploy@example.com:/var/www/site/

# 4. 验证远程文件
ssh deploy@example.com 'find /var/www/site -maxdepth 2 -type f | sort | head'

备份模板

# 1. 预演并限制最大删除数量
rsync -avnih --delete --max-delete=100 /srv/data/ backup:/backup/data/

# 2. 确认后执行，并记录日志
rsync -avih --delete --max-delete=100 /srv/data/ backup:/backup/data/ \
  | tee -a /var/log/rsync-data-backup.log
流程底线： 自动任务第一次上线前，必须在测试目录跑通 dry-run 和真实执行；不要在首次运行时直接指向生产数据。

排障流程图：rsync 失败或结果不对时怎么查

排障顺序固定下来后，大多数 rsync 问题都能快速定位：路径、权限、过滤、网络、元数据。

15. 常见故障与排障

问题 1：目标端多了一个 src 目录
源路径用了 src 而不是 src/。用 dry-run 对比两种写法。
问题 2：文件没有被删除
默认不会删除目标端额外文件。需要镜像语义时使用 --delete，但必须先 -n -i。
问题 3：权限或属主不对
远程用户没有权限保留属主/组，考虑 --no-owner --no-group 或调整目标目录权限。
问题 4：include 没生效
父目录可能被排除了。加入 --include '*/' 并检查规则顺序。
问题 5：每次都重复传
检查时间戳是否保留、两端时钟、文件系统精度，必要时用 -c 验证。
问题 6：大文件中断后重来
使用 --partial-dir=.rsync-partial 并重复运行同一条命令。
问题 7：SSH 连接失败
先单独运行 ssh user@host，再检查 -e 'ssh -p ...'。
问题 8：文件名含空格出问题
避免自己拼接未引用路径；脚本中变量使用双引号。

排障模板

# 1. 先确认 SSH
ssh deploy@example.com 'pwd; id; ls -ld /var/www/site'

# 2. 单文件 dry-run
rsync -avni ./public/index.html deploy@example.com:/var/www/site/index.html

# 3. 大目录 dry-run + 明细
rsync -avnih --delete public/ deploy@example.com:/var/www/site/

# 4. 需要更多日志时
rsync -avvni public/ deploy@example.com:/var/www/site/

16. 脚本化、定时任务与日志

自动化 rsync 时，重点不是少写几行命令，而是让失败可见、路径可靠、日志可追踪、删除有保险丝。脚本里应显式设置变量、检查源目录存在、记录退出码。

#!/usr/bin/env bash
set -euo pipefail

SRC="/srv/app/data/"
DEST="backup@example.com:/backup/app-data/"
LOG="/var/log/rsync-app-data.log"

if [ ! -d "$SRC" ]; then
  echo "source not found: $SRC" >&2
  exit 1
fi

rsync -avh --delete --max-delete=500 \
  --partial-dir=.rsync-partial \
  "$SRC" "$DEST" | tee -a "$LOG"

cron 示例

# 每天 02:30 运行备份脚本
30 2 * * * /usr/local/bin/backup-app-data.sh >>/var/log/backup-app-data.cron.log 2>&1
自动化提醒： cron 环境变量很少，脚本里使用绝对路径更稳妥；首次上线前先手动运行，并保留一次 dry-run 日志。

17. 学习路线与练习任务

第一阶段：会同步

  • 理解 SOURCE DESTINATION 位置关系。
  • 掌握 src 与 src/ 的区别。
  • 熟练使用 -a、-v、-n、-i。

第二阶段：会安全使用

  • 涉及 --delete 时先 dry-run 并审查 *deleting。
  • 掌握常见 exclude 规则，知道 include/exclude 的顺序影响。
  • 知道如何使用 --backup、--backup-dir、--max-delete 做保险。

第三阶段：工程化

  • 掌握 SSH 传输、密钥、端口和远程权限排障。
  • 根据文件类型决定是否使用 -z、--partial-dir、--bwlimit。
  • 能写可重复运行、有日志、有失败退出的备份或部署脚本。

练习

  1. 创建两个临时目录，分别测试 rsync -a src dst/ 与 rsync -a src/ dst/ 的结果。
  2. 用 rsync -avni 观察新增文件、修改文件、目录时间戳变化的 itemize 输出。
  3. 在目标端创建一个源端不存在的文件，比较有无 --delete 的 dry-run 输出。
  4. 写一组规则，只同步 *.md 和 images/，排除其他文件。
  5. 模拟大文件中断，使用 --partial-dir 继续同步。
  6. 用 --backup --backup-dir 保存被覆盖文件，并练习回滚。
