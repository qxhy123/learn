awk 深度教程：从记录字段模型到日志统计与文本报表

这份教程按 Linux 常用命令 awk 讲解。它不是选项速查表，而是从“输入如何被拆成记录、记录如何被拆成字段、模式如何选择记录、动作如何计算和输出”这个核心模型出发，系统讲清楚：pattern { action }、FS/OFS、内置变量、BEGIN/END、聚合统计、数组、格式化输出、CSV 限制、与 sed/cut/Python 的边界，以及生产排障方法。

1. awk 是什么

awk 解决的问题是：从文本流中按记录和字段抽取信息，执行轻量计算，并输出新的文本、汇总值或小型报表。它常用于日志统计、列式文本处理、配置清单检查、命令输出整理和临时数据分析。

它擅长什么
按列过滤、字段重排、分组计数、求和平均、轻量报表、对管道输出做即时统计。
它不擅长什么
完整 CSV/JSON/XML 解析、复杂业务逻辑、大型可测试程序、需要第三方库的数据处理。
它的本质
读一条记录 → 拆字段 → 依次测试规则 → 执行动作 → 继续下一条记录。
# 打印第 1 列和第 3 列
awk '{print $1, $3}' data.txt

# 统计第 2 列总和
awk '{sum += $2} END {print sum}' numbers.txt

# 只输出包含 ERROR 的行号和原文
awk '/ERROR/ {print NR, $0}' app.log

# 指定逗号分隔
awk -F, '{print $1, $4}' users.csv
关键区别： grep 主要找行，sed 主要改行，cut 主要切固定列；awk 可以在“选中行”的同时理解字段、保存状态并做计算。

信息图：awk 的整体执行模型

掌握 awk 的关键是把输入看成“记录集合”，把每条记录看成“字段集合”，再用规则把筛选、计算和输出串起来。

2. 基本语法与第一批例子

awk [options] 'program' [file...]

# program 由一组规则组成
pattern { action }

# 没有 file 时从 stdin 读取
# pattern 省略表示每条记录都匹配
# action 省略表示打印整条记录 $0
命令实际效果
awk '{print $1}' file打印每行第 1 个字段
awk '$3 > 100 {print $1, $3}' file第 3 字段大于 100 时打印第 1、3 字段
awk -F: '{print $1}' /etc/passwd按冒号拆分并打印用户名前缀
awk 'END {print NR}' file打印记录总数，常用于数行

从管道开始理解

# 统计 ps 输出中每个命令出现次数
ps -eo comm= | awk '{count[$1]++} END {for (cmd in count) print count[cmd], cmd}'

# 查看磁盘使用率超过 80% 的挂载点
df -h | awk 'NR > 1 {gsub(/%/, "", $5); if ($5 > 80) print $5 "%", $6}'

# 把空白分隔的三列重排成 CSV
printf 'alice 90 A\nbob 72 C\n' | awk 'BEGIN {OFS=","} {print $1, $3, $2}'
默认行为： 默认输入记录分隔符 RS 是换行；默认字段分隔符 FS 是一段空白；print a, b 会用 OFS 连接字段。

3. 记录与字段：NR、FNR、NF、$0、$1

awk 每次读入一条记录后，把完整记录放在 $0，再根据 FS 拆出 $1、$2 到 $NF。字段编号从 1 开始，NF 是当前记录字段数，NR 是所有输入累计记录号，FNR 是当前文件内记录号。

名称含义常见用法
$0整条记录打印原行、做正则匹配、整行替换
$1...$NF第 1 到最后一个字段抽列、重排、条件判断
NF当前记录字段数跳过字段不足的坏行，打印最后一列 $NF
NR全局记录号跳过表头、打印行号、总行数
FNR当前文件记录号多文件处理时识别每个文件的表头
FILENAME当前文件名输出来源文件、按文件统计
# 打印行号、字段数、整行
awk '{print NR, NF, $0}' data.txt

# 打印最后一列
awk '{print $NF}' access.log

# 多文件时每个文件都跳过第一行表头
awk 'FNR == 1 {next} {print FILENAME, $0}' *.tsv

# 字段不足时跳过，避免把坏行纳入统计
awk 'NF >= 3 {sum += $3; n++} END {print sum, n}' data.txt
字段访问提醒： $3 是第 3 个字段；field = 3; $field 才是“编号变量指向的字段”。裸写 field 只是普通变量。

流程图：pattern-action 如何选择和处理记录

每条记录都会依次测试每条规则。awk 的强大之处在于 action 可以保存状态，因此它能跨记录聚合。

4. pattern-action 模型

awk 程序由一组 pattern { action } 规则组成。pattern 决定当前记录是否命中，action 决定命中后做什么。省略 pattern 表示所有记录；省略 action 表示打印当前记录。

pattern 类型例子含义
空 pattern{print $1}对每条记录执行
正则 pattern/ERROR/整条记录匹配正则时执行默认打印
字段比较$3 >= 90 {print $1}第 3 字段满足条件时执行
组合条件$2 == "GET" && $9 >= 500逻辑与、或、非组合
范围 pattern/BEGIN/,/END/从命中 BEGIN 到命中 END 的记录范围
特殊 patternBEGIN、END输入前后执行初始化和收尾
# action 省略：匹配 ERROR 的整行会被打印
awk '/ERROR/' app.log

# pattern 省略：每行打印第 1 列
awk '{print $1}' data.txt

# 条件过滤：只打印状态码 5xx
awk '$9 ~ /^5/ {print $1, $7, $9}' access.log

# 范围匹配：抽取块
awk '/^BEGIN REPORT/,/^END REPORT/' report.txt
正则位置： /ERROR/ 默认匹配 $0；如果要匹配某个字段，用 $3 ~ /ERROR/ 或 $3 !~ /ERROR/。

5. FS、OFS、RS、ORS 分隔符

分隔符决定 awk 如何读入和输出。FS 是输入字段分隔符，OFS 是输出字段分隔符，RS 是输入记录分隔符，ORS 是输出记录分隔符。

变量默认值作用例子
FS一段空白把记录拆成字段awk -F, '{print $1}'
OFS空格print a, b 的字段连接符BEGIN {OFS=","}
RS换行把输入拆成记录BEGIN {RS=""} 按空行分段
ORS换行每次 print 末尾追加BEGIN {ORS="\0"}
# -F 是设置 FS 的常用快捷方式
awk -F: '{print $1, $7}' /etc/passwd

# 输出 TSV
awk 'BEGIN {OFS="\t"} {print $1, $3, $NF}' data.txt

# 输入逗号分隔，输出也保持逗号分隔
awk -F, 'BEGIN {OFS=","} {print $1, $4, $2}' users.csv

# 按空行分段：每个段落是一条记录
awk 'BEGIN {RS=""; FS="\n"} {print "段落行数:", NF}' notes.txt
默认 FS 的特殊性： 默认 FS=" " 不是普通单个空格，而是“任意连续空白，并忽略行首行尾空白”。如果你写 -F' '，多数 awk 仍按这个特殊规则处理；要按单个字面空格拆分，应使用更明确的正则策略并测试样本。

信息图：分隔符如何影响输入和输出

很多 awk 问题本质是分隔符问题：先确认记录怎么切，再确认字段怎么切，最后确认输出怎么拼。

6. BEGIN 与 END

BEGIN 在读取任何输入前执行，适合初始化分隔符、打印表头、设置常量。END 在所有输入处理完后执行，适合打印汇总、平均值、总数和最终报表。

# 初始化输出表头，最后打印平均值
awk '
BEGIN {print "name score"}
NR > 1 {sum += $2; n++; print $1, $2}
END {if (n) print "avg", sum / n}
' scores.txt

# 没有输入文件也能执行 BEGIN
awk 'BEGIN {print 60 * 60 * 24}'

# 给报表添加首尾
awk 'BEGIN {print "---- start ----"} {print} END {print "---- end ----"}' file.txt
阶段能做什么不能依赖什么
BEGIN初始化变量、设置 FS/OFS、打印表头不能依赖输入记录字段，因为还没有读入 $0
普通规则逐记录过滤、计算、累积状态不要在这里打印最终汇总，除非就是逐行报表
END输出总数、平均值、TopN 前的完整结果输入为空时要防止除以零
可维护写法： 把 FS/OFS、表头和常量放在 BEGIN，把聚合结果放在 END，中间规则只处理单条记录。

7. 变量、类型和表达式

awk 变量无需声明。它会根据上下文在字符串和数字之间转换：参与算术时按数字使用，参与拼接或正则时按字符串使用。未初始化变量默认像数字 0，也像空字符串。

写法含义例子
x = 1赋值{total += $3}
x++自增{count[$1]++}
a b字符串拼接{id = $1 ":" $2}
== != < >比较$3 >= 90
~ !~正则匹配/不匹配$7 ~ /^\/api\//
# 数值上下文：求和
awk '{sum += $2} END {print sum}' nums.txt

# 字符串拼接：没有 + 号
awk '{key = $1 ":" $2; print key}' data.txt

# 传入 shell 变量时用 -v，避免拼接引号灾难
threshold=90
awk -v min="$threshold" '$3 >= min {print $1, $3}' scores.txt

# 正则变量：右侧不写斜杠时可来自变量
awk -v re='^ERR' '$2 ~ re {print}' app.log
类型提醒： 字符串 "08" 参与数值比较时会变成数字 8；如果 ID、邮编、版本号不能丢前导零，应按字符串比较或直接输出。

8. 条件、循环与函数

awk 是小型编程语言，支持 if、for、while、next、exit，也有常用字符串和数学函数。复杂到影响可读性时，应转成脚本文件或换 Python。

类别示例用途
条件if ($3 > 90) print分支处理
循环for (i=1; i<=NF; i++)遍历字段
跳过记录next跳过表头或坏行
退出exit找到目标后提前结束
字符串函数length、substr、split、gsub清洗和拆解文本
数学函数int、sqrt、rand轻量计算
# 遍历每个字段，找出空字段位置
awk -F, '{for (i=1; i<=NF; i++) if ($i == "") print NR, "empty field", i}' data.csv

# 清洗百分号后比较
df -h | awk 'NR > 1 {use=$5; gsub(/%/, "", use); if (use > 80) print $6, use "%"}'

# 找到第一个匹配后退出
awk '$1 == "target" {print NR, $0; exit}' file.txt

# split 把字段再拆一层
awk -F, '{split($3, parts, "-"); print parts[1], parts[2]}' data.csv
控制流原则： 能用 pattern 表达的条件优先写在 pattern 里；需要多步处理时再进入 action 的 if 和循环。

9. 数组、分组和聚合

awk 的数组是关联数组，键可以是字符串。它非常适合分组计数、按类别求和、去重、建立小型映射表。数组会跨记录保留，通常在 END 中遍历输出。

# 分组计数：统计第 1 列出现次数
awk '{count[$1]++} END {for (k in count) print k, count[k]}' data.txt

# 按状态码统计请求数
awk '{status[$9]++} END {for (s in status) print s, status[s]}' access.log

# 按用户求和
awk -F, 'NR > 1 {sum[$1] += $3} END {for (u in sum) print u, sum[u]}' orders.csv

# 去重：第一次见到某个 key 才打印
awk '!seen[$1]++ {print $1}' users.txt

排序问题

POSIX awk 遍历数组的顺序不保证稳定。需要排序时，常把 awk 输出交给 sort；GNU awk 有 PROCINFO["sorted_in"]，但它不是所有 awk 都支持。

# Top 10 IP：awk 聚合，sort 排序，head 截断
awk '{ip[$1]++} END {for (i in ip) print ip[i], i}' access.log | sort -nr | head -10

# 按用户金额降序
awk -F, 'NR > 1 {sum[$1] += $3} END {for (u in sum) print sum[u], u}' orders.csv | sort -nr
工程建议： awk 负责可靠地把“键 值”吐出来，排序、TopN、唯一化可以交给 sort、uniq、head，管道组合通常更清晰。

10. 格式化输出与报表

print 简单直接，printf 更适合对齐、控制小数位和生成固定格式输出。printf 不会自动追加换行，需要显式写 \n。

格式含义例子
%s字符串printf "%s\n", $1
%d整数printf "%d\n", count
%.2f两位小数printf "%.2f\n", avg
%-12s左对齐宽度 12printf "%-12s %8.2f\n", name, score
# 对齐报表
awk '
BEGIN {printf "%-12s %8s\n", "name", "score"}
NR > 1 {printf "%-12s %8.2f\n", $1, $2}
' scores.txt

# 输出 Markdown 表格
awk -F, '
BEGIN {print "|用户|金额|"; print "|---|---:|"}
NR > 1 {printf "|%s|%.2f|\n", $1, $3}
' orders.csv

# print 使用 OFS，printf 完全由格式串控制
awk 'BEGIN {OFS=","} {print $1,$2; printf "%s|%s\n", $1,$2}' data.txt
输出提醒： print a b 是字符串拼接，没有分隔符；print a, b 才会用 OFS 分隔。

11. 日志分析实战

awk 常用于临时分析日志，因为日志通常是行式记录，并包含可抽取的字段。下面示例以常见 access log 为例，真实环境要先确认字段位置和日志格式。

# 查看样本字段位置：先打印行号和每个字段
awk 'NR == 1 {for (i=1; i<=NF; i++) print i, $i}' access.log

# 统计 HTTP 状态码
awk '{code[$9]++} END {for (c in code) print c, code[c]}' access.log | sort -n

# 找出请求最多的 IP
awk '{ip[$1]++} END {for (i in ip) print ip[i], i}' access.log | sort -nr | head -10

# 统计 API 路径的 5xx
awk '$7 ~ /^\/api\// && $9 ~ /^5/ {err[$7]++} END {for (p in err) print err[p], p}' access.log | sort -nr

# 计算响应体字节数平均值，跳过 "-" 或字段缺失
awk '$10 ~ /^[0-9]+$/ {sum += $10; n++} END {if (n) printf "%.2f\n", sum/n}' access.log

面向生产的分析流程

  1. 先用 head 和 awk 'NR==1 {for ...}' 确认字段编号。
  2. 先在小样本上验证条件，避免直接扫全量大文件。
  3. 输出中间结果给 sort、uniq、head，每一步都能解释。
  4. 遇到引号、转义、嵌套结构时，不要假设空白分隔一定可靠。

12. CSV 与结构化数据 caveats

awk -F, 适合“简单逗号分隔文本”，不等于完整 CSV 解析器。标准 CSV 允许字段内包含逗号、双引号和换行，这些都会破坏简单的 FS="," 模型。

输入-F, 是否可靠原因
alice,90,A通常可靠字段中没有逗号、引号、换行
"alice, a",90,A不可靠逗号在引号内，不应作为分隔符
"a ""quote""",90,A不可靠需要处理引号转义
字段内含换行不可靠默认 RS="\n" 会把一条 CSV 记录切断
# 简单 CSV-ish 可以这样处理
awk -F, 'BEGIN {OFS=","} NR > 1 {print $1, $3}' simple.csv

# 先检测字段数是否异常
awk -F, 'NF != 5 {print "bad line", NR, "fields", NF, $0}' simple.csv

# 真正复杂 CSV 建议用 Python csv 模块、mlr、xsv 或数据库工具
python3 -c 'import csv,sys; print(sum(1 for _ in csv.reader(sys.stdin)))' < data.csv
CSV 警告： 如果数据来自 Excel、业务系统导出或外部客户，不要默认 awk -F, 能正确解析。先确认是否存在引号、字段内逗号和换行。

13. awk vs sed/cut/python

工具优势劣势适合
cut极简单、快、语义直接只能按固定分隔符/字符切割，不能复杂判断稳定分隔符下抽列
sed替换、删除、行级转换强字段计算和聚合可读性差批量替换、简单清洗
awk字段访问、条件、变量、数组、聚合强复杂解析和大型程序维护性有限日志统计、列式数据、临时报表
Python库丰富、可测试、适合复杂逻辑管道 one-liner 不如 awk 轻便CSV/JSON、复杂业务、长期脚本
# cut：只切第 1 列
cut -d, -f1 users.csv

# sed：替换域名
sed 's#old.example.com#new.example.com#g' config.txt

# awk：按字段过滤并求和
awk -F, '$4 == "paid" {sum += $3} END {print sum}' orders.csv

# Python：正确解析带引号 CSV
python3 -c 'import csv,sys; [print(r[0]) for r in csv.reader(sys.stdin)]' < users.csv
选择原则： 一行 awk 如果已经需要十几个分支、复杂转义或多人维护，通常已经超过最佳使用区间。

14. 安全处理文件与脚本化

awk 默认把结果写到标准输出，不会修改原文件。要生成新文件时使用重定向；要覆盖原文件时先写临时文件、检查结果，再移动替换。GNU awk 有 -i inplace 扩展，但可移植性不如显式临时文件流程。

# 安全预览：不修改原文件
awk -F, 'BEGIN {OFS=","} {$3 = $3 * 1.1; print}' prices.csv

# 用 diff 预览变化
awk -F, 'BEGIN {OFS=","} {$3 = $3 * 1.1; print}' prices.csv | diff -u prices.csv -

# 确认后写入新文件
awk -F, 'BEGIN {OFS=","} {$3 = $3 * 1.1; print}' prices.csv > prices.new.csv

# 覆盖前保留备份
cp prices.csv prices.csv.bak
mv prices.new.csv prices.csv

复杂 awk 写入脚本文件

cat > report.awk <<'AWK'
BEGIN {
  FS = ","
  OFS = "\t"
  print "user", "total"
}
NR > 1 && $4 == "paid" {
  sum[$1] += $3
}
END {
  for (u in sum) print u, sum[u]
}
AWK

awk -f report.awk orders.csv | sort -k2,2nr
生产警告： 不要把 awk 的输出重定向到同一个输入文件，例如 awk ... file > file。Shell 会先截断输出文件，导致数据丢失。

15. 常见坑、排障与练习

坑 1：字段编号猜错
先运行 awk 'NR==1 {for (i=1;i<=NF;i++) print i,$i}'。
坑 2：把简单 CSV 当标准 CSV
字段内逗号、引号、换行会破坏 -F,。
坑 3：print a b 没有分隔符
要用 print a, b 或 printf。
坑 4：printf 忘记换行
printf "%s\n", $1 才会每条记录一行。
坑 5：数组输出顺序不稳定
需要顺序时交给 sort 或使用 GNU awk 特性。
坑 6：空输入除以零
END {if (n) print sum/n}。
坑 7：Shell 变量拼接引号混乱
用 awk -v name="$name" '...'。
坑 8：输出重定向到原文件
awk ... file > file 会先截断文件。

排障模板

# 1. 构造最小输入
printf 'alice,90,A\nbob,72,C\n' | awk -F, '{print NR, NF, $1, $2, $3}'

# 2. 显示字段编号
awk 'NR == 1 {for (i=1; i<=NF; i++) print i, "[" $i "]"}' file.txt

# 3. 验证 pattern 是否命中
awk '$3 > 90 {print "hit", NR, $0}' scores.txt

# 4. 对文件变换做 diff
awk 'BEGIN {OFS=","} {$2=toupper($2); print}' data.csv | diff -u data.csv -
