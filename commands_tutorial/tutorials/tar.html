tar 深度教程：从归档模型到安全备份与解包

这份教程系统讲解 Linux 常用命令 tar。重点不是背 czvf，而是先建立“归档”和“压缩”分层模型，再深入掌握创建、查看、解包、gzip/xz/zstd 压缩、路径处理、--strip-components、tarbomb 安全、增量备份、管道传输、与 zip/rsync 的边界，以及生产排障方法。

一句话理解： tar 的核心工作是把多个文件和目录打包成一个“归档流”；压缩只是可选的外层编码，常由 gzip、xz、zstd 等算法完成。
最重要原则： 解压未知归档前先 tar -tf 查看内容，最好解到新建空目录；创建归档前先确认包含路径，避免把错误目录、缓存、密钥或大文件打进去。

1. tar 是什么

tar 最初是 tape archive 的缩写，用于把一组文件顺序写入磁带。今天它更多用于打包源码、备份目录、容器层、日志归档和跨机器迁移。它保留的不只是文件内容，还包括目录结构、权限、时间戳、符号链接，必要时也可以保留属主、组和特殊文件信息。

它擅长什么
把目录树保存成单个归档文件或流，适合备份、分发、迁移和管道传输。
它不等于什么
tar 本身不是压缩算法；.tar.gz 是 tar 归档再经过 gzip 压缩后的结果。
它的关键风险
解包会创建文件和目录，可能覆盖现有文件、散落大量文件，或写入意外路径。
# 创建未压缩归档
tar -cf project.tar project/

# 查看归档内容，不解包
tar -tf project.tar

# 解包到指定目录
mkdir -p /tmp/project-restore
tar -xf project.tar -C /tmp/project-restore
先看再解： 未知归档永远先用 tar -tf archive.tar* 检查路径，再决定解包目录和是否需要 --strip-components。

信息图：归档与压缩是两层不同工作

把 .tar 理解成“文件系统快照的顺序记录”，把 .gz/.xz/.zst 理解成“对这个记录流的压缩”。

2. 基本语法与模式

tar 由一个主动作加若干选项组成。常见动作互斥：创建 -c、列出 -t、解包 -x。归档文件通常用 -f 指定，详细输出用 -v。

tar [动作] [选项] -f 归档文件 [路径...]

# 三个最常见动作
tar -cf app.tar app/      # create：创建
tar -tf app.tar           # table/list：列出
tar -xf app.tar           # extract：解包
动作/选项含义说明
-c创建归档后面跟要打包的文件或目录。
-t列出归档内容安全检查未知归档的第一步。
-x解包归档建议配合 -C 解到指定目录。
-f FILE指定归档文件-f 后面必须紧跟文件名；- 表示 stdin/stdout。
-v显示处理文件可读性好，但在大归档上会产生大量输出。
-C DIR切换工作目录创建和解包时都很常用。
选项顺序提醒： 现代 tar 通常接受 tar -czf app.tar.gz app/，老式写法 tar czf app.tar.gz app/ 也常见；生产脚本中建议显式加短横线，减少歧义。

流程图：create、list、extract 三个核心动作

很多 tar 事故都来自跳过中间的检查步骤：创建后不看内容，解包前也不看路径。

3. 创建归档

创建归档时最重要的是“归档中保存什么路径”。在当前目录直接打包目录，会保存相对路径；用绝对路径打包时，GNU tar 通常会移除开头的 / 并给出提示，这是为了避免解包时写到系统根目录。

# 打包整个目录，归档内路径以 project/ 开头
tar -cf project.tar project/

# 压缩为 gzip 格式，常用于源码分发
tar -czf project.tar.gz project/

# 从 /var/log 切换目录后只归档 nginx/，避免保存绝对路径
tar -czf nginx-logs.tar.gz -C /var/log nginx/

# 查看创建结果
tar -tf nginx-logs.tar.gz | sed -n '1,20p'
目标推荐命令原因
打包目录tar -cf app.tar app/保留清晰顶层目录，解包后不散落。
打包目录内容tar -cf app-content.tar -C app .归档内从 ./ 开始，适合恢复到指定目标目录。
打包多个路径tar -cf bundle.tar README.md src/ docs/适合发布小型项目或资料包。
从文件列表创建tar -cf selected.tar -T files.txt适合精确控制包含项。
避免误打包： 不要在项目根目录随手执行 tar -czf backup.tar.gz . 而不排除 .git、缓存、依赖目录、密钥和已有归档文件。

4. 列出与检查内容

tar -t 是最便宜的安全检查。它不会写文件，只读取归档目录项。对未知来源归档，先看路径是否包含绝对路径、..、大量顶层文件、可疑属主或超大文件。

# 列出全部路径
tar -tf release.tar.gz

# 只看前 30 行，判断顶层目录结构
tar -tf release.tar.gz | sed -n '1,30p'

# 显示更详细的权限、属主、大小、时间
tar -tvf release.tar.gz | sed -n '1,30p'

# 统计归档里有多少条目
tar -tf release.tar.gz | wc -l
好归档的常见形态
大多数条目位于同一个顶层目录，如 project-1.2.0/...，解包后不会污染当前目录。
高风险形态
顶层散落很多文件、路径含 ../、看起来像绝对路径、或包含 .ssh/、系统目录、设备文件。
实用习惯： 下载源码包后先运行 tar -tf 包名 | head。如果没有统一顶层目录，就新建空目录再解。

5. 安全解包

解包是 tar 中最需要谨慎的动作，因为它会在文件系统中创建或覆盖路径。安全做法是：先列出内容，再创建空目录，最后用 -C 解进去。

# 第一步：只查看，不写入
tar -tf unknown.tar.gz | sed -n '1,40p'

# 第二步：准备隔离目录
mkdir -p /tmp/tar-check

# 第三步：解包到隔离目录
tar -xzf unknown.tar.gz -C /tmp/tar-check

# 第四步：检查结果
find /tmp/tar-check -maxdepth 2 -print | sed -n '1,40p'
命令含义推荐场景
tar -xf app.tar解包未压缩归档已知安全且当前目录合适。
tar -xzf app.tar.gz解包 gzip 压缩归档常见 .tgz/.tar.gz。
tar -xJf app.tar.xz解包 xz 压缩归档体积优先的发布包。
tar --zstd -xf app.tar.zst解包 zstd 压缩归档速度和体积均衡的现代备份。
tar -xf app.tar -C out/解到指定目录生产默认推荐。
覆盖风险： 如果归档内路径与当前目录已有文件同名，解包可能覆盖它们。未知归档不要直接在项目根目录或家目录解包。

6. gzip、xz、zstd 压缩

压缩选项决定归档流如何编码。gzip 兼容性最好，xz 压缩率高但慢，zstd 通常在速度和体积之间更均衡。现代 GNU tar 常能根据 -a 和文件后缀自动选择压缩器，但脚本中显式写选项更清楚。

格式常见后缀创建解包特点
无压缩.tartar -cf a.tar dir/tar -xf a.tar最快，体积大，可流式处理。
gzip.tar.gz / .tgztar -czf a.tar.gz dir/tar -xzf a.tar.gz兼容性好，速度快，压缩率中等。
bzip2.tar.bz2tar -cjf a.tar.bz2 dir/tar -xjf a.tar.bz2老牌格式，现在常被 xz/zstd 替代。
xz.tar.xztar -cJf a.tar.xz dir/tar -xJf a.tar.xz压缩率高，CPU 开销大。
zstd.tar.zsttar --zstd -cf a.tar.zst dir/tar --zstd -xf a.tar.zst速度很快，适合大备份和 CI 缓存。
# 让 tar 根据后缀自动压缩，GNU tar 常见可用
tar -caf app.tar.zst app/

# 指定 zstd 压缩级别，适合需要调优的备份
tar -cf - app/ | zstd -T0 -19 -o app.tar.zst

# 验证压缩包能被读取
tar -tf app.tar.zst | sed -n '1,20p'
选型建议： 对外发布优先 gzip；追求小体积用 xz；本机备份、缓存、日志归档优先考虑 zstd。

信息图：路径、-C 与 strip-components

-C 改变解包目标目录；--strip-components=N 改变归档路径落地前保留几层。

7. 路径、-C 与 --strip-components

tar 保存的是归档内路径。创建时的当前目录、传给 tar 的路径、以及 -C 会共同决定归档结构；解包时 -C 决定写入哪里，--strip-components 决定丢弃路径前几层。

# 创建：归档内保存 project/bin/app
tar -czf project.tar.gz project/

# 创建：先进入 project，再保存 ./bin/app、./conf/app.yml
tar -czf project-content.tar.gz -C project .

# 解包：写入 /opt/stage/project/...
mkdir -p /opt/stage
tar -xzf project.tar.gz -C /opt/stage

# 解包：剥掉 project/ 顶层，写入 /opt/app/bin、/opt/app/conf
mkdir -p /opt/app
tar -xzf project.tar.gz -C /opt/app --strip-components=1
需求命令结果
保留源码包顶层目录tar -xzf pkg.tar.gz -C /tmp/tmp/pkg-version/...
把内容直接部署到目标目录tar -xzf pkg.tar.gz -C /srv/app --strip-components=1/srv/app/bin、/srv/app/conf
只解包某个子目录tar -xzf pkg.tar.gz pkg/docs/ -C /tmp只还原匹配路径。
创建无绝对路径归档tar -czf etc-nginx.tar.gz -C /etc nginx归档内为 nginx/...。
不要依赖当前目录记忆： 脚本中尽量显式使用 -C 和绝对目标目录变量，避免在错误目录创建或解包。

8. 排除文件与文件列表

真实项目归档往往要排除缓存、构建产物、依赖目录、敏感文件和归档文件本身。--exclude 适合少量规则，--exclude-from 适合团队维护的规则文件，-T 适合明确列出包含项。

# 排除常见大目录和 Git 历史
tar -czf app.tar.gz app/ \
  --exclude='app/.git' \
  --exclude='app/node_modules' \
  --exclude='app/.cache'

# 使用排除规则文件
cat > tar-excludes.txt <<'EOF'
.git
node_modules
.cache
*.log
*.tar
*.tar.gz
EOF
tar -czf app.tar.gz app/ --exclude-from=tar-excludes.txt

# 从文件列表精确创建
find app -type f -name '*.conf' -print > files.txt
tar -czf configs.tar.gz -T files.txt
--exclude
快速排除少量模式；注意模式匹配归档路径。
--exclude-from
把规则版本化，适合备份脚本和发布脚本。
-T
白名单式包含，适合审计性更强的归档。
文件名安全： 如果文件名可能包含换行，GNU tar 可结合 --null -T 读取 NUL 分隔列表；普通文本列表无法安全表达所有文件名。

9. 权限、属主与特殊文件

tar 可以保存权限、时间戳、符号链接、硬链接、属主、组名和设备文件等元数据。普通用户解包时通常只能恢复自己有权限设置的部分；root 解包时风险更高，因为可能恢复属主、设备节点或覆盖系统路径。

主题默认行为常用控制
权限模式归档会记录权限，解包受 umask 和权限限制影响。--same-permissions 或 -p 尽量恢复权限。
属主/组归档记录名字和数字 ID；非 root 通常不能随意设置。--numeric-owner 按数字 ID 显示/恢复。
时间戳通常保存并恢复 mtime。--mtime 可用于可复现归档。
符号链接默认归档链接本身，不跟随链接目标。-h/--dereference 跟随符号链接。
特殊文件root 备份系统时可能包含设备、FIFO 等。未知归档不要以 root 直接解包。
# 查看权限和属主信息
tar -tvf backup.tar | sed -n '1,20p'

# 以数字 UID/GID 显示，排查跨机器属主问题
tar --numeric-owner -tvf backup.tar | sed -n '1,20p'

# 创建尽量可复现的源码归档示例
tar --sort=name --mtime='UTC 2024-01-01' --owner=0 --group=0 --numeric-owner \
  -czf source.tar.gz source/
root 解包警告： 只有在信任归档来源并明确需要恢复系统元数据时，才用 root 解包。否则先用普通用户在隔离目录检查。

10. tarbomb 与未知归档安全

tarbomb 指解包后大量文件直接散落到当前目录，或通过恶意路径造成覆盖、污染甚至安全问题。现代 tar 对绝对路径和 .. 有一定防护，但安全流程仍应由使用者保证。

# 安全检查模板：先看顶层结构
tar -tf unknown.tar.gz | sed -n '1,60p'

# 查看是否多顶层散落
tar -tf unknown.tar.gz | awk -F/ '{print $1}' | sort -u | sed -n '1,30p'

# 解到新建目录，避免污染当前位置
mkdir -p /tmp/unpack-unknown
tar -xzf unknown.tar.gz -C /tmp/unpack-unknown

# 如果归档有统一顶层目录，且你只想要其内容
mkdir -p /tmp/unpack-content
tar -xzf unknown.tar.gz -C /tmp/unpack-content --strip-components=1
安全信号
有单一顶层目录；路径不含 ..；没有绝对路径；文件数量和大小合理；没有意外敏感路径。
危险信号
直接包含 .bashrc、.ssh/、etc/、大量散落文件、奇怪链接、设备文件或覆盖性路径。
覆盖控制： GNU tar 提供 --keep-old-files、--skip-old-files、--warning 等选项，但最可靠的默认策略仍是解到空目录。

安全图：未知归档解包决策

未知归档的默认策略：查看、隔离、再解包。不要在重要目录里直接试错。

11. 备份与恢复策略

tar 很适合做目录级备份，但备份不是只创建一个文件。可靠备份至少包括：明确范围、排除规则、压缩选择、校验、恢复演练和保留策略。

# 一次性备份 /etc/nginx，归档内从 nginx/ 开始
backup="nginx-$(date +%F).tar.zst"
tar --zstd -cf "$backup" -C /etc nginx

# 生成校验和
sha256sum "$backup" > "$backup.sha256"

# 验证归档可读
tar --zstd -tf "$backup" | sed -n '1,20p'

# 恢复演练到临时目录
mkdir -p /tmp/restore-nginx
tar --zstd -xf "$backup" -C /tmp/restore-nginx

增量备份

GNU tar 支持 --listed-incremental 记录快照状态，实现增量备份。它适合熟悉 GNU tar 语义的环境；如果团队不熟，恢复链复杂时应考虑专业备份系统。

# 第一次：完整备份，并写入快照文件
tar --listed-incremental=backup.snar -czf home-full.tar.gz /home/alice

# 后续：基于同一个 snar 文件创建增量包
tar --listed-incremental=backup.snar -czf home-inc-$(date +%F).tar.gz /home/alice

# 恢复时通常按完整包、增量包时间顺序依次解包到目标目录
备份现实： 没有恢复演练的备份只能算“希望”。至少定期用 tar -tf 和临时目录恢复测试验证归档可用。

12. 管道、远程复制与流式处理

tar 可以把归档写到 stdout，也可以从 stdin 读取归档。使用 -f - 时，tar 变成管道中的一环，非常适合目录复制、远程传输和边生成边压缩。

# 本机目录复制：保留权限和链接，比 cp 管道更适合复杂树
mkdir -p /tmp/app-copy
tar -cf - -C app . | tar -xf - -C /tmp/app-copy

# 边打包边用 zstd 压缩
tar -cf - app/ | zstd -T0 -o app.tar.zst

# 从 zstd 压缩流解包
zstd -dc app.tar.zst | tar -xf - -C /tmp/restore

# 远程复制目录，先在测试目录验证目标路径
ssh host 'mkdir -p /tmp/app-restore'
tar -cf - app/ | ssh host 'tar -xf - -C /tmp/app-restore'
管道优势
不需要中间归档文件，可边读边写，适合大目录、远程传输和容器构建场景。
管道风险
错误会跨机器放大。远程解包前先确认目标目录，必要时加 set -e 和恢复检查。
迁移建议： 一次性同机/跨机复制可用 tar 管道；长期同步、断点续传、差异更新应优先考虑 rsync。

13. tar vs zip vs rsync

这些工具解决的问题相邻但不相同。tar 偏向 Unix 文件树归档，zip 偏向跨平台单文件压缩包，rsync 偏向目录同步和增量传输。

工具核心模型优势短板适合场景
tar把文件树串成归档流，可外接压缩。保留 Unix 元数据好，管道能力强。随机访问差，解包需注意路径风险。源码包、系统备份、容器层、日志归档。
zip每个文件独立压缩并带目录索引。Windows/macOS 用户直接可用，单文件访问方便。Unix 权限/链接语义不如 tar 自然。面向普通用户分发文档、图片、轻量项目。
rsync比较源和目标，只同步差异。增量、高效、可删除目标多余文件。不是归档格式，需要源/目标两端参与。持续部署、备份同步、跨机器目录镜像。
# 发布给 Linux 用户：tar.gz 常见
tar -czf tool-1.0.0.tar.gz tool-1.0.0/

# 发布给普通桌面用户：zip 更友好
zip -r docs.zip docs/

# 同步目录：rsync 比反复 tar 全量更合适
rsync -a --delete app/ deploy:/srv/app/
决策口诀： “保存一个 Unix 目录树”选 tar；“发给不懂命令行的人”选 zip；“反复同步两个目录”选 rsync。

14. 常见错误与排障

错误：Cannot open: No such file
检查 -f 后面的归档文件名是否正确，当前目录是否正确。
错误：This does not look like a tar archive
可能文件损坏、格式不是 tar，或压缩层没有正确解开。
错误：gzip: stdin: not in gzip format
用了 -z 解非 gzip 归档。先用 file archive 或按后缀判断。
错误：Unexpected EOF
归档可能下载不完整或传输中断。重新获取并校验哈希。
问题：解包后多了一层目录
使用 --strip-components=1，但先确认归档结构。
问题：解包后文件散落
这是 tarbomb 风险。下次先解到空目录。
问题：权限/属主不对
检查是否以 root 解包、是否需要 -p 或 --numeric-owner。
问题：归档包含自己导致变大
创建归档时输出文件在被打包目录内，应放到目录外或 --exclude。

排障模板

# 1. 判断文件类型
file archive.tar.gz

# 2. 不解包，只列目录
tar -tf archive.tar.gz | sed -n '1,40p'

# 3. 详细列出元数据
tar -tvf archive.tar.gz | sed -n '1,40p'

# 4. 测试解到空目录
rm -rf /tmp/tar-debug && mkdir -p /tmp/tar-debug
tar -xf archive.tar.gz -C /tmp/tar-debug

# 5. 检查结果
find /tmp/tar-debug -maxdepth 3 -print | sed -n '1,80p'
排障底线： 不要为了“看看能不能解”而在生产目录执行 tar -xf。先列出，再隔离解包。

15. 生产清单与练习

创建归档前

  • 确认归档范围：是目录本身，还是目录内容。
  • 确认输出文件不在被归档目录内，或已用 --exclude 排除。
  • 确认是否需要排除缓存、依赖、日志、密钥和临时文件。
  • 创建后立刻 tar -tf 检查前几十行和条目数量。

解包归档前

  • 先 tar -tf 查看路径结构。
  • 未知归档解到新建空目录。
  • 需要部署到目标目录时，先在临时目录验证 --strip-components。
  • 尽量不要以 root 解包未知归档。

练习任务

  1. 创建一个测试目录，分别生成 .tar、.tar.gz、.tar.xz。
  2. 用 tar -tf 比较“打包目录”和“打包目录内容”的路径差异。
  3. 创建带统一顶层目录的归档，再用 --strip-components=1 解到空目录。
  4. 写一个 tar-excludes.txt，排除 .git、node_modules、*.log。
  5. 用 tar 管道把一个目录复制到 /tmp 下，并比较文件数量。
# 练习环境
rm -rf /tmp/tar-demo /tmp/tar-demo-out
mkdir -p /tmp/tar-demo/project/{bin,conf,logs}
printf '#!/bin/sh\necho hello\n' > /tmp/tar-demo/project/bin/app
printf 'port=8080\n' > /tmp/tar-demo/project/conf/app.conf
printf 'debug log\n' > /tmp/tar-demo/project/logs/app.log

# 创建带排除规则的归档
tar -czf /tmp/tar-demo/project.tar.gz -C /tmp/tar-demo project --exclude='project/logs'

# 检查并解包
tar -tf /tmp/tar-demo/project.tar.gz
mkdir -p /tmp/tar-demo-out
tar -xzf /tmp/tar-demo/project.tar.gz -C /tmp/tar-demo-out

16. 速查表

任务命令备注
创建 tartar -cf app.tar app/未压缩，速度快。
创建 tar.gztar -czf app.tar.gz app/最常见、兼容性好。
创建 tar.xztar -cJf app.tar.xz app/体积小，速度慢。
创建 tar.zsttar --zstd -cf app.tar.zst app/现代备份常用。
列出内容tar -tf app.tar.gz解包前必做。
详细列出tar -tvf app.tar.gz看权限、属主、大小。
解到目录tar -xzf app.tar.gz -C out/安全默认做法。
剥掉顶层目录tar -xzf app.tar.gz -C out/ --strip-components=1先确认路径结构。
排除目录tar -czf app.tar.gz app/ --exclude='app/.git'模式匹配归档内路径。
从列表创建tar -czf selected.tar.gz -T files.txt适合白名单归档。
管道复制tar -cf - -C src . | tar -xf - -C dst保留目录树元数据。
测试恢复mkdir out && tar -xf backup.tar -C out备份验证关键步骤。
最小心智模型： -c 创建，-t 查看，-x 解包；-f 指文件；-C 控制目录；-z/-J/--zstd 控制压缩层。
