1. 为什么模型量化如此重要？

对深度学习部署而言，瓶颈通常不只是算力，而是显存容量、显存带宽、KV Cache、批处理吞吐和端侧功耗。 量化的基本目标是：让模型用更少的 bit 表示权重和激活，从而降低存储与搬运成本；如果硬件有对应低精度 kernel，还能降低计算延迟。

显存容量

70B 参数模型若用 FP16 权重，单权重约 2 bytes，仅权重就约 140GB；INT4 理想情况下约 35GB，但还要加 scales、zero-points、KV cache、运行时 buffer。

显存带宽

推理时大量层是矩阵乘。权重越小，每次从显存搬运的数据越少。很多场景下，速度提升来自“少搬数据”而不只是“低精度乘法更快”。

部署可达性

量化让原本必须多卡运行的模型，有机会在单卡、消费级 GPU、边缘设备、手机或 CPU 上运行。

关键提醒：量化不是“越低 bit 越好”。低 bit 会放大离群值、范围估计错误、层间误差积累、kernel 不匹配等问题。工程上要以“任务质量 + 延迟 + 显存 + 稳定性”联合验收。

2. 第一性原理：量化到底在做什么？

2.1 从实数到格点：Scale 与 Zero-point

神经网络中的权重和激活通常是浮点数。量化把连续浮点值压到有限个离散整数格点中。最常见的是线性量化：

\[ q = \operatorname{clip}\left(\operatorname{round}\left(\frac{x}{s}\right) + z,\ q_{\min}, q_{\max}\right) \] \[ \hat{x} = s \cdot (q - z) \]

其中 \(x\) 是原始浮点值，\(q\) 是整数值，\(s\) 是 scale，\(z\) 是 zero-point，\(\hat{x}\) 是反量化后的近似值。 ONNX Runtime 文档中也把 8-bit 线性量化表述为 \(val_{fp32}=scale \times (val_{quantized}-zero\_point)\)。

图：量化误差来自“连续值被迫落到有限格点”。

2.2 对称量化 vs 非对称量化

类型形式优点缺点常见用途
对称量化 \(z=0\)，范围大致为 \([-a,a]\) 计算简单，kernel 友好 如果分布偏移明显，会浪费一侧区间 权重 per-channel / per-group 量化
非对称量化 \(z \ne 0\)，范围 \([x_{\min},x_{\max}]\) 能覆盖偏移分布 zero-point 处理会增加计算复杂度 激活量化、CPU / ONNX 部署

2.3 Per-tensor、Per-channel、Group-wise

scale 的粒度决定误差与元数据开销。一个 tensor 共用一个 scale 最省，但误差大；每个通道一个 scale 更准；LLM INT4 常用 group-wise，例如每 128 个权重共享一组 scale。

Per-tensor

整个矩阵一个 scale。元数据最少，但如果某一列有离群值，会压扁其他值的有效分辨率。

Per-channel

每个输出通道一个 scale。CNN 和 Linear 权重量化常用，精度更稳。

Group-wise

每组若干元素一个 scale。LLM INT4 常用，兼顾精度、压缩率和 kernel 访问模式。

2.4 误差从哪里来？

\[ \epsilon = x - \hat{x} \] \[ y = Wx,\quad \hat{y} = \hat{W}\hat{x},\quad y-\hat{y} = (W-\hat{W})x + W(x-\hat{x}) + (W-\hat{W})(x-\hat{x}) \]

权重误差、激活误差、二者交互误差会沿网络传播。深层 Transformer 中，LayerNorm、Attention projection、MLP up/gate/down projection、KV cache 都可能成为误差放大点。

4. PTQ：后训练量化

PTQ 的思想是：不重新训练或只做少量校准，就把已有模型转换成低精度模型。它是工业部署中最常见的第一选择。 

flowchart LR
    A[FP16/FP32 原模型] --> B[准备校准集]
    B --> C[收集权重/激活统计]
    C --> D[选择量化粒度
per-tensor / per-channel / group]
    D --> E[计算 scale / zero-point]
    E --> F[插入 Q/DQ 或打包低精度权重]
    F --> G[离线评测]
    G --> H{指标达标?}
    H -- 是 --> I[导出部署格式]
    H -- 否 --> J[调整校准集/粒度/排除层/混合精度]
    J --> C
流程图：PTQ 的核心循环是“校准—转换—评测—回退/调参”。

4.1 校准集的作用

校准集不是训练集，而是用来估计激活范围、离群值、scale 和 clipping 阈值的小样本集合。校准集必须代表真实输入分布： 聊天模型要覆盖常见 prompt 长度、语言、格式；VLM 要覆盖图片尺寸和视觉域；检测模型要覆盖真实场景光照、尺度和类别。

好的校准集

  • 覆盖线上输入长度、语言、格式。
  • 包含难样本和长尾样本。
  • 样本量不必巨大，但分布必须贴近生产。
  • 和评测集隔离，避免过拟合校准。

坏的校准集

  • 只用短 prompt 校准长上下文模型。
  • 只用英文校准中文业务模型。
  • 只用干净图片校准桌面/监控/低光场景。
  • 拿线上验收集反复调参导致虚高。

5. QAT：量化感知训练

QAT 在训练或微调期间模拟量化误差，让模型学会适应低精度。它通常比 PTQ 更稳，尤其适合 INT8 激活量化、极低 bit、检测/分割等对数值敏感的模型。

    participant Opt as 优化器

    Data->>FP: 前向传播输入

5.1 Fake Quantization

FakeQuant 的前向过程通常是“量化再反量化”，使计算图仍能在浮点框架中训练：

\[ \operatorname{FakeQuant}(x)=s\cdot\left(\operatorname{clip}\left(\operatorname{round}\left(\frac{x}{s}\right)+z,q_{\min},q_{\max}\right)-z\right) \]

难点在于 round 不可导，所以常用 Straight-Through Estimator（STE）：反向传播时近似把量化函数当作恒等映射。

5.2 什么时候需要 QAT？

经验规则：如果 PTQ 后任务指标下降在可接受范围内，就优先 PTQ；如果低 bit 后出现明显退化，或者模型用于检测、OCR、语音、视觉几何等数值敏感任务，再考虑 QAT。
情况建议
分类/Embedding 模型 INT8 后几乎不掉点直接 PTQ，避免额外训练成本
检测模型 mAP 明显下降QAT 或混合精度保护首尾层、检测头
LLM INT4 后数学/代码能力下降换校准集、AWQ/GPTQ 参数；必要时 LoRA 修复
端侧必须 INT8 全图加速QAT 通常更可靠

6. LLM 专用量化：为什么比 CNN 更难？

LLM 的量化难点主要来自：激活离群值、长上下文 KV cache、层数深导致误差累积、生成式任务评测难、低 bit kernel 与推理引擎强绑定。

信息图：LLM 的大部分参数在 Linear 层，但激活离群值和 KV cache 决定了量化难度。

6.1 LLM.int8：把离群通道单独保护

LLM.int8 的关键发现是 Transformer 中存在对预测很重要的离群特征。它使用向量级量化处理大多数值，同时把离群维度拆出来用较高精度计算；论文称超过 99.9% 的值仍可在 8-bit 路径中处理。

6.2 GPTQ：基于近似二阶信息的一次性权重量化

GPTQ 面向 GPT 类生成模型，目标是最小化量化前后层输出差异。直觉上，某个权重能不能粗糙量化，不只取决于它自身大小，还取决于输入激活分布以及该权重对输出误差的影响。

\[ \arg\min_{\hat{W}}\ \|WX-\hat{W}X\|_2^2 \]

这里 \(W\) 是原始权重，\(\hat{W}\) 是量化权重，\(X\) 是校准输入激活。GPTQ 使用近似 Hessian 信息来决定量化顺序与误差补偿。

6.3 AWQ：Activation-aware Weight Quantization

AWQ 的核心不是“保护最大的权重”，而是利用激活统计找出对输出更关键的通道。AWQ 论文指出，保护少量显著权重/通道可以显著降低量化误差，并通过等价缩放使实现更硬件友好。 

flowchart LR

    B --> C[找出显著通道
activation-aware]
    C --> D[搜索缩放因子]
    D --> E[等价变换保护关键通道]

流程图：AWQ 通过激活分布判断哪些权重通道更值得保护。

6.4 SmoothQuant：把激活量化难度迁移给权重

LLM 中“权重量化相对容易，激活量化更难”是常见现象。SmoothQuant 的核心思想是用数学等价变换把激活离群值压力转移到权重上，从而支持 W8A8 量化。

\[ Y = XW = (X \operatorname{diag}(s)^{-1})(\operatorname{diag}(s) W) \]

这个变换不改变浮点结果，但改变了激活与权重的数值分布，使激活更容易被 INT8 量化。

6.5 QLoRA / NF4：训练不是直接训练 4-bit 权重

QLoRA 通常把基础模型权重量化为 4-bit 并冻结，只训练 LoRA adapter。NF4 是面向近似正态分布权重设计的 4-bit 类型，常用于 4-bit 微调。

实战判断：如果目标是“显存够用并做 LoRA 微调”，优先 bitsandbytes 4-bit NF4；如果目标是“部署推理”，优先考虑 AWQ/GPTQ/GGUF/引擎原生格式；如果目标是“高吞吐服务”，要看 vLLM、TensorRT-LLM、SGLang、TGI 等运行时对具体格式的 kernel 支持。

7. 格式、kernel 与推理引擎：量化能不能快，取决于谁来执行

很多量化模型“显存小了但速度没变快”，原因是实际执行时仍然要反量化回 FP16，或者使用的推理引擎没有对应低精度 kernel。

存储格式

权重以 INT4/NF4/GGUF/AWQ/GPTQ 等方式打包，主要影响磁盘和显存占用。

计算 kernel

真正决定速度的是 MatMul/Attention/MLP 是否用低精度或融合 kernel 执行。

调度引擎

vLLM、TensorRT-LLM、ONNX Runtime、llama.cpp、MLX 等负责图优化、batching、KV cache 和设备调度。

常见误区：“模型文件小 4 倍”不等于“推理快 4 倍”。如果瓶颈在采样、KV cache、Python 调度、网络传输、batch 太小、反量化 kernel，实际速度提升会小很多。

8.3 第三步：层级回退策略

当量化后质量不达标，不要盲目换模型。优先按下面顺序排查：

  1. 评测是否可靠：评测集是否覆盖真实场景？生成采样参数是否一致？
  2. 校准是否匹配：prompt 长度、图片分辨率、语言、领域是否匹配？
  3. 粒度是否太粗：从 per-tensor 改 per-channel / group-wise。
  4. 敏感层是否需要保留高精度：embedding、lm_head、首尾层、LayerNorm、检测头。
  5. bit 是否过低：INT4 不行就试 INT8 / FP8 / 混合精度。
  6. 后端 kernel 是否正确：确认不是被 silent fallback 到慢路径或错误路径。

9. 评测与验收：如何判断量化成功？

质量评测

  • 分类：Accuracy、F1、AUC。
  • 检测：mAP、Recall、误检/漏检分析。
  • Embedding：Recall@K、MRR、NDCG。
  • LLM：perplexity、MT-Bench、MMLU、GSM8K、HumanEval、业务集、人工盲测。
  • VLM：OCR、定位、问答、多图、多模态推理。

性能评测

  • 单请求：TTFT、TPOT、P50/P95/P99。
  • 吞吐：tokens/s、requests/s、batch scaling。
  • 资源：峰值显存、显存碎片、CPU RAM、功耗。
  • 稳定：长上下文、并发、长时间 soak test。
  • 成本：每 1M tokens 成本、每图成本。

9.2 LLM 评测要避免的坑

  • 只看 perplexity 不够：生成式模型可能 perplexity 变化小，但代码、数学、工具调用、中文指令能力下降。
  • 采样参数要固定：temperature、top_p、max_tokens、system prompt 不一致会掩盖量化影响。
  • 注意长上下文：短 prompt 达标不代表长上下文和 KV cache 量化达标。
  • 人工评测要盲测：避免评测者知道哪一个是量化模型。

10. 实战代码模板

10.1 Transformers + bitsandbytes：4-bit NF4 加载

适合快速节省显存、做 QLoRA 微调或本地推理实验。

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

model_id = "your-org/your-model"

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",              # QLoRA 常用
    bnb_4bit_compute_dtype=torch.bfloat16,  # Ampere+ 通常可用 bf16
    bnb_4bit_use_double_quant=True          # 二次量化，进一步省显存
)

tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    quantization_config=bnb_config,
    device_map="auto",
    trust_remote_code=True
)

prompt = "解释一下模型量化的核心思想。"
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
out = model.generate(**inputs, max_new_tokens=256)
print(tokenizer.decode(out[0], skip_special_tokens=True))

10.2 GPTQ：校准式 4-bit 权重量化思路

适合 LLM 推理部署。Transformers 当前 GPTQ 文档建议使用 GPT-QModel 后端。

from transformers import AutoModelForCausalLM, AutoTokenizer, GPTQConfig

    bits=4,

    tokenizer=tokenizer

model = AutoModelForCausalLM.from_pretrained(
    model_id,
    quantization_config=gptq_config,
    device_map="auto"

model.save_pretrained("./model-gptq-int4")
tokenizer.save_pretrained("./model-gptq-int4")

11. 故障排查：量化后变慢、变笨、崩溃怎么办？

flowchart TD
    A[量化后异常] --> B{质量下降?}
    A --> C{速度没提升?}
    A --> D{显存没下降?}
    A --> E{运行崩溃?}

    B --> B1[检查评测一致性]
    B1 --> B2[换业务校准集]
    B2 --> B3[排除敏感层/混合精度]
    B3 --> B4[提高 bit 或 QAT]

    C --> C1[确认是否真实低精度 kernel]
    C1 --> C2[检查 batch / prompt 长度 / KV cache]
    C2 --> C3[检查反量化瓶颈]
    C3 --> C4[换后端: vLLM/TensorRT-LLM/GGUF/ONNX EP]

    D --> D1[检查是否只量化部分层]
    D1 --> D2[统计 scales/KV/cache/buffer]
    D2 --> D3[确认 device_map 和 dtype]

    E --> E1[版本兼容]
    E1 --> E2[算子不支持]
    E2 --> E3[NaN/Inf/溢出]
    E3 --> E4[回退到 FP16 对照]
故障排查图：先区分是质量、速度、显存还是稳定性问题，再定位到校准、kernel、后端或格式。

11.1 量化后质量下降

  • 先看输入分布：校准集是不是太短、太干净、太单一？
  • 再看敏感层：embedding、lm_head、LayerNorm、首尾层、检测头可先保留 FP16。
  • 再看粒度：per-tensor 改 per-channel / group-wise；group size 从 128 改 64 可能更稳但更占内存。
  • 最后看方法：换 GPTQ/AWQ/SmoothQuant/QAT，而不是只调一个 scale。

11.2 量化后速度没提升

  • 模型可能只是“低精度存储”，计算时仍反量化到 FP16。
  • batch 太小，Python overhead 或采样开销掩盖了 kernel 提升。
  • attention / KV cache / sampling 才是瓶颈，不是 MLP 权重读取。
  • 推理后端没有使用对应量化 kernel。
  • CPU/GPU 之间发生隐式拷贝，或者部分层 fallback。

11.3 量化后显存没降多少

LLM 显存不只有权重，还包括 KV cache、activation buffer、CUDA graph buffer、allocator fragmentation、temporary workspace、LoRA adapter、embedding/lm_head 高精度部分。

排查命令建议：记录加载前后、首 token 后、生成中、生成结束后的显存；同时固定 batch size、输入长度、输出长度。只看一次 nvidia-smi 峰值很容易误判。

13.1 最小可行实验设计

  1. 选一个 FP16/BF16 基线模型，记录质量、显存、延迟。
  2. 准备 100～1000 条代表性校准/验证样本；LLM 至少覆盖短、中、长 prompt。
  3. 先试保守量化：INT8 或 W4A16；不要一开始就全图 INT4。
  4. 固定采样参数和硬件环境，对比输出差异。
  5. 记录每个版本的：量化方法、bit、group size、校准集、排除层、引擎、commit hash。
  6. 只在“质量 + 性能 + 稳定性”同时达标时进入灰度。

14. 术语表

术语解释
Scale浮点值与整数格点之间的比例因子。
Zero-point让真实零值映射到某个整数点的偏移。
Calibration用代表性样本估计量化范围、激活分布、缩放因子。
PTQ训练后量化，不重新训练或仅少量校准。
QAT量化感知训练，在训练中模拟量化误差。
Weight-only只量化权重，激活通常保持 FP16/BF16。
W8A8权重 8-bit，激活 8-bit。
W4A16权重 4-bit，激活 16-bit。
Group size每多少个权重共享一组 scale/zero-point。
Outlier数值分布中的异常大值，常导致量化范围被拉大。
KV Cache自回归 LLM 推理时缓存历史 token 的 Key/Value，长上下文时显存占用明显。
Q/DQQuantize / Dequantize 节点，用于显式表达量化图。
