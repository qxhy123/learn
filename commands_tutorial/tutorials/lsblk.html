1. lsblk 是什么

lsblk 来自 util-linux 工具集，用来列出 Linux 块设备。它读取内核和 udev 暴露的信息，并按父子关系显示磁盘、分区、设备映射器、软件 RAID、LVM、加密层和挂载点。

它回答的问题
哪块盘存在？分区如何挂载？训练数据目录落在哪个块设备？某个 LVM 卷背后是什么 NVMe？
它不负责的问题
它不测实时吞吐、不读 SMART 健康细节、不显示完整 NVMe 控制器日志，也不会修复文件系统。
AI Infra 价值
训练节点通常有本地 NVMe、系统盘、网络盘、RAID、LVM 和容器挂载。lsblk 是把这些层次串起来的入口。
# 默认树状输出
lsblk

# 推荐的 AI Infra 盘点视图
lsblk -o NAME,TYPE,SIZE,FSTYPE,FSUSED,FSAVAIL,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED

# 文件系统、UUID、挂载点视图
lsblk -f

# 拓扑和队列参数视图
lsblk -t
注意： lsblk 输出是当前系统视图。热插拔、云盘 attach、udev 延迟、容器命名空间、LVM 激活状态都会影响你看到的结果。

信息图：lsblk 展示的是块设备树

不要把 lsblk 当成“磁盘列表”。它真正强的是树：上层目录、文件系统、映射卷和底层物理盘之间的关系。

2. 快速上手：常用命令组合

生产环境不要依赖默认输出。默认列会因版本和发行版不同而变化，脚本和巡检要显式指定 -o 列。

命令用途AI Infra 场景
lsblk看树状块设备关系快速判断机器是否识别到本地盘和云盘
lsblk -f看文件系统、LABEL、UUID、挂载点确认数据盘是否格式化、是否挂载到预期目录
lsblk -t看 I/O 拓扑和队列参数核对 NVMe 队列、对齐、最小/最佳 I/O 粒度
lsblk -JJSON 输出自动化盘点、资产上报、训练作业预检
lsblk -p显示完整设备路径脚本中避免 sda、nvme0n1 名称歧义
lsblk -S列出 SCSI 设备SAS/SATA/JBOD 服务器盘点
# 显式列出训练节点常用字段
lsblk -o NAME,KNAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED

# 只看真实磁盘，排除 loop 设备，显示完整路径
lsblk -p -e 7 -o NAME,TYPE,SIZE,MODEL,SERIAL,ROTA

# 看某个设备的完整层次
lsblk /dev/nvme0n1

# 不显示树，便于脚本 grep/awk
lsblk -n -r -o NAME,TYPE,SIZE,MOUNTPOINTS
字段选择原则： 面向人阅读用树状输出；面向脚本用 -J 或 -P；面向变更审查显式包含 MODEL、SERIAL、WWN、UUID。

3. 输出列：NAME、TYPE、SIZE、MODEL、ROTA

理解列含义比背选项更重要。AI 训练节点上的磁盘经常名字相似，但介质、用途和可靠性完全不同。

列含义判断价值
NAME/KNAME设备名和内核设备名识别树节点，注意重启后 sdb 可能变
TYPEdisk、part、raid、lvm、crypt、rom、loop 等判断是物理盘、分区还是映射层
SIZE设备大小核对采购规格、云盘规格、训练缓存容量
MODEL/VENDOR厂商和型号区分本地 NVMe、企业 SSD、SATA HDD、虚拟云盘
SERIAL/WWN序列号或全球唯一名资产绑定、坏盘定位、工单沟通
ROTA是否旋转介质，0 常见于 SSD/NVMe，1 常见于 HDD粗略判断磁盘类型，但不要把它当健康或性能结论
SCHED当前 I/O scheduler核对 NVMe 常用调度策略和发行版默认配置
# 重点看“设备身份”
lsblk -o NAME,TYPE,SIZE,MODEL,SERIAL,WWN,ROTA,SCHED

# 示例输出片段
# NAME        TYPE   SIZE MODEL                 SERIAL       ROTA SCHED
# nvme0n1     disk   3.5T P4510 NVMe SSD        PHMB12340001    0 none
# nvme1n1     disk   3.5T P4510 NVMe SSD        PHMB12340002    0 none
# sda         disk 447.1G SATADOM               SYS00001        0 mq-deadline
# md0         raid0  7.0T                                      0
不要只看设备名： /dev/sdb 不是稳定身份。做资产和挂载策略时优先使用 /dev/disk/by-id/、UUID、LABEL、序列号或 WWN。

4. 文件系统与挂载点：-f、-m、MOUNTPOINTS

lsblk -f 适合回答“这个块设备是否已经有文件系统、UUID 是什么、挂在哪里”。新版本中 MOUNTPOINTS 能显示多挂载点，避免旧 MOUNTPOINT 只能显示一个位置的误判。

字段含义生产解读
FSTYPE文件系统类型，如 xfs、ext4、swap、LVM2_member判断是否可直接挂载，或只是 LVM/RAID 成员
FSVER文件系统版本排查老内核、老 xfs/ext 特性兼容问题
LABEL文件系统标签适合标记 datasets、scratch、checkpoints
UUID文件系统 UUID/etc/fstab 中比设备名更稳定
FSAVAIL/FSUSE%可用空间和使用率训练任务预检和容量告警
MOUNTPOINTS一个设备可能对应多个挂载点识别 bind mount、容器 runtime、重复挂载
# 文件系统视图
lsblk -f

# 面向训练数据盘的容量视图
lsblk -o NAME,TYPE,SIZE,FSTYPE,FSAVAIL,FSUSE%,MOUNTPOINTS

# 结合 findmnt 看挂载选项
findmnt -no SOURCE,FSTYPE,OPTIONS,TARGET /mnt/datasets
格式化前检查： 如果 FSTYPE 非空、MOUNTPOINTS 非空，或 TYPE 是 lvm/raid/crypt 的一部分，不要直接 mkfs。先确认它不是已有数据、RAID 成员或业务挂载。

流程图：lsblk -t 如何辅助判断 I/O 拓扑

lsblk -t 适合解释“块设备栈看起来是否合理”，但吞吐、延迟、队列拥塞要继续用性能和健康工具验证。

5. 块设备拓扑：lsblk -t

-t 展示拓扑字段，常用于确认分区对齐、扇区大小、I/O 粒度、设备队列能力。AI 训练中的大文件顺序读、checkpoint 写入、shuffle 小文件读都会受到底层拓扑和队列策略影响。

字段常见含义排障价值
ALIGNMENT对齐偏移非零可能提示分区或映射层对齐问题
MIN-IO设备最小 I/O 大小理解小请求放大和 RAID 条带影响
OPT-IO最佳 I/O 大小为大块顺序读写和文件系统参数提供线索
PHY-SEC/LOG-SEC物理/逻辑扇区大小排查 512e、4Kn 兼容性和旧工具问题
ROTA是否旋转介质训练数据热路径不应意外落到 HDD
SCHEDI/O 调度器核对 NVMe 上是否为 none、mq-deadline 等预期策略
RQ-SIZE请求队列大小解释高并发数据加载时的队列行为线索
# 拓扑视图
lsblk -t

# 更聚焦地看队列和调度器
lsblk -o NAME,TYPE,SIZE,ROTA,SCHED,RQ-SIZE,MIN-IO,OPT-IO,PHY-SEC,LOG-SEC

# 如果怀疑分区对齐，配合 parted 只读检查
parted /dev/nvme0n1 align-check optimal 1
AI 训练解读： lsblk -t 不会告诉你“快不快”，但能告诉你“为什么可能不快”：比如训练数据路径落到旋转盘、RAID/LVM 栈暴露的最佳 I/O 粒度异常、或 scheduler 与平台基线不一致。

6. AI 训练节点的磁盘盘点流程

训练节点上线前，建议把 lsblk 当成硬件和文件系统验收的一部分：先确认系统识别到了所有预期设备，再确认数据路径挂载到正确层次，最后记录稳定身份。

推荐盘点顺序

  1. 列出所有块设备，排除 loop 设备。
  2. 识别系统盘、训练数据盘、checkpoint 盘、临时 scratch 盘。
  3. 核对型号、序列号、容量、ROTA、scheduler。
  4. 核对文件系统、UUID、挂载点、容量余量。
  5. 把 lsblk -J 结果写入节点资产记录或预检报告。
# 上线验收：不要省略关键身份列
lsblk -e 7 -o NAME,TYPE,SIZE,FSTYPE,FSAVAIL,FSUSE%,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED

# 只看候选数据盘
lsblk -e 7 -o NAME,TYPE,SIZE,MOUNTPOINTS,MODEL,SERIAL | grep -E 'datasets|scratch|checkpoint|nvme|md'

# 保存快照，便于变更前后对比
lsblk -J -O > /var/tmp/lsblk-$(hostname)-$(date +%F-%H%M%S).json
验收基线： 每台训练节点至少记录：设备路径、稳定 ID、容量、挂载点、文件系统、用途、是否本地盘、是否 RAID/LVM 成员、是否可丢弃重建。

7. NVMe 设备识别

NVMe 命名通常形如 /dev/nvme0n1，分区形如 /dev/nvme0n1p1。多盘训练节点中，nvme0n1 的编号不应作为长期身份，因为重启、热插拔或 BIOS/PCIe 拓扑变化可能改变枚举顺序。

目标命令说明
看 NVMe 盘基本身份lsblk -d -o NAME,SIZE,MODEL,SERIAL,ROTA,SCHED-d 只显示整盘，不展开分区
看稳定路径ls -l /dev/disk/by-id/ | grep nvme用于 fstab、资产系统和坏盘定位
看控制器信息nvme listlsblk 的补充，不是替代
看健康和温度nvme smart-log /dev/nvme0需要 nvme-cli，关注 media errors、temperature、available spare
# 列出所有 NVMe namespace 和挂载关系
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL | grep -E 'NAME|nvme'

# 只看整盘，避免被分区刷屏
lsblk -d -o NAME,SIZE,MODEL,SERIAL,ROTA,SCHED /dev/nvme*n1

# 交叉验证稳定设备 ID
for d in /dev/disk/by-id/nvme-*; do
  printf '%s -> %s\n' "$d" "$(readlink -f "$d")"
done
NVMe 多 namespace 提醒： 一块控制器可能暴露多个 namespace。lsblk 看到的是块设备 namespace；控制器级健康、固件和 PCIe 信息要用 nvme、lspci、dmesg 补充。

8. RAID、LVM、dm-crypt 与多层映射

AI 节点常把多个本地 NVMe 组成 RAID0 作为高速 scratch，把企业 SSD 做 LVM 池，或用加密层保护数据。lsblk 的树能直接展示这些层次。

# 典型层次示例
# NAME             TYPE   SIZE FSTYPE      MOUNTPOINTS
# nvme0n1          disk   3.5T
# `-nvme0n1p1      part   3.5T linux_raid_member
#   `-md0          raid0  7.0T LVM2_member
#     `-vg0-data   lvm    7.0T xfs         /mnt/datasets
# nvme1n1          disk   3.5T
# `-nvme1n1p1      part   3.5T linux_raid_member
#   `-md0          raid0  7.0T LVM2_member

# 看映射关系
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS,PKNAME

# RAID 详情和 LVM 详情分别用专用工具确认
cat /proc/mdstat
mdadm --detail /dev/md0
pvs
vgs
lvs -a -o +devices
TYPE说明风险点
raid0/raid1/raid10软件 RAID 层RAID0 任意单盘故障都会丢失整个卷；只适合可重建 scratch 或缓存
lvm逻辑卷不要对 PV 成员盘直接格式化；扩容要看 VG/LV 关系
cryptdm-crypt/LUKS 映射层底层设备和解密后的 mapper 设备不要混淆
mpath多路径设备SAN/企业存储中不要绕过 multipath 直接操作单路径盘
高风险规则： 任何显示为 RAID/LVM/crypt 成员的底层盘，都不应被单独 mkfs、mount 或加入其他阵列。先理解整棵树，再操作最上层业务设备。

9. 用 JSON 输出做自动化

巡检脚本不要解析默认树状文本。lsblk -J 输出结构化 JSON，更适合生成节点资产、训练作业预检、容量告警和变更前后差异报告。

# 结构化输出，显式指定列
lsblk -J -o NAME,PATH,TYPE,SIZE,FSTYPE,FSAVAIL,FSUSE%,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED

# 如果系统有 jq，可以筛选已挂载的数据盘
lsblk -J -o NAME,TYPE,SIZE,MOUNTPOINTS,MODEL,SERIAL |
  jq -r '.blockdevices[] | .. | objects | select(.mountpoints? | tostring | test("/mnt/(datasets|scratch)"))'

# key=value 风格，适合简单 shell 解析
lsblk -P -o NAME,TYPE,SIZE,MOUNTPOINTS,MODEL,SERIAL

Python 预检示例

#!/usr/bin/env python3
import json
import subprocess

cols = "NAME,PATH,TYPE,SIZE,MOUNTPOINTS,MODEL,SERIAL,ROTA"
data = subprocess.check_output(["lsblk", "-J", "-o", cols], text=True)
tree = json.loads(data)["blockdevices"]

def walk(nodes):
    for node in nodes:
        yield node
        yield from walk(node.get("children", []))

for dev in walk(tree):
    mounts = dev.get("mountpoints") or []
    if any(m and m.startswith("/mnt/datasets") for m in mounts):
        print(dev["path"], dev["type"], dev["size"], dev.get("model"), dev.get("serial"))
脚本稳定性： 不同 util-linux 版本支持的列可能不同。部署脚本前先在目标发行版运行 lsblk --list-columns，并为缺失列设计降级路径。

用例图：把训练数据路径映射到物理盘

训练性能异常时，先确认数据路径是否真的落在预期介质上，再谈缓存、DataLoader worker、网络和 GPU 利用率。

10. 映射训练数据目录到物理盘

当训练吞吐异常时，最常见的误判是“以为读的是本地 NVMe，实际读的是系统盘、网络盘、容器 overlay 或慢速云盘”。lsblk 需要和 findmnt、df、realpath 一起用。

# 第一步：规范化路径
realpath /mnt/datasets/imagenet

# 第二步：找该路径所在挂载源
findmnt -T /mnt/datasets/imagenet -o SOURCE,FSTYPE,TARGET,OPTIONS

# 第三步：从 SOURCE 回到块设备树
lsblk -o NAME,PATH,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL,PKNAME

# 第四步：如果 SOURCE 是 /dev/mapper/vg-data，继续看上游
lsblk /dev/mapper/vg-data -o NAME,PATH,TYPE,SIZE,FSTYPE,MOUNTPOINTS,PKNAME

训练前预检脚本片段

dataset=/mnt/datasets/imagenet
src=$(findmnt -T "$dataset" -no SOURCE)
printf 'dataset=%s\nsource=%s\n' "$dataset" "$src"
lsblk -o NAME,PATH,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED "$src" 2>/dev/null || lsblk -o NAME,PATH,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED
性能定位顺序： 路径真实位置 → 块设备层次 → 实时 I/O 压力 → 文件系统和挂载选项 → 数据加载代码。不要一开始就调 batch size 或 DataLoader 参数。

11. 调度器、旋转属性与 I/O 策略

ROTA 和 SCHED 是快速判断 I/O 策略是否合理的入口。NVMe 上常见调度器是 none 或 mq-deadline，SATA/SAS SSD 和 HDD 的默认策略会随内核和发行版变化。

观察可能含义下一步
ROTA=1 的设备承载训练热数据数据路径可能在 HDD 或虚拟层错误报告用 iostat -x 看延迟，用资产记录确认介质
NVMe scheduler 与基线不一致内核默认、udev 规则或手工修改读取 /sys/block/<dev>/queue/scheduler，确认平台规范
RQ-SIZE 很小且队列饱和高并发小读可能被队列限制结合 iostat -x 1、pidstat -d、应用侧 worker 数判断
多层 dm/LVM 后属性不清晰上层设备继承或聚合了底层属性沿 lsblk 树查看每个底层物理盘
# 查看 scheduler
lsblk -o NAME,TYPE,ROTA,SCHED,RQ-SIZE,MOUNTPOINTS
cat /sys/block/nvme0n1/queue/scheduler

# 只读观察，不修改
for q in /sys/block/nvme*n1/queue/scheduler; do
  printf '%s: ' "$q"
  cat "$q"
done
调参边界： 修改 scheduler、read_ahead_kb、nr_requests 是系统级行为，可能影响所有训练任务。先采集 lsblk、iostat、fio 基线，再按变更流程修改。

对比图：lsblk 与周边存储工具怎么分工

lsblk 是入口，不是终点。它告诉你“查哪块盘”，其他工具告诉你“盘是否健康、现在是否忙、性能是否达标”。

12. lsblk vs nvme/smartctl/iostat/findmnt

工具最擅长不适合典型组合
lsblk块设备树、挂载点、设备身份、拓扑实时性能、健康细节、压测先用它定位设备和层次
findmnt路径到挂载源、挂载选项硬件型号和队列参数findmnt -T path 后接 lsblk
nvmeNVMe 控制器、namespace、SMART logSATA/SAS 通用盘用 lsblk 找设备，再 nvme smart-log
smartctlSATA/SAS/NVMe 健康、介质错误挂载树和文件系统容量坏盘定位和预测性维护
iostat实时吞吐、IOPS、await、util文件系统归属和物理身份确认训练时是哪块盘忙
fio可控 I/O 基准直接解释生产 workload 全貌上线验收、变更前后对比
# 一条排障链路：路径 -> 设备 -> 实时压力 -> 健康
findmnt -T /mnt/datasets -o SOURCE,TARGET,FSTYPE,OPTIONS
lsblk -o NAME,PATH,TYPE,SIZE,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED
iostat -xz 1
smartctl -a /dev/nvme0n1
nvme smart-log /dev/nvme0
经验法则： 如果你还不知道训练作业读写的是哪块设备，先别跑压测；如果你已经知道设备但不知道是否饱和，去看 iostat；如果出现错误、掉盘、降速，再看 dmesg 和健康工具。

13. 容器、Kubernetes 与云盘场景

容器中的 lsblk 视图可能受权限、命名空间和挂载传播影响。Kubernetes Pod 内看到的路径不一定能看到宿主机完整块设备树，尤其是 CSI 卷、bind mount、overlayfs 和只读容器。

场景现象建议
Docker/Containerd 容器Pod 内 lsblk 缺少宿主机设备或没有权限在宿主机或 privileged debug 容器中确认
Kubernetes PVC路径是 CSI 挂载，底层可能是云盘、网络盘或本地 PV从 Pod 路径用 findmnt，再到 Node 上看 lsblk
云主机设备名如 nvme1n1 但实际是远端块存储结合云厂商 by-id、metadata、volume ID 和性能规格
overlayfs训练代码写到容器层导致空间或性能异常确认 checkpoint/cache 是否显式落到数据卷
# 在 Pod 中先定位路径挂载情况
findmnt -T /workspace/data -o SOURCE,FSTYPE,TARGET,OPTIONS
df -hT /workspace/data

# 在节点上确认块设备和挂载关系
lsblk -o NAME,PATH,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL
findmnt | grep -E 'kubelet|pvc|datasets|scratch'
云盘命名提醒： 云环境中看到 nvme 不一定代表本地直连 NVMe；可能是云厂商用 NVMe 协议暴露远端块存储。要结合实例类型和云控制台卷信息判断。

14. 安全检查清单

lsblk 本身只读，但它经常位于危险操作之前。把它用对，能避免格式化错盘、挂载错盘、把训练数据写进系统盘、或把 RAID 成员当空盘使用。

格式化前
确认 TYPE=disk/part 是否真是目标，FSTYPE 是否为空，MOUNTPOINTS 是否为空，是否不是 RAID/LVM/crypt 成员。
挂载前
确认 UUID/LABEL 和 /etc/fstab 一致，不依赖可能变化的 /dev/sdX 名称。
扩容前
确认云盘容量、分区、PV、VG、LV、文件系统每一层的大小变化路径。
下线前
确认没有业务挂载、没有训练进程读写、不是其他上层映射设备的父设备。
# 变更前最小证据包
lsblk -f
lsblk -o NAME,PATH,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL,PKNAME
findmnt
cat /proc/mdstat
pvs 2>/dev/null
lvs -a -o +devices 2>/dev/null
禁止凭感觉操作： “这台机器上最大的空盘应该就是它”不是安全依据。必须用型号、序列号、UUID、挂载点、上层映射关系和变更目标交叉确认。

排障流程图：训练 I/O 异常时怎么用 lsblk 开局

训练 I/O 排障的第一步不是改模型代码，而是确认路径、挂载、设备层次和介质类型。

15. 常见问题与排障

问题 1：看不到新加的盘
先查 dmesg、云控制台 attach 状态、PCIe/NVMe 枚举，再尝试 udevadm settle。不要盲目重启生产训练节点。
问题 2：设备名变了
改用 /dev/disk/by-id/、UUID、LABEL、WWN，不要在 fstab 或脚本中依赖 /dev/sdb。
问题 3：挂载点为空
可能是未挂载、只作为 RAID/LVM 成员、在其他命名空间挂载，或被容器 bind mount 隐藏。
问题 4：ROTA 不符合预期
虚拟化或存储阵列可能报告不准确。结合型号、云盘规格和实际 iostat 表现判断。
问题 5：lsblk -f 没有 UUID
可能没有文件系统、文件系统损坏、权限不足、或设备是上层映射的成员。
问题 6：JSON 字段缺失
util-linux 版本差异。先运行 lsblk --list-columns，脚本中不要假设所有发行版都有同一列。
问题 7：训练写满系统盘
用 findmnt -T checkpoint_path 确认 checkpoint/cache 是否真的在数据盘，而不是容器 overlay 或根分区。
问题 8：RAID/LVM 树看不懂
用 lsblk -o NAME,TYPE,PKNAME,MOUNTPOINTS 找父设备，再用 mdadm、pvs、lvs 展开。

排障模板

# 1. 看路径到底挂在哪里
findmnt -T /mnt/datasets -o SOURCE,FSTYPE,TARGET,OPTIONS

# 2. 看完整设备树和身份
lsblk -e 7 -o NAME,PATH,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED,PKNAME

# 3. 看内核是否有 I/O 错误
dmesg -T | grep -Ei 'nvme|blk|i/o error|reset|timeout|medium error'

# 4. 看实时压力
iostat -xz 1

# 5. 看健康信息
smartctl -a /dev/nvme0n1
nvme smart-log /dev/nvme0

16. 练习任务与参考命令清单

练习任务

  1. 在一台测试机上运行 lsblk、lsblk -f、lsblk -t，解释每个 TYPE 节点。
  2. 找到根目录 / 的底层物理盘，并记录型号和序列号。
  3. 找到一个训练数据目录，使用 findmnt -T 和 lsblk 说明它是否在本地盘上。
  4. 生成 lsblk -J 快照，并用 jq 或 Python 输出所有挂载在 /mnt 下的设备。
  5. 比较 lsblk、iostat、smartctl 对同一块盘给出的不同信息。
  6. 在没有数据风险的测试盘上创建分区和文件系统前，写出你会执行的只读确认命令。

常用命令清单

# 人读：完整盘点
lsblk -e 7 -o NAME,PATH,TYPE,SIZE,FSTYPE,FSAVAIL,FSUSE%,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED

# 人读：文件系统和挂载点
lsblk -f

# 人读：拓扑和队列
lsblk -t

# 脚本：JSON
lsblk -J -o NAME,PATH,TYPE,SIZE,FSTYPE,MOUNTPOINTS,MODEL,SERIAL,ROTA,SCHED

# 设备身份：整盘
lsblk -d -o NAME,PATH,SIZE,MODEL,SERIAL,WWN,ROTA

# 路径定位：数据目录到挂载源
findmnt -T /mnt/datasets -o SOURCE,FSTYPE,TARGET,OPTIONS
学习路线： 先读懂 TYPE 和树，再掌握 -f、-t、-o、-J，最后把它接入训练节点预检和变更审查。
