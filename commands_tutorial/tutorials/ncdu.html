ncdu 深度教程：AI Infra 磁盘用量交互式排查

这份教程按 AI Infra 的真实场景讲解 ncdu：训练节点磁盘打满、共享数据集膨胀、checkpoint 按实验堆积、日志目录无限增长、容器缓存占满系统盘、远程无图形环境需要离线分析。重点不是背选项，而是建立“先扫描成目录树，再交互式下钻定位大户，最后用只读/确认/导出流程安全处置”的工作模型。

交互式磁盘分析AI 数据集Checkpoint日志清理排除路径远程节点导出/导入删除安全生产排障
一句话理解： ncdu 是带 TUI 的 du：它先递归扫描目录用量，生成可排序、可下钻的目录树，让你快速看见“是谁吃掉了磁盘”。
最重要原则： 在生产训练机和共享存储上先用 ncdu -r 只读模式或导出快照分析；需要删除时先确认路径、所属任务、是否有软链接/挂载点，再用版本化清理脚本或明确确认执行。

1. ncdu 是什么

ncdu 全称常被理解为 NCurses Disk Usage。它用终端字符界面展示目录占用，适合在 SSH、跳板机、训练节点、容器和没有桌面的服务器上快速定位磁盘大户。

它擅长什么
在一个目录树里交互式下钻、按大小排序、看每个目录/文件占比，并快速决定后续清理对象。
它不擅长什么
实时监控、按时间范围自动清理、跨主机聚合统计、判断文件能不能删。这些需要监控、策略和业务上下文。
它的本质
递归扫描文件系统元数据和大小信息，再在 TUI 中浏览扫描结果。
# 扫描当前目录
ncdu .

# 扫描数据集根目录
ncdu /data/datasets

# 只读浏览，禁用 ncdu 内置删除
ncdu -r /data/checkpoints

# 不跨文件系统，避免从 / 扫到 /mnt、/proc、/run 等挂载点
ncdu -x /
权限提醒： ncdu 只能准确统计当前用户有权限访问的路径。遇到 Permission denied 时，结果可能低估；是否使用 sudo 要按机器治理规则决定。

2. AI Infra 为什么需要 ncdu

AI 工作负载的磁盘增长通常不是单个大文件，而是“数据集 + 预处理缓存 + checkpoint + tensorboard/event 日志 + 容器层 + 临时 shard”的组合。传统 df -h 只能告诉你磁盘满了，不能告诉你是哪条实验线、哪个用户、哪个缓存目录在增长。

场景常见症状ncdu 的价值
数据集镜像/data 或共享 NAS 用量持续上涨下钻到数据集、版本、预处理产物，区分原始数据和派生缓存
模型 checkpoint训练正常但保存失败，报 No space left on device按实验目录排序，快速发现重复保存、过密保存、未清理失败实验
日志目录系统盘或任务盘被 *.log、event 文件填满定位大日志目录，再用 find 按时间和文件名安全处理
容器/缓存/var/lib/docker、pip/conda/cache 暴涨判断是镜像层、容器写层、包缓存还是临时构建产物
多用户训练节点不知道谁的目录占用最大按 /home、/workspace、/scratch 下钻到项目和用户维度
工作边界： ncdu 帮你“定位空间在哪里”，但不能替你判断“是否可以删除”。生产清理要结合任务状态、数据血缘、保留策略和负责人确认。

信息图：ncdu 的整体心智模型

先选范围，再扫描，再下钻，最后安全处置。范围选错会让扫描慢、结果乱，甚至误扫网络盘和系统伪文件系统。

3. 安装与版本检查

ncdu 通常在 Linux 发行版仓库中可直接安装。AI Infra 环境里常见的是 Ubuntu/Debian、RHEL/CentOS/Rocky、容器镜像和 macOS 本地调试机。

环境安装命令备注
Ubuntu/Debiansudo apt-get update && sudo apt-get install -y ncdu训练节点上按组织包管理规范执行
RHEL/CentOS/Rockysudo dnf install -y ncdu老系统可能用 yum 或需要 EPEL
Alpine 容器apk add --no-cache ncdu适合临时排查容器内目录
macOSbrew install ncdu本地分析导出的扫描文件时方便
# 确认版本和路径
command -v ncdu
ncdu --version

# 查看帮助，确认当前版本支持的选项
ncdu --help | sed -n '1,80p'
版本提醒： ncdu 1.x 与 2.x 在界面和部分选项上可能存在差异。教程中的 -x、-r、--exclude、-o、-f 是常见能力；生产脚本先用 ncdu --help 在目标机器确认。

4. 第一次扫描和界面键位

最小用法是给 ncdu 一个目录。扫描完成后进入交互界面，常用动作是上下移动、回车进入目录、左键或 h 返回、按大小排序、查看帮助、退出。

# 在当前项目中试用
ncdu .

# 扫描用户目录
ncdu "$HOME"

# 扫描根目录但不要跨文件系统
sudo ncdu -x /
键位作用AI Infra 场景
↑/↓ 或 j/k移动选择浏览目录列表，优先看最大项
Enter/→进入目录从 /data 下钻到具体数据集或实验
←/h返回上级在多个候选目录之间切换
?查看内置帮助确认当前版本支持的键位
d删除选中项，通常会确认仅在确认安全时使用；生产建议先 -r
q退出结束分析
界面读法： 顶层显示最大目录时，不要马上删除。先进入该目录，继续下钻到“可解释、可归属、可处置”的层级，例如 run-2026-04-25/checkpoints/epoch_120。

5. 扫描大数据集目录

AI 数据目录常包含原始数据、解压副本、tokenized 缓存、shard、中间特征、索引文件和临时下载残留。ncdu 的价值是把“感觉很大”变成“哪个版本、哪个阶段、哪个子目录最大”。

# 只读扫描数据集根目录
ncdu -r /data/datasets

# 扫描单个项目数据目录
ncdu -r /data/datasets/vision/imagenet-derived

# 避免跨到其他挂载点，尤其是 /data 下有 bind mount 时
ncdu -rx /data
原始数据
例如 raw/、download/、archives/。通常不能随意删，要看是否有上游备份。
派生缓存
例如 tokenized/、features/、preprocessed/。可再生，但再生成成本可能很高。
临时残留
例如 tmp/、.partial、失败下载、重复解压。通常是优先清理候选。

配合 find 做二次确认

# 先用 ncdu 找到大目录，再用 find 看近期是否还在写入
find /data/datasets/myset -maxdepth 3 -type f -mtime -2 -printf '%TY-%Tm-%Td %TH:%TM %p\n' | head

# 查看最大文件，避免误删正在使用的大 shard
find /data/datasets/myset -type f -printf '%s %p\n' | sort -nr | head -20
共享数据提醒： 数据集目录经常被多个训练任务复用。即使 ncdu 显示某个目录很大，也要确认 owner、引用关系、数据目录约定和保留策略。

流程图：从磁盘告警到 checkpoint 清理

ncdu 是定位工具，不是审批工具。checkpoint 删除必须经过任务状态和保留策略确认。

6. Checkpoint 与实验输出排查

Checkpoint 目录通常是 AI Infra 最常见的空间黑洞：同一实验保存过密、多个 seed 重复输出、失败任务留下完整权重、评估产物复制模型、对象存储同步失败导致本地堆积。

# 从实验根目录只读下钻
ncdu -r /data/checkpoints

# 限定到一个团队或项目
ncdu -r /data/checkpoints/nlp-foundation

# 找出最近仍在写入的 checkpoint，避免误清正在训练的 run
find /data/checkpoints/nlp-foundation -type f -mtime -1 -printf '%TY-%Tm-%Td %TH:%TM %p\n' | head -50

推荐清理策略

对象风险建议
最后一个 checkpoint高通常保留，除非实验已明确废弃
中间 epoch 大量权重中按策略保留最后 N 个、最佳 N 个、关键里程碑
失败实验完整目录中确认无复现实验价值后删除或归档
重复复制的 best.pt/latest.pt中确认硬链接/软链接/真实副本后处理
评估临时输出低到中优先清理，但保留指标和配置
# dry-run：列出 30 天前的中间 checkpoint，不删除
find /data/checkpoints/myproj -type f \
  -name 'epoch_*.pt' -mtime +30 -print

# 执行前二次确认：抽样查看路径
find /data/checkpoints/myproj -type f \
  -name 'epoch_*.pt' -mtime +30 -print | sed -n '1,20p'
删除警告： 不要只凭文件名删除 *.pt、*.safetensors 或 *.ckpt。先确认实验状态、是否已上传、是否有追溯要求，以及是否被下游评估或蒸馏任务引用。

7. 日志目录和临时文件定位

日志膨胀经常发生在长训练、分布式任务、debug 级别过高、重复重试和 TensorBoard event 文件堆积时。ncdu 能快速定位哪个 run 的日志最大，然后用 find 按时间、文件名和大小做安全处理。

# 扫描常见日志根目录
ncdu -r /data/logs
ncdu -r /var/log
ncdu -r /workspace/runs

# 扫描 TensorBoard/event 输出
ncdu -r /data/experiments/tensorboard
目录/文件可能原因处理建议
events.out.tfevents.*训练指标、histogram、embedding 写入过多保留近期或关键实验，压缩/归档历史
stdout.log/stderr.log每步打印、debug 日志过多先确认任务已结束，再截断或归档
wandb//mlruns/离线缓存未同步或未清理确认同步状态后清理缓存
tmp//.cache/预处理或下载中断按最近修改时间和 owner 判断
# dry-run：列出 14 天前的大日志
find /data/logs -type f -name '*.log' -mtime +14 -size +100M -print

# dry-run：查看大于 1G 的 event 文件
find /data/experiments -type f -name 'events.out.tfevents.*' -size +1G -print

# 安全截断前先确认：只对已结束任务的日志执行
# : > /data/logs/finished-run/stdout.log
截断提醒： 对正在运行的进程日志直接删除，空间可能不会立刻释放，因为文件描述符仍被进程持有。需要看 lsof +L1 或重启/让进程重新打开日志。

用例图：扫描范围、排除路径和挂载点

AI 训练节点常有本地 NVMe、共享 NAS、对象存储挂载和容器伪文件系统。先限定范围，结果才可解释。

8. 排除路径与限定文件系统

大目录扫描的第一优化不是“让 ncdu 更快”，而是“不扫描不该扫描的东西”。常见手段是 -x 限定单一文件系统，以及 --exclude 或 --exclude-from 排除已知无关路径。

# 不跨文件系统：扫描 / 时尤其重要
sudo ncdu -x /

# 只读 + 不跨文件系统：适合生产排查
sudo ncdu -rx /data

# 排除常见缓存和临时目录
ncdu -r /workspace \
  --exclude '.git' \
  --exclude '__pycache__' \
  --exclude '.cache' \
  --exclude 'tmp'

用排除文件管理团队规则

cat > /tmp/ncdu-excludes.txt <<'EOF'
.git
__pycache__
*.pyc
.ipynb_checkpoints
node_modules
tmp
EOF

ncdu -r --exclude-from /tmp/ncdu-excludes.txt /workspace/myproj
选项作用使用建议
-x不跨越文件系统边界扫 /、/data、容器宿主机时优先考虑
--exclude PATTERN排除匹配模式的文件或目录适合少量规则；模式语义以当前版本帮助为准
--exclude-from FILE从文件读取排除规则适合团队共享规则和可重复扫描
-r只读模式生产、共享目录和远程快照分析优先使用
排除提醒： 排除规则会让统计结果“不含被排除部分”。报告磁盘占用时要说明扫描命令，否则别人可能把结果误解为完整用量。

9. 删除安全与只读模式

ncdu 可以在界面中删除选中项，但在 AI Infra 生产环境里，直接在 TUI 里按 d 清理通常不是最可审计的方式。更稳妥的流程是：用 ncdu -r 定位，复制路径，用 find 或清理脚本 dry-run，确认后执行。

# 推荐：只读分析，不允许 ncdu 内置删除
ncdu -r /data/checkpoints

# dry-run：列出候选文件
find /data/checkpoints/myrun -type f -name 'epoch_*.pt' -mtime +30 -print

# dry-run：看候选总大小
find /data/checkpoints/myrun -type f -name 'epoch_*.pt' -mtime +30 -printf '%s\n' \
  | awk '{s += $1} END {printf "%.2f GiB\n", s/1024/1024/1024}'

# 执行删除前建议先把候选列表保存下来
find /data/checkpoints/myrun -type f -name 'epoch_*.pt' -mtime +30 -print \
  > /tmp/delete-candidates.txt
生产删除底线： 不要在不理解路径含义时删除；不要删除正在运行任务的输出；不要在共享数据集根目录试错；不要用通配符直接 rm -rf 未审查列表。

删除前检查清单

路径归属
目录属于哪个用户、项目、任务、实验？是否有 issue、工单或保留策略？
任务状态
训练是否仍在写入？调度系统里任务是否 Running？日志是否还在增长？
数据血缘
是否是原始数据、可再生缓存、最终模型、评估结果或临时文件？
恢复能力
是否已上传对象存储？是否有备份？删除后重新生成成本多大？

10. 远程与 Headless 用法

ncdu 的优势之一是只需要终端，不需要图形界面。你可以直接 SSH 到节点运行，也可以在远程节点导出扫描结果，再在本地或跳板机导入浏览。

# 直接 SSH 到训练节点交互式排查
ssh gpu-node-01
ncdu -r /data

# 如果网络不稳定，用 tmux/screen 包住交互会话
tmux new -s disk-debug
ncdu -r /data/checkpoints

远程导出、本地导入

# 在远程执行扫描并把结果写回本地文件
ssh gpu-node-01 'ncdu -0xo- /data/checkpoints' > gpu-node-01-checkpoints.ncdu

# 本地或跳板机导入浏览
ncdu -f gpu-node-01-checkpoints.ncdu

# 数据很大时压缩传输
ssh gpu-node-01 'ncdu -0xo- /data/checkpoints' | gzip > gpu-node-01-checkpoints.ncdu.gz
gzip -dc gpu-node-01-checkpoints.ncdu.gz | ncdu -f-
Headless 心法： 远程机器负责扫描，本地机器负责浏览。这样可以避免长时间占用 SSH 交互，也方便把快照附到排障记录里。

11. 导出/导入扫描结果

导出/导入适合三类场景：扫描耗时很长、需要离线分析、需要把磁盘快照交给其他人复核。导出的文件是某一时刻的快照，不会随磁盘变化自动更新。

# 导出到文件
ncdu -o /tmp/data-scan.ncdu /data

# 从文件导入浏览
ncdu -f /tmp/data-scan.ncdu

# 输出到 stdout，适合管道和 ssh
ncdu -0xo- /data > /tmp/data-scan.ncdu

# 从 stdin 导入
cat /tmp/data-scan.ncdu | ncdu -f-
方式优点注意事项
ncdu -o file dir简单直观，适合本机保存文件可能包含路径结构，按内部信息规范保存
ncdu -0xo- dir适合脚本、SSH、压缩管道-0 常用于非交互/无进度输出场景，先确认版本支持
ncdu -f file无需重新扫描即可浏览看到的是快照，不代表当前实时状态
协作建议： 排障记录中保存 df -h、mount、ncdu 扫描命令和导出文件路径，后续复盘时能还原当时判断依据。

对比图：ncdu、du、find、ls 怎么分工

ncdu 最适合“探索式定位”；真正批量删除和审计仍建议交给可复现的 shell 命令或清理脚本。

12. ncdu vs du/find/ls

工具优势劣势最佳用途
df -h极快，看文件系统总体用量不知道哪个目录占用告警第一步，确认满的是哪块盘
du脚本友好，适合生成文本报告交互探索不方便，层级切换慢定期报表、浅层目录统计
ncdu交互式、排序、下钻快扫描是快照，不是实时监控；TUI 删除不易审计人工排障、定位空间大户
find按时间、大小、名字、类型精确筛选不适合自由探索目录树生成清理候选列表和执行批处理
ls查看单目录文件属性方便不递归汇总目录真实占用查看 ncdu 定位后的具体文件
# du：快速看一层目录大小
du -h --max-depth=1 /data 2>/dev/null | sort -h

# ncdu：交互式定位最大子树
ncdu -r /data

# find：生成可审计候选列表
find /data/checkpoints -type f -name 'epoch_*.pt' -mtime +30 -print
选择标准： 如果你已经知道要找“30 天前的 checkpoint”，用 find；如果你还不知道空间在哪，用 ncdu。

13. 性能、权限与并发影响

ncdu 扫描会遍历目录树并读取元数据。对本地 NVMe 通常很快；对 NFS、Lustre、CephFS、海量小文件目录或对象存储挂载，扫描可能给元数据服务带来压力。

海量小文件
瓶颈常在元数据，不在吞吐。避免高峰期扫全量目录。
权限不足
会漏统计无法进入的目录。排查系统盘时可能需要管理员配合。
目录变化
扫描期间训练仍在写入，结果只是近似快照。需要结合时间戳和任务状态判断。
# 先确认挂载类型和目录边界
df -hT /data
findmnt /data

# 网络文件系统上优先缩小范围
ncdu -r /data/checkpoints/team-a

# 高峰期避免全局扫描，必要时导出给离线分析
ncdu -0x -o /tmp/team-a-scan.ncdu /data/checkpoints/team-a
风险表现缓解
扫描太慢长时间停在 scanning缩小根目录、加排除规则、避开共享 FS 高峰
结果偏小有权限错误或隐藏挂载记录错误，必要时用具备权限的账号重新扫
空间未释放删除后 df 不变检查打开的已删除文件、快照、回收站、配额
误扫挂载点扫描范围异常大使用 -x，先查看 findmnt

14. 典型 AI Infra Runbook

下面是一个从告警到处置的可复制流程。它刻意把“定位”和“删除”分开，方便审计和复盘。

场景 A：训练节点系统盘满

# 1. 确认满的是哪块盘
df -hT

# 2. 不跨文件系统扫描系统盘
sudo ncdu -rx /

# 3. 常见候选：容器层、日志、包缓存
sudo ncdu -r /var/lib/docker
sudo ncdu -r /var/log
ncdu -r "$HOME/.cache"

场景 B：checkpoint 挂载点满

# 1. 看挂载点和用量
df -hT /data/checkpoints

# 2. 只读扫描团队目录
ncdu -r /data/checkpoints/team-a

# 3. 生成候选，不直接删除
find /data/checkpoints/team-a -type f -name 'epoch_*.pt' -mtime +30 -print \
  > /tmp/team-a-old-checkpoints.txt

场景 C：共享数据集异常膨胀

# 1. 先扫项目级，不扫整个共享存储
ncdu -r /data/datasets/project-x

# 2. 找派生缓存和临时目录
find /data/datasets/project-x -maxdepth 4 -type d \
  \( -name 'tmp' -o -name 'cache' -o -name 'preprocessed' \) -print

# 3. 只列候选，交给 owner 确认
find /data/datasets/project-x -type f -name '*.partial' -print
Runbook 输出物： 每次清理最好留下扫描命令、候选列表、确认人、执行命令、释放空间前后的 df -h。这比“我在 ncdu 里删了一些东西”更可维护。

安全排障图：ncdu 结果不符合预期时怎么查

删除后空间没变不一定是 ncdu 错了，常见原因是文件仍被进程打开、文件系统快照保留、配额统计延迟或删错挂载点。

15. 常见坑与排障

坑 1：直接扫 / 且不加 -x
可能跨到远程挂载、容器目录或伪文件系统。优先 ncdu -x /。
坑 2：把 ncdu 快照当实时监控
扫描后目录继续增长，界面不会自动代表最新状态。需要重新扫描或配合监控。
坑 3：权限不足导致低估
普通用户无法进入的目录不会完整统计。记录权限错误，必要时让管理员扫描。
坑 4：TUI 里误删
生产环境用 -r，把删除动作交给 dry-run 后的脚本。
坑 5：删除文件但 df 不降
进程仍打开已删除文件、文件系统快照、配额延迟都可能导致空间未释放。
坑 6：软链接和挂载点误判
目录树里的路径不一定等于物理归属。先用 findmnt、ls -l、readlink 确认。
坑 7：网络文件系统高峰期全量扫
元数据压力可能影响训练。缩小范围或在低峰扫描。
坑 8：只看最大目录，不看业务含义
最大的目录可能是关键数据集，不是清理对象。要下钻到可归属层级。

排障命令模板

# 确认文件系统视角
df -hT /data
findmnt /data

# 确认目录视角
du -h --max-depth=1 /data 2>/dev/null | sort -h
ncdu -r /data

# 删除后空间未释放：查已删除但仍打开的文件
sudo lsof +L1 | sed -n '1,40p'

# 查某目录最近是否还在写
find /data/checkpoints/myrun -type f -mmin -60 -printf '%TY-%Tm-%Td %TH:%TM %p\n' | head

16. 学习路线与练习任务

第一阶段：会定位

  • 用 df -h 确认满的是哪个挂载点。
  • 用 ncdu -r 在只读模式中浏览目录树。
  • 练习进入、返回、排序、查看帮助和退出。

第二阶段：会控范围

  • 理解 -x 的作用，避免误扫其他挂载点。
  • 使用 --exclude 和 --exclude-from 排除无关缓存。
  • 在网络文件系统上优先扫描项目级目录，而不是全局根目录。

第三阶段：会安全处置

  • 把 ncdu 定位结果转成 find dry-run 候选列表。
  • 计算候选总大小，确认释放空间是否足够。
  • 保留扫描命令、候选列表、确认记录和执行前后的 df -h。

本地练习

# 准备练习目录
mkdir -p /tmp/ncdu-demo/{raw,cache,logs,checkpoints}
dd if=/dev/zero of=/tmp/ncdu-demo/raw/data.bin bs=1M count=32
dd if=/dev/zero of=/tmp/ncdu-demo/cache/features.bin bs=1M count=64
dd if=/dev/zero of=/tmp/ncdu-demo/checkpoints/epoch_001.pt bs=1M count=16
printf 'hello\n' > /tmp/ncdu-demo/logs/train.log

# 只读浏览
ncdu -r /tmp/ncdu-demo

# 导出再导入
ncdu -o /tmp/ncdu-demo.ncdu /tmp/ncdu-demo
ncdu -f /tmp/ncdu-demo.ncdu

# 清理练习目录前先确认路径，再交互式确认删除
find /tmp/ncdu-demo -maxdepth 2 -type f -print
rm -ri /tmp/ncdu-demo /tmp/ncdu-demo.ncdu
练习提醒： dd 会真实占用磁盘空间。示例使用 /tmp 和较小文件，执行前仍要确认本机剩余空间。
