Ch. 01

为何要量化

想象一下：你训练好的 LLaMA-70B 模型权重以 FP16 存储，需要 140 GB 显存——这超过了任何单张消费级 GPU 的容量，甚至超过了大多数数据中心 GPU 的显存上限。即便是 7B 的小模型，在 FP32 下也需要 28 GB。模型部署的"最后一公里"，往往不是算法不够强，而是硬件装不下、跑不动、耗不起。

量化（Quantization），本质上是一种有损压缩：用较少的比特数去近似表达原本占用更多比特的浮点数值。一个 FP32 的权重需要 32 比特，量化为 INT8 后只需 8 比特——存储立减 4 倍，许多硬件上整数运算还比浮点快 2–4 倍。这听起来像是免费的午餐，但代价是精度的损失，而量化研究的全部内容，几乎都在回答同一个问题：如何把这个损失压到最小？

量化带来的四重价值

这四个维度的收益并非孤立。显存的减少意味着可以在同一张 GPU 上承载更大的模型或更高的并发；速度的提升来自整数运算单元（如 NVIDIA Tensor Core 的 INT8 模式）的天然优势以及内存带宽压力的缓解；能耗的下降则直接转化为运营成本与碳足迹的降低；而精度的微小损失，在精心设计的量化方案下，往往可以控制在百分之一以内。

核心洞察

量化不是简单的"把数字变小"。它是在表达精度与计算成本之间寻找最优平衡的工程艺术。一个好的量化方案，需要同时理解神经网络的统计特性、硬件的执行特征与算法的数值稳定性。

Ch. 02

数学本质

所有量化方法的内核，都是同一个简单到近乎朴素的线性映射。给定一个浮点张量 x，我们希望用整数 q 来表示它，使得：

x ≈ s · (q − z)

其中 s 是缩放因子（scale），决定了一个整数单位代表多大的浮点跨度；z 是零点（zero-point），决定了浮点零对应到哪个整数。这两个参数共同定义了整个量化方案。反向操作（反量化）则是：

q = round(x / s) + z

这个过程包含三个不可逆的损失源：截断（clipping）——超出量化范围的值会被截断到边界；舍入（rounding）——连续值被映射到离散网格；以及范围选择——不同的 s 与 z 选择会带来不同的误差分布。

关键参数：α、s、z

选择"截断阈值" α 是量化设计的第一个关键决策。最朴素的做法是取张量绝对值的最大值（α = max|x|），这样不会产生截断误差，但若张量中存在离群值（outliers），整个量化网格的精度就会被这些异常点吞噬。更聪明的做法是基于直方图统计选择 α，例如使 KL 散度最小、或选择 99.9% 分位点——这是 TensorRT 等推理引擎的核心校准逻辑。

给定 α 后，对于 INT8 的对称量化，s = α / 127，z = 0。对于非对称量化，s = (max − min) / 255，z = round(−min / s)。看似简单的公式背后，藏着关于分布形态的深刻假设——量化器的好坏，本质上取决于它对张量分布的刻画有多准确。

数值稳定性提示

当我们说"INT8 量化"时，权重和激活值实际上是被存储为整数的，但在计算过程中，累加器（accumulator）通常使用 INT32 来防止溢出——8 位整数相乘最多产生 16 位结果，连续累加 K 次需要约 16 + log₂K 位存储空间。这是硬件设计的关键考量。

Ch. 03

分类体系

量化方案可以从多个正交的维度被分类，理解这个分类体系，是阅读任何量化论文的前置条件。下面这张用例图刻画了不同应用场景下，工程师面对的核心抉择空间。

四个核心维度

把上图中的用例展开，量化方案沿着以下四个维度进行设计：

  1. 对称性（Symmetry）：对称量化将零点固定为 0，反量化时只需一次乘法；非对称量化允许零点偏移，能更紧凑地包裹偏斜分布——例如 ReLU 之后的非负激活值。
  2. 粒度（Granularity）：是为整个张量共用一组 (s, z)（per-tensor），还是为每个输出通道单独配置（per-channel），抑或是更细的分块（per-group / per-block）？粒度越细，精度越高，但元数据开销和计算复杂度也越大。
  3. 时机（Timing）：量化参数在训练后通过校准集统计得到（PTQ），还是在训练中作为可学习参数进行端到端优化（QAT）？
  4. 范围（Scope）：只量化权重（weight-only），还是同时量化激活值（W&A）、甚至 KV 缓存？范围越广，加速效果越显著，但精度风险也越高。
Ch. 04

对称 与 非对称

这是最基础的二选一，几乎所有量化决策都从这里开始。差别在于零点（zero-point）是否被强制设为整数零。一句话总结：对称量化把浮点 0 直接对齐到整数 0；非对称量化则允许浮点 0 落在整数轴的任意位置。

这两种方案各有所长。对称量化的优势在于硬件友好：因为 z = 0，矩阵乘法 Y = (W − z_w)(X − z_x) 中没有交叉项，反量化只需要一次乘法 y_real = s · q_y，整数乘加管线非常干净。这也是 NVIDIA Tensor Core 的 INT8 模式默认使用对称量化的原因。

但当激活分布不对称时——例如 ReLU 之后所有值都为非负——对称量化会浪费一半的整数表达能力（INT8 的 [-128, -1] 范围全部空置）。非对称量化通过引入 z ≠ 0 的偏移，让整个 [0, 255] 网格都被有效利用，相同位宽下精度可以提升近一倍。代价是矩阵乘法展开后多出三个交叉项需要额外处理。

维度对称量化非对称量化
零点z = 0（固定）z 任意整数
整数范围[−127, +127]（INT8）[0, 255] 或 [−128, +127]
反量化x = s · qx = s · (q − z)
典型应用权重、tanh 激活ReLU 输出、KV-cache

Ch. 05

粒度的艺术

粒度（granularity）回答的是：一组量化参数（s, z）应当被多少元素共享？这是一个清晰的工程权衡——共享得越多，元数据越少、计算越简单；共享得越少，量化误差越小、但开销越大。

在实践中，权重通常使用 per-channel 或 per-group 量化，因为权重是静态的，可以离线计算每个通道的最优 scale；激活值由于其动态特性，往往只能采用 per-tensor 量化，否则会带来巨大的运行时开销。这种"权重精细、激活粗放"的不对称组合，是大多数生产级量化方案的默认配置。

而 LLM 量化的特殊性在于：transformer 的激活值往往存在极端的离群值——少数特征通道的数值可以比其他通道大 100 倍。这迫使了 SmoothQuant、GPTQ 等专门算法的诞生，它们的核心创新都围绕"如何在保持硬件友好的粒度下，仍然处理好这些离群值"这个矛盾。

Ch. 06

PTQ 与 QAT

"PTQ 是一次精巧的统计学手术，QAT 是一场漫长的端到端训练——它们解决的是同一个问题的两种哲学。"

PTQ（Post-Training Quantization，训练后量化）的逻辑是：拿一个已经训练好的浮点模型，用一小批"校准数据"喂进去，统计每一层激活的分布，由此确定每一层的 (s, z) 参数，然后把权重转成整数存储。整个过程不需要梯度回传，几分钟到几小时就能完成，不需要原始训练数据，是工业部署的默认选择。

QAT（Quantization-Aware Training，量化感知训练）则将"量化-反量化"作为一个伪节点（fake quant node）插入计算图中，在前向传播时模拟量化误差，在反向传播时通过直通估计器（Straight-Through Estimator, STE）把梯度传过不可导的 round 操作。模型在训练中"知道"自己最终会被量化，因而可以学习对量化误差更鲁棒的权重分布。QAT 的精度通常显著高于 PTQ，但需要原始训练数据和数小时到数天的训练时间。

STE：跨越离散障碍的桥梁

QAT 的精髓在 STE（Straight-Through Estimator）。round 函数在数学上几乎处处导数为零，普通梯度无法通过它回传。STE 的解决方案近乎"耍赖"——前向计算时正常使用 round，反向计算时假装它是恒等函数，让梯度无损穿过。这种近似在工程上极为有效，是几乎所有 QAT 框架的基石。

class FakeQuant(torch.autograd.Function):
    # 前向：模拟量化-反量化的误差注入
    @staticmethod
    def forward(ctx, x, scale, zero_point, qmin, qmax):
        q = torch.round(x / scale) + zero_point
        q = torch.clamp(q, qmin, qmax)
        return (q - zero_point) * scale
    
    # 反向：STE — 梯度恒等通过
    @staticmethod
    def backward(ctx, grad_output):
        return grad_output, None, None, None, None
何时选 PTQ，何时选 QAT

选 PTQ，如果：模型对量化敏感度低（如 ResNet 等 CNN）、原始训练数据不可得、追求快速部署、或目标是 INT8 这种相对宽松的位宽。

选 QAT，如果：要做 INT4 / INT2 这类激进量化、模型本身（如轻量化 MobileNet 或 LLM 中关键层）对量化敏感、有充足的训练算力与数据，并希望精度逼近浮点基线。

Ch. 07

数值格式图谱

"几比特量化"远不止是位数那么简单。同样是 8 位，INT8 与 FP8 是两种截然不同的格式；同样是 4 位，INT4 与 NF4 在数值分布上有本质区别。理解这些格式的内部结构，是阅读量化论文的必备词汇。

三种 4-bit 格式的暗战

大模型推理普遍使用 4 比特量化，但"4 比特"有多种实现方式：

  • INT4：均匀分布的 16 个整数级别（−8 到 +7）。简单，硬件友好，但对正态分布的权重而言"中间挤、两边松"，精度不优。
  • NF4（NormalFloat4）：QLoRA 提出的"信息论最优"4 比特格式。将权重视为标准正态分布，将 16 个量化级别按正态分布的分位点放置——分布密集处量化点也密集，分布稀疏处量化点也稀疏。在权重量化场景下精度显著高于 INT4。
  • FP4：4 位浮点（通常 E2M1，1 符号位 + 2 指数位 + 1 尾数位）。具有非线性的取值分布，对动态范围大的张量友好，但硬件原生支持有限。

Ch. 08

前沿算法

大模型量化的算法景观在过去三年急剧扩张。下面这张决策图按"是否需要训练"和"量化范围"两个维度，把主流方法摆到了一张地图上。

GPTQ：Hessian 引导的逐列量化

GPTQ 的核心洞察来自经典的 OBQ（Optimal Brain Quantization）：当我们量化权重矩阵的某一列时，剩余未量化的列可以通过权重更新来"补偿"这次量化引入的误差。最优补偿方向由该层 Hessian 矩阵的逆决定。GPTQ 把这个思想从单层扩展到了大模型，并通过"批量列处理 + Cholesky 分解 + 懒惰更新"等工程技巧，使得 175B 参数模型可以在单张 A100 上几小时内完成 INT4 量化。

GPTQ 是权重量化（weight-only）方法——它只把权重压到 4 位，激活值仍保持 FP16。因此在推理时，需要一个反量化-计算-激活的特殊算子（dequant-and-matmul），现代推理框架（vLLM、TensorRT-LLM）都对此有原生优化。

AWQ：保护"显著权重"

AWQ（Activation-aware Weight Quantization）的观察更直觉化：权重的重要性并不均匀，大约 1% 的"显著权重"（salient weights）承载了模型表现的大部分，而判断显著与否的依据，不是权重本身的幅值，而是其对应输入激活的幅值。

AWQ 的解决方案是巧妙的：对于每个权重列 i，计算一个缩放因子 s_i，将权重放大、激活缩小（W·X = (W·s)·(X/s)，等价变换），使得显著权重在量化前被"放大"到量化网格更精细的区域。这种方法不需要反向传播，只需要一小批校准数据来统计激活幅值，因此实施极其简单——这正是 AWQ 在工业界广受欢迎的原因。

SmoothQuant：把激活的离群值"擦"到权重上

SmoothQuant 解决的是一个更棘手的问题：同时量化权重和激活（W8A8）。LLM 激活中的离群值会让 per-tensor 量化精度崩溃，但激活的动态特性又让 per-channel 难以实施。SmoothQuant 的招数是数学等价变换：

Y = X · W = (X · diag(s)⁻¹) · (diag(s) · W)

通过选择合适的 s（通常基于激活与权重幅值的几何平均），把激活中的"难量化性"转移到权重上——而权重本来就量化得更好。这一步在离线完成，是编译期变换而非运行期开销，因此推理性能完全等同于普通的 W8A8。

QLoRA：量化基座 + 浮点适配器

QLoRA 把"量化"和"微调"合并为一个流程：用 NF4 把基座模型的权重压到 4 位且冻结，然后在每层旁边附加一对低秩浮点适配器（LoRA）进行训练。结果是——65B 模型可以在单张 48GB 显卡上微调。这不是严格意义上的量化算法，但它定义了"量化推理 + 浮点适配"这一新范式，深刻影响了后续 LLM 部署生态。

GGUF / k-quants：消费级硬件的灵魂

GGUF 是 llama.cpp 项目定义的模型格式，配套的 k-quants 量化方案（Q2_K, Q3_K, Q4_K, Q5_K, Q6_K, Q8_0 等）是为CPU 与消费级 GPU 推理设计的。其特点是混合精度——一个张量内部，重要的"超级块"（super-block）使用更多比特，不重要的部分使用更少比特，整体平均位数可以在 2.5、3.5、4.5 等小数位上灵活配置。这种工程友好性使得 7B 模型能跑在树莓派上、70B 模型能跑在游戏笔记本上。

推理时序

讲了这么多算法，让我们把镜头拉远，看看一次量化推理在系统层面是如何展开的。下面这张时序图刻画了 W4A16 模型（如 GPTQ 量化的 LLaMA）执行单次前向传播的完整调用链。

这张时序图揭示了量化推理性能优化的核心秘诀：反量化必须在片上完成。INT4 权重从 HBM（高带宽显存）加载到 GPU shared memory 时占用的带宽只有 FP16 的 1/4——这才是 W4 量化加速的真正来源。如果反量化后再写回 HBM、再读出来送进 Tensor Core，那么所有带宽优势都将被抵消殆尽。这也是为什么手写 CUDA kernel 在量化推理中如此重要：vLLM 的 Marlin、TensorRT-LLM 的 W4A16 GEMM、ExLlamaV2 的 kernel，全都围绕"在片上 fuse 反量化与矩阵乘"展开。

性能陷阱

很多新手在尝试 INT4 量化时发现"为什么模型变小了但速度没变快？"——99% 的情况是因为推理框架只做了 weight packing 而没有 fused dequant kernel，导致在 batch size = 1 的小负载下根本没有从内存带宽节省中获益。务必使用支持 fused W4A16 GEMM 的推理引擎（vLLM、TensorRT-LLM、ExLlamaV2、llama.cpp）。

Ch. 10

实战代码

理论之后，让我们看看真正的代码。下面三段示例展示了从最简单的动态量化、到 PTQ 校准、再到 LLM 量化的完整工作流。

示例一：PyTorch 动态量化（10 行搞定）

动态量化是最轻量级的量化方式：权重在加载时被量化为 INT8，激活值在每次推理时动态被量化（基于该次前向传播观察到的 min/max），不需要校准数据。它特别适合 RNN、Transformer 的 Linear 层。

import torch
from torch.quantization import quantize_dynamic

# 加载浮点模型
model_fp32 = torch.load("model_fp32.pt")
model_fp32.eval()

# 一行完成动态量化：仅量化 Linear 层为 INT8
model_int8 = quantize_dynamic(
    model_fp32,
    {torch.nn.Linear},   # 指定要量化的模块类型
    dtype=torch.qint8
)

# 比较模型大小
torch.save(model_fp32.state_dict(), "fp32.pt")
torch.save(model_int8.state_dict(), "int8.pt")
# int8.pt 通常约为 fp32.pt 的 25%

# 推理使用方式完全相同
output = model_int8(input_tensor)

示例二：静态 PTQ 校准（典型工业流程）

静态量化精度更高，因为激活的 (s, z) 通过校准数据预先确定，运行时无需动态计算。代价是需要数百到数千个代表性样本来做校准。

import torch
from torch.quantization import get_default_qconfig, prepare, convert

# Step 1: 设置量化配置（per-channel 权重 + per-tensor 激活）
model.qconfig = get_default_qconfig("fbgemm")  # x86 后端

# Step 2: 插入观察者（observer），但还不真正量化
model_prepared = prepare(model, inplace=False)

# Step 3: 喂入校准数据，让 observer 收集激活分布统计量
with torch.no_grad():
    for images, _ in calibration_loader:
        model_prepared(images)
        # 不需要 backward，不需要标签

# Step 4: 转换为真正的 INT8 模型
model_int8 = convert(model_prepared, inplace=False)

# Step 5: 评估精度并对比
acc_fp32 = evaluate(model, val_loader)
acc_int8 = evaluate(model_int8, val_loader)
print(f"FP32: {acc_fp32:.2%} → INT8: {acc_int8:.2%}")

示例三：用 GPTQ 量化 LLaMA（HuggingFace + auto-gptq）

from transformers import AutoModelForCausalLM, AutoTokenizer
from auto_gptq import BaseQuantizeConfig

# 量化配置：4-bit, group size 128, 对称量化
quantize_config = BaseQuantizeConfig(
    bits=4,
    group_size=128,
    desc_act=False,         # 是否按激活幅值降序量化（精度↑速度↓）
    damp_percent=0.01,      # Hessian 阻尼项
)

# 加载原始 FP16 模型
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    quantize_config=quantize_config,
    torch_dtype=torch.float16,
)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3-8B")

# 准备 128 条校准样本（C4、wikitext 等通用语料）
calibration_data = []
for text in load_calibration_corpus(n=128):
    encoded = tokenizer(text, return_tensors="pt", max_length=2048, truncation=True)
    calibration_data.append(encoded)

# 执行 GPTQ 量化（约 30 分钟 / 8B 模型 / 单 A100）
model.quantize(calibration_data)

# 保存量化模型
model.save_quantized("./llama3-8b-gptq-4bit")

# 推理：使用方式与原模型完全相同，但占用显存仅 ~5GB
output = model.generate(input_ids, max_length=256)
最佳实践

校准数据的选择对 PTQ 至关重要：使用与目标推理域分布相似的样本，但不要使用训练集本身（容易过拟合 outliers）。100~512 个 2048-token 序列对 LLM 量化通常已经足够；图像分类则建议 200~1000 张验证集图像。

Ch. 11

硬件版图

量化算法的最终归宿是硬件。一个数值格式只有当目标硬件原生支持时，量化才能真正带来速度收益——否则你只是在 FP16 上模拟整数运算，反而更慢。下表是当前主流 AI 加速器对各种数值格式的支持矩阵。

硬件FP16BF16FP8INT8INT4
NVIDIA H100 / B200✓✓✓ 原生✓✓ TC
NVIDIA A100✓✓—✓ TC稀疏 TC
NVIDIA RTX 40/50✓✓✓ 部分✓✓ TC
AMD MI300X✓✓✓✓—
Apple Silicon (ANE)✓——✓✓ 软件
Google TPU v4/v5✓✓✓✓—
Intel Xeon (AMX)✓✓—✓ 原生—
ARM (Neon/SVE)✓✓—✓软件

TC = Tensor Core 加速；"原生"指有专用计算单元；"软件"指通过位操作模拟，无加速增益。

这张表里有几个关键认知值得反复回味：

  • FP8 是 H100/B200 的"专属红利"。在 A100 上做 FP8 推理只是为了节省内存，速度上反而不如 INT8。
  • INT4 在消费级 GPU 上的速度优势主要来自带宽，而非计算吞吐——RTX 4090 的 INT4 Tensor Core 吞吐确实高，但小 batch 推理瓶颈在显存带宽，因此 7B 模型 INT4 推理速度通常是 FP16 的 1.5~2 倍而不是 4 倍。
  • 苹果芯片的 ANE（Apple Neural Engine）对 INT8 极其友好，但 INT4 需要软件实现；这就是为什么 MLX 框架优先支持 4-bit 权重 + 软件反量化路径。
Ch. 12

陷阱与抉择

本章是写给即将真正动手做量化的工程师的。下面这些坑、决策点和经验法则，几乎每一个都来自真实的"翻车现场"。

常见陷阱

  1. 校准数据偏移：在 ImageNet 上校准的 ResNet 拿去做医学图像分类，量化精度可能崩溃 5~10%。规则：校准数据必须代表实际推理分布。
  2. BatchNorm 折叠忘记同步：QAT 的 BN 层处理是个微妙的工程，未折叠或折叠时机错误会导致训练发散或部署精度下降。规则：使用框架提供的 fuse_modules，不要手写。
  3. 逐层精度退化的诊断：当量化模型整体精度下降时，往往是 1~2 个特定层的灾难性放大导致的。规则：用 per-layer SQNR（信噪比）排查，找到精度损失最严重的层并切回 FP16（混合精度）。
  4. LLM 第一层与最后一层的特殊性：embedding 层和 lm_head 通常对量化敏感，主流方案（如 GPTQ、AWQ）默认保留它们为 FP16，不要轻易尝试量化它们。
  5. 动态范围溢出：累加器溢出在 INT8 推理中并不罕见，特别是输入序列很长或矩阵尺寸很大时。规则：使用 INT32 累加器（这是大多数框架的默认行为），但要确认导出格式没有"省略"这一点。

抉择决策树

三条经验法则

法则一：永远先做 baseline。在尝试任何复杂量化方案之前，先用最朴素的对称 INT8 PTQ 跑一遍，看看精度损失有多大。如果损失在可接受范围内，就此打住——工程上越简单的方案越值得选。

法则二：量化是端到端工程，不是孤立的算法步骤。校准数据、模型结构、推理框架、目标硬件，任意一个环节出问题都会让量化"失效"。从一开始就要考虑全链路。

法则三：保留浮点逃生通道。对于关键层（embedding、lm_head、softmax 前的 projection），不要害怕保留 FP16——混合精度量化往往能用极小的内存代价换回大量精度。

"好的量化方案，是让模型在不知道自己被量化的情况下，依然忠实地完成任务。"

未来的方向

2024-2025 是 LLM 量化技术快速演进的一年。FP8 训练正在成为前沿大模型的默认配置（如 DeepSeek-V3、Llama 3.1 系列的训练管线）；1.58-bit 量化（BitNet）展示了"加法即乘法"的极端可能性，三值权重 {-1, 0, +1} 让矩阵乘退化为加减法；KV 缓存量化（KIVI、Atom 等）正在解决长上下文推理的内存瓶颈；而 MX 格式（Microscaling Format）作为 OCP 推动的统一标准，可能会让"格式碎片化"在未来收敛。

无论技术如何演进，量化的底层哲学不会变：用尽可能少的比特，表达尽可能丰富的语义。这是信息论的永恒主题，也是工程师永不停歇的优化战场。
