1. du 是什么：目录树磁盘用量核算器

du 是 disk usage 的缩写。它不是看磁盘分区还剩多少空间，而是核算某个文件或目录树实际消耗了多少磁盘块。AI Infra 中常见问题是“训练节点磁盘满了，谁占用最多？”这时第一反应通常不是 ls -lh，而是从挂载点或工作目录开始用 du 分层缩小范围。

它回答
/data/jobs/exp42 这个目录树累计占用了多少空间？哪一级目录最大？
它不回答
整个文件系统剩余多少空间、inode 是否耗尽、某个已删除但仍被进程打开的文件是否占空间。
AI Infra 高频对象
数据集副本、tokenized shards、模型 checkpoint、tensorboard event、wandb/mlflow 缓存、容器层和日志。
# 看当前目录总用量
du -sh .

# 看 /data 下第一层目录各占多少
du -h --max-depth=1 /data

# 排序找最大目录
du -h --max-depth=1 /data | sort -h
不要误读： du 默认显示的是磁盘块占用，不一定等于文件“逻辑长度”；稀疏 checkpoint、压缩文件系统、快照和硬链接都可能让结果看起来反直觉。

信息图：du 的整体心智模型

理解 du 的关键是：它沿目录树累加“分配给文件的块”，而不是简单把 ls -l 的字节长度相加。

2. 核心模型：遍历、stat、块数、汇总

du 的执行模型可以拆成四步：从起点路径开始，递归遍历目录项；对每个文件读取元数据；取文件系统记录的已分配块数；把子目录结果向父目录累加。这个模型解释了为什么权限、挂载边界、硬链接、稀疏文件和快照会影响结果。

阶段du 在做什么常见影响因素
遍历读取目录项，进入子目录权限不足、目录项过多、远端文件系统慢
读取元数据获取大小、块数、inode、链接等信息stat 调用量、FUSE/NFS 响应速度
核算默认按已分配块计入大小稀疏文件、压缩、去重、硬链接
输出按目录层级输出或只汇总-s、-h、--max-depth、排序管道
# 心智模型对应到命令：限制范围、控制输出、再排序
du -xh --max-depth=1 /data 2>/tmp/du.err | sort -hr | head -20
核心判断： 如果你关心“文件系统为什么满”，用默认 du 的块占用口径；如果你关心“这些文件逻辑上有多大”，再加 --apparent-size 交叉验证。

3. 最常用命令：du -sh 与单位选择

du -sh PATH 是排查磁盘占用时最常见的入口：-s 汇总总量，-h 用 KiB/MiB/GiB/TiB 等人类可读单位显示。没有 -s 时，du 会输出遍历到的各级目录用量。

命令含义AI Infra 用法
du -sh .当前目录总量看一个实验目录整体是否异常膨胀
du -sh /data/*看第一层每个对象总量快速比较 datasets、models、runs、logs
du -sk path以 KiB 输出脚本中更稳定，便于数值比较
du -sb path以字节输出GNU 常见；跨平台要确认支持
# 训练工作目录整体占用
du -sh /data/train-runs/exp-042

# 看用户缓存目录
du -sh ~/.cache ~/.cache/huggingface ~/.cache/torch 2>/dev/null

# 脚本中用固定单位，避免解析 1.5G / 800M
du -sk /data/datasets/imagenet
单位提示： GNU du -h 通常使用 1024 进制；如果团队报表要求十进制 GB，可确认是否支持 --si。

4. 目录深度：--max-depth / -d

AI 训练目录通常层级很深，直接 du -h /data 会输出海量行。深度控制让你像剥洋葱一样定位：先看第一层，再进入最大的目录看下一层。

命令作用备注
du -h --max-depth=1 /data显示 /data 及其直接子目录GNU 常见写法
du -h -d 1 /data同样限制深度为 1BSD/macOS 常见写法，GNU 也支持
du -h --max-depth=2 runs显示到第二层适合实验/用户/任务三级结构
du -sh runs/*由 shell 展开第一层目录很多时可能触发参数过长
# 从挂载点开始定位第一层
du -h --max-depth=1 /data | sort -h

# 进入最大目录后继续下钻
du -h --max-depth=1 /data/train-runs | sort -h

# 第二层看用户目录下每个项目
du -h --max-depth=2 /data/users/alice | sort -h | tail -30
定位策略： 每轮只扩大一个层级，始终用 sort -h | tail 看最大项；不要一开始全盘递归输出再人工翻屏。

流程图：分层定位磁盘大户

用 du 排查磁盘告警时，核心动作是“分层汇总、排序、进入最大项、重复”。

5. 排序找大户：du + sort + head

du 负责核算，sort -h 负责人类可读单位排序，tail 或 head 负责截取最大/最小项。这个组合是 AI Infra 磁盘排障的基础套路。

# 当前目录第一层，从小到大
du -h --max-depth=1 . | sort -h

# 只看最大的 20 个目录
du -h --max-depth=1 /data | sort -h | tail -20

# 反向排序，看最大的在前
du -h --max-depth=1 /data | sort -hr | head -20

# 固定 KiB 输出，更适合脚本阈值判断
du -sk /data/* 2>/dev/null | sort -n | tail -20
目标推荐命令原因
人手排查du -h --max-depth=1 PATH | sort -h可读性好
脚本报警du -sk PATH固定单位，便于比较
最大 N 个目录sort -hr | head -N大项在前
兼容旧环境du -k ... | sort -n不依赖 sort -h
排序注意： 如果你的系统没有 sort -h，不要对 -h 输出做普通字典序排序；改用 du -k | sort -n。

6. AI Infra 场景：数据集、checkpoint、日志、缓存

AI Infra 的磁盘增长通常不是单个随机文件，而是某类对象持续累积。用 du 的目标不是“立刻删”，而是把大类对象拆清楚：谁生成、是否还在使用、是否可重建、是否有保留策略。

数据集
原始压缩包、解压副本、预处理 shard、tokenized cache、重复下载。
Checkpoint
每 N step 保存、optimizer state、EMA、LoRA adapter、best/latest 软链接。
日志
tensorboard event、训练 stdout、debug dump、NCCL 日志、core dump。
缓存
Hugging Face、pip、conda、torch extensions、容器镜像层。
# 数据集目录第一层
du -h --max-depth=1 /data/datasets | sort -hr | head -30

# checkpoint 目录按实验排序
du -h --max-depth=2 /data/train-runs | sort -hr | head -50

# 常见用户缓存
du -sh ~/.cache/huggingface ~/.cache/torch ~/.cache/pip ~/.conda 2>/dev/null

# 日志目录定位
du -h --max-depth=2 /var/log /data/logs 2>/dev/null | sort -hr | head -40
清理边界： 训练仍在运行时不要直接删除 checkpoint 或日志；先用 lsof +D DIR、作业系统、实验跟踪平台或目录 owner 确认使用状态。

7. 磁盘占用 vs 表观大小：--apparent-size

默认 du 统计的是文件实际分配的磁盘块。--apparent-size 统计文件逻辑长度，更接近 ls -l 看到的 size。两者差异常见于稀疏文件、小文件块浪费、压缩/去重文件系统和对象存储挂载。

视角命令含义适用场景
实际占用du -sh path文件系统分配了多少块排查磁盘满、容量规划
表观大小du -sh --apparent-size path文件逻辑长度累加估算传输量、对象逻辑体积
文件长度ls -lh file单个目录项记录的长度查看单文件元数据
# 比较 checkpoint 的实际占用和表观大小
du -sh /data/runs/exp42/checkpoint-10000
du -sh --apparent-size /data/runs/exp42/checkpoint-10000

# 稀疏文件演示：逻辑上 10G，实际可能很小
truncate -s 10G sparse.bin
ls -lh sparse.bin
du -h sparse.bin
du -h --apparent-size sparse.bin
rm sparse.bin
关键 caveat： 复制稀疏文件时，如果工具不保留 sparse 属性，目标端实际占用可能暴涨；迁移 checkpoint、镜像或虚拟磁盘前要确认复制工具参数。

对比图：块占用、表观大小、df 的不同视角

排查“磁盘满”先用 df 看分区，再用 du 在挂载点内定位目录树大户。

8. 稀疏文件、硬链接与重复统计 caveat

AI 系统中可能出现稀疏文件、硬链接数据集、共享缓存和快照。它们会让“看起来的大小”和“真实占用”偏离直觉。du 有去重硬链接的默认行为，但不同参数、不同起点和不同文件系统特性会影响结果。

现象原因排查方式
ls -lh 很大，du -h 很小稀疏文件未实际分配全部块比较 du 与 du --apparent-size
多个路径看似重复，合计却不翻倍硬链接指向同一 inode，du 通常只计一次ls -li 看 inode 和 link count
快照目录占用难理解CoW/快照共享块，释放策略依赖文件系统结合 btrfs/zfs/lvm 工具查看
对象存储挂载结果奇怪FUSE 层可能模拟 stat 信息用后端对象清单或云端计量交叉验证
# 查看 inode，识别硬链接
ls -li dataset-a/file.bin dataset-b/file.bin

# du 默认通常不重复计入同一硬链接文件
du -sh dataset-a dataset-b

# 如果确实要把每个硬链接路径都计入，可查看系统是否支持 -l
du -sh -l dataset-a dataset-b
工程建议： 对共享数据集、快照和缓存做容量报表时，先定义口径：按路径逻辑大小、按实际块占用，还是按用户/项目 chargeback 规则分摊。

9. 文件系统边界：--one-file-system / -x

集群节点常见多个挂载点：本地 NVMe、共享 NFS、对象存储 FUSE、容器 overlay、作业临时盘。默认 du / 可能跨入其他挂载点，导致扫描很慢或统计范围错误。-x 或 --one-file-system 可以限制在起点所在文件系统内。

# 查看挂载点和文件系统
df -hT / /data /scratch 2>/dev/null
findmnt /data

# 只统计 /data 所在文件系统，不跨入其他挂载
du -xh --max-depth=1 /data | sort -h

# 排查根目录时避免跨入 /proc /sys /run /data 等其他文件系统
sudo du -xh --max-depth=1 / 2>/dev/null | sort -h
场景风险建议
根目录排查跨入 NFS 或容器挂载，扫描巨大du -x 并排除虚拟文件系统
共享存储一个节点上扫描影响元数据服务限制深度，避开高峰，优先按项目目录查
容器内排查overlay 与宿主机视角不同同时看容器内路径和宿主机 overlay 目录
边界提醒： -x 的含义是“不跨越文件系统边界”，不是“不跨目录边界”；先用 df 或 findmnt 确认起点所在挂载。

10. 包含/排除路径：--exclude 与 shell glob

排查时经常需要跳过超大但已知的目录，例如缓存、虚拟环境、对象存储挂载或旧归档。GNU du 支持 --exclude；跨平台脚本要先确认目标系统实现。

# 跳过 .git 和 Python 虚拟环境
du -h --max-depth=2 --exclude='.git' --exclude='.venv' .

# 只看 checkpoint 目录
du -sh /data/train-runs/*/checkpoint-* 2>/dev/null

# 用 find 精确选择目录，再交给 du 汇总
find /data/train-runs -maxdepth 2 -type d -name 'checkpoint-*' -print0 |
  xargs -0 du -sh 2>/dev/null |
  sort -h
glob 限制： /data/* 由 shell 展开，目录过多时可能报 “argument list too long”。这时用 find -print0 | xargs -0 更稳。

11. du vs df：为什么结果不一致

df 看文件系统级别的已用/可用空间，du 看路径树内可遍历文件的累计占用。两者不一致非常常见，尤其是日志被删除但进程仍打开、权限导致 du 看不到部分目录、文件系统元数据/保留块、快照或挂载边界混乱。

现象可能原因下一步
df 很满，du 找不到大目录已删除但仍被进程打开的文件、权限不足、隐藏挂载点sudo lsof +L1，用 sudo du，检查 findmnt
du 统计很大，df 变化不明显统计路径不在目标文件系统、硬链接/快照/压缩影响df path 确认挂载点
删除大文件后空间没释放进程仍持有文件句柄，或快照保留块重启/关闭相关进程，检查快照
# 先确认哪个文件系统满
df -hT

# 在对应挂载点内分层找大户
sudo du -xh --max-depth=1 /data 2>/dev/null | sort -h

# 找已删除但仍占空间的文件
sudo lsof +L1 | sort -k7 -n | tail -20
生产警告： 不要因为 du 暂时没找到大目录就随机删除；先确认 df 的目标挂载点、权限和已删除打开文件。

选择图：du、df、find、ncdu、ls 怎么选

先用 df 判断哪个文件系统满，再用 du 找目录，用 find 找具体文件，用 ncdu 做交互式浏览。

12. du vs find/ncdu/ls：工具边界

工具强项短板AI Infra 用法
du目录树汇总、容量核算不擅长按 mtime/name 精确筛选单文件找最大目录、容量报表
find按大小、时间、名称、类型筛选默认不汇总目录树找大 checkpoint、旧日志、core dump
ncdu交互式浏览，体验好可能未安装，不适合自动化人工排查复杂目录树
df文件系统容量视角不能告诉你目录大户告警入口、确认挂载点
ls/stat单文件元数据不递归汇总检查 inode、mtime、逻辑大小
# 找超过 20G 的单文件，适合 checkpoint / core dump
find /data -xdev -type f -size +20G -print 2>/dev/null

# 找 14 天前的训练日志，先打印确认，不直接删除
find /data/logs -type f -name '*.log' -mtime +14 -print

# 如果安装了 ncdu，可在大目录中交互式浏览
ncdu -x /data
组合思路： du 先定位“哪个目录大”，find 再定位“哪些文件满足清理条件”。

13. 权限、性能与大目录扫描策略

du 需要遍历目录项并读取元数据，面对数千万小文件、NFS 元数据瓶颈、对象存储 FUSE 或容器 overlay 时可能很慢。权限不足会导致低估用量并输出 “Permission denied”。

权限不足
用普通用户看不到其他用户目录时，结果不完整；容量排障可用 sudo du，但要谨慎控制范围。
元数据压力
du 会触发大量 stat/readdir，对共享存储可能造成压力；优先限制深度和路径。
脚本自动化
用固定单位、超时控制、低频采样；不要每分钟全量扫大型 NFS。
# 控制范围，只看一个挂载点第一层
sudo du -xh --max-depth=1 /data 2>/tmp/du-errors.log | sort -h

# 后台低优先级扫描，降低对训练任务影响
ionice -c3 nice -n 19 du -xh --max-depth=2 /data > /tmp/du-data.txt 2>/tmp/du-data.err

# 只查项目目录，不扫整个共享存储
du -h --max-depth=1 /data/projects/team-a | sort -hr | head -30
共享存储提醒： 在元数据服务紧张时，全量 du 可能影响训练启动和 dataloader；优先使用存储系统 quota/report，或在维护窗口扫描。

14. 安全清理流程：从定位到删除前确认

du 本身是只读工具，但它常出现在清理前。安全流程应该把“定位”和“删除”拆开：先证明对象确实大，再证明对象可删除，最后执行可回滚或可审计的清理。

推荐流程

# 1. 确认哪个文件系统满
df -hT /data

# 2. 分层定位大目录
du -xh --max-depth=1 /data | sort -hr | head -20
du -xh --max-depth=1 /data/train-runs | sort -hr | head -20

# 3. 找候选文件，只打印
find /data/train-runs/exp42 -type f -name '*.pt' -mtime +30 -size +5G -print

# 4. 抽样确认归属和最近访问/修改时间
ls -lh /data/train-runs/exp42/checkpoint-10000/model.pt
stat /data/train-runs/exp42/checkpoint-10000/model.pt

# 5. 删除前可先移动到隔离目录，观察一段时间
mkdir -p /data/.trash-review/exp42
mv /data/train-runs/exp42/checkpoint-10000 /data/.trash-review/exp42/
不要直接复制粘贴删除： 把 find ... -delete、rm -rf 放在最后一步；执行前先把同一选择条件用 -print 完整审查。
对象删除前必须确认更安全替代
checkpoint是否是 latest/best、是否需恢复训练、是否归档保留 best/latest，移动旧 step 到隔离区
数据集 shard是否可重建、是否被多个任务共享记录来源和生成命令，先降副本数
日志是否仍被进程写入、是否用于审计压缩、轮转、保留近期窗口
缓存是否团队共享、重建成本用工具自带 prune/clean 命令

安全图：从告警到清理的守门点

清理事故通常不是 du 造成的，而是把“找到大文件”误当成“可以删除”。

15. 排障：du 慢、报错、数值不符合预期

慢：目录项太多
先限制 --max-depth 和起点；对共享存储用低优先级扫描。
慢：跨入远端挂载
加 -x，用 findmnt 检查挂载边界。
Permission denied
普通用户结果可能低估；容量排障用 sudo du 并记录错误日志。
结果和 df 不一致
检查已删除打开文件、快照、保留块、文件系统元数据和权限。
结果和 ls 不一致
检查稀疏文件、块大小、压缩/去重和 --apparent-size。
排序错乱
没有 sort -h 时用 du -k | sort -n。

排障命令模板

# 记录错误，避免 stderr 混入排序
sudo du -xh --max-depth=1 /data 2>/tmp/du.err | sort -hr | head -30

# 验证路径所在文件系统
df -hT /data/some/path
findmnt -T /data/some/path

# 查 deleted open files
sudo lsof +L1 | awk '{print $7, $9}' | sort -n | tail -20

# 对比实际块占用与表观大小
du -sh big-file
du -sh --apparent-size big-file

16. 常用命令速查

目标命令
当前目录总大小du -sh .
第一层目录大小du -h --max-depth=1 . | sort -h
最大 20 个目录du -h --max-depth=1 PATH | sort -hr | head -20
只在当前文件系统内统计du -xh --max-depth=1 PATH
脚本友好 KiB 输出du -sk PATH
比较表观大小du -sh --apparent-size PATH
跳过目录du -h --exclude='.git' --max-depth=2 .
找大文件find PATH -xdev -type f -size +10G -print
交互式查看ncdu -x PATH
df/du 不一致排查sudo lsof +L1
记忆法： df 看“盘”，du 看“目录树”，find 找“文件”，ncdu 做“交互浏览”。

17. 练习任务

基础练习

  1. 在一个实验目录中分别运行 du -sh . 和 du -h --max-depth=1 . | sort -h，解释每一行含义。
  2. 用 du -sk 写一个脚本片段：当目录超过 500 GiB 时打印告警。
  3. 创建一个稀疏文件，对比 ls -lh、du -h 和 du -h --apparent-size。
  4. 用 df -hT 找到某路径所在文件系统，再用 du -x 限制扫描范围。
  5. 用 find 只打印 30 天前、超过 5 GiB 的 checkpoint 候选，不执行删除。
