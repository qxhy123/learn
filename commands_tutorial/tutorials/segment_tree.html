1. 线段树是什么

线段树（Segment Tree）是一种针对区间问题设计的数据结构。它把数组区间反复二分，构造成一棵二叉树，每个节点代表一个连续区间，例如 [l, r]，并存储这个区间上的某种统计信息。

对象
一个长度为 n 的数组或值域区间。
节点含义
每个节点不是单个元素，而是一个区间。
核心用途
高效处理“区间查询 + 修改”的组合问题。

线段树擅长什么

操作类型是否适合线段树原因
区间求和 / 最值 / gcd非常适合可由左右子区间合并
单点修改非常适合只影响一条根到叶子的路径
区间加 / 区间赋值适合可配合懒标记
静态区间查询，无修改不一定最优前缀和或 ST 表可能更简单
注意： 线段树不是为了“所有问题都变快”，它的主要价值是在 区间信息需要频繁查询，且数组又会被修改 时体现出来。

信息图：为什么前缀和不够用了

线段树的存在意义，几乎可以浓缩成一句话：前缀和太偏向查询，暴力法太偏向修改，而线段树在两者之间取得了结构化平衡。

2. 第一性原理：为什么需要线段树

设有一个数组 a[1..n]，我们要支持两类操作：

  • 查询某个区间 [L, R] 的和、最值等；
  • 修改某个位置，甚至修改某个区间。

如果没有修改，那么前缀和很强；如果没有查询，那么直接改数组即可。但只要“查询和修改同时频繁出现”，很多简单方法都会失效。

初始数组：2 1 5 3 4 6 7 8
操作 1：查询 [2, 6] 的和
操作 2：把 a[4] 改成 100
操作 3：再查询 [2, 6] 的和
操作 4：把区间 [3, 7] 每个数都加 5
操作 5：查询 [1, 8] 的最大值
核心洞察： 很多区间统计都具有“可合并性”。只要一个大区间的答案可以由左右子区间的答案合成，那么线段树就有机会发挥作用。

3. 区间分治的本质

线段树的根节点表示整个区间 [1, n]。然后不断二分：

  • 左孩子表示 [l, mid]
  • 右孩子表示 [mid+1, r]

直到区间长度为 1，叶子节点对应原数组中的单个元素。

answer([l, r]) = merge(answer([l, mid]), answer([mid+1, r]))
第一性原理版定义： 线段树其实就是一种“把大区间答案递归分解为小区间答案，再用 merge 规则拼回去”的数据结构。

结构图：一棵线段树长什么样

线段树不是“值的树”，而是“区间的树”。真正理解这一点后，后面的建树、查询、更新都会变得自然。

4. 节点到底维护什么

很多初学者只记住“线段树能查区间和”，但其实线段树的灵魂并不是“和”，而是：节点中维护的统计信息，以及左右子区间如何合并。

维护值节点含义合并方式
sum区间和sum = left.sum + right.sum
mx区间最大值mx = max(left.mx, right.mx)
mn区间最小值mn = min(left.mn, right.mn)
gcd区间 gcdgcd = gcd(left.gcd, right.gcd)
cnt某种计数按题意合并
最关键的判断标准： 只要一个区间答案可以由左右子区间答案在 O(1) 或较低代价下合并出来，就有很大概率能用线段树。

5. 线段树的结构与编号

实现线段树常有两种方式：

  • 数组实现（最常见）：把树节点存在数组中，根为 1，左孩子是 2*u，右孩子是 2*u+1。
  • 指针实现：显式建节点对象，适合动态开点或复杂场景。

虽然线段树实际节点数不到 4n，但为了简化数组映射，竞赛和面试里通常直接开 tree = [0] * (4*n)。

记住： 数组下标代表的是“树节点编号”，不是原数组下标。一个树节点往往同时需要知道它代表的区间 [l, r]。

6. 建树：Build

def build(u, l, r):
    if l == r:
        tree[u] = a[l]
        return

    mid = (l + r) // 2
    build(u * 2, l, mid)
    build(u * 2 + 1, mid + 1, r)
    tree[u] = tree[u * 2] + tree[u * 2 + 1]
  1. 如果当前区间只剩一个元素，那么这是叶子节点，直接赋值。
  2. 否则把区间切成左右两半。
  3. 递归建左子树与右子树。
  4. 用 merge 规则把两个子区间的答案合并成当前区间答案。
为什么是 O(n)： 线段树总节点数是 O(n)，每个节点只会被处理一次，所以建树复杂度不是 O(n log n)，而是 O(n)。

流程图：建树过程是怎样自底向上汇总的

建树的方向是“先到底，再向上合并”。叶子节点来自原数组，内部节点来自 merge。

7. 区间查询：Query

def query(u, l, r, L, R):
    if L <= l and r <= R:
        return tree[u]

    mid = (l + r) // 2
    ans = 0
    if L <= mid:
        ans += query(u * 2, l, mid, L, R)
    if R > mid:
        ans += query(u * 2 + 1, mid + 1, r, L, R)
    return ans

查询的三种关系：

  • 完全覆盖：当前节点区间完全落在查询区间内，直接返回该节点信息。
  • 完全无关：当前节点区间和查询区间无交集，直接忽略。
  • 部分相交：继续递归下探左右子树。
一个非常关键的理解： 查询不是遍历所有区间，而是把 [L, R] 表示成若干个线段树节点区间的并。

区间拆分图：查询 [2, 7] 时，线段树如何分解

线段树查询的本质，是把目标区间拆成少量节点区间。这种表示通常只需要 O(log n) 个节点。

8. 单点修改：Update Point

def update(u, l, r, pos, val):
    if l == r:
        tree[u] = val
        return

    mid = (l + r) // 2
    if pos <= mid:
        update(u * 2, l, mid, pos, val)
    else:
        update(u * 2 + 1, mid + 1, r, pos, val)

    tree[u] = tree[u * 2] + tree[u * 2 + 1]

因为每层只会走一个分支，树高是 O(log n)，回溯时重新计算祖先节点信息即可。

时序图：单点修改如何沿路径下传再回溯

单点修改的核心是“定位到叶子 + 回溯重算祖先”，因此复杂度与树高成正比。

9. 区间修改：Lazy Propagation（懒标记）

当我们要对整个区间 [L, R] 都做修改时，如果一个个下沉到叶子，会退化成 O(n)。懒标记的核心思想是：先把这次更新记在当前节点上，等将来真的需要访问子节点时再下推。

若节点 u 表示区间 [l, r]，要给整个区间都加 x：

  • tree[u] += (r - l + 1) * x
  • lazy[u] += x
def push_down(u, l, r):
    if lazy[u] == 0:
        return
    mid = (l + r) // 2
    add = lazy[u]

    tree[u * 2] += (mid - l + 1) * add
    tree[u * 2 + 1] += (r - mid) * add

    lazy[u * 2] += add
    lazy[u * 2 + 1] += add
    lazy[u] = 0
def range_add(u, l, r, L, R, val):
    if L <= l and r <= R:
        tree[u] += (r - l + 1) * val
        lazy[u] += val
        return

    push_down(u, l, r)
    mid = (l + r) // 2

    if L <= mid:
        range_add(u * 2, l, mid, L, R, val)
    if R > mid:
        range_add(u * 2 + 1, mid + 1, r, L, R, val)

    tree[u] = tree[u * 2] + tree[u * 2 + 1]
一句话抓住懒标记： 节点的区间值先更新，子节点的具体更新先欠着，等需要时再还。

示意图：懒标记到底在“懒”什么

懒标记不是偷懒不做，而是“延迟做”。它把大区间更新的成本压缩到了少量相关节点上。

10. 动态开点与可持久化思路

如果值域很大，比如 [1, 10^9]，但真正访问的位置很少，可以使用动态开点线段树：只有在访问到某个区间时，才创建对应节点。

如果需要保存每次修改后的历史版本，可以使用可持久化线段树：每次修改只复制根到叶子路径上的节点，其他未修改部分共享旧节点。

进阶版本适用场景核心思路
动态开点值域大、访问稀疏按需创建节点
可持久化查询历史版本、主席树路径复制，版本共享

11. 与前缀和 / 树状数组 / 分块的比较

数据结构区间查询单点修改区间修改适用场景
前缀和快（常 O(1)）慢（常 O(n)）慢静态区间和
树状数组前缀和 / 某些区间和快快（O(log n)）部分支持实现简洁的求和类问题
分块中等中等中等实现简单，复杂度折中
线段树快（O(log n)）快（O(log n)）快（O(log n)，需懒标记）复杂动态区间问题
一个实战判断： 如果题目只是“单点改 + 前缀和 / 区间和”，树状数组常更省事；如果题目要维护复杂区间状态，优先考虑线段树。

12. 经典题型

  • 区间和 + 单点修改：最经典入门题。
  • 区间最大值 / 最小值：只要替换 merge 逻辑。
  • 区间加法 + 区间和：懒标记标准模板题。
  • 最大子段和：节点维护 sum / lmax / rmax / tmax。
  • 区间赋值 / 翻转 / 覆盖：难点是懒标记之间的组合关系。

13. 复杂度分析与常见坑

操作复杂度说明
建树O(n)每个节点只处理一次
区间查询O(log n)访问少量相关节点
单点修改O(log n)只影响一条路径
区间修改（懒标记）O(log n)通过延迟下传压缩代价
空间复杂度O(n)数组实现常开 4n
坑 1：下标混乱
原数组是 0-based 还是 1-based，一定要统一。
坑 2：mid 写错
尤其在区间边界和左右儿子区间划分时最容易出错。
坑 3：push_up 忘了写
修改完子节点后，父节点必须重新合并。
坑 4：push_down 时长度算错
区间和题里左右子区间长度必须准确。
坑 5：懒标记没清零
下推后如果不清空当前标记，会重复下推。
坑 6：区间覆盖判断不完整
完全覆盖、无交集、部分相交三类关系要分清。
最深层的错误来源： 绝大多数线段树 bug，不是代码敲错，而是“节点语义、区间语义、merge 语义和 lazy 语义”没有先想清楚。

14. 刷题路线与练习建议

阶段建议题型训练目标
入门区间和 + 单点修改掌握 build / query / update 基本框架
基础区间最值、gcd掌握 merge 的替换思维
进阶区间加法 + 区间和掌握 lazy propagation
强化区间赋值、翻转、覆盖掌握复杂标记组合

  1. 每写一道线段树题，先用自然语言写清楚“节点维护什么”。
  2. 再写清楚 merge 规则。
  3. 如果有修改，再明确“修改如何作用到节点值”和“lazy 如何传播”。
  4. 最后再开始写代码。
最有效的训练法： 同一道题分别用暴力、前缀和、树状数组、线段树思考一遍，你会真正感受到线段树的存在价值，而不是死背模板。

最终总结：线段树的核心心法

  1. 线段树是一棵“区间递归切半”的二叉树，不是普通值树。
  2. 每个节点维护的是一个区间的统计信息，关键在于节点语义。
  3. 只要大区间答案能由左右子区间答案 merge 出来，线段树就有机会适用。
  4. 建树是自底向上汇总，因此复杂度是 O(n)。
  5. 查询的本质是把目标区间拆成少量节点区间，因此通常是 O(log n)。
  6. 单点修改只影响一条路径，因此也是 O(log n)。
  7. 懒标记的本质是“先更新当前节点，再延迟对子节点的传播”。
  8. 线段树比树状数组更通用，但实现也更复杂。
  9. 真正写对线段树的关键，不是模板，而是：节点维护什么、merge 怎么写、lazy 怎么解释。

推荐复习主线：区间和建树 → 区间查询 → 单点修改 → 区间加法懒标记 → 区间最值 → 区间赋值 → 最大子段和 → 动态开点 / 可持久化。
