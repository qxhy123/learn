rg / ripgrep 深度教程：面向 AI Infra 的高速代码与日志搜索

这份教程围绕 rg（ripgrep）讲解：它如何递归搜索代码和日志，如何尊重 .gitignore，如何用 glob、文件类型、上下文、JSON、多行、PCRE2、压缩日志和二进制策略把搜索变成可靠的 AI Infra 排障工具。重点不是背选项，而是建立“候选文件集合 → 正则匹配 → 输出给人或机器”的心智模型。

一句话理解： rg 是“默认懂项目边界的递归 grep”：它自动跳过 ignored、hidden、binary 文件，优先让你在大型代码仓库和海量日志目录里快速看到高信号匹配。

1. rg 是什么：AI Infra 为什么常用它

rg 是一个递归文本搜索工具。它通常比传统 grep -R 更适合现代工程仓库：默认尊重 .gitignore，跳过隐藏目录和二进制文件，输出格式适合人类阅读，也能用 --json 交给自动化脚本处理。

代码搜索
快速定位配置项、实验开关、CUDA/NCCL 调用、Kubernetes YAML、模型服务路由和 Python/Go/Rust 源码中的关键路径。
日志搜索
在训练日志、推理服务日志、驱动日志和容器日志中查找 OOM、NCCL WARN、timeout、rank、CUDA error 等证据。
自动化入口
用 rg -l、rg --files、rg --json 把“查找”变成下游脚本的安全输入，而不是手工复制终端输出。
# 在当前仓库递归搜索，默认跳过 .gitignore 中排除的路径
rg 'NCCL|CUDA|OOM'

# 搜索指定目录
rg 'error|timeout' logs/ services/

# 只列出包含匹配的文件，适合交给后续命令
rg -l 'old_endpoint|legacy_model' .

# 只列出 rg 实际会搜索的文件
rg --files
不要把 rg 当成全磁盘取证工具： 默认行为是“项目友好”，不是“无差别扫描”。如果要搜隐藏文件、ignored 文件或二进制文件，需要显式打开对应选项。

2. 核心模型：文件发现、过滤、匹配、输出

很多“rg 搜不到”的问题不在正则，而在文件发现层：ignored、hidden、binary、glob/type 过滤和路径边界先决定了搜索空间。

3. 安装、版本与基本语法

常见 Linux 发行版和 macOS 都能直接安装 ripgrep。AI Infra 环境里，建议把 rg --version 纳入调试记录：是否启用 PCRE2、运行在哪个节点、是否使用容器内工具链，都会影响某些高级匹配能力。

# 查看版本与特性，PCRE2 可用时会显示相关信息
rg --version

# Ubuntu/Debian
sudo apt-get update
sudo apt-get install ripgrep

# Fedora/RHEL 系
sudo dnf install ripgrep

# macOS
brew install ripgrep
语法含义例子
rg PATTERN在当前目录递归搜索rg 'CUDA out of memory'
rg PATTERN PATH...只搜索指定路径rg 'NCCL WARN' /var/log/training
command | rg PATTERN搜索标准输入kubectl logs pod/x | rg 'error|timeout'
rg -e PATTERN模式以 - 开头时避免被当作选项rg -e '-Xmx' config/
rg -- PATTERN显式结束选项解析rg -- '-foo'
版本提示： 本页示例按现代 ripgrep 行为编写；本地验证环境为 ripgrep 15.1.0，并启用了 PCRE2。

4. 第一组高频搜索命令

先掌握这组命令，就能覆盖大多数代码审计、训练失败定位和服务日志 triage。

看匹配位置
rg -n 'pattern' 输出文件、行号和匹配行。多数场景下 -n 是默认可见的，但显式写出来更适合脚本和教程。
看上下文
rg -C 3 'error' 显示前后 3 行，适合看堆栈、异常上下文和配置块。
列文件
rg -l 'pattern' 只列匹配文件，适合后续用编辑器、xargs 或审查脚本处理。
数匹配
rg -c 'pattern' 按文件计数，适合快速判断异常是否集中在某些日志。
# 训练日志：看 OOM 附近上下文
rg -n -C 4 'CUDA out of memory|OutOfMemoryError|OOM' logs/train/

# 推理服务：只看请求失败、超时、重试
rg -n 'timeout|deadline exceeded|connection reset|5[0-9]{2}' logs/inference/

# 代码仓库：找所有使用旧模型路径的文件
rg -l '/mnt/models/legacy|legacy_model_name' .

# 只输出匹配片段，例如抽取 rank 编号
rg -o 'rank[=: ][0-9]+' logs/

# 搜索 stdin，适合快速过滤运行中命令输出
journalctl -u kubelet --since '1 hour ago' | rg -n 'image pull|OOMKilled|Back-off'

5. 正则、字面量、大小写与 PCRE2

rg 默认把模式当正则表达式。日志里很多关键字包含 .、[、]、?、+ 等正则元字符，如果你只是想按字面文本搜，用 -F 更安全。

选项用途AI Infra 示例
-F / --fixed-strings字面量搜索，不解释正则rg -F 'ncclCommInitRank() failed' logs/
-i忽略大小写rg -i 'error|failed|timeout' logs/
-S智能大小写：模式含大写则区分，否则不区分rg -S 'cuda' src/
-w按单词边界匹配rg -w 'rank' logs/
-x整行匹配rg -x 'READY' healthcheck.log
-P使用 PCRE2，支持 look-around 等高级能力rg -P '(?<=latency_ms=)\d+'
# 正则：匹配 GPU 编号和错误码
rg -n 'GPU [0-9]+|cudaError[A-Za-z]+' logs/

# 字面量：方括号不再需要转义
rg -F '[rank 0] NCCL WARN' logs/

# 多个模式：任一模式命中就输出
rg -e 'NCCL WARN' -e 'CUDA error' -e 'collective timeout' logs/

# 模式文件：把排障关键字维护成一行一个
cat > /tmp/ai-infra-errors.txt <<'EOF2'
CUDA out of memory
NCCL WARN
collective timeout
OOMKilled
EOF2
rg -f /tmp/ai-infra-errors.txt logs/

# PCRE2 lookbehind：只抽取字段值
rg -P -o '(?<=step=)\d+' train.log
正则安全感： 如果你不确定某段日志是否含正则元字符，先用 -F；如果你需要 lookbehind、lookahead 或更接近 Perl 的语法，再用 -P。

6. 输出控制：行号、列号、上下文、统计

搜索不是只为了看到匹配行。排障时常需要上下文、列号、计数、排序、统计信息，或者只需要文件名。

输出目标命令说明
定位到文件和行rg -n 'pattern'适合跳转到代码或日志位置
定位到列rg -n --column 'pattern'适合编辑器集成和精确匹配
显示前后文rg -A 3 -B 2 'pattern'-C 3 是前后各 3 行
只列文件rg -l 'pattern'适合下游批处理
按文件计数rg -c 'pattern'适合找异常集中点
总览性能rg --stats 'pattern'看扫描文件数、匹配数、耗时
稳定输出顺序rg --sort path 'pattern'并行搜索默认输出顺序可能变化
# 堆栈排障：显示错误前 2 行、后 8 行
rg -n -B 2 -A 8 'Traceback|Exception|RuntimeError' logs/

# 只看每个文件有多少 timeout
rg -c 'timeout|deadline exceeded' logs/

# 看搜索范围和耗时
rg --stats 'NCCL WARN|CUDA error' logs/

# 用稳定路径排序，方便生成可 diff 的报告
rg --sort path -n 'deprecated_api|legacy_config' src/ configs/
并行与排序： rg 为速度会并行搜索，输出顺序不一定稳定。报告、CI、快照测试里优先加 --sort path。

7. ignore 规则：为什么有些文件搜不到

ripgrep 的速度很大一部分来自“少搜不该搜的文件”。这对项目开发友好，但做事故排障时必须知道如何放宽过滤。

ignore 规则实战

需求命令注意
查看 rg 会搜索哪些文件rg --files排查“为什么没搜到”的第一步
包含隐藏文件和目录rg --hidden 'pattern'仍会尊重 ignore；.git 可能需要额外排除
忽略 ignore 规则rg --no-ignore 'pattern'会扩大搜索范围，可能很慢
快速放宽一级rg -u 'pattern'等价于不尊重 ignore
放宽到隐藏文件rg -uu 'pattern'相当于 no-ignore + hidden
连二进制也扫rg -uuu 'pattern'风险高，输出可能污染终端
解释跳过原因rg --debug 'pattern'看 ignore、glob、binary 等决策
# 先看候选文件里有没有目标日志
rg --files logs/ | rg 'worker-42|rank_7'

# 搜隐藏配置，但不要扫 .git
rg --hidden -g '!.git/' 'HF_TOKEN|NCCL_' .

# 事故现场需要搜 ignored 日志
rg -n -u 'CUDA out of memory|NCCL WARN' logs/

# 仍然搜不到时，看调试输出
rg --debug 'target_pattern' logs/ 2>/tmp/rg-debug.txt
sed -n '1,80p' /tmp/rg-debug.txt
-uuu 慎用： 它会放开 ignore、hidden 和 binary 限制。生产机器上应先限制路径和 glob，例如 rg -uuu -g '*.log' 'pattern' /var/log/app/。

8. glob 与文件类型过滤

AI Infra 仓库往往混合 Python、C++、CUDA、YAML、Helm、Terraform、日志和数据文件。用 glob/type 先收窄候选文件，比写复杂正则更可靠。

命令作用例子
-g '*.py'只包含 Python 文件rg -g '*.py' 'torch.compile'
-g '!*.ipynb'排除 notebookrg -g '!*.ipynb' 'wandb'
-t py按内置类型搜索rg -t py 'DataLoader'
-T json排除某类型rg -T json 'secret'
--type-list查看可用类型rg --type-list | rg 'cuda|python|yaml'
--type-add临时添加类型rg --type-add 'cu:*.cu' -t cu '__global__'
# 只搜 Python 和 YAML，找服务端口配置
rg -n -g '*.py' -g '*.yaml' -g '*.yml' 'port|grpc|http' .

# 排除生成目录和大输出目录
rg -n -g '!outputs/**' -g '!wandb/**' -g '!checkpoints/**' 'learning_rate|batch_size' .

# 搜 CUDA/C++ 相关源码
rg --type-add 'cuda:*.cu' --type-add 'cuda:*.cuh' -t cuda -t cpp 'cudaMalloc|ncclAllReduce' .

# rg 的 glob 优先级很高，可用于重新包含 ignore 之外的路径
rg -n -g 'logs/**/*.log' 'OOM|timeout' .
glob 心法： -g 作用在文件路径上，不作用在匹配行上；“哪些文件进来”与“哪些行匹配”要分开思考。

9. AI 代码仓库检索套路

排查 AI 训练或推理问题时，常见任务不是“找一个字符串”，而是沿着配置、调用、环境变量、模型路径和错误处理链路快速建立上下文。

配置入口
搜索 batch_size、world_size、tensor_parallel、NCCL_、CUDA_VISIBLE_DEVICES。
调用链
搜索函数名、类名、RPC 路由、Kubernetes service name、模型 registry key。
风险点
搜索 TODO、deprecated、unsafe、eval(、硬编码路径、临时 fallback。
# 从环境变量入手
rg -n 'NCCL_|CUDA_VISIBLE_DEVICES|TORCH_DISTRIBUTED_DEBUG|HF_HOME|TRANSFORMERS_CACHE' .

# 找训练并行策略
rg -n 'world_size|rank|local_rank|tensor_parallel|pipeline_parallel|fsdp|deepspeed' src/ configs/

# 找推理服务路由和模型名
rg -n 'model_name|model_path|served_model|chat/completions|grpc|uvicorn|gunicorn' .

# 找潜在危险实现
rg -n -t py 'eval\(|exec\(|pickle\.loads|subprocess\.(run|Popen)|shell=True' .

# 只看匹配文件并交给编辑器或审查流程
rg -l 'legacy_tokenizer|old_checkpoint' src/ configs/
代码检索建议： 先宽泛搜概念词，再用 -g、-t、-C 收窄上下文；不要一开始就写过于聪明的正则。

10. 训练、推理与系统日志排障

日志排障的目标是缩短“第一条错误、根因错误、连锁错误”之间的距离。rg 的上下文、计数和路径过滤很适合先做粗筛，再进入单个日志文件深挖。

场景搜索关键词推荐命令形态
GPU 显存OOM、CUDA out of memory、allocationrg -n -C 4 'OOM|CUDA out of memory'
NCCL 通信NCCL WARN、unhandled system error、collective timeoutrg -n -C 6 'NCCL WARN|timeout'
容器调度OOMKilled、Evicted、Back-off、ImagePullBackOffkubectl describe pod ... | rg -n -C 3 'OOMKilled|Back-off'
推理延迟latency、deadline、queue、429、503rg -n 'latency_ms|deadline|503'
节点问题Xid、mlx、ib、PCIe、resetjournalctl -k | rg -n 'Xid|mlx|PCIe|reset'
# 多个 rank 日志中找第一批异常
rg -n --sort path -C 3 'Traceback|NCCL WARN|CUDA error|OOM' runs/exp-042/

# 统计各个 worker 日志里的 timeout 数量
rg -c 'timeout|deadline exceeded' runs/exp-042/worker-*.log

# 只抽取 step、rank、loss 字段附近信息
rg -n -o 'step=[0-9]+|rank[=: ][0-9]+|loss=[0-9.e+-]+' train.log

# 从 systemd 日志中过滤最近一小时的 GPU/网络错误
journalctl --since '1 hour ago' | rg -n 'NVRM|Xid|mlx5|ib_core|PCIe|GPU has fallen off the bus'
日志顺序提醒： 多文件并行搜索的输出不是严格时间线。需要事故时间线时，先按文件/时间排序，或把候选行导出后再按时间戳排序。

11. 多行搜索与跨行异常

默认情况下，rg 按行匹配。Python traceback、Java stack trace、NCCL 多行错误、YAML 配置块经常需要跨行上下文。多数时候 -C 已经足够；只有确实要“一个匹配跨越换行”时才用 -U / --multiline。

方式适合场景示例
-C NUM看上下文，不改变匹配语义rg -C 10 'Traceback'
-U允许模式跨越多行rg -U 'Traceback(.|\n)*RuntimeError'
--multiline-dotall让 . 匹配换行rg -U --multiline-dotall 'BEGIN.*END'
-P -UPCRE2 多行高级正则rg -P -U 'Traceback(?s:.)*?CUDA out of memory'
# 推荐优先级 1：上下文足够时不要跨行匹配
rg -n -C 12 'Traceback|RuntimeError|CUDA out of memory' logs/

# 跨行匹配：从 Traceback 到 CUDA OOM
rg -n -U 'Traceback(.|\n)*CUDA out of memory' logs/

# PCRE2 + 非贪婪：更精确，但依赖 PCRE2
rg -n -P -U 'Traceback(?s:.)*?CUDA out of memory' logs/

# YAML 配置块粗查：找包含 tensor_parallel 的 model 块
rg -n -U 'model:\n(?:  .+\n)*  tensor_parallel:' configs/
多行搜索风险： -U 会改变内存和性能特征。对超大日志先限制路径、glob 和文件大小，例如 rg -U --max-filesize 200M -g '*.log'。

12. JSON 输出与机器可读管道

--json 会输出结构化事件，适合交给 Python、日志平台导入脚本或 CI 审查工具。开启 JSON 时，一些人类输出选项会失效，并且 --stats 会隐式启用。

# 输出 JSON Lines，每行一个事件
rg --json 'NCCL WARN|CUDA error|OOM' logs/ > rg-events.jsonl

# 用 jq 查看匹配事件中的路径、行号和文本
rg --json 'timeout' logs/ |
  jq -r 'select(.type=="match") |
         [.data.path.text, .data.line_number, .data.lines.text] | @tsv'

# 没有 jq 时，用 Python 处理 JSON Lines
rg --json 'CUDA out of memory' logs/ |
python3 -c 'import sys,json
for line in sys.stdin:
    ev=json.loads(line)
    if ev.get("type")=="match":
        d=ev["data"]
        print(d["path"]["text"], d["line_number"], d["lines"]["text"].rstrip(), sep=":")'
事件类型含义用途
begin开始搜索某个文件审计扫描范围
match一个匹配事件抽取路径、行号、匹配文本
context上下文行保留错误附近证据
end文件搜索结束统计每个文件的匹配情况
summary总体统计生成报告和 CI 证据
自动化边界： 给程序消费时优先用 --json，不要解析带颜色、heading 和上下文分隔符的人类输出。

13. 二进制、压缩包与超大日志

AI Infra 日志目录可能包含 checkpoint、core dump、protobuf、sqlite、压缩日志和 GB 级文本。ripgrep 默认跳过二进制文件，这是保护终端和性能的正确默认值。

需求命令说明
把二进制当文本搜rg -a 'pattern'适合确认某些 protobuf、dump 中是否有明文片段
显式按二进制策略搜rg --binary 'pattern'可让 -l 尽早停在二进制匹配
搜索压缩日志rg -z 'pattern' logs/支持常见压缩格式，依赖解压工具在 PATH 中
限制大文件rg --max-filesize 200M 'pattern'避免误扫超大日志或数据文件
指定编码rg --encoding utf-16le 'pattern'处理非 UTF-8 文本
# 搜压缩后的轮转日志
rg -z -n 'NCCL WARN|CUDA error|OOMKilled' /var/log/ml/

# 事故现场先避免超大文件拖慢 triage
rg -n --max-filesize 500M 'timeout|OOM|Xid' /data/runs/

# 只确认 dump 里是否含某个明文 endpoint，不打印整片二进制
rg -a -l 'old-api.internal' dumps/

# 先列大文件，再决定是否单独处理
find logs/ -type f -size +1G -print
终端保护： 不要随手 rg -a 扫未知目录。二进制内容可能包含控制字符、密钥片段或大量不可读输出；优先配合 -l、路径限制和 --max-filesize。

14. 集群日志 triage 工作流

集群排障要避免“在所有日志里盲搜所有词”。先限制范围，再统计分布，再深挖上下文，最后产出可复查证据。

可复制的集群 triage 模板

# 0. 记录上下文
date
hostname
pwd

# 1. 确认候选文件，避免搜错目录
rg --files runs/job-813/ | rg 'worker|rank|stderr|stdout|log'

# 2. 粗筛异常分布
rg -c --sort path 'Traceback|CUDA out of memory|NCCL WARN|collective timeout|OOMKilled|Xid' runs/job-813/

# 3. 找最可疑文件
rg -l 'CUDA out of memory|NCCL WARN|collective timeout' runs/job-813/ > /tmp/suspect-logs.txt
sed -n '1,20p' /tmp/suspect-logs.txt

# 4. 对单个文件保留证据片段
rg -n -C 10 'CUDA out of memory|NCCL WARN|collective timeout' "$(sed -n '1p' /tmp/suspect-logs.txt)"

# 5. 机器可读报告，供后续脚本归档
rg --json 'CUDA out of memory|NCCL WARN|collective timeout' runs/job-813/ > /tmp/job-813-rg.jsonl
证据优先： 事故复盘里最有价值的不是“我搜过”，而是能复现的命令、受影响文件、匹配行号和上下文片段。

15. rg vs grep/ag/find 怎么选

rg 不是替代所有工具。它适合高速递归文本搜索；如果你要严格 POSIX 环境、纯文件查找、复杂字段统计或结构化数据解析，应选择更匹配的工具。

工具优势限制AI Infra 建议
rg快，默认尊重 ignore，输出友好，支持 JSON、glob、types不是 POSIX 标配；默认不搜 hidden/ignored/binary代码仓库和日志目录首选
grep几乎所有 Linux 都有，适合脚本兼容递归搜索和 ignore 体验弱救援环境、极简容器、POSIX 脚本
ag历史上很快，代码搜索友好生态活跃度和功能完整性通常不如 rg已有老工具链时可用，新环境优先 rg
find文件发现强，按时间/大小/权限过滤不负责内容搜索先找大日志、老文件、异常权限，再交给 rg
awk字段处理和统计强递归文件发现不是重点rg 先筛日志，再 awk 汇总字段
jqJSON 解析可靠只适合 JSONrg --json 或应用 JSON 日志后续处理
# rg 搜内容，find 找文件属性：组合更强
find logs/ -type f -mtime -1 -name '*.log' -print0 |
  xargs -0 rg -n 'NCCL WARN|CUDA error'

# rg 搜出候选 JSON 日志，再交给 jq 做结构化过滤
rg -l '"level":"error"' logs/ |
  xargs jq -r 'select(.level=="error") | [.ts,.msg] | @tsv'

16. 安全管道与批量操作边界

rg 经常作为“候选文件生成器”。危险不在 rg 本身，而在后面接的 xargs rm、sed -i、远程执行或批量上传。原则是：先打印、再抽样、再 dry-run、最后执行。

目标推荐做法避免
文件名含空格/换行rg -0 -l 'pattern' | xargs -0 ...直接按换行分割未知文件名
批量替换先 rg -l，再单文件 diff dry-run直接 xargs sed -i
删除文件先输出候选列表并人工审查rg -l ... | xargs rm
跨节点执行限制节点、路径和时间窗，保存命令输出在所有节点扫根目录
# 安全列文件：NUL 分隔，适合任意文件名
rg -0 -l 'old-api.internal' configs/ | xargs -0 -n 1 printf 'candidate: %s\n'

# 批量替换前 dry-run：先对一个文件看 diff
first_file=$(rg -l 'old-api.internal' configs/ | sed -n '1p')
sed 's/old-api.internal/new-api.internal/g' "$first_file" | diff -u "$first_file" -

# 真要批量替换：建议在 Git 干净、已审查文件列表后执行
rg -0 -l 'old-api.internal' configs/ |
  xargs -0 sed -i.bak 's/old-api.internal/new-api.internal/g'

# 删除前只打印，不删除
rg -0 -l 'DO_NOT_USE_MODEL' experiments/ |
  xargs -0 -n 1 printf 'would review: %s\n'
破坏性操作底线： rg 可以快速生成大量路径，因此后接破坏性命令必须增加路径限制、NUL 分隔、抽样检查、备份或版本控制审查。

17. 排障：无结果、太慢、输出异常

排障顺序：候选文件 → 匹配模式 → 输出格式 → 性能边界 → 安全管道。

常见问题清单

搜不到 ignored 文件
先 rg --files | rg target，再尝试 -u、--hidden、--debug。
正则被 shell 吃掉
模式优先用单引号包裹；搜索单引号本身时再考虑双引号或转义。
模式以短横线开头
用 rg -e '-Xmx' 或 rg -- '-Xmx'。
速度突然变慢
检查是否用了 -uuu、-U、-P、-z、--pre 或扫了超大目录。
输出顺序不稳定
报告和 CI 使用 --sort path；极端情况下可用 -j 1 降低并行性。
中文或非 UTF-8 异常
确认文件编码；必要时指定 --encoding，或先用专用工具转码。
JSON 管道解析失败
不要混入普通输出；让 rg --json 直接进 jq 或 Python。
颜色控制字符污染日志
重定向时通常自动关闭颜色；脚本中可显式 --color never。
# 最小化验证正则：先不用真实大日志
printf 'rank=7 NCCL WARN timeout\nrank=8 ok\n' | rg -n 'rank=[0-9]+.*WARN'

# 查看某个目标文件是否在 rg 候选集合中
rg --files . | rg -F 'path/to/target.log'

# 解释为什么跳过
rg --debug -F 'needle' . 2>/tmp/rg-debug.txt
rg -n 'ignore|hidden|binary|glob|skip' /tmp/rg-debug.txt

# 慢查询加边界
rg --stats --max-filesize 200M -g '*.log' -n 'needle' logs/
